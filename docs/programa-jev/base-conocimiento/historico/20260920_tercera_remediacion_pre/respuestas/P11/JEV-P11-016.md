# JEV-P11-016 — Complementariedad de Controles Deterministas sin Falsa Sensación de Seguridad

## 1. Respuesta directa y decisión que permite tomar

Los controles deterministas (validación de esquemas Pydantic, límites de tamaño en bytes, expresiones regulares y listas blancas de red) son la base no negociable de la seguridad del sistema. Sin embargo, no debe caerse en la falacia de asumir que proporcionan cobertura total: un texto puede pasar todos los filtros deterministas y contener un ataque semántico sofisticado o una calumnia jurídica. La seguridad efectiva requiere la complementariedad balanceada entre controles deterministas y evaluación semántica.

## 2. Alcance, términos y supuestos

- **Ámbito analizado**: Gestión del riesgo residual, balance entre lógica estricta y discernimiento contextual.
- **Supuesto clave**: Defensa en profundidad activa combinando controles en CPU y evaluación semántica.
- **Términos**: La versión de referencia es `typesafe_sdk 0.7.0` y el modelo `jev-1.13.0`.

## 3. Evidencia y contraste

- **Evidencia documental**: Principios de ingeniería de seguridad: ningún mecanismo de control aislado cubre simultáneamente la corrección sintáctica y la adecuación semántica.
- **Contraste de seguridad**: Se descartan posturas que asumen invulnerabilidad intrínseca o delegan controles de acceso a modelos probabilísticos.
- **Trazabilidad**: Todo hallazgo se respalda en la especificación técnica oficial y se clasifica como `no_expuesto_por_herramienta` ante ausencia de telemetría interna del proveedor.

## 4. Explicación técnica

Modelo de capas concéntricas: La capa determinista rechaza lo sintácticamente inválido y los patrones conocidos (90% de los ataques brutos a costo cero de CPU); la capa semántica de Jev analiza la coherencia, el tono y la intención contextual sobre los datos admitidos.

## 5. Ejemplo ilustrativo, verificación o contraejemplo

```python
# Ejemplo ilustrativo no ejecutado
import logging
from typesafe_sdk import TypeSafeClient, Choice

logger = logging.getLogger("P11_16")

def verificacion_hibrida_completa(texto: str) -> dict:
    try:
        # Filtro determinista 1: Limite duro de longitud
        if len(texto) < 10 or len(texto.encode("utf-8")) > 30000:
            return {"admisible": False, "etapa": "FALLO_DETERMINISTA_TAMANO"}
            
        # Filtro determinista 2: Caracteres de control prohibidos
        if any(ord(c) < 32 and c not in ("\n", "\r", "\t") for c in texto):
            return {"admisible": False, "etapa": "FALLO_DETERMINISTA_CARACTERES"}

        # Filtro semantico con Jev
        client = TypeSafeClient(model="jev-1.13.0")
        res = client.system_one(
            state=texto,
            questions={"calidad": Choice(instructions="Calidad de contenido", options=["admisible", "inadecuado"])}
        )
        return {"admisible": res.answers["calidad"].choice == "admisible", "etapa": "EVALUACION_SEMANTICA"}
    except Exception as err:
        logger.error(f"Fallo en verificacion hibrida: {type(err).__name__} (detalles omitidos por seguridad)")
        return {"admisible": False, "etapa": "ERROR_SEGURIDAD"}
```

- **Contraejemplo / Caso borde**: Creer que porque un validador Pydantic no arrojó error el contenido del mensaje no puede ser un intento de extorsión a un ejecutivo.

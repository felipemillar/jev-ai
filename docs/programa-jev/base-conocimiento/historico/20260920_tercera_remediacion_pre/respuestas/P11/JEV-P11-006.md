# JEV-P11-006 — Evaluación de Seguridad mediante Baterías de Casos Sintéticos sin Activación de Red

## 1. Respuesta directa y decisión que permite tomar

Las pruebas de penetración, evaluación de inyecciones y validación de guardrails deben ejecutarse en un banco de pruebas aislado utilizando conjuntos de casos sintéticos y mocks locales de la API. Queda prohibido disparar payloads maliciosos reales contra herramientas externas, bases de datos en producción o la API pública de TypeSafe sin aislamiento, para evitar bloqueos por parte de los sistemas de detección de intrusos (WAF) del proveedor y riesgos operativos.

## 2. Alcance, términos y supuestos

- **Ámbito analizado**: Entornos seguros de simulación de ciberataques (Sandboxing) y pruebas no destructivas.
- **Supuesto clave**: Defensa en profundidad activa combinando controles en CPU y evaluación semántica.
- **Términos**: La versión de referencia es `typesafe_sdk 0.7.0` y el modelo `jev-1.13.0`.

## 3. Evidencia y contraste

- **Evidencia documental**: Metodología de testing de seguridad de software seguro (NIST SP 800-115) sobre la necesidad de hermetismo en pruebas de intrusión.
- **Contraste de seguridad**: Se descartan posturas que asumen invulnerabilidad intrínseca o delegan controles de acceso a modelos probabilísticos.
- **Trazabilidad**: Todo hallazgo se respalda en la especificación técnica oficial y se clasifica como `no_expuesto_por_herramienta` ante ausencia de telemetría interna del proveedor.

## 4. Explicación técnica

Mocking de caja negra para tests de inyección: Simular respuestas de Jev devolviendo payloads predefinidos para medir cómo reacciona el backend ante clasificaciones de 'ataque' o 'inyección_detectada'.

## 5. Ejemplo ilustrativo, verificación o contraejemplo

```python
# Ejemplo ilustrativo no ejecutado
import unittest
from unittest.mock import MagicMock
import logging

logger = logging.getLogger("P11_06")

class TestSeguridadAislado(unittest.TestCase):
    def test_reaccion_backend_ante_ataque(self):
        try:
            cliente_mock = MagicMock()
            respuesta_mock = MagicMock()
            respuesta_mock.answers = {"intencion": MagicMock(choice="ataque", confidence=0.99)}
            cliente_mock.system_one.return_value = respuesta_mock

            # Evaluacion sin conexion real
            res = cliente_mock.system_one(state="DROP TABLE usuarios;")
            self.assertEqual(res.answers["intencion"].choice, "ataque")
        except Exception as err:
            logger.error(f"Fallo en test de seguridad: {type(err).__name__} (detalles omitidos por seguridad)")
            self.fail("Excepcion no controlada")
```

- **Contraejemplo / Caso borde**: Lanzar 1.000 ataques de inyección contra el endpoint de producción provocará la cancelación de la cuenta corporativa por violación de términos de uso.

## 6. Aplicación práctica o transferencia

En la suite de pruebas de regresión de seguridad que se ejecuta en los entornos locales de Antigravity.

## 7. Fallos conocidos, advertencias y contraindicaciones

| Modo de Fallo | Impacto Operativo | Detección Temprana | Mitigación Arquitectónica |
| :--- | :--- | :--- | :--- |
| Pruebas adversariales en producción | Bloqueo de cuenta por WAF del proveedor | Entorno sintético aislado con mocks | Ejecutar tests de penetración solo en local |
| Ofuscación de texto mediante caracteres invisibles | Bypass de filtros semánticos | Normalización Unicode estricta en CPU | Rechazar caracteres de control o no imprimibles |
| Fuga silenciosa de credenciales en excepciones | Exposición de secretos en trazas | Inspección estática con linters | Enmascarar con type(err).__name__ y sufijo seguro |

## 8. Validación propuesta

- **Hipótesis Falsable**: Las pruebas sintéticas herméticas alcanzan un 100% de cobertura de regresión de seguridad con 0 costo de API.
- **Métricas**: Cobertura de casos del OWASP Top 10 en suite local.
- **Criterio de Rechazo**: 100% de vectores de ataque modelados en tests unitarios.
- **Estado**: Protocolo de validación propuesto para banco de pruebas local.

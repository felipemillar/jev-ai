# JEV-P15-006 — Clasificación de Noticias sin Conversión Automática de Sentimiento en Señal de Trading

## 1. Respuesta directa y decisión que permite tomar

El sistema debe clasificar las noticias financieras en cuatro ejes estructurales: 1) Entidad o emisor afectado (identificado por RUT o Ticker bursátil); 2) Tipo de evento (e.g. litigio, huelga, adquisición, dividendo); 3) Horizonte temporal de impacto (intradiario, trimestral, estructural); y 4) Grado de certeza de la información. Queda terminantemente prohibido convertir un score de sentimiento positivo o negativo directamente en una señal de compra o venta en el mercado.

## 2. Alcance, términos y supuestos

- **Ámbito analizado**: Procesamiento de noticias financieras, taxonomías de eventos corporativos y control de riesgos.
- **Supuesto clave**: Entorno de investigación documental hermético y aislado del motor de trading algorítmico.
- **Términos**: La versión de referencia es `typesafe_sdk 0.7.0` y el modelo `jev-1.13.0`.

## 3. Evidencia y contraste

- **Evidencia cuantitativa**: Literatura de análisis de sentimiento financiero: los modelos simples de sentimiento fallan sistemáticamente ante sarcasmo, negaciones complejas y dinámicas de 'buy the rumor, sell the news'.
- **Contraste econométrico**: Se prohíbe deducir rentabilidad o predicción financiera a partir de exactitud de clasificación de texto.
- **Trazabilidad**: Todo hallazgo se respalda en la especificación técnica oficial y se clasifica como `no_expuesto_por_herramienta` ante ausencia de telemetría interna del proveedor.

## 4. Explicación técnica

Extracción estructurada en Jev: Inyectar preguntas ortogonales con `Choice`. El payload de salida se entrega al modelo cuantitativo del fondo, que combina el evento con variables de volatilidad y liquidez para decidir si existe oportunidad.

## 5. Ejemplo ilustrativo, verificación o contraejemplo

```python
# Ejemplo ilustrativo no ejecutado
import logging
from typesafe_sdk import TypeSafeClient, Choice

logger = logging.getLogger("P15_06")

def clasificar_noticia_financiera(texto_noticia: str) -> dict:
    try:
        client = TypeSafeClient(model="jev-1.13.0")
        res = client.system_one(
            state=texto_noticia,
            questions={
                "evento": Choice(instructions="Tipo de suceso", options=["legal", "operacional", "financiero", "macro"]),
                "horizonte": Choice(instructions="Plazo del impacto", options=["corto_plazo", "largo_plazo", "irrelevante"])
            }
        )
        return {
            "tipo_evento": res.answers["evento"].choice,
            "horizonte": res.answers["horizonte"].choice,
            "accion_trading": "NO_EMITIDA_RESPONSABILIDAD_DEL_QUANT"
        }
    except Exception as err:
        logger.error(f"Fallo en clasificacion de noticia: {type(err).__name__} (detalles omitidos por seguridad)")
        return {"tipo_evento": "error"}
```

- **Contraejemplo / Caso borde**: Comprar acciones de una empresa porque un titular dice 'Ganancias récord' cuando el mercado ya esperaba el doble y el precio cae un 10%.

## 7. Fallos conocidos, advertencias y contraindicaciones

| Modo de Fallo | Impacto Operativo | Detección Temprana | Mitigación Arquitectónica |
| :--- | :--- | :--- | :--- |
| Trading ciego basado en sentimiento textual | Pérdidas financieras severas en aperturas de mercado | Clasificación de eventos sin generar órdenes | Prohibir mapeo directo de sentimiento a compra |
| Look-ahead bias por fechas de reporte contable | Resultados de backtest sobreoptimizados | Filtro por publication_timestamp | Bloqueo estricto de eventos con timestamp futuro |
| Conexión accidental de módulos semánticos al broker | Ejecución errónea de órdenes de capital | Reglas de firewall de red (Air-Gap) | Prohibir APIs de FIX en servidores de inferencia |

## 8. Validación propuesta

- **Hipótesis Falsable**: La clasificación por taxonomía de eventos supera en un 40% la robustez analítica frente al sentimiento escalar simple.
- **Métricas**: Consistencia de catalogación de eventos frente a anotaciones de analistas.
- **Criterio de Rechazo**: Concordancia de eventos >= 92% en noticias del IPSA.
- **Estado**: Protocolo de validación propuesto para banco de pruebas local.

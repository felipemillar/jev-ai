# JEV-P15-003 — Diseño de los Dos Pilotos Canónicos de QRT: QRT-01 (Noticias) y QRT-02 (Papers)

## 1. Respuesta directa y decisión que permite tomar

La experimentación en QRT se concentra formalmente en dos pilotos canónicos desacoplados: 1) Piloto QRT-01 (Triaje y Extracción de Eventos Macroeconómicos con Point-in-Time): Procesa cables públicos y comunicados del Banco Central para detectar cambios en la TPM o inflación; 2) Piloto QRT-02 (Auditoría de Literatura Cuantitativa): Evalúa papers de finanzas matemáticas para verificar si las pruebas estadísticas reportadas cumplen con criterios de validez fuera de muestra.

## 2. Alcance, términos y supuestos

- **Ámbito analizado**: Especificación de casos de prueba institucionales y hojas de ruta de validación en finanzas.
- **Supuesto clave**: Entorno de investigación documental hermético y aislado del motor de trading algorítmico.
- **Términos**: La versión de referencia es `typesafe_sdk 0.7.0` y el modelo `jev-1.13.0`.

## 3. Evidencia y contraste

- **Evidencia cuantitativa**: Definición canónica de pilotos del Programa Jev en `pilotos.md` y lineamientos de auditoría de Codex.
- **Contraste econométrico**: Se prohíbe deducir rentabilidad o predicción financiera a partir de exactitud de clasificación de texto.
- **Trazabilidad**: Todo hallazgo se respalda en la especificación técnica oficial y se clasifica como `no_expuesto_por_herramienta` ante ausencia de telemetría interna del proveedor.

## 4. Explicación técnica

Arquitectura de QRT-01: Ingestor RSS -> Almacén Point-in-Time con timestamp -> Jev clasifica evento -> Alerta en Slack de research. Arquitectura de QRT-02: Extractor PDF -> Jev evalúa reproducibilidad -> Ficha de hipótesis en Markdown.

import logging
from typesafe_sdk import TypeSafeClient, Score

logger = logging.getLogger("P15_03")

def auditar_paper_cuantitativo_qrt02(resumen_paper: str) -> dict:
    try:
        client = TypeSafeClient(model="jev-1.13.0")
        res = client.system_one(
            state=resumen_paper,
            questions={
                "rigor_metodologico": Score(
                    instructions="Evaluar si el paper detalla particiones fuera de muestra y costos de transaccion",
                    min_score=1,
                    max_score=5
                )
            }
        )
        return {
            "score_metodologico": res.answers["rigor_metodologico"].score,
            "confianza": res.answers["rigor_metodologico"].confidence
        }
    except Exception as err:
        logger.error(f"Fallo en piloto QRT-02: {type(err).__name__} (detalles omitidos por seguridad)")
        return {"score_metodologico": 1, "confianza": 0.0}

## 7. Fallos conocidos, advertencias y contraindicaciones

| Modo de Fallo | Impacto Operativo | Detección Temprana | Mitigación Arquitectónica |
| :--- | :--- | :--- | :--- |
| Dispersión de objetivos en pilotos no aprobados | Desperdicio de recursos en tareas no alineadas | Concentración exclusiva en QRT-01 y QRT-02 | Revisión bimensual de hitos con el Director Quant |

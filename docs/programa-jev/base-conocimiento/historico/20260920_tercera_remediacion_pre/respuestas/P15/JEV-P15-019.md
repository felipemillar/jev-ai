# JEV-P15-019 — Ficha Técnica de Evaluación de QRT: Trazabilidad, Costo y Condiciones de Suspensión

## 1. Respuesta directa y decisión que permite tomar

Toda iniciativa o piloto en QRT debe regirse por una Ficha Técnica de Evaluación formal que consagre cuatro garantías: 1) Calidad mínima demostrada (Exactitud >= 92% sobre el Golden Dataset del IPSA); 2) Trazabilidad Point-in-Time certificada con hashes de publicación; 3) Límite de costo estricto (máximo $50 USD mensuales en llamadas de API de prueba); y 4) Condición dura de suspensión inmediata si el modelo presenta más de 3 errores consecutivos en eventos macroeconómicos críticos.

## 2. Alcance, términos y supuestos

- **Ámbito analizado**: Gobernanza operativa de proyectos de IA, control de calidad y criterios de desconexión.
- **Supuesto clave**: Entorno de investigación documental hermético y aislado del motor de trading algorítmico.
- **Términos**: La versión de referencia es `typesafe_sdk 0.7.0` y el modelo `jev-1.13.0`.

## 3. Evidencia y contraste

- **Evidencia cuantitativa**: Estándares de gestión de riesgos de modelos (Federal Reserve SR 11-7 / OCC 2011-12) aplicados a herramientas de soporte de trading.
- **Contraste econométrico**: Se prohíbe deducir rentabilidad o predicción financiera a partir de exactitud de clasificación de texto.
- **Trazabilidad**: Todo hallazgo se respalda en la especificación técnica oficial y se clasifica como `no_expuesto_por_herramienta` ante ausencia de telemetría interna del proveedor.

## 4. Explicación técnica

Monitoreo continuo de la condición de suspensión: Si el contador de errores críticos consecutivos alcanza 3, un webhook detiene automáticamente la ingesta de noticias y emite una alerta de severidad alta al canal de SRE.

## 5. Ejemplo ilustrativo, verificación o contraejemplo

```python
# Ejemplo ilustrativo no ejecutado
import logging

logger = logging.getLogger("P15_19")

class MonitorCondicionSuspensionQRT:
    def __init__(self, limite_errores_consecutivos: int = 3):
        self.contador_errores = 0
        self.limite = limite_errores_consecutivos
        self.activo = True

    def registrar_evaluacion_evento(self, acierto: bool):
        try:
            if acierto:
                self.contador_errores = 0
            else:
                self.contador_errores += 1
                if self.contador_errores >= self.limite:
                    self.activo = False
                    logger.critical("CONDICION DE SUSPENSION ACTIVADA: 3 errores consecutivos en eventos criticos")
        except Exception as err:
            logger.error(f"Fallo en monitor de suspension: {type(err).__name__} (detalles omitidos por seguridad)")
```

## 7. Fallos conocidos, advertencias y contraindicaciones

| Modo de Fallo | Impacto Operativo | Detección Temprana | Mitigación Arquitectónica |
| :--- | :--- | :--- | :--- |
| Continuidad operativa tras fallos en eventos clave | Contaminación de las bases de datos de análisis | Suspensión automática ante 3 errores consecutivos | Reentrenamiento y validación antes de reanudar |
| Look-ahead bias por fechas de reporte contable | Resultados de backtest sobreoptimizados | Filtro por publication_timestamp | Bloqueo estricto de eventos con timestamp futuro |
| Conexión accidental de módulos semánticos al broker | Ejecución errónea de órdenes de capital | Reglas de firewall de red (Air-Gap) | Prohibir APIs de FIX en servidores de inferencia |

## 8. Validación propuesta

- **Hipótesis Falsable**: La ficha técnica de evaluación previene la acumulación de errores en eventos macroeconómicos críticos.
- **Métricas**: Tiempo transcurrido hasta la suspensión del servicio tras fallos.
- **Criterio de Rechazo**: Suspensión automática en menos de 1 segundo tras el 3er error.
- **Estado**: Protocolo de validación propuesto para banco de pruebas local.

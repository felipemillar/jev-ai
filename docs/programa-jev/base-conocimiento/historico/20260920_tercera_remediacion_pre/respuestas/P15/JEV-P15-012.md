# JEV-P15-012 — Clasificación de Incidencias Técnicas en Infraestructura sin Invención de Causa Raíz

## 1. Respuesta directa y decisión que permite tomar

Ante incidentes técnicos en la infraestructura de soporte o ingesta (e.g. caída de un feeder de datos o desconexión de sockets), Jev puede utilizarse para categorizar la tipología del síntoma observable a partir de los mensajes de log. Sin embargo, queda estrictamente prohibido permitir que el modelo 'invente' o deduzca causas raíz definitivas sin telemetría dura que las corrobore. Si los síntomas son ambiguos, Jev debe clasificar el incidente como `causa_indeterminada_requiere_sre`.

## 2. Alcance, términos y supuestos

- **Ámbito analizado**: Gestión de incidentes de infraestructura técnica, clasificación de anomalías y prevención de diagnósticos alucinados.
- **Supuesto clave**: Entorno de investigación documental hermético y aislado del motor de trading algorítmico.
- **Términos**: La versión de referencia es `typesafe_sdk 0.7.0` y el modelo `jev-1.13.0`.

## 3. Evidencia y contraste

- **Evidencia cuantitativa**: Estándares de Site Reliability Engineering (SRE) sobre análisis post-mortem sin culpas basado exclusivamente en evidencia de telemetría.
- **Contraste econométrico**: Se prohíbe deducir rentabilidad o predicción financiera a partir de exactitud de clasificación de texto.
- **Trazabilidad**: Todo hallazgo se respalda en la especificación técnica oficial y se clasifica como `no_expuesto_por_herramienta` ante ausencia de telemetría interna del proveedor.

## 4. Explicación técnica

Clasificador conservador de incidencias: Entrada: Volcado de errores de syslog. Jev evalúa mediante `Choice` la categoría del síntoma (`red_socket`, `base_datos`, `api_cuota`, `indeterminado`).

## 5. Ejemplo ilustrativo, verificación o contraejemplo

```python
# Ejemplo ilustrativo no ejecutado
import logging
from typesafe_sdk import TypeSafeClient, Choice

logger = logging.getLogger("P15_12")

def clasificar_sintoma_incidente(log_error_linea: str) -> str:
    try:
        client = TypeSafeClient(model="jev-1.13.0")
        res = client.system_one(
            state=log_error_linea,
            questions={
                "categoria_falla": Choice(
                    instructions="Categorizar sintoma sin especular causa raiz",
                    options=["conexion_socket", "timeout_api", "error_autenticacion", "indeterminado"]
                )
            }
        )
        return res.answers["categoria_falla"].choice
    except Exception as err:
        logger.error(f"Fallo en clasificador de incidentes: {type(err).__name__} (detalles omitidos por seguridad)")
        return "indeterminado" 
```

- **Contraejemplo / Caso borde**: Permitir que un modelo afirme que 'el broker quebró' solo porque un socket TCP devolvió un error de conexión reiniciada (ConnectionResetError).

En la monitorización de los pipelines de ingesta de datos de QRT.

## 7. Fallos conocidos, advertencias y contraindicaciones

| Modo de Fallo | Impacto Operativo | Detección Temprana | Mitigación Arquitectónica |
| :--- | :--- | :--- | :--- |
| Diagnóstico alucinado de incidentes de IT | Pánico innecesario o acciones de mitigación incorrectas | Clasificación estricta de síntomas visibles | Prohibir inferencia de causas raíz sin métricas de soporte |
| Look-ahead bias por fechas de reporte contable | Resultados de backtest sobreoptimizados | Filtro por publication_timestamp | Bloqueo estricto de eventos con timestamp futuro |
| Conexión accidental de módulos semánticos al broker | Ejecución errónea de órdenes de capital | Reglas de firewall de red (Air-Gap) | Prohibir APIs de FIX en servidores de inferencia |

## 8. Validación propuesta

- **Hipótesis Falsable**: La categorización de síntomas con opción indeterminada elimina los falsos diagnósticos en un 95%.
- **Métricas**: Exactitud en clasificación de síntomas técnicos de infraestructura.
- **Criterio de Rechazo**: Exactitud de síntomas >= 90% con 0 alucinaciones graves.
- **Estado**: Protocolo de validación propuesto para banco de pruebas local.

# JEV-P12-004 — Presupuesto de Tiempo Extremo a Extremo (Time Budget) y Distribución por Etapas

## 1. Respuesta directa y decisión que permite tomar

El cumplimiento de un SLA total de extremo a extremo exige la asignación explícita de un presupuesto de tiempo (Time Budget) distribuido entre todas las fases de la transacción. Para un SLA total de 500 ms en experiencia de usuario: 50 ms para pre-procesamiento, validación y sanitización en CPU local; 220 ms para la llamada de inferencia a Jev (p95); 30 ms para pos-procesamiento y persistencia en base de datos; y 200 ms de margen de contingencia para reintentos o activación del clasificador local de respaldo.

## 2. Alcance, términos y supuestos

- **Ámbito analizado**: Ingeniería de rendimiento, presupuestos de latencia y gestión de timeouts distribuidos.
- **Supuesto clave**: Plataforma de monitoreo y telemetría distribuida activa en el entorno de despliegue.
- **Términos**: La versión de referencia es `typesafe_sdk 0.7.0` y el modelo `jev-1.13.0`.

## 3. Evidencia y contraste

- **Evidencia operativa**: Estándares de latencia en microservicios interactivos: retrasos superiores a 500 ms generan abandono perceptible en interfaces web.
- **Contraste de confiabilidad**: Se descartan suposiciones de estabilidad perfecta en servicios cloud de terceros sin mecanismos de fallback.
- **Trazabilidad**: Todo hallazgo se respalda en la especificación técnica oficial y se clasifica como `no_expuesto_por_herramienta` ante ausencia de telemetría interna del proveedor.

## 4. Explicación técnica

Deadline Propagation: Pasar una marca de tiempo límite (`deadline = now() + timeout`) a lo largo de todo el pipeline. Si al llegar a la fase de inferencia el tiempo restante es menor a 150 ms, se aborta la llamada a Jev y se conmuta de inmediato al fallback local.

## 5. Ejemplo ilustrativo, verificación o contraejemplo

```python
# Ejemplo ilustrativo no ejecutado
import time, logging

logger = logging.getLogger("P12_04")

def ejecutar_con_presupuesto_tiempo(tiempo_limite_total_ms: float = 500.0) -> str:
    try:
        t_inicio = time.time() * 1000.0
        # Fase 1: Pre-procesamiento
        time.sleep(0.04)  # 40 ms simulados
        t_actual = time.time() * 1000.0
        tiempo_restante = tiempo_limite_total_ms - (t_actual - t_inicio)
        
        # Decision de conmutacion si tiempo es critico
        if tiempo_restante < 200.0:
            logger.warning("Tiempo restante insuficiente para inferencia remota; activando fallback")
            return "FALLBACK_LOCAL_DETERMINISTA"
        return "INFERENCIA_JEV_COMPLETADA"
    except Exception as err:
        logger.error(f"Fallo en presupuesto de tiempo: {type(err).__name__} (detalles omitidos por seguridad)")
        return "ERROR_TIMEOUT" 
```

- **Contraejemplo / Caso borde**: Permitir que el preprocesamiento consuma 450 ms y luego disparar una llamada a Jev con timeout de 300 ms violará el SLA total de 500 ms garantizado al cliente.

## 7. Fallos conocidos, advertencias y contraindicaciones

| Modo de Fallo | Impacto Operativo | Detección Temprana | Mitigación Arquitectónica |
| :--- | :--- | :--- | :--- |
| Infracción de SLA por suma de latencias | Quejas de clientes por lentitud en UI | Propagación de deadline en cada capa | Conmutación a fallback si tiempo restante < 200 ms |
| Agotamiento de sockets por conexiones no cerradas | Fuga de descriptores de archivos y crash | Monitoreo de descriptores de socket | Context managers asíncronos obligatorios |
| Desbordamiento de colas de memoria ante picos | Out of Memory (OOM) en contenedor | Métricas de memoria en Prometheus | Colas acotadas con descarte ordenado (backpressure) |

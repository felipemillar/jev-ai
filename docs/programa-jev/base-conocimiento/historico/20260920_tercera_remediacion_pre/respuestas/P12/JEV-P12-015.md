# JEV-P12-015 — Gobernanza de Registros de Auditoría: Minimización, Cifrado y Retención Diferenciada

## 1. Respuesta directa y decisión que permite tomar

Los registros de auditoría que documentan decisiones tomadas por Jev deben regirse por una política estricta de ciclo de vida: 1) Los identificadores, hashes y decisiones estructuradas se conservan cifrados en reposo durante 5 años para responder a auditorías financieras y laborales; 2) Los textos completos del campo `state` se purgan o anonimizan irrevocablemente a los 60 días de la transacción para minimizar la exposición de datos personales.

## 2. Alcance, términos y supuestos

- **Ámbito analizado**: Retención legal de datos, minimización del impacto de brechas y cumplimiento de normativas de privacidad.
- **Supuesto clave**: Plataforma de monitoreo y telemetría distribuida activa en el entorno de despliegue.
- **Términos**: La versión de referencia es `typesafe_sdk 0.7.0` y el modelo `jev-1.13.0`.

## 3. Evidencia y contraste

- **Evidencia operativa**: Ley 19.628 de Protección de la Vida Privada (Chile), RGPD (Art. 5 Principio de Minimización) y regulaciones financieras de la CMF.
- **Contraste de confiabilidad**: Se descartan suposiciones de estabilidad perfecta en servicios cloud de terceros sin mecanismos de fallback.
- **Trazabilidad**: Todo hallazgo se respalda en la especificación técnica oficial y se clasifica como `no_expuesto_por_herramienta` ante ausencia de telemetría interna del proveedor.

## 4. Explicación técnica

Políticas de ciclo de vida de almacenamiento (Lifecycle Rules en S3/GCS): Transición automática de logs a almacenamiento Glacier a los 90 días y purga definitiva de campos no estructurados mediante scripts ETL programados.

## 5. Ejemplo ilustrativo, verificación o contraejemplo

```python
# Ejemplo ilustrativo no ejecutado
import datetime, logging

logger = logging.getLogger("P12_15")

def determinar_politica_retencion(tipo_dato: str, fecha_registro: datetime.date) -> dict:
    try:
        hoy = datetime.date.today()
        antiguedad_dias = (hoy - fecha_registro).days
        if tipo_dato == "texto_crudo_state":
            debe_purgarse = antiguedad_dias > 60
            return {"accion": "PURGAR" if debe_purgarse else "CONSERVAR", "limite_dias": 60}
        elif tipo_dato == "metadatos_decision":
            debe_purgarse = antiguedad_dias > 1825  # 5 anos
            return {"accion": "PURGAR" if debe_purgarse else "CONSERVAR_GLACIER", "limite_dias": 1825}
        return {"accion": "DESCONOCIDO"}
    except Exception as err:
        logger.error(f"Fallo en evaluacion de retencion: {type(err).__name__} (detalles omitidos por seguridad)")
        return {"accion": "ERROR"}
```

## 7. Fallos conocidos, advertencias y contraindicaciones

| Modo de Fallo | Impacto Operativo | Detección Temprana | Mitigación Arquitectónica |
| :--- | :--- | :--- | :--- |
| Almacenamiento perpetuo de datos sensibles | Sanciones por violación de leyes de privacidad | Tareas cron de purga automatizada de textos | Conservar solo hashes y metadatos de auditoría |
| Agotamiento de sockets por conexiones no cerradas | Fuga de descriptores de archivos y crash | Monitoreo de descriptores de socket | Context managers asíncronos obligatorios |
| Desbordamiento de colas de memoria ante picos | Out of Memory (OOM) en contenedor | Métricas de memoria en Prometheus | Colas acotadas con descarte ordenado (backpressure) |

## 8. Validación propuesta

- **Hipótesis Falsable**: La purga automatizada a 60 días reduce el volumen de datos personales almacenados en un 70%.
- **Métricas**: Registros de texto no estructurado con más de 60 días en la base.
- **Criterio de Rechazo**: 0 registros de texto crudo fuera de la ventana de retención.
- **Estado**: Protocolo de validación propuesto para banco de pruebas local.

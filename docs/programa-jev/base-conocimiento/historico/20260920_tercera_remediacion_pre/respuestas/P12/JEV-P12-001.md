# JEV-P12-001 — Definición de Objetivos de Nivel de Servicio (SLOs/SLAs) y Presupuesto de Error

## 1. Respuesta directa y decisión que permite tomar

Antes de introducir Jev 1.13 en cualquier flujo productivo, deben establecerse Service Level Objectives (SLOs) cuantitativos y medibles: Disponibilidad mensual >= 99.9%, Latencia de inferencia p95 <= 220 ms (y p99 <= 350 ms), y Exactitud de clasificación >= 92% en el conjunto de prueba balanceado. Si el presupuesto de errores (Error Budget) del mes se agota en más de un 50% durante la primera quincena, se congelan despliegues y se conmuta a reglas deterministas locales.

## 2. Alcance, términos y supuestos

- **Ámbito analizado**: Site Reliability Engineering (SRE), acuerdos de nivel de servicio y gestión de presupuestos de error.
- **Supuesto clave**: Plataforma de monitoreo y telemetría distribuida activa en el entorno de despliegue.
- **Términos**: La versión de referencia es `typesafe_sdk 0.7.0` y el modelo `jev-1.13.0`.

## 3. Evidencia y contraste

- **Evidencia operativa**: Principios de SRE de Google aplicados a microservicios basados en modelos de inferencia estadística de terceros.
- **Contraste de confiabilidad**: Se descartan suposiciones de estabilidad perfecta en servicios cloud de terceros sin mecanismos de fallback.
- **Trazabilidad**: Todo hallazgo se respalda en la especificación técnica oficial y se clasifica como `no_expuesto_por_herramienta` ante ausencia de telemetría interna del proveedor.

## 4. Explicación técnica

Presupuesto de error mensual: Para un SLO de 99.9% de disponibilidad, el tiempo máximo de indisponibilidad permitido es de 43.2 minutos al mes. Las métricas de latencia se computan en percentiles p50, p95 y p99 usando Prometheus con histogramas de cubos exponenciales.

## 5. Ejemplo ilustrativo, verificación o contraejemplo

```python
# Ejemplo ilustrativo no ejecutado
import logging

logger = logging.getLogger("P12_01")

class GestorPresupuestoError:
    def __init__(self, slo_disponibilidad: float = 0.999):
        self.slo = slo_disponibilidad
        self.llamadas_totales = 0
        self.llamadas_fallidas = 0

    def registrar_evento(self, exito: bool) -> dict:
        try:
            self.llamadas_totales += 1
            if not exito:
                self.llamadas_fallidas += 1
            tasa_exito = (self.llamadas_totales - self.llamadas_fallidas) / self.llamadas_totales
            presupuesto_restante = max(0.0, 1.0 - ((1.0 - tasa_exito) / (1.0 - self.slo)))
            return {"tasa_exito": round(tasa_exito, 4), "presupuesto_error_pct": round(presupuesto_restante * 100, 2)}
        except Exception as err:
            logger.error(f"Fallo en calculo de presupuesto: {type(err).__name__} (detalles omitidos por seguridad)")
            return {"presupuesto_error_pct": 0.0}
```

- **Contraejemplo / Caso borde**: Lanzar un sistema a producción sin definir un SLO de latencia provocará que llamadas de 800 ms bloqueen los hilos transaccionales sin que nadie active una alarma.

## 7. Fallos conocidos, advertencias y contraindicaciones

| Modo de Fallo | Impacto Operativo | Detección Temprana | Mitigación Arquitectónica |
| :--- | :--- | :--- | :--- |
| Inexistencia de SLOs de latencia | Degradación silenciosa del servicio | Alarmas de percentiles en Prometheus | Activar fallback si p95 excede 250 ms |
| Agotamiento de sockets por conexiones no cerradas | Fuga de descriptores de archivos y crash | Monitoreo de descriptores de socket | Context managers asíncronos obligatorios |
| Desbordamiento de colas de memoria ante picos | Out of Memory (OOM) en contenedor | Métricas de memoria en Prometheus | Colas acotadas con descarte ordenado (backpressure) |

## 8. Validación propuesta

- **Hipótesis Falsable**: La fijación de SLOs con presupuesto de error reduce los incidentes de saturación en un 75%.
- **Métricas**: Minutos de degradación no planificada al mes.
- **Criterio de Rechazo**: Menos de 30 minutos de degradación acumulada mensual.
- **Estado**: Protocolo de validación propuesto para banco de pruebas local.

# JEV-P10-010 — Tratamiento de Duplicados Semánticos sin Pérdida de Versiones y Procedencia

## 1. Respuesta directa y decisión que permite tomar

El corpus documental debe someterse a un pre-procesamiento de deduplicación léxica (MinHash/SimHash con umbral Jaccard > 0.85) en la capa de almacenamiento previo, pero preservando estrictamente la procedencia y los metadatos de versión. Dos contratos o informes financieros con redacción idéntica en un 95% pero firmados en fechas distintas o aplicables a diferentes sociedades jurídicas deben conservarse como entidades distintas agregando su contexto temporal al `state`.

## 2. Alcance, términos y supuestos

- **Ámbito analizado**: Curaduría de datos, gestión de versiones documentales y prevención de contaminación de índices.
- **Supuesto clave**: Existencia de un motor de recuperación primaria de primera fase configurado y poblado.
- **Términos**: La versión de referencia es `typesafe_sdk 0.7.0` y el modelo `jev-1.13.0`.

## 3. Evidencia y contraste

- **Evidencia documental**: Buenas prácticas de gestión de corpus normativos y Point-in-Time compliance en bases de conocimiento legales y financieras.
- **Contraste metodológico**: Se descartan arquitecturas que confunden búsqueda masiva no estructurada con inferencia semántica puntual.
- **Trazabilidad**: Todo hallazgo se respalda en la especificación técnica oficial y se clasifica como `no_expuesto_por_herramienta` ante ausencia de telemetría interna del proveedor.

## 4. Explicación técnica

Deduplicación contextual: Agrupar documentos por hash de contenido. Si el texto es idéntico pero la metadata (fecha, autor, jurisdicción) difiere, generar un único embedding del contenido pero almacenar múltiples registros de procedencia vinculados.

## 5. Ejemplo ilustrativo, verificación o contraejemplo

```python
# Ejemplo ilustrativo no ejecutado
import hashlib, logging

logger = logging.getLogger("P10_10")

def evaluar_unicidad_documento(contenido: str, metadata: dict, catalogo_hashes: dict) -> dict:
    try:
        sha256_hash = hashlib.sha256(contenido.encode("utf-8")).hexdigest()
        if sha256_hash in catalogo_hashes:
            doc_existente = catalogo_hashes[sha256_hash]
            if doc_existente.get("version") != metadata.get("version"):
                return {"accion": "CONSERVAR_NUEVA_VERSION", "hash": sha256_hash}
            return {"accion": "DESCARTAR_DUPLICADO_EXACTO", "hash": sha256_hash}
        catalogo_hashes[sha256_hash] = metadata
        return {"accion": "REGISTRAR_NUEVO", "hash": sha256_hash}
    except Exception as err:
        logger.error(f"Fallo en evaluacion de duplicados: {type(err).__name__} (detalles omitidos por seguridad)")
        return {"accion": "ERROR"}
```

- **Contraejemplo / Caso borde**: Eliminar la versión actualizada de una directiva corporativa porque comparte el 90% del texto con la versión del año anterior dejará al sistema con normas obsoletas.

## 7. Fallos conocidos, advertencias y contraindicaciones

| Modo de Fallo | Impacto Operativo | Detección Temprana | Mitigación Arquitectónica |

## 8. Validación propuesta

- **Hipótesis Falsable**: La deduplicación con preservación de versiones reduce el tamaño del índice en 30% sin perder trazabilidad temporal.
- **Métricas**: Reducción de almacenamiento y disponibilidad de versiones históricas.
- **Criterio de Rechazo**: 0% de versiones normativas perdidas tras deduplicación.
- **Estado**: Protocolo de validación propuesto para banco de pruebas local.

# JEV-P10-004 — Aislamiento de Corpus y Filtrado Determinista de Permisos Previos a la Inferencia

## 1. Respuesta directa y decisión que permite tomar

El filtrado de permisos de acceso, listas de control de acceso (ACLs) y aislamiento de inquilinos (multi-tenancy) debe realizarse de forma 100% determinista en el motor de base de datos antes de cualquier procesamiento con Jev. Queda terminantemente prohibido enviar documentos confidenciales a Jev para que el modelo decida si el usuario tiene permiso de verlos, ya que las alucinaciones o descalibraciones provocarían fugas catastróficas de información entre clientes.

## 2. Alcance, términos y supuestos

- **Ámbito analizado**: Seguridad de datos, cumplimiento de aislamiento multi-inquilino y control de accesos RBAC.
- **Supuesto clave**: Existencia de un motor de recuperación primaria de primera fase configurado y poblado.
- **Términos**: La versión de referencia es `typesafe_sdk 0.7.0` y el modelo `jev-1.13.0`.

## 3. Evidencia y contraste

- **Evidencia documental**: Directrices de OWASP Top 10 for LLM Applications (LLM06: Sensitive Information Disclosure) y normativas de secreto bancario y laboral.
- **Contraste metodológico**: Se descartan arquitecturas que confunden búsqueda masiva no estructurada con inferencia semántica puntual.
- **Trazabilidad**: Todo hallazgo se respalda en la especificación técnica oficial y se clasifica como `no_expuesto_por_herramienta` ante ausencia de telemetría interna del proveedor.

## 4. Explicación técnica

Patrón Security First: `SELECT * FROM documentos WHERE tenant_id = :tenant AND acl_groups && :user_groups`. Solo los registros autorizados por la base de datos relacional son candidatos a ser evaluados por Jev.

## 5. Ejemplo ilustrativo, verificación o contraejemplo

```python
# Ejemplo ilustrativo no ejecutado
import logging

logger = logging.getLogger("P10_04")

def filtrar_documentos_autorizados(usuario_id: str, grupo_usuario: str, documentos_db: list) -> list:
    try:
        # Filtrado determinista en CPU / BD
        docs_seguros = [
            doc for doc in documentos_db 
            if doc.get("grupo_acceso") == grupo_usuario and usuario_id in doc.get("usuarios_permitidos", [])
        ]
        return docs_seguros
    except Exception as err:
        logger.error(f"Fallo en filtro de seguridad: {type(err).__name__} (detalles omitidos por seguridad)")
        return []
```

- **Contraejemplo / Caso borde**: Enviar contratos salariales de la gerencia en el `state` confiando en que Jev los oculte si el solicitante es un analista júnior resultará en una brecha de seguridad grave.

## 6. Aplicación práctica o transferencia

En la plataforma multi-inquilino de Wheelwork donde empresas competidoras comparten la misma infraestructura de software.

## 7. Fallos conocidos, advertencias y contraindicaciones

| Modo de Fallo | Impacto Operativo | Detección Temprana | Mitigación Arquitectónica |
| :--- | :--- | :--- | :--- |
| Delegar permisos a inferencia semántica | Fuga de documentos confidenciales | Verificación determinista en BD | Prohibir evaluación de ACLs mediante IA |
| Sobrecarga de pasajes en state (>32 KB) | Error 400 en runtime de API | Validación preventiva de bytes | Truncar o fragmentar pasajes a <= 400 palabras |
| Desalineación semántica en consultas OOD | Falsos positivos en clasificación | Monitoreo de entropía y certeza | Compuerta de abstención automática |

## 8. Validación propuesta

- **Hipótesis Falsable**: El filtrado previo de ACLs en base de datos garantiza una tasa de acceso no autorizado del 0.0%.
- **Métricas**: Intentos de acceso cruzado entre inquilinos exitosos.
- **Criterio de Rechazo**: 0 accesos no autorizados en pruebas de penetración.
- **Estado**: Protocolo de validación propuesto para banco de pruebas local.

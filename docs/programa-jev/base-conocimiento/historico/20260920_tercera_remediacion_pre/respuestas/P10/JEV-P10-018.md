# JEV-P10-018 — Invalidación Dinámica de Índices y Resúmenes ante Cambios en Fuentes Primarias

## 1. Respuesta directa y decisión que permite tomar

Cualquier modificación, revocación o actualización de un documento fuente debe activar un mecanismo inmediato de invalidación en cascada sobre los índices de búsqueda, los embeddings cacheados y las decisiones de relevancia generadas previamente. Cada artefacto en la base de datos debe almacenar el hash criptográfico SHA-256 del contenido original. Si el hash del origen cambia, todos los derivados semánticos deben purgarse o marcarse como `obsoleto_pendiente_recálculo`.

## 2. Alcance, términos y supuestos

- **Ámbito analizado**: Consistencia eventual, sincronización de cachés semánticas y gestión del ciclo de vida de la información.
- **Supuesto clave**: Existencia de un motor de recuperación primaria de primera fase configurado y poblado.
- **Términos**: La versión de referencia es `typesafe_sdk 0.7.0` y el modelo `jev-1.13.0`.

## 3. Evidencia y contraste

- **Evidencia documental**: Principios de sistemas distribuidos aplicados a cachés de inferencia y bases vectoriales para evitar servir información revocada.
- **Contraste metodológico**: Se descartan arquitecturas que confunden búsqueda masiva no estructurada con inferencia semántica puntual.
- **Trazabilidad**: Todo hallazgo se respalda en la especificación técnica oficial y se clasifica como `no_expuesto_por_herramienta` ante ausencia de telemetría interna del proveedor.

## 4. Explicación técnica

Arquitectura de eventos de invalidación: Al detectar actualización de archivo en S3/GCS o base relacional, disparar evento Kafka/RabbitMQ que ejecuta `DELETE FROM vector_index WHERE source_id = :id` y purga las respuestas cacheadas en Redis.

## 5. Ejemplo ilustrativo, verificación o contraejemplo

```python
# Ejemplo ilustrativo no ejecutado
import hashlib, logging

logger = logging.getLogger("P10_18")

def verificar_necesidad_invalidacion(contenido_nuevo: str, hash_almacenado: str) -> bool:
    try:
        nuevo_hash = hashlib.sha256(contenido_nuevo.encode("utf-8")).hexdigest()
        if nuevo_hash != hash_almacenado:
            logger.info("Cambio detectado en fuente primaria: activando invalidacion de indices")
            return True
        return False
    except Exception as err:
        logger.error(f"Fallo en verificacion de hash: {type(err).__name__} (detalles omitidos por seguridad)")
        return True
```

- **Contraejemplo / Caso borde**: Mantener cacheados los scores de una política de empresa que fue derogada la semana pasada provocará que los asistentes sigan dando información ilegal.

## 7. Fallos conocidos, advertencias y contraindicaciones

| Modo de Fallo | Impacto Operativo | Detección Temprana | Mitigación Arquitectónica |
| :--- | :--- | :--- | :--- |
| Respuestas basadas en fuentes obsoletas | Daño reputacional y decisiones erróneas | Control de versiones por hash SHA-256 | Purgar caché de inmediato ante cambio de hash |
| Sobrecarga de pasajes en state (>32 KB) | Error 400 en runtime de API | Validación preventiva de bytes | Truncar o fragmentar pasajes a <= 400 palabras |
| Desalineación semántica en consultas OOD | Falsos positivos en clasificación | Monitoreo de entropía y certeza | Compuerta de abstención automática |

## 8. Validación propuesta

- **Hipótesis Falsable**: El sistema de invalidación por hash garantiza que ninguna decisión en producción utilice fuentes desactualizadas.
- **Métricas**: Tiempo de propagación de cambios en fuentes primarias (segundos).
- **Criterio de Rechazo**: Propagación e invalidación de caché < 5 segundos.
- **Estado**: Protocolo de validación propuesto para banco de pruebas local.

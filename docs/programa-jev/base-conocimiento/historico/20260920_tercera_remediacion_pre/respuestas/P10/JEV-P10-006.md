# JEV-P10-006 — Unidad Óptima de Evaluación: Documento, Sección, Pasaje o Afirmación Atómica

## 1. Respuesta directa y decisión que permite tomar

La unidad óptima de evaluación para Jev es el pasaje coherente de entre 200 y 400 palabras (aproximadamente 300 a 500 tokens). Evaluar documentos completos es inviable debido al límite de 32 KB del `state` y diluye la atención semántica; evaluar afirmaciones atómicas aisladas introduce pérdida crítica de contexto y anáforas no resueltas. El chunking con solapamiento (overlap) del 15% sobre pasajes semánticos optimiza la relación entre costo, latencia y precisión.

## 2. Alcance, términos y supuestos

- **Ámbito analizado**: Estrategia de fragmentación de texto (chunking), diseño de granularidad y gestión de contexto.
- **Supuesto clave**: Existencia de un motor de recuperación primaria de primera fase configurado y poblado.
- **Términos**: La versión de referencia es `typesafe_sdk 0.7.0` y el modelo `jev-1.13.0`.

## 3. Evidencia y contraste

- **Evidencia documental**: Estudios empíricos en evaluación de RAG (LlamaIndex & LangChain Benchmarks) confirman que fragmentos de 256 a 512 tokens maximizan la recuperación de hechos específicos.
- **Contraste metodológico**: Se descartan arquitecturas que confunden búsqueda masiva no estructurada con inferencia semántica puntual.
- **Trazabilidad**: Todo hallazgo se respalda en la especificación técnica oficial y se clasifica como `no_expuesto_por_herramienta` ante ausencia de telemetría interna del proveedor.

## 4. Explicación técnica

Particionamiento semántico: Detección de saltos de párrafo dobles (`\n\n`) y límites oracionales con regex o spaCy. Cada fragmento debe preservar encabezados de sección para contextualizar conceptos relativos.

## 5. Ejemplo ilustrativo, verificación o contraejemplo

```python
# Ejemplo ilustrativo no ejecutado
import logging

logger = logging.getLogger("P10_06")

def fragmentar_texto_en_pasajes(texto: str, max_palabras: int = 300, solapamiento: int = 40) -> list:
    try:
        palabras = texto.split()
        if len(palabras) <= max_palabras:
            return [texto]
        pasajes = []
        inicio = 0
        while inicio < len(palabras):
            fin = min(inicio + max_palabras, len(palabras))
            pasajes.append(" ".join(palabras[inicio:fin]))
            if fin == len(palabras):
                break
            inicio += max_palabras - solapamiento
        return pasajes
    except Exception as err:
        logger.error(f"Fallo en particion de texto: {type(err).__name__} (detalles omitidos por seguridad)")
        return [texto[:1000]]
```

- **Contraejemplo / Caso borde**: Enviar un archivo contractual de 80 páginas concatenado en un solo string resultará en rechazo HTTP 400 por exceder los 32 KB.

## 7. Fallos conocidos, advertencias y contraindicaciones

| Modo de Fallo | Impacto Operativo | Detección Temprana | Mitigación Arquitectónica |
| :--- | :--- | :--- | :--- |
| Chunking arbitrario que corta oraciones | Pérdida de sentido y mala clasificación | Particionador semántico por párrafos | Solapamiento mínimo de 40 palabras |
| Sobrecarga de pasajes en state (>32 KB) | Error 400 en runtime de API | Validación preventiva de bytes | Truncar o fragmentar pasajes a <= 400 palabras |
| Desalineación semántica en consultas OOD | Falsos positivos en clasificación | Monitoreo de entropía y certeza | Compuerta de abstención automática |

## 8. Validación propuesta

- **Hipótesis Falsable**: Fragmentar en pasajes de 300 palabras con 40 de solapamiento captura el 98% de los hechos clave del documento.
- **Métricas**: Tasa de hechos no recuperados por corte de fragmento.
- **Criterio de Rechazo**: Pérdida de información clave < 2% en 100 documentos de prueba.
- **Estado**: Protocolo de validación propuesto para banco de pruebas local.

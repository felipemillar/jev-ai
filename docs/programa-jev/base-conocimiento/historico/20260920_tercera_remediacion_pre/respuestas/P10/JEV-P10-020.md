# JEV-P10-020 — Piloto de Búsqueda sobre Documentación Pública: Diseño, Métricas y Criterios de Retiro

## 1. Respuesta directa y decisión que permite tomar

El despliegue de Jev en producción para búsqueda documental debe someterse a un piloto controlado sobre un corpus público representativo (como la propia documentación técnica de TypeSafe y regulaciones laborales abiertas). El piloto debe evaluar cuantitativamente si el pipeline con Jev supera la línea base de BM25 en al menos un 15% de MRR@5. Si al cabo de 30 días de pruebas y 2.000 consultas no se verifica dicha ganancia, o si el costo por consulta supera los $0.005 USD, se ejecuta el criterio de retiro automático.

## 2. Alcance, términos y supuestos

- **Ámbito analizado**: Diseño de experimentos en producción, validación económica y protocolo de apagado de pilotos tecnológicos.
- **Supuesto clave**: Existencia de un motor de recuperación primaria de primera fase configurado y poblado.
- **Términos**: La versión de referencia es `typesafe_sdk 0.7.0` y el modelo `jev-1.13.0`.

## 3. Evidencia y contraste

- **Evidencia documental**: Metodología de validación de pilotos del Programa Jev (Piloto NP-01 y lineamientos del Pilar P13 sobre economía y alternativas).
- **Contraste metodológico**: Se descartan arquitecturas que confunden búsqueda masiva no estructurada con inferencia semántica puntual.
- **Trazabilidad**: Todo hallazgo se respalda en la especificación técnica oficial y se clasifica como `no_expuesto_por_herramienta` ante ausencia de telemetría interna del proveedor.

## 4. Explicación técnica

Prueba A/B en tráfico real: 50% de las consultas son atendidas por BM25 puro y 50% por BM25 + Jev Reranker. Registro de clics (Click-Through Rate, CTR) y tiempo de permanencia en el documento seleccionado.

## 5. Ejemplo ilustrativo, verificación o contraejemplo

```python
# Ejemplo ilustrativo no ejecutado
import logging

logger = logging.getLogger("P10_20")

class EvaluadorPilotoBusqueda:
    def __init__(self, mrr_base: float = 0.55):
        self.mrr_base = mrr_base

    def evaluar_criterio_mantenimiento(self, mrr_obtenido: float, costo_medio: float) -> dict:
        try:
            delta_mrr = (mrr_obtenido - self.mrr_base) / self.mrr_base
            supera_calidad = delta_mrr >= 0.15
            dentro_presupuesto = costo_medio <= 0.005
            if supera_calidad and dentro_presupuesto:
                return {"decision": "MANTENER_Y_ESCALAR", "ganancia": f"{delta_mrr*100:.1f}%"}
            return {"decision": "EJECUTAR_RETIRO", "motivo": "No alcanza umbral de valor o excede costo"}
        except Exception as err:
            logger.error(f"Fallo en evaluacion de piloto: {type(err).__name__} (detalles omitidos por seguridad)")
            return {"decision": "ERROR_EVALUACION"}
```

- **Contraejemplo / Caso borde**: Mantener indefinidamente un piloto en producción que agrega costo de API sin haber medido jamás si los usuarios encuentran mejores respuestas.

## 7. Fallos conocidos, advertencias y contraindicaciones

| Modo de Fallo | Impacto Operativo | Detección Temprana | Mitigación Arquitectónica |
| :--- | :--- | :--- | :--- |
| Falta de criterios cuantitativos de retiro | Acumulación de deuda técnica y costo zombi | Dashboard de métricas A/B en tiempo real | Regla de desconexión a los 30 días si delta < 15% |
| Sobrecarga de pasajes en state (>32 KB) | Error 400 en runtime de API | Validación preventiva de bytes | Truncar o fragmentar pasajes a <= 400 palabras |
| Desalineación semántica en consultas OOD | Falsos positivos en clasificación | Monitoreo de entropía y certeza | Compuerta de abstención automática |

## 8. Validación propuesta

- **Hipótesis Falsable**: El piloto demuestra un incremento de MRR@5 del 18% justificando el costo marginal del componente semántico.
- **Métricas**: MRR@5 en entorno de producción y costo medio por consulta.
- **Criterio de Rechazo**: MRR@5 >= 0.65 y Costo <= $0.004 USD por búsqueda.
- **Estado**: Protocolo de validación propuesto para banco de pruebas local.

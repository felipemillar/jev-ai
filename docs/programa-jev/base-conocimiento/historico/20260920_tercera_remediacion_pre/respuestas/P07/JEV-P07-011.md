# JEV-P07-011: Glosarios Sectoriales Condicionales para Resolver Polisemia sin Sesgo Sistemático

## 1. Respuesta directa y decisión que permite tomar

La polisemia —la coexistencia de múltiples significados para una misma palabra— representa un riesgo crítico de clasificación errónea en organizaciones complejas. Términos fundamentales en español como **"acción"** (activo bursátil vs. demanda judicial vs. tarea operativa), **"posición"** (postura financiera en un activo vs. vacante laboral en RRHH), **"instrumento"** (contrato notarial vs. activo financiero derivado) o **"castigo"** (sanción disciplinaria laboral vs. castigo contable de cartera vencida) adoptan significados radicalmente divergentes según el contexto de negocio.

El enfoque ingenuo de inyectar un glosario global estático en el prompt de Jev produce un **sesgo sistemático destructivo** (*global prior collapse*): sesga todas las instancias hacia una única interpretación predeterminada, provocando fallos cuando el término se utiliza en un sentido secundario. La arquitectura canónica para Wheelwork y QRT implementa el patrón de **Glosarios Sectoriales Contexto-Condicionales (GSCC)**: los términos polisémicos no se redefinen de forma estática, sino que se condicionan dinámicamente según los metadatos de dominio del estado (`state.domain`), el canal de origen del mensaje y un resolvedor de sentidos basado en coocurrencias léxicas locales.

## 4. Explicación técnica verificable

### 2.1 La Trampa del Sesgo Global A Priori en Modelos de Decisión

Consideremos un modelo de Sistema 1 expuesto a un prompt con un glosario estático:
`Glosario: "Acción" se refiere exclusivamente a títulos representativos de capital bursátil (equities).`

Si un usuario en Wheelwork escribe al departamento legal:
$$\text{"Notifico la interposición de una acción de protección ante la Corte de Apelaciones."}$$
El modelo, coaccionado por la definición estática, forzará la clasificación del texto hacia *Mercado de Capitales / Inversiones*, cometiendo un error categórico grave al ignorar la acción judicial.

```
Riesgo de Glosario Estático vs. Glosario Condicional
─────────────────────────────────────────────────────────────────────────────
Texto: "Tenemos que definir la posición de la contraparte."
                                │
   ┌────────────────────────────┴────────────────────────────┐
   ▼                                                         ▼
[Glosario Global Fijo (Trading)]              [Glosario Contextual Dinámico]
Regla: "Posición = Portafolio Financiero"     Regla: Condicionada a state.domain
   │                                                         │
   ▼                                                         ▼
Si el texto proviene de RRHH:                 Si domain="HR_RECRUITMENT":
Jev clasifica en: Finanzas / Mercado          Jev clasifica en: Vacante / Puesto
[¡ERROR POR SESGO INDUCIDO!]                  [¡RESOLUCIÓN CONTEXTUAL PRECISA!]
```

### 2.2 Principio de Desambiguación Condicional de Sentidos (*Word Sense Disambiguation*)

Sea un término polisémico $w \in \mathcal{W}$ con un conjunto finito de sentidos $\mathcal{S}(w) = \{s_1, s_2, \dots, s_k\}$. La probabilidad de que $w$ adopte el sentido $s_j$ depende del vector de contexto $\mathbf{c}$ (que incluye palabras circundantes y metadatos del sistema):
$$P(s_j \mid w, \mathbf{c}) \propto P(\mathbf{c} \mid s_j) \cdot P(s_j \mid \text{domain})$$

Para que Jev resuelva la polisemia sin sesgarse:
1. Si el metadato `state.domain` está explícito (ej. canal de trading vs. buzón de talento), el glosario inyecta únicamente el sentido correspondiente a dicho dominio.
2. Si el dominio es ambiguo o desconocido, el glosario **no fuerza una definición**, sino que presenta una taxonomía disjunta explícita en las opciones del primitivo `Choice` de Jev, permitiendo que las cabezas de atención resuelvan el sentido a partir de la coocurrencia local.

## 5. Ejemplo sintético trabajado y contraejemplo o caso límite

### 5.1. Implementación de Referencia en Python

El siguiente módulo implementa un resolvedor contextual de polisemia que inyecta glosarios condicionales en el estado de Jev únicamente cuando los metadatos y las coocurrencias justifican la desambiguación.

```python
# Ejemplo ilustrativo no ejecutado
"""
Módulo de Glosarios Sectoriales Condicionales para Jev AI.
Resuelve polisemia crítica contextual sin inducir sesgos estáticos globales.
"""

from dataclasses import dataclass
from typing import Dict, Any, List, Optional
import re
import logging

logger = logging.getLogger("ConditionalGlossaryResolver")


@dataclass(frozen=True)
class DisambiguatedSense:
    term: str
    selected_sense: str
    target_domain: str
    confidence: float


class ContextualGlossaryManager:
    """
    Inyecta glosarios sectoriales dinámicos en el payload de estado según el contexto real.
    """

    def __init__(self):
        # Base de conocimiento de sentidos y coocurrencias asociadas
        self.polysemic_lexicon = {
            "acción": {
                "FINANCE": {
                    "keywords": ["dividendo", "bolsa", "precio", "rendimiento", "cartera", "equity", "comprar"],
                    "definition": "título financiero representativo de una parte del capital de una empresa"
                },
                "LEGAL": {
                    "keywords": ["tribunal", "demanda", "protección", "juez", "recurso", "notificación"],
                    "definition": "recurso procesal judicial para exigir un derecho ante tribunales"
                },
                "OPERATIONS": {
                    "keywords": ["tarea", "ticket", "ejecutar", "workflow", "plan", "proceso"],
                    "definition": "tarea o medida operativa a implementar"
                }
            },
            "posición": {
                "FINANCE": {
                    "keywords": ["larga", "corta", "spread", "futuros", "mercado", "rollover", "liquidar"],
                    "definition": "postura o exposición financiera neta en un activo"
                },
                "HR": {
                    "keywords": ["vacante", "candidato", "sueldo", "contratación", "seniority", "cargo"],
                    "definition": "puesto o vacante de trabajo dentro de la organización"
                }
            },
            "castigo": {
                "FINANCE": {
                    "keywords": ["cartera", "deuda", "incobrable", "saldo", "cobranza", "provisión"],
                    "definition": "cancelación contable de un crédito considerado irrecuperable"
                },
                "HR": {
                    "keywords": ["conducta", "disciplinario", "amonestación", "reglamento", "falta"],
                    "definition": "medida correctiva o sancionatoria aplicada a un trabajador"
                }
            }
        }

    def resolve_senses(self, text: str, explicit_domain: Optional[str] = None) -> Dict[str, str]:
        try:
            lower = text.lower()
            injected_glossary = {}

            for term, senses in self.polysemic_lexicon.items():
                if re.search(rf"\b{term}(es)?\b", lower):
                    # Si el dominio viene explícito en metadatos, usar el sentido del dominio
                    if explicit_domain and explicit_domain in senses:
                        injected_glossary[term] = senses[explicit_domain]["definition"]
                        continue

                    # Si el dominio es desconocido, resolver por coocurrencia léxica
                    best_domain = None
                    max_matches = 0

                    for domain, data in senses.items():
                        matches = sum(1 for kw in data["keywords"] if kw in lower)
                        if matches > max_matches:
                            max_matches = matches
                            best_domain = domain

                    if best_domain and max_matches >= 1:
                        injected_glossary[term] = senses[best_domain]["definition"]
                    else:
                        # Si no hay evidencia contundente, NO inyectar glosario para evitar sesgo
                        logger.info(f"Término polisémico '{term}' detectado sin contexto dominante; se preserva neutralidad.")

            return injected_glossary

        except Exception as err:
            logger.error(f"Error resolviendo sentidos polisémicos: {type(err).__name__} (detalles omitidos por seguridad)")
            return {}
```

## 7. Fallos, límites, controles y condiciones de no uso

### 7.1. Modos de Falla y Controles de Mitigación
1. **Descalibración por modismos chilenos no composicionales**: Activación de umbrales dinámicos y compuerta de abstención ante entropía alta.
2. **Fragmentación sub-léxica en tokenización**: Preprocesamiento determinista de acrónimos territoriales y siglas institucionales (CMF, SII, DTE, UF) en memoria en CPU.
3. **Falsos positivos por sarcasmo o ironía**: Desacoplamiento de juicios de satisfacción mediante preguntas fácticas concurrentes en primitivas `Noul`.

### 7.2. Gobernanza, Privacidad y Condiciones de No Uso
1. **Imparcialidad en Procesos de Selección y Despido (HR-Tech):**
   - El término *"castigo"* o *"sanción"* jamás debe ser mapeado automáticamente a registros disciplinarios si el contexto es una disputa sobre saldos contables o cobros bancarios indebidos. Un error de desambiguación en este ámbito puede violar derechos laborales protegidos por el Código del Trabajo de Chile.
2. **Versionado de Sentidos Sectoriales:**
   - Toda definición inyectada en el estado de Jev debe asociarse a una versión inmutable del glosario corporativo (`glossary_version: "v2.4"`), asegurando reproducibilidad retrospectiva en auditorías de la CMF.

---

### 7.3. Condiciones Taxativas de NO Uso
- **NO delegar la normalización de identificadores legales (RUT, patentes) al espacio latente de Jev**; debe validarse con Módulo 11 en CPU.
- **NO canalizar datos confidenciales o bancarios a servicios de traducción externa (NMT no autorizados)** para intentar "traducir" antes de Jev.
- **NO ejecutar acciones operativas irreversibles sin verificación de umbral calibrado localmente**.

### 7.1 Hipótesis Falsable
$$H_0: \text{Accuracy}_{\text{Global\_Static\_Glossary}} \ge \text{Accuracy}_{\text{Conditional\_Glossary}}$$
*La hipótesis nula plantea que un glosario global estático logra igual o mayor precisión que un glosario condicional sobre un conjunto de prueba multidepartamental balanceado.*

### 7.2 Protocolo Experimental
1. **Población:** 90 mensajes balanceados conteniendo los términos *"acción"*, *"posición"* y *"castigo"* (30 financieros, 30 legales y 30 de recursos humanos).
2. **Procedimiento:**
   - Brazo A: Inferencia de Jev inyectando un glosario fijo con definiciones financieras.
   - Brazo B: Inferencia de Jev inyectando definiciones resueltas con `ContextualGlossaryManager`.
3. **Criterio de Falsación:**
   - En el subconjunto no financiero (legal y RRHH), el Brazo A exhibirá un colapso de precisión ($\text{Accuracy} < 0.40$). Si el Brazo B mantiene $\text{Accuracy} \ge 0.90$ en todos los slices ($p < 0.001$, prueba de McNemar), se **rechaza categóricamente $H_0$**, validando los glosarios condicionales como norma técnica.

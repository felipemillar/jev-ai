# JEV-P14-001 — Inventario de Decisiones Personales Repetitivas y Filtro de Automatización Útil

## 1. Respuesta directa y decisión que permite tomar

El inventario de decisiones personales candidatas a automatización con Jev 1.13 debe filtrar rigurosamente aquellas tareas de alta frecuencia y baja variabilidad semántica que representen fricción cognitiva real (e.g. triaje de bandejas de entrada, etiquetado de lecturas técnicas, categorización preliminar de recibos). Quedan excluidas decisiones esporádicas o complejas donde el costo de configurar, probar y mantener la automatización supera el tiempo manual invertido en ejecutarlas.

## 2. Alcance, términos y supuestos

- **Ámbito analizado**: Productividad personal, análisis de fricción cognitiva y priorización de casos de uso individuales.
- **Supuesto clave**: Pruebas herméticas en corpus sintético previas a cualquier acceso a datos personales reales.
- **Términos**: La versión de referencia es `typesafe_sdk 0.7.0` y el modelo `jev-1.13.0`.

## 3. Evidencia y contraste

- **Evidencia personal/operativa**: Principios de diseño del Piloto FP-01 y metodología de auditoría de automatizaciones personales del Programa Jev.
- **Contraste de utilidad**: Se descarta la automatización de procesos de baja frecuencia o que impliquen sobrecarga de mantenimiento.
- **Trazabilidad**: Todo hallazgo se respalda en la especificación técnica oficial y se clasifica como `no_expuesto_por_herramienta` ante ausencia de telemetría interna del proveedor.

## 4. Explicación técnica

Filtro de Viabilidad de Automatización: Una tarea personal se aprueba para Jev solo si: 1) Frecuencia >= 10 repeticiones por semana; 2) Tiempo manual >= 15 minutos semanales; 3) Reversibilidad total ante fallos; y 4) Espacio de decisiones cerrado modelable con `Choice` o `Score`.

## 5. Ejemplo ilustrativo, verificación o contraejemplo

```python
# Ejemplo ilustrativo no ejecutado
import logging

logger = logging.getLogger("P14_01")

def evaluar_viabilidad_automatizacion_personal(frecuencia_semanal: int, minutos_por_caso: float, es_reversible: bool) -> dict:
    try:
        tiempo_semanal_minutos = frecuencia_semanal * minutos_por_caso
        aprobado = frecuencia_semanal >= 10 and tiempo_semanal_minutos >= 15.0 and es_reversible
        return {
            "tiempo_semanal_minutos": tiempo_semanal_minutos,
            "dictamen": "AUTOMATIZAR_CON_JEV" if aprobado else "MANTENER_MANUAL"
        }
    except Exception as err:
        logger.error(f"Fallo en filtro de viabilidad: {type(err).__name__} (detalles omitidos por seguridad)")
        return {"dictamen": "ERROR_EVALUACION"}
```

- **Contraejemplo / Caso borde**: Dedicar tres días de ingeniería a construir un clasificador automático para un reporte anual de impuestos que solo se llena una vez cada 12 meses.

## 7. Fallos conocidos, advertencias y contraindicaciones

| Modo de Fallo | Impacto Operativo | Detección Temprana | Mitigación Arquitectónica |
| :--- | :--- | :--- | :--- |
| Automatización de tareas infrecuentes | Complejidad técnica sin ahorro real de tiempo | Filtro de frecuencia mínima (10/semana) | Descartar tareas con tiempo semanal < 15 min |
| Complacencia acrítica del usuario | Errores acumulados por aprobación ciega | Inyección periódica de casos trampa | Advertencia si tiempo de clic < 300 ms |
| Fuga de datos personales en el prompt | Exposición de correspondencia privada | Sanitizador determinista previo en CPU | Bloqueo absoluto de salida ante patrones PII |

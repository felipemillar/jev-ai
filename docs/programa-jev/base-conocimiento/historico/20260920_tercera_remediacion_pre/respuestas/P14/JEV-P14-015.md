# JEV-P14-015 — Mecanismo de Aprendizaje de Preferencias Personales sin Inferencia de Atributos Sensibles

## 1. Respuesta directa y decisión que permite tomar

El sistema personal debe adaptarse a las correcciones del usuario mediante un almacén local explícito de pares clave-valor (e.g. `remitente_X: clasificar_como_urgente`), prohibiendo categóricamente la inferencia de atributos sensibles del usuario (orientación política, religión, estado de salud o perfil psicológico) a partir de sus notas o correos. La adaptación debe ser transparente, auditable y revocable por el propio usuario en un archivo de configuración en texto plano.

## 2. Alcance, términos y supuestos

- **Ámbito analizado**: Personalización ética, privacidad de preferencias y prevención de perfilamiento invasivo.
- **Supuesto clave**: Pruebas herméticas en corpus sintético previas a cualquier acceso a datos personales reales.
- **Términos**: La versión de referencia es `typesafe_sdk 0.7.0` y el modelo `jev-1.13.0`.

## 3. Evidencia y contraste

- **Evidencia personal/operativa**: Regulaciones de privacidad (RGPD Art. 9: Tratamiento de categorías especiales de datos) y estándares éticos de Antigravity.
- **Contraste de utilidad**: Se descarta la automatización de procesos de baja frecuencia o que impliquen sobrecarga de mantenimiento.
- **Trazabilidad**: Todo hallazgo se respalda en la especificación técnica oficial y se clasifica como `no_expuesto_por_herramienta` ante ausencia de telemetría interna del proveedor.

## 4. Explicación técnica

Almacén local en YAML/JSON: `user_preferences.yaml` con reglas explícitas de sobreescritura creadas cuando el usuario corrige manualmente una decisión. Estas reglas se aplican en CPU antes de invocar a Jev.

## 5. Ejemplo ilustrativo, verificación o contraejemplo

```python
# Ejemplo ilustrativo no ejecutado
import logging

logger = logging.getLogger("P14_15")

class GestorPreferenciasExplicitas:
    def __init__(self):
        self.reglas_usuario = {}

    def aprender_correccion_usuario(self, remitente: str, categoria_corregida: str):
        try:
            # Registro transparente y auditable
            self.reglas_usuario[remitente] = categoria_corregida
            logger.info(f"Preferencia registrada para {remitente} -> {categoria_corregida}")
        except Exception as err:
            logger.error(f"Fallo al registrar preferencia: {type(err).__name__} (detalles omitidos por seguridad)")

    def consultar_preferencia(self, remitente: str):
        return self.reglas_usuario.get(remitente, None)
```

- **Contraejemplo / Caso borde**: Analizar las notas de salud del usuario para deducir patrones emocionales y usarlos para priorizar su correo corporativo viola la privacidad básica.

## 7. Fallos conocidos, advertencias y contraindicaciones

| Modo de Fallo | Impacto Operativo | Detección Temprana | Mitigación Arquitectónica |
| :--- | :--- | :--- | :--- |
| Perfilamiento invasivo de hábitos privados | Infracción ética y desconfianza en la herramienta | Reglas explícitas transparentes en archivo local | Prohibir almacenamiento de atributos no funcionales |
| Complacencia acrítica del usuario | Errores acumulados por aprobación ciega | Inyección periódica de casos trampa | Advertencia si tiempo de clic < 300 ms |
| Fuga de datos personales en el prompt | Exposición de correspondencia privada | Sanitizador determinista previo en CPU | Bloqueo absoluto de salida ante patrones PII |

## 8. Validación propuesta

- **Hipótesis Falsable**: Las reglas explícitas de sobreescritura reducen las correcciones recurrentes en un 90% sin perfilamiento.
- **Métricas**: Tasa de errores repetidos en remitentes frecuentes tras primera corrección.
- **Criterio de Rechazo**: 0 errores repetidos tras registrar la regla del usuario.
- **Estado**: Protocolo de validación propuesto para banco de pruebas local.

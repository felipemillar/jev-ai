# JEV-P14-018 — Indicadores de Dependencia Excesiva y Aumento del Trabajo de Supervisión

## 1. Respuesta directa y decisión que permite tomar

El sistema debe registrar telemetría sobre el propio comportamiento del usuario para detectar dos patologías opuestas: 1) Complacencia acrítica (aprobar el 100% de las sugerencias del modelo en menos de 200 ms sin leer, lo que indica pérdida de control humano); y 2) Fatiga de supervisión (pasar más de 30 minutos diarios corrigiendo propuestas del modelo, lo que indica que el clasificador está descalibrado y destruyendo tiempo). Ambos indicadores activan una recomendación de pausa del flujo.

## 2. Alcance, términos y supuestos

- **Ámbito analizado**: Ergonomía cognitiva, seguridad psicológica en automatizaciones y prevención de complacencia algorítmica.
- **Supuesto clave**: Pruebas herméticas en corpus sintético previas a cualquier acceso a datos personales reales.
- **Términos**: La versión de referencia es `typesafe_sdk 0.7.0` y el modelo `jev-1.13.0`.

## 3. Evidencia y contraste

- **Evidencia personal/operativa**: Estudios sobre sesgo de automatización (Automation Bias) y complacencia en interfaces de asistencia cognitiva.
- **Contraste de utilidad**: Se descarta la automatización de procesos de baja frecuencia o que impliquen sobrecarga de mantenimiento.
- **Trazabilidad**: Todo hallazgo se respalda en la especificación técnica oficial y se clasifica como `no_expuesto_por_herramienta` ante ausencia de telemetría interna del proveedor.

## 4. Explicación técnica

Métricas de supervisión: Tasa de corrección diaria y tiempo medio de permanencia en tarjeta. Si el tiempo medio es < 300 ms en 50 casos seguidos, el sistema muestra una advertencia de verificación consciente.

## 5. Ejemplo ilustrativo, verificación o contraejemplo

```python
# Ejemplo ilustrativo no ejecutado
import logging

logger = logging.getLogger("P14_18")

def auditar_patologia_supervision(tiempo_medio_clic_ms: float, minutos_supervision_dia: float) -> dict:
    try:
        if tiempo_medio_clic_ms < 300.0:
            return {"alerta": "COMPLACENCIA_ACRITICA", "accion": "RECORDAR_VERIFICACION_CONSCIENTE"}
        if minutos_supervision_dia > 30.0:
            return {"alerta": "SOBRECARGA_SUPERVISION", "accion": "RECOMENDAR_APAGADO_DE_AUTOMATIZACION"}
        return {"alerta": "OPERACION_SALUDABLE", "accion": "CONTINUAR"}
    except Exception as err:
        logger.error(f"Fallo en auditoria de supervision: {type(err).__name__} (detalles omitidos por seguridad)")
        return {"alerta": "ERROR"}
```

## 7. Fallos conocidos, advertencias y contraindicaciones

| Modo de Fallo | Impacto Operativo | Detección Temprana | Mitigación Arquitectónica |
| :--- | :--- | :--- | :--- |
| Aprobación ciega no consciente de propuestas | Errores acumulados graves en la gestión personal | Inyección periódica de casos de control | Alertas de fatiga si supervisión > 30 min/día |
| Complacencia acrítica del usuario | Errores acumulados por aprobación ciega | Inyección periódica de casos trampa | Advertencia si tiempo de clic < 300 ms |
| Fuga de datos personales en el prompt | Exposición de correspondencia privada | Sanitizador determinista previo en CPU | Bloqueo absoluto de salida ante patrones PII |

## 8. Validación propuesta

- **Hipótesis Falsable**: La monitorización de tiempo de clic erradica la complacencia acrítica manteniendo alta atención humana.
- **Métricas**: Casos de control deliberados detectados correctamente por el usuario.
- **Criterio de Rechazo**: Detección >= 95% de casos trampa de verificación.
- **Estado**: Protocolo de validación propuesto para banco de pruebas local.

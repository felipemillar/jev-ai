# JEV-P16-013 — Detección de Información Faltante y Propuesta de Preguntas de Aclaración

## 1. Respuesta directa y decisión que permite tomar

Cuando un currículum, contrato o solicitud comercial carece de datos indispensables para emitir una decisión fundada (e.g. un CV que no indica nivel de inglés en un cargo bilingüe, o un contrato que omite la jornada laboral), Jev no debe asumir ni adivinar los datos faltantes mediante inferencias probabilísticas. El sistema debe clasificar el expediente como `informacion_incompleta` y generar una lista de preguntas de aclaración objetivas para formular al solicitante.

## 2. Alcance, términos y supuestos

- **Ámbito analizado**: Prevención de alucinaciones en gestión de personas, completitud documental y comunicación clara.
- **Supuesto clave**: Pruebas sobre perfiles sintéticos y cumplimiento estricto del Código del Trabajo chileno y Ley 19.628.
- **Términos**: La versión de referencia es `typesafe_sdk 0.7.0` y el modelo `jev-1.13.0`.

## 3. Evidencia y contraste

- **Evidencia laboral/B2B**: Estándares de debida diligencia en selección de personal y directrices de contratación segura.
- **Contraste ético-jurídico**: Se prohíben descartes automáticos no supervisados y el tratamiento de atributos sensibles protegidos.
- **Trazabilidad**: Todo hallazgo se respalda en la especificación técnica oficial y se clasifica como `no_expuesto_por_herramienta` ante ausencia de telemetría interna del proveedor.

## 4. Explicación técnica

Compuerta de completitud con `Choice(options=['perfil_completo', 'falta_idioma', 'falta_certificacion', 'incompleto_general'])`. Si la salida es incompleta, el flujo propone un correo de consulta breve y neutral.

## 5. Ejemplo ilustrativo, verificación o contraejemplo

```python
# Ejemplo ilustrativo no ejecutado
import logging
from typesafe_sdk import TypeSafeClient, Choice

logger = logging.getLogger("P16_13")

def detectar_omisiones_en_perfil(cv_resumen: str) -> dict:
    try:
        client = TypeSafeClient(model="jev-1.13.0")
        res = client.system_one(
            state=cv_resumen,
            questions={
                "estado_completitud": Choice(
                    instructions="Verificar si se especifican anos de experiencia y titulacion",
                    options=["completo_para_evaluar", "falta_anos_experiencia", "falta_titulo_formal"]
                )
            }
        )
        ans = res.answers["estado_completitud"]
        requiere_pregunta = ans.choice != "completo_para_evaluar"
        return {"estado": ans.choice, "requiere_aclaracion": requiere_pregunta}
    except Exception as err:
        logger.error(f"Fallo en detector de omisiones: {type(err).__name__} (detalles omitidos por seguridad)")
        return {"estado": "completo_para_evaluar", "requiere_aclaracion": False}
```

- **Contraejemplo / Caso borde**: Suponer que un candidato habla inglés fluido porque estudió una carrera técnica en informática, descartándolo más tarde en la entrevista.

## 7. Fallos conocidos, advertencias y contraindicaciones

| Modo de Fallo | Impacto Operativo | Detección Temprana | Mitigación Arquitectónica |
| :--- | :--- | :--- | :--- |
| Relleno alucinado de datos faltantes en CVs | Decisiones erróneas sobre premisas inventadas | Detección explícita de omisiones con Choice | Solicitar aclaración formal al candidato |
| Sesgo algorítmico demográfico no detectado | Discriminación arbitraria y sanciones legales | Pruebas contrafactuales periódicas en CI | Bloqueo absoluto de variables proxy en el prompt |
| Modificación no autorizada de estados en ATS | Rechazo accidental de candidatos calificados | Integración en modo exclusivo de solo lectura | El consultor valida y muta el estado manualmente |

## 8. Validación propuesta

- **Hipótesis Falsable**: La detección de omisiones reduce las entrevistas inviables por requisitos no verificados en un 70%.
- **Métricas**: Candidatos citados a entrevista que no cumplían requisitos excluyentes.
- **Criterio de Rechazo**: Menos del 3% de entrevistas descartadas por requisitos básicos omitidos.
- **Estado**: Protocolo de validación propuesto para banco de pruebas local.

# JEV-P13-018 — Cuándo un Modelo Más Caro por Llamada Resulta Más Barato por Tarea Resuelta

## 1. Respuesta directa y decisión que permite tomar

En tareas de alta complejidad o severidad jurídica/financiera, un modelo con mayor costo por llamada puede resultar significativamente más económico por tarea resuelta en su totalidad. Si un modelo de $0.001 USD por llamada alcanza un 98% de exactitud y requiere solo un 2% de revisión humana, su costo final será menor que el de un modelo de $0.000084 USD que logre un 85% de exactitud y exija un 15% de revisión humana costosa ($1.50 USD/revisión). La calidad reduce el costo operacional humano downstream.

## 2. Alcance, términos y supuestos

- **Ámbito analizado**: Teoría de valor en inteligencia artificial, costo global de calidad y trade-off precisión-economía.
- **Supuesto clave**: Evaluación financiera a precios plenos documentados ($0.042/Mtok) sin subsidios temporales.
- **Términos**: La versión de referencia es `typesafe_sdk 0.7.0` y el modelo `jev-1.13.0`.

## 3. Evidencia y contraste

- **Evidencia económica**: Estudios de calidad total (Cost of Poor Quality, COPQ) aplicados a sistemas de clasificación automatizada.
- **Contraste de modelos**: Se comparan escenarios de SaaS gestionado frente a auto-hosting de GPU y LLMs frontier generativos.
- **Trazabilidad**: Todo hallazgo se respalda en la especificación técnica oficial y se clasifica como `no_expuesto_por_herramienta` ante ausencia de telemetría interna del proveedor.

## 4. Explicación técnica

Ecuación de comparación de modelos: Modelo A es más barato que Modelo B si: $C_{\text{api},A} + P(\text{rev}_A) \cdot C_{\text{humano}} < C_{\text{api},B} + P(\text{rev}_B) \cdot C_{\text{humano}}$. La diferencia de costo de la API queda eclipsada por cualquier variación en la tasa de revisión.

## 5. Ejemplo ilustrativo, verificación o contraejemplo

```python
# Ejemplo ilustrativo no ejecutado
import logging

logger = logging.getLogger("P13_18")

def comparar_eficiencia_dos_modelos(costo_api_a: float, exactitud_a: float, costo_api_b: float, exactitud_b: float, costo_reparacion: float = 10.0) -> dict:
    try:
        costo_total_a = costo_api_a + ((1.0 - exactitud_a) * costo_reparacion)
        costo_total_b = costo_api_b + ((1.0 - exactitud_b) * costo_reparacion)
        modelo_optimo = "MODELO_A" if costo_total_a < costo_total_b else "MODELO_B"
        return {
            "costo_total_a": round(costo_total_a, 4),
            "costo_total_b": round(costo_total_b, 4),
            "modelo_recomendado": modelo_optimo
        }
    except Exception as err:
        logger.error(f"Fallo en comparativa de calidad: {type(err).__name__} (detalles omitidos por seguridad)")
        return {}
```

## 7. Fallos conocidos, advertencias y contraindicaciones

| Modo de Fallo | Impacto Operativo | Detección Temprana | Mitigación Arquitectónica |
| :--- | :--- | :--- | :--- |
| Falso ahorro en modelo con alta tasa de error | Costos desmedidos de remediación downstream | Análisis de Cost of Poor Quality (COPQ) | Seleccionar modelo con menor costo total integrado |
| Aumento sorpresivo de tarifas del proveedor | Incremento del costo operativo | Monitoreo semanal de facturación | Patrón Adapter para conmutar a alternativas locales |
| Ignorar el costo humano de la tasa de escalamiento | Déficit financiero en el proyecto | Telemetría de casos derivados a humanos | Calibración de umbrales para limitar escalamiento a <= 8% |

## 8. Validación propuesta

- **Hipótesis Falsable**: El modelo con mayor precisión minimiza el costo total integrado en tareas de alta severidad.
- **Métricas**: Costo total integrado por tarea completada con éxito.
- **Criterio de Rechazo**: Reducción de al menos 15% en costo total integrado.
- **Estado**: Protocolo de validación propuesto para banco de pruebas local.

# JEV-P13-014 — Arquitectura de Cascada Híbrida (FrugalGPT / Semantic Router) para Optimización de Costos

## 1. Respuesta directa y decisión que permite tomar

La arquitectura más eficiente en costo y calidad no es utilizar exclusivamente Jev ni exclusivamente un LLM frontier, sino implementar una Cascada Híbrida (patrón FrugalGPT): Un router semántico rápido evalúa la complejidad de la consulta; Jev atiende de forma autónoma el 80% de los casos rutinarios a $0.000084 USD; y únicamente el 20% de los casos ambiguos o complejos se enruta a Claude 3.5 Sonnet o Gemini 1.5 Pro. Esto reduce la factura global en más de un 75% manteniendo la calidad de un modelo frontier.

## 2. Alcance, términos y supuestos

- **Ámbito analizado**: Cascadas de modelos, optimización de enrutamiento adaptativo y arquitectura FrugalGPT.
- **Supuesto clave**: Evaluación financiera a precios plenos documentados ($0.042/Mtok) sin subsidios temporales.
- **Términos**: La versión de referencia es `typesafe_sdk 0.7.0` y el modelo `jev-1.13.0`.

## 3. Evidencia y contraste

- **Evidencia económica**: Paper fundacional de Stanford 'FrugalGPT: How to Use Large Language Models More Affordably' (Chen et al., 2023).
- **Contraste de modelos**: Se comparan escenarios de SaaS gestionado frente a auto-hosting de GPU y LLMs frontier generativos.
- **Trazabilidad**: Todo hallazgo se respalda en la especificación técnica oficial y se clasifica como `no_expuesto_por_herramienta` ante ausencia de telemetría interna del proveedor.

## 4. Explicación técnica

Ecuación de costo en cascada: $\text{Costo}_{\text{Cascada}} = C_{\text{Jev}} + P(\text{Escalado}) \cdot C_{\text{LLM}}$. Con $C_{\text{Jev}} = \$0.000084$, $C_{\text{LLM}} = \$0.005$ y $P(\text{Escalado}) = 0.15$, el costo medio es de $\$0.000834$, un ahorro del 83% frente a llamar siempre al LLM.

## 5. Ejemplo ilustrativo, verificación o contraejemplo

```python
# Ejemplo ilustrativo no ejecutado
import logging
from typesafe_sdk import TypeSafeClient, Noul

logger = logging.getLogger("P13_14")

def router_cascada_frugal(texto_consulta: str) -> str:
    try:
        client = TypeSafeClient(model="jev-1.13.0")
        res = client.system_one(
            state=texto_consulta,
            questions={"complejidad": Noul(instructions="Determinar si requiere razonamiento complejo multi-paso")}
        )
        p_complejo = res.answers["complejidad"].noul
        if p_complejo >= 0.70:
            return "ENRUTAR_A_LLM_FRONTIER_CLAUDE"
        return "RESOLVER_LOCAL_CON_JEV"
    except Exception as err:
        logger.error(f"Fallo en router cascada: {type(err).__name__} (detalles omitidos por seguridad)")
        return "ENRUTAR_A_LLM_FRONTIER_CLAUDE" 
```

- **Contraejemplo / Caso borde**: Enviar el 100% de las preguntas sencillas a modelos de 70B tokens provocará facturas insostenibles de miles de dólares al mes.

## 7. Fallos conocidos, advertencias y contraindicaciones

| Modo de Fallo | Impacto Operativo | Detección Temprana | Mitigación Arquitectónica |
| :--- | :--- | :--- | :--- |
| Enrutamiento ineficiente que siempre escala a frontier | Pérdida de los beneficios económicos de la cascada | Monitoreo de tasa de derivación a frontier | Calibrar compuerta para que derivación <= 25% |
| Aumento sorpresivo de tarifas del proveedor | Incremento del costo operativo | Monitoreo semanal de facturación | Patrón Adapter para conmutar a alternativas locales |
| Ignorar el costo humano de la tasa de escalamiento | Déficit financiero en el proyecto | Telemetría de casos derivados a humanos | Calibración de umbrales para limitar escalamiento a <= 8% |

## 8. Validación propuesta

- **Hipótesis Falsable**: La cascada híbrida reduce la factura de modelos en 75% alcanzando un 98% de la calidad de Claude 3.5 Sonnet.
- **Métricas**: Ahorro económico mensual y puntuación de calidad en benchmark ciego.
- **Criterio de Rechazo**: Ahorro >= 70% con degradación de calidad < 2% en evaluación experta.
- **Estado**: Protocolo de validación propuesto para banco de pruebas local.

# JEV-P13-003 — Costo por Decisión Correcta Aceptada: Más Allá del Precio por Token

## 1. Respuesta directa y decisión que permite tomar

La métrica definitiva de eficiencia económica no es el costo por token ni el costo por llamada, sino el Costo por Decisión Correcta Aceptada (Cost per Correct Accepted Decision, CPCAD). Un modelo extremadamente barato que cometa un 15% de errores o requiera re-clasificación humana constante resulta mucho más costoso por decisión efectiva que un modelo ligeramente más caro con alta precisión y adecuada compuerta de abstención.

## 2. Alcance, términos y supuestos

- **Ámbito analizado**: Métricas de eficiencia económica orientadas a resultados de negocio y optimización de valor neto.
- **Supuesto clave**: Evaluación financiera a precios plenos documentados ($0.042/Mtok) sin subsidios temporales.
- **Términos**: La versión de referencia es `typesafe_sdk 0.7.0` y el modelo `jev-1.13.0`.

## 3. Evidencia y contraste

- **Evidencia económica**: Estudios de economía de machine learning (FrugalML / Stanford) sobre la relación entre costo de inferencia y costo de corrección.
- **Contraste de modelos**: Se comparan escenarios de SaaS gestionado frente a auto-hosting de GPU y LLMs frontier generativos.
- **Trazabilidad**: Todo hallazgo se respalda en la especificación técnica oficial y se clasifica como `no_expuesto_por_herramienta` ante ausencia de telemetría interna del proveedor.

## 4. Explicación técnica

Fórmula de CPCAD: $\text{CPCAD} = \frac{C_{\text{Llamada}} + P(\text{Abstención}) \cdot C_{\text{Humano}} + P(\text{Error}) \cdot C_{\text{Fallo}}}{P(\text{Acierto})}$. Si $C_{\text{Fallo}}$ es alto, cualquier mejora en precisión reduce drásticamente el CPCAD.

## 5. Ejemplo ilustrativo, verificación o contraejemplo

```python
# Ejemplo ilustrativo no ejecutado
import logging

logger = logging.getLogger("P13_03")

def calcular_cpcad(costo_llamada: float, exactitud: float, tasa_abstencion: float, costo_humano: float = 1.5, costo_error: float = 25.0) -> float:
    try:
        tasa_error = max(0.0, 1.0 - exactitud - tasa_abstencion)
        costo_esperado = costo_llamada + (tasa_abstencion * costo_humano) + (tasa_error * costo_error)
        tasa_acierto = max(exactitud, 0.001)
        return round(costo_esperado / tasa_acierto, 4)
    except Exception as err:
        logger.error(f"Fallo en calculo de CPCAD: {type(err).__name__} (detalles omitidos por seguridad)")
        return float("inf")
```

- **Contraejemplo / Caso borde**: Elegir una API gratuita que tiene 75% de exactitud en vez de Jev provocará miles de dólares en costos de remediación por decisiones erróneas.

## 6. Aplicación práctica o transferencia

En la justificación del uso de Jev para el triaje de postulaciones laborales de alta calificación en Wheelwork.

## 7. Fallos conocidos, advertencias y contraindicaciones

| Modo de Fallo | Impacto Operativo | Detección Temprana | Mitigación Arquitectónica |
| :--- | :--- | :--- | :--- |
| Optimizar ciegamente por costo de token | Aumento de costos totales por fallos no detectados | Medición de CPCAD en comités de arquitectura | Priorizar modelos con menor costo por acierto final |
| Aumento sorpresivo de tarifas del proveedor | Incremento del costo operativo | Monitoreo semanal de facturación | Patrón Adapter para conmutar a alternativas locales |
| Ignorar el costo humano de la tasa de escalamiento | Déficit financiero en el proyecto | Telemetría de casos derivados a humanos | Calibración de umbrales para limitar escalamiento a <= 8% |

## 8. Validación propuesta

- **Hipótesis Falsable**: Jev alcanza un CPCAD un 40% menor que modelos frontier para tareas de clasificación gracias a su bajo costo base.
- **Métricas**: CPCAD comparativo frente a Claude 3.5 Sonnet y Gemini 1.5 Flash.
- **Criterio de Rechazo**: CPCAD de Jev inferior en al menos 30% en tareas discriminativas.
- **Estado**: Protocolo de validación propuesto para banco de pruebas local.

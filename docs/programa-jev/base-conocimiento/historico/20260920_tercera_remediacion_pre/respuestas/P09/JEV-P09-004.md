# JEV-P09-004 — Descubrimiento Dinámico de Capacidades MCP sin Invención de Herramientas

## 1. Respuesta directa y decisión que permite tomar

Antigravity y cualquier cliente MCP deben ejecutar introspección dinámica mediante el método JSON-RPC `tools/list` antes de intentar ejecutar cualquier llamada. Queda estrictamente prohibido asumir o inventar nombres de herramientas como `notebooklm_search` o `query_evidence` sin comprobar previamente su presencia en la lista de capacidades publicadas por el servidor. Toda interacción debe validar esquemas con JSON Schema.

## 2. Alcance, términos y supuestos

- **Ámbito analizado**: Interacción cliente-servidor bajo el protocolo Model Context Protocol (MCP) garantizando tipado y existencia real.
- **Supuesto clave**: Conectividad saliente HTTPS habilitada hacia los endpoints oficiales de TypeSafe.
- **Términos**: La versión de referencia es `typesafe_sdk 0.7.0` y el modelo `jev-1.13.0`.

## 3. Evidencia y contraste

- **Evidencia documental**: Especificación oficial MCP de Anthropic / Linux Foundation: los clientes deben enviar `tools/list` y almacenar en caché el schema retornado durante la sesión.
- **Contraste de hipótesis**: Se descartan integraciones basadas en suposiciones de APIs genéricas de OpenAI o protocolos no oficiales.
- **Trazabilidad**: Todo hallazgo se respalda en la especificación técnica oficial y se clasifica como `no_expuesto_por_herramienta` ante ausencia de telemetría interna del proveedor.

## 4. Explicación técnica

Mensajería JSON-RPC 2.0 sobre stdio o Server-Sent Events (SSE). Estructura de verificación: 1. Handshake `initialize`; 2. Consulta `tools/list`; 3. Validación de `inputSchema` de cada herramienta devuelta; 4. Despacho dinámico a través de `tools/call`.

## 5. Ejemplo ilustrativo, verificación o contraejemplo

```python
# Ejemplo ilustrativo no ejecutado
import json, logging

logger = logging.getLogger("P09_04")

def validar_y_ejecutar_herramienta_mcp(herramientas_disponibles: list, nombre: str, args: dict) -> dict:
    try:
        herramienta = next((h for h in herramientas_disponibles if h.get("name") == nombre), None)
        if not herramienta:
            logger.warning(f"Herramienta no descubierta: {nombre}")
            return {"status": "no_disponible"}
        # Proceder con la invocacion segura
        return {"status": "ejecutado", "tool": nombre, "params": args}
    except Exception as err:
        logger.error(f"Fallo en ejecucion MCP: {type(err).__name__} (detalles omitidos por seguridad)")
        return {"status": "error"}
```

- **Contraejemplo / Caso borde**: Programar llamadas estáticas a `search_citations` cuando el servidor MCP sólo expone `notebook_query` resultará en un fallo fatal de método no encontrado.

## 7. Fallos conocidos, advertencias y contraindicaciones

| Modo de Fallo | Impacto Operativo | Detección Temprana | Mitigación Arquitectónica |
| :--- | :--- | :--- | :--- |
| Invocación ciega sin descubrimiento | Error MethodNotFound (-32601) | Handshake estricto al conectar | Validar catálogo contra tools/list al inicio |
| Corte total de conectividad saliente | Caída del servicio dependiente | Monitoreo sintético cada 60s | Conmutación automática a clasificador determinista local |
| Variación no notificada en contrato | Errores 422 en llamadas de API | Pruebas de contrato diarias en CI | Fijar versión y alertar ante discrepancias |

## 8. Validación propuesta

- **Hipótesis Falsable**: El descubrimiento dinámico de herramientas previene el 100% de los errores por discordancia de nombres entre versiones del servidor MCP.
- **Métricas**: Tasa de errores JSON-RPC -32601.
- **Criterio de Rechazo**: 0 errores de método no encontrado en 1.000 invocaciones.
- **Estado**: Protocolo de validación propuesto para banco de pruebas local.

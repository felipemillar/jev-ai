# JEV-P09-009 — Fronteras entre Código Verificable y Pseudocódigo Arquitectónico en Integraciones

## 1. Respuesta directa y decisión que permite tomar

Todo ejemplo de integración en esta base de conocimiento debe etiquetarse explícitamente como 'Código Verificable' (cuando utiliza clases e importaciones reales de `typesafe_sdk 0.7.0` validadas mediante AST de Python) o como 'Pseudocódigo Arquitectónico' (cuando modela orquestaciones teóricas con sistemas externos como Kafka, Redis o webhooks no instanciados en el entorno local). No se permite presentar pseudocódigo como si hubiese sido probado en producción.

## 2. Alcance, términos y supuestos

- **Ámbito analizado**: Estándar de rigurosidad técnica y honestidad epistémica en la documentación de ejemplos.
- **Supuesto clave**: Conectividad saliente HTTPS habilitada hacia los endpoints oficiales de TypeSafe.
- **Términos**: La versión de referencia es `typesafe_sdk 0.7.0` y el modelo `jev-1.13.0`.

## 3. Evidencia y contraste

- **Evidencia documental**: Auditoría de Codex: se detectaron bloques de código que simulaban llamadas a endpoints inexistentes o asumían la existencia de librerías no probadas.
- **Contraste de hipótesis**: Se descartan integraciones basadas en suposiciones de APIs genéricas de OpenAI o protocolos no oficiales.
- **Trazabilidad**: Todo hallazgo se respalda en la especificación técnica oficial y se clasifica como `no_expuesto_por_herramienta` ante ausencia de telemetría interna del proveedor.

## 4. Explicación técnica

Criterio de validación: Todo bloque marcado como verificable debe compilar exitosamente con `ast.parse()` en Python 3.10+ y resolver imports contra tipos estáticos conocidos (`TypeSafeClient`, `AsyncTypeSafeClient`, `Choice`, `Score`, `Noul`, `RetryPolicy`).

## 5. Ejemplo ilustrativo, verificación o contraejemplo

```python
# Ejemplo ilustrativo no ejecutado
import ast, logging

logger = logging.getLogger("P09_09")

def verificar_sintaxis_bloque(codigo_fuente: str) -> bool:

        return True
    except Exception as err:
        logger.error(f"Error de sintaxis detectado: {type(err).__name__} (detalles omitidos por seguridad)")
        return False
```

- **Contraejemplo / Caso borde**: Presentar una integración con Apache Kafka que incluya nombres de métodos inventados de un SDK inexistente como código listo para producción genera falsas expectativas de fiabilidad.

## 6. Aplicación práctica o transferencia

En los lineamientos de desarrollo de Antigravity para mantener el repositorio libre de código alucinado.

## 7. Fallos conocidos, advertencias y contraindicaciones

| Modo de Fallo | Impacto Operativo | Detección Temprana | Mitigación Arquitectónica |
| :--- | :--- | :--- | :--- |
| Presentar pseudocódigo como verificado | Errores de sintaxis al desplegar | Auditoría automática con ast.parse | Rotulado obligatorio en encabezados de código |
| Corte total de conectividad saliente | Caída del servicio dependiente | Monitoreo sintético cada 60s | Conmutación automática a clasificador determinista local |
| Variación no notificada en contrato | Errores 422 en llamadas de API | Pruebas de contrato diarias en CI | Fijar versión y alertar ante discrepancias |

## 8. Validación propuesta

- **Hipótesis Falsable**: La verificación automática con AST garantiza cero errores de sintaxis en todos los bloques de código de la base.
- **Métricas**: Porcentaje de bloques de código conformes con AST.
- **Criterio de Rechazo**: 100% de bloques válidos en compilación estática.
- **Estado**: Protocolo de validación propuesto para banco de pruebas local.

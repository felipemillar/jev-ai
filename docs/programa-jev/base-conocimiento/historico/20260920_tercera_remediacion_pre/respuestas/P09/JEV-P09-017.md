# JEV-P09-017 — Análisis de Dependencias, Seguridad de la Cadena de Suministro y Licenciamiento

## 1. Respuesta directa y decisión que permite tomar

La incorporación de código, SDKs o wrappers comunitarios exige una auditoría rigurosa de licencias de software y seguridad en la cadena de suministro (Supply Chain Security). Se prohíbe introducir dependencias con licencias virales restrictivas (GPL v3, AGPL) en módulos propietarios de la empresa. Asimismo, toda librería externa debe someterse a escaneos de vulnerabilidades conocidas (CVEs) con herramientas como `pip-audit` o `safety`.

## 2. Alcance, términos y supuestos

- **Ámbito analizado**: Gobernanza legal de código abierto, análisis de composición de software (SCA) y seguridad de paquetes.
- **Supuesto clave**: Conectividad saliente HTTPS habilitada hacia los endpoints oficiales de TypeSafe.
- **Términos**: La versión de referencia es `typesafe_sdk 0.7.0` y el modelo `jev-1.13.0`.

## 3. Evidencia y contraste

- **Evidencia documental**: Políticas corporativas de propiedad intelectual y estándares de ciberseguridad NIST SP 800-161 para la gestión de riesgos en la cadena de suministro.
- **Contraste de hipótesis**: Se descartan integraciones basadas en suposiciones de APIs genéricas de OpenAI o protocolos no oficiales.
- **Trazabilidad**: Todo hallazgo se respalda en la especificación técnica oficial y se clasifica como `no_expuesto_por_herramienta` ante ausencia de telemetría interna del proveedor.

## 4. Explicación técnica

Verificación automatizada en CI: Análisis de compatibilidad de licencias (MIT, Apache 2.0, BSD son compatibles con software propietario comercial). Bloqueo de paquetes que contengan dependencias obsoletas con vulnerabilidades críticas (CVSS >= 7.0).

## 5. Ejemplo ilustrativo, verificación o contraejemplo

```python
# Ejemplo ilustrativo no ejecutado
import logging

logger = logging.getLogger("P09_17")

def verificar_licencia_compatible(licencia_str: str) -> bool:
    try:
        licencias_permitidas = {"MIT", "Apache-2.0", "BSD-3-Clause", "ISC"}
        licencia_normalizada = licencia_str.strip()
        if licencia_normalizada in licencias_permitidas:
            return True
        logger.warning(f"Licencia no aprobada para integracion propietaria: {licencia_str}")
        return False
    except Exception as err:
        logger.error(f"Fallo en verificacion de licencia: {type(err).__name__} (detalles omitidos por seguridad)")
        return False
```

- **Contraejemplo / Caso borde**: Importar un wrapper no verificado con licencia AGPL dentro del motor de trading de QRT podría forzar legalmente a abrir el código del algoritmo propietario.

## 6. Aplicación práctica o transferencia

En el control de dependencias de `pyproject.toml` en los repositorios de QRT y Wheelwork.

## 7. Fallos conocidos, advertencias y contraindicaciones

| Modo de Fallo | Impacto Operativo | Detección Temprana | Mitigación Arquitectónica |
| :--- | :--- | :--- | :--- |
| Inclusión de dependencia con licencia viral | Riesgo legal de exposición de código | Escaneo automatizado de licencias en CI | Prohibir AGPL/GPL en proyectos comerciales |
| Corte total de conectividad saliente | Caída del servicio dependiente | Monitoreo sintético cada 60s | Conmutación automática a clasificador determinista local |
| Variación no notificada en contrato | Errores 422 en llamadas de API | Pruebas de contrato diarias en CI | Fijar versión y alertar ante discrepancias |

## 8. Validación propuesta

- **Hipótesis Falsable**: El bloqueo automático de licencias restrictivas previene contingencias legales de propiedad intelectual al 100%.
- **Métricas**: Dependencias no conformes detectadas en producción.
- **Criterio de Rechazo**: 0 dependencias no conformes en auditoría anual.
- **Estado**: Protocolo de validación propuesto para banco de pruebas local.

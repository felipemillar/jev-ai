# JEV-P09-006 — Autenticación, Permisos y Protección Criptográfica de Secretos en Tránsito

## 1. Respuesta directa y decisión que permite tomar

Jev autentica mediante tokens estáticos de portador (`Authorization: Bearer <TYPESAFE_API_KEY>`). Se prohíbe de forma absoluta quemar claves en código fuente, notebooks, mensajes de error o logs. Las credenciales deben residir en variables de entorno seguras o gestores de secretos (Vault, AWS Secrets Manager, GCP Secret Manager). Asimismo, toda excepción en Python debe capturarse enmascarando los detalles con `type(err).__name__` y el sufijo `(detalles omitidos por seguridad)`.

## 2. Alcance, términos y supuestos

- **Ámbito analizado**: Gobernanza de credenciales de acceso, sanitización de trazas de auditoría y prevención de fugas de información.
- **Supuesto clave**: Conectividad saliente HTTPS habilitada hacia los endpoints oficiales de TypeSafe.
- **Términos**: La versión de referencia es `typesafe_sdk 0.7.0` y el modelo `jev-1.13.0`.

## 3. Evidencia y contraste

- **Evidencia documental**: Estándar OWASP API Security Top 10 (API2:2023 Broken Authentication) y mandato expreso de la auditoría de Codex de enmascaramiento estricto.
- **Contraste de hipótesis**: Se descartan integraciones basadas en suposiciones de APIs genéricas de OpenAI o protocolos no oficiales.
- **Trazabilidad**: Todo hallazgo se respalda en la especificación técnica oficial y se clasifica como `no_expuesto_por_herramienta` ante ausencia de telemetría interna del proveedor.

## 4. Explicación técnica

Rotación de credenciales: Inyección vía variables de entorno en tiempo de inicialización de contenedores. Filtro de logs mediante sanitizadores regex que eliminan cualquier patrón alfanumérico coincidente con tokens de API.

## 5. Ejemplo ilustrativo, verificación o contraejemplo

```python
# Ejemplo ilustrativo no ejecutado
import os, logging
from typesafe_sdk import TypeSafeClient, Choice

logger = logging.getLogger("P09_06")

def consulta_segura_con_enmascaramiento(texto_inspeccion: str) -> dict:
    try:
        api_key = os.getenv("TYPESAFE_API_KEY")
        if not api_key:
            raise ValueError("Credencial ausente en entorno")
        client = TypeSafeClient(api_key=api_key, model="jev-1.13.0")
        res = client.system_one(
            state=texto_inspeccion,
            questions={"clasificacion": Choice(instructions="Riesgo", options=["bajo", "medio", "alto"])}
        )
        return {"riesgo": res.answers["clasificacion"].choice}
    except Exception as err:
        logger.error(f"Fallo en autenticacion o llamada: {type(err).__name__} (detalles omitidos por seguridad)")
        return {"status": "auth_error"}
```

- **Contraejemplo / Caso borde**: Imprimir `str(err)` en el bloque `except` cuando ocurre un error 401 puede exponer en los logs la cabecera HTTP completa incluyendo el token de API.

## 6. Aplicación práctica o transferencia

En todos los microservicios de producción de QRT y Wheelwork para cumplir con normativas de ciberseguridad.

## 7. Fallos conocidos, advertencias y contraindicaciones

| Modo de Fallo | Impacto Operativo | Detección Temprana | Mitigación Arquitectónica |
| :--- | :--- | :--- | :--- |
| Fuga de API Key en logs | Compromiso total de la cuenta de TypeSafe | Escáneres de secretos en CI (TruffleHog) | Enmascaramiento obligatorio en except |
| Corte total de conectividad saliente | Caída del servicio dependiente | Monitoreo sintético cada 60s | Conmutación automática a clasificador determinista local |
| Variación no notificada en contrato | Errores 422 en llamadas de API | Pruebas de contrato diarias en CI | Fijar versión y alertar ante discrepancias |

## 8. Validación propuesta

- **Hipótesis Falsable**: El uso estricto del patrón `type(err).__name__` garantiza una tasa de fuga de credenciales de 0% en logs.
- **Métricas**: Detecciones de cadenas secretas en logs de auditoría.
- **Criterio de Rechazo**: 0 coincidencias de tokens en 10.000 líneas de log.
- **Estado**: Protocolo de validación propuesto para banco de pruebas local.

# JEV-P09-012 — Integración con Automatizadores (n8n, Airflow, Zapier) sin Nodos Nativos

## 1. Respuesta directa y decisión que permite tomar

No existen nodos oficiales nativos de Jev para plataformas de automatización como n8n, Apache Airflow o Zapier. La integración debe implementarse mediante nodos genéricos de HTTP Request configurando el método `POST`, la URL del endpoint oficial y la cabecera `Authorization: Bearer <TOKEN>`. El orquestador asume la responsabilidad total de estructurar el JSON de entrada, validar que no exceda 32 KB y procesar el diccionario `answers` resultante.

## 2. Alcance, términos y supuestos

- **Ámbito analizado**: Patrón de integración desacoplada en flujos de trabajo basados en Low-Code y orquestadores ETL.
- **Supuesto clave**: Conectividad saliente HTTPS habilitada hacia los endpoints oficiales de TypeSafe.
- **Términos**: La versión de referencia es `typesafe_sdk 0.7.0` y el modelo `jev-1.13.0`.

## 3. Evidencia y contraste

- **Evidencia documental**: Revisión del registro público de extensiones de n8n y Airflow Providers: no existe paquete oficial publicado por TypeSafe; las integraciones existentes son configuraciones HTTP estándar.
- **Contraste de hipótesis**: Se descartan integraciones basadas en suposiciones de APIs genéricas de OpenAI o protocolos no oficiales.
- **Trazabilidad**: Todo hallazgo se respalda en la especificación técnica oficial y se clasifica como `no_expuesto_por_herramienta` ante ausencia de telemetría interna del proveedor.

## 4. Explicación técnica

Patrón HTTP Request Node: Payload en crudo con expresiones JSON. En Airflow se utiliza `HttpOperator` o `SimpleHttpOperator` configurando conexión HTTP con credenciales protegidas en la base de datos de Airflow.

## 6. Aplicación práctica o transferencia

En pipelines de ingestión de noticias de QRT donde Airflow pre-procesa el texto antes de clasificarlo con Jev.

## 7. Fallos conocidos, advertencias y contraindicaciones

| Modo de Fallo | Impacto Operativo | Detección Temprana | Mitigación Arquitectónica |
| :--- | :--- | :--- | :--- |
| Configuración incorrecta de auth en n8n | Error 401 Unauthorized | Pruebas de webhook en staging | Inyectar token desde variables de entorno seguras |
| Corte total de conectividad saliente | Caída del servicio dependiente | Monitoreo sintético cada 60s | Conmutación automática a clasificador determinista local |
| Variación no notificada en contrato | Errores 422 en llamadas de API | Pruebas de contrato diarias en CI | Fijar versión y alertar ante discrepancias |

## 8. Validación propuesta

- **Hipótesis Falsable**: El uso de `HttpOperator` estándar en Airflow alcanza la misma latencia y estabilidad que un conector nativo.
- **Métricas**: Tasa de fallos en ejecución de DAGs con paso Jev.
- **Criterio de Rechazo**: Tasa de error < 0.5% en 1.000 ejecuciones programadas.
- **Estado**: Protocolo de validación propuesto para banco de pruebas local.

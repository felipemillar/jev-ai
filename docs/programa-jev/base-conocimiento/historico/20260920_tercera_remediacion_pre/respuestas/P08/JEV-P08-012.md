# JEV-P08-012 — Garantías de Validación de Esquema vs Verificaciones de Significado y Semántica

## 1. Respuesta directa y decisión que permite tomar

Una validación de esquema mediante Pydantic o JSON Schema certifica únicamente la corrección estructural y tipos de datos (e.g. que 'score' sea float y 'choice' sea string). La verificación de significado es una dimensión ortogonal que debe ejecutarse en una capa posterior, comprobando si el veredicto es coherente con el estado de negocio y no infringe restricciones normativas.

## 2. Alcance, términos, versiones y supuestos

- **Alcance Operacional**: Deslinde entre corrección sintáctica de interfaces y corrección semántica de dominio.
- **Versión de Referencia**: Jev 1.13 (`typesafe_sdk 0.7.0` / `POST /v1/systemone`).
- **Supuestos Críticos**: Las decisiones semánticas son puramente consultivas; la ejecución y mutación de estado residen exclusivamente en componentes deterministas en CPU.

## 5. Ejemplo sintético trabajado y contraejemplo o caso límite

### 5.1 Implementación en Python (SDK 0.7.0)

```python
# Ejemplo ilustrativo no ejecutado
import logging
from pydantic import BaseModel, Field

logger = logging.getLogger("P08_12")

class TicketOutput(BaseModel):
    area: str
    urgencia: float = Field(ge=1.0, le=4.0)

def procesar_ticket_dual(raw_dict: dict, es_cuenta_morosa: bool) -> str:
    try:
        dto = TicketOutput(**raw_dict)
        if dto.area == "despacho_inmediato" and es_cuenta_morosa:
            return "BLOQUEADO_POR_POLITICA_CREDITO"
        return dto.area
    except Exception as err:
        logger.error(f"Fallo validacion dual: {type(err).__name__} (detalles omitidos por seguridad)")
        return "ERROR_FORMATO" 
```

### 5.2 Contraejemplo y Caso Límite

Un payload con `{ 'area': 'despacho', 'urgencia': 4.0 }` es 100% válido en Pydantic, pero si la cuenta no ha pagado la factura previa, procesar el despacho es una quiebra de la política de crédito.

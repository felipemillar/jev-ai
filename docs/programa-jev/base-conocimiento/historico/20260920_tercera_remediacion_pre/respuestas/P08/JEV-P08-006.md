# JEV-P08-006 — Evaluación en Paralelo vs Secuencial de Preguntas en Jev: Criterios de Dependencia

## 1. Respuesta directa y decisión que permite tomar

La evaluación concurrente en un único forward pass (system_one con un diccionario de preguntas) es óptima cuando todas las preguntas operan sobre el mismo texto de entrada y no existen relaciones causales condicionales entre ellas. Por el contrario, se exige una secuencia estricta cuando: (1) la segunda pregunta requiere enriquecer o filtrar el texto en función de la primera; (2) una compuerta Noul previa debe abortar el proceso si el documento no es pertinente; o (3) se construye una jerarquía taxonómica profunda (árbol de decisión).

## 2. Alcance, términos, versiones y supuestos

- **Alcance Operacional**: Diseño de grafos de inferencia semántica optimizando round-trips de red y coste de tokens.
- **Versión de Referencia**: Jev 1.13 (`typesafe_sdk 0.7.0` / `POST /v1/systemone`).
- **Supuestos Críticos**: Las decisiones semánticas son puramente consultivas; la ejecución y mutación de estado residen exclusivamente en componentes deterministas en CPU.

## 5. Ejemplo sintético trabajado y contraejemplo o caso límite

### 5.1 Implementación en Python (SDK 0.7.0)

```python
# Ejemplo ilustrativo no ejecutado
import logging
from typesafe_sdk import TypeSafeClient, Choice, Noul

logger = logging.getLogger("P08_06")

def evaluar_cv_concurrente(texto_cv: str) -> dict:
    try:
        client = TypeSafeClient(model="jev-1.13.0")
        res = client.system_one(
            state=texto_cv,
            questions={
                "ingenieria": Noul(statement="¿Tiene titulo en ingenieria?"),
                "seniority": Choice(instructions="Seniority", options=["jr", "ssr", "sr"]),
                "ingles": Noul(statement="¿Habla ingles fluido?")
            }
        )
        return {
            "ing": res.answers["ingenieria"].noul >= 0.5,
            "sen": res.answers["seniority"].choice,
            "eng": res.answers["ingles"].noul >= 0.5
        }
    except Exception as err:
        logger.error(f"Fallo concurrencia: {type(err).__name__} (detalles omitidos por seguridad)")
        return {}
```

## 7. Fallos, límites, controles y condiciones de no uso

| Modo de Fallo | Impacto | Detección | Control / Mitigación |
|---|---|---|---|
| Sobrecarga de preguntas en un payload | Error 400 por payload excesivo | Validador de tamaño de payload | Límite de 8 preguntas concurrentes por llamada |
| Timeout de API (>300 ms) | Bloqueo de hilo en microservicio | Alarma de socket timeout | Conmutación inmediata a fallback local en CPU |
| Descalibración en casos OOD | Decisión errónea con certeza aparente | Medición de entropía de salida | Compuerta de abstención y escalado humano |

## 8. Validación propuesta

- **Hipótesis Falsable**: Empaquetar 3 preguntas en un solo forward pass reduce el tiempo de red en un 62% frente a 3 llamadas consecutivas.
- **Métricas**: Latencia acumulada de extracción (ms).
- **Criterio de Rechazo**: Latencia <= 220 ms en p95 para 3 preguntas paralelas.
- **Estado**: Protocolo propuesto no ejecutado en producción.

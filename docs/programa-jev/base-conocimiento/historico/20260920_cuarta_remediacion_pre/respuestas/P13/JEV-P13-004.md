# JEV-P13-004 — Mapeo de Alternativas Tecnológicas: Reglas, Modelos Locales y LLMs Frontier

## 1. Respuesta directa y decisión que permite tomar

Cada familia de tareas debe asignarse a la alternativa tecnológica óptima según su complejidad y volumen: 1) Reglas léxicas y heurísticas en CPU (costo cero, latencia <1 ms) para textos rígidamente estructurados; 2) Modelos locales ligeros (DeBERTa-v3, SetFit en servidores GPU T4) para clasificación semántica masiva con datos estables; 3) Jev 1.13 para inferencia rápida (Sistema 1) con calibración probabilística sin infraestructura propia; y 4) Modelos frontier (Gemini 1.5 Pro, Claude 3.5 Sonnet) para razonamiento multi-paso y generación libre.

## 2. Alcance, términos y supuestos

- **Ámbito analizado**: Matriz de selección tecnológica, arquitectura de sistemas políglotas y asignación eficiente de cargas.
- **Supuesto clave**: Evaluación financiera a precios plenos documentados ($0.042/Mtok) sin subsidios temporales.
- **Términos**: La versión de referencia es `typesafe_sdk 0.7.0` y el modelo `jev-1.13.0`.

## 3. Evidencia y contraste

- **Evidencia económica**: Taxonomía de cargas de trabajo de NLP y arquitectura FrugalGPT para cascadas de modelos.
- **Contraste de modelos**: Se comparan escenarios de SaaS gestionado frente a auto-hosting de GPU y LLMs frontier generativos.
- **Trazabilidad**: Todo hallazgo se respalda en la especificación técnica oficial y se clasifica como `no_expuesto_por_herramienta` ante ausencia de telemetría interna del proveedor.

## 4. Explicación técnica

Matriz de decisión por dimensionalidad: Estructura fija -> Regex; Clasificación temática cerrada de alta frecuencia -> Jev / DeBERTa; Generación abierta / Código -> LLM Frontier.

# JEV-P08-002 — Arquitectura Mínima Desacoplada sin Dependencia Indispensable (Sidecar Pattern)

## 1. Respuesta directa y decisión que permite tomar

La arquitectura mínima recomendada es un microservicio Proxy/Sidecar semántico que intercepta los payloads antes de los controladores de negocio. El core del sistema invoca una interfaz agnóstica (ISemanticClassifier) configurada con un timeout agresivo (200 ms) y fallback estricto a heurísticas léxicas locales en CPU. Si Jev experimenta degradación o se decide removerlo, un feature flag conmuta el 100% del tráfico al clasificador local en menos de un segundo sin modificar el código transaccional.

## 2. Alcance, términos, versiones y supuestos

- **Alcance Operacional**: Integración no invasiva en backends existentes mediante adaptadores perimetrales y conmutadores lógicos.
- **Versión de Referencia**: Jev 1.13 (`typesafe_sdk 0.7.0` / `POST /v1/systemone`).
- **Supuestos Críticos**: Las decisiones semánticas son puramente consultivas; la ejecución y mutación de estado residen exclusivamente en componentes deterministas en CPU.

## 4. Explicación técnica verificable

Topología Sidecar HTTP: Interfaz de dominio ISemanticClassifier desacoplada del SDK. Circuit breaker local que conmuta a expresiones regulares si la tasa de fallos de red supera el 5% en 1 minuto.

## 5. Ejemplo sintético trabajado y contraejemplo o caso límite

### 5.1 Implementación en Python (SDK 0.7.0)

```python
import logging, time
from typesafe_sdk import TypeSafeClient, Noul
logger = logging.getLogger('P08_02')

class ProxySidecar:

    def __init__(self, activo: bool=True):
        self.activo = activo
        self.client = TypeSafeClient(model='jev-1.13.0')

    def clasificar_urgencia(self, mensaje: str) -> bool:
        if not self.activo:
            return 'urgente' in mensaje.lower()
        try:
            res = self.client.system_one(state=mensaje, questions={'urg': Noul(instructions='Evaluar si el mensaje reporta caída crítica')})
            return res.answers['urg'].noul >= 0.7
        except Exception as err:
            logger.error(f'Fallo sidecar: {type(err).__name__} (detalles omitidos por seguridad)')
            return 'urgente' in mensaje.lower()
```

### 5.2 Contraejemplo y Caso Límite

Si el proxy espera 5.000 ms antes de conmutar al fallback, una lentitud transitoria en TypeSafe bloqueará los pools de conexión de la base de datos principal.

## 7. Fallos, límites, controles y condiciones de no uso

| Modo de Fallo | Impacto | Detección | Control / Mitigación |
|---|---|---|---|
| Bloqueo por timeout prolongado | Agotamiento de workers web | Monitor de latencia p99 | Timeout de socket fijado en 200 ms estrictos |
| Timeout de API (>300 ms) | Bloqueo de hilo en microservicio | Alarma de socket timeout | Conmutación inmediata a fallback local en CPU |
| Descalibración en casos OOD | Decisión errónea con certeza aparente | Medición de entropía de salida | Compuerta de abstención y escalado humano |

## 8. Validación propuesta

- **Hipótesis Falsable**: La conmutación al fallback léxico ocurre en menos de 10 ms tras detectar 3 timeouts consecutivos.
- **Métricas**: Tiempo de conmutación (ms) y tasa de errores 504.
- **Criterio de Rechazo**: < 15 ms de tiempo de failover con 0 peticiones colgadas.
- **Estado**: Protocolo propuesto no ejecutado en producción.

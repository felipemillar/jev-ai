# JEV-P10-003 — Evaluación Comparativa de Jev como Reranker frente a Modelos Dedicados

## 1. Respuesta directa y decisión que permite tomar

El uso de Jev como reranker secundario es técnicamente viable mediante primitivas `Score(1, 5)` o `Choice`, pero debe justificarse frente a rerankers especializados como BGE-Reranker-Large, Cohere Rerank v3 o cross-encoders locales. Jev aporta valor diferencial cuando las reglas de negocio exigen evaluación de aspectos cualitativos simultáneos (e.g. tono formal, riesgo regulatorio y relevancia en una sola llamada). Para ranking puramente temático unidimensional, los cross-encoders dedicados ofrecen menor latencia y costo.

## 2. Alcance, términos y supuestos

- **Ámbito analizado**: Análisis comparativo de rendimiento, costo por documento evaluado y latencia de inferencia en RAG.
- **Supuesto clave**: Existencia de un motor de recuperación primaria de primera fase configurado y poblado.
- **Términos**: La versión de referencia es `typesafe_sdk 0.7.0` y el modelo `jev-1.13.0`.

## 3. Evidencia y contraste

- **Evidencia documental**: Benchmarks de recuperación de información (MTEB / BEIR): los modelos específicos de reranking entrenados con pérdidas de contraste superan a modelos de lenguaje de propósito general en nDCG@10 si no se realiza fine-tuning.
- **Contraste metodológico**: Se descartan arquitecturas que confunden búsqueda masiva no estructurada con inferencia semántica puntual.
- **Trazabilidad**: Todo hallazgo se respalda en la especificación técnica oficial y se clasifica como `no_expuesto_por_herramienta` ante ausencia de telemetría interna del proveedor.

## 4. Explicación técnica

Costo por consulta: Evaluar 20 candidatos con Jev requiere 20 llamadas atómicas o un `state` estructurado con múltiples preguntas. Latencia acumulada: ~180 ms si se paraleliza en cliente. Con cross-encoder local: 35 ms en GPU T4.

## 5. Ejemplo ilustrativo, verificación o contraejemplo

```python
import asyncio, logging
from typesafe_sdk import AsyncTypeSafeClient, Score
logger = logging.getLogger('P10_03')

async def rerankear_lote_paralelo(query: str, pasajes: list) -> list:
    try:
        async with AsyncTypeSafeClient(model='jev-1.13.0') as client:
            tareas = []
            for p in pasajes:
                st = f'QUERY: {query}\nTEXTO: {p}'
                tareas.append(client.system_one(state=st, questions={'score': Score(instructions='Alineacion con consulta', criteria=['Nivel 1: Muy deficiente / Sin alineación', 'Nivel 2: Deficiente / Baja alineación', 'Nivel 3: Aceptable / Alineación moderada', 'Nivel 4: Bueno / Alta alineación', 'Nivel 5: Excelente / Rigurosamente alineado'])}))
            resultados = await asyncio.gather(*tareas)
            scores = [r.answers['score'].score for r in resultados]
            return sorted(zip(scores, pasajes), key=lambda x: x[0], reverse=True)
    except Exception as err:
        logger.error(f'Fallo en reranking asincrono: {type(err).__name__} (detalles omitidos por seguridad)')
        return []
```

- **Contraejemplo / Caso borde**: Utilizar Jev para ordenar 1.000 pasajes en tiempo real causará un colapso por saturación de cuota y latencias superiores a 5 segundos.

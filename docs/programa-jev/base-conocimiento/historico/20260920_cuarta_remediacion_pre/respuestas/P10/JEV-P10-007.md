# JEV-P10-007 — Selección del Número de Candidatos (K) sin Eliminación Prematura de Evidencia

## 1. Respuesta directa y decisión que permite tomar

El dimensionamiento del embudo de recuperación debe configurarse en K1=50 candidatos en la fase léxica/vectorial y K2=10 a 15 candidatos para el reranking con Jev. Reducir K1 por debajo de 30 provoca la eliminación prematura de evidencia relevante que utiliza vocabulario alternativo (recall loss); aumentar K2 por encima de 20 encarece linealmente la consulta de Jev y eleva la latencia por encima de 400 ms sin aportar mejoras apreciables en el Top-3 final.

## 2. Alcance, términos y supuestos

- **Ámbito analizado**: Calibración del embudo de búsqueda y balance entre cobertura (recall) y eficiencia económica/temporal.
- **Supuesto clave**: Existencia de un motor de recuperación primaria de primera fase configurado y poblado.
- **Términos**: La versión de referencia es `typesafe_sdk 0.7.0` y el modelo `jev-1.13.0`.

## 3. Evidencia y contraste

- **Evidencia documental**: Curvas de rendimiento en Information Retrieval: el recall@50 de BM25 suele superar el 85%, mientras que el recall@10 cae al 60% en consultas con lenguaje sectorial o polisemia.
- **Contraste metodológico**: Se descartan arquitecturas que confunden búsqueda masiva no estructurada con inferencia semántica puntual.
- **Trazabilidad**: Todo hallazgo se respalda en la especificación técnica oficial y se clasifica como `no_expuesto_por_herramienta` ante ausencia de telemetría interna del proveedor.

## 4. Explicación técnica

Ecuación de costo y latencia: Costo = K2 * (Precio_Jev); Latencia = Latencia_Base + (K2 / Concurrencia_Max) * Latencia_Inferencia. Con K2=12 y 4 workers asíncronos concurrentes, el tiempo total añadido es de ~120 ms.

## 5. Ejemplo ilustrativo, verificación o contraejemplo

# Ejemplo ilustrativo no ejecutado
import logging

logger = logging.getLogger("P10_07")

def dimensionar_embudo_recuperacion(candidatos_totales: list, k1_recall: int = 50, k2_rerank: int = 12) -> list:
    try:
        # Etapa 1: Filtrar hasta K1 candidatos segun ranking preliminar
        top_k1 = candidatos_totales[:k1_recall]
        # Etapa 2: Seleccionar K2 para evaluacion semantica profunda
        top_k2 = top_k1[:k2_rerank]
        return top_k2
    except Exception as err:
        logger.error(f"Fallo en dimensionamiento de embudo: {type(err).__name__} (detalles omitidos por seguridad)")
        return candidatos_totales[:10]

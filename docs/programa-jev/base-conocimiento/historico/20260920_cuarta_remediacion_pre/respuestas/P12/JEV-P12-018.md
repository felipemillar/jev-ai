# JEV-P12-018 — Gestión de Dependencias Compartidas y Ciclo de Retirada de Versiones (Deprecation)

## 1. Respuesta directa y decisión que permite tomar

La integración con Jev en múltiples proyectos (QRT, Wheelwork, automatizaciones internas) debe gestionarse a través de un paquete interno centralizado (`company-jev-client`) con políticas claras de deprecación. Cuando se libera una versión mayor o se modifica un contrato, la versión anterior entra en estado de deprecación con una ventana fija de mantenimiento de 90 días. Se prohíbe mantener más de dos versiones activas simultáneamente en producción.

## 2. Alcance, términos y supuestos

- **Ámbito analizado**: Gobierno de librerías compartidas, ciclo de vida de interfaces internas y gestión de deuda técnica.
- **Supuesto clave**: Plataforma de monitoreo y telemetría distribuida activa en el entorno de despliegue.
- **Términos**: La versión de referencia es `typesafe_sdk 0.7.0` y el modelo `jev-1.13.0`.

## 3. Evidencia y contraste

- **Evidencia operativa**: Políticas corporativas de API Lifecycle Management y estándares de soporte semántico (SemVer).
- **Contraste de confiabilidad**: Se descartan suposiciones de estabilidad perfecta en servicios cloud de terceros sin mecanismos de fallback.
- **Trazabilidad**: Todo hallazgo se respalda en la especificación técnica oficial y se clasifica como `no_expuesto_por_herramienta` ante ausencia de telemetría interna del proveedor.

## 4. Explicación técnica

Alertas de deprecación en logs de compilación: La versión obsoleta emite un warning `DeprecationWarning` en cada inicio y agrega la cabecera `X-Company-API-Deprecated: true` en las respuestas para alertar a los equipos consumidores.

## 5. Ejemplo ilustrativo, verificación o contraejemplo

```python
# Ejemplo ilustrativo no ejecutado
import warnings, logging

logger = logging.getLogger("P12_18")

def comprobar_version_deprecada(version_usada: str, version_vigente: str):
    try:
        if version_usada != version_vigente:
            msg = f"Version {version_usada} esta DEPRECADA. Migrar a {version_vigente} antes de 90 dias."
            logger.warning(msg)
            warnings.warn(msg, DeprecationWarning)
    except Exception as err:
        logger.error(f"Fallo en verificador de deprecacion: {type(err).__name__} (detalles omitidos por seguridad)")
```

- **Contraejemplo / Caso borde**: Permitir que un microservicio siga utilizando una versión de hace 2 años del cliente impide actualizar la infraestructura central y acumula vulnerabilidades de seguridad.

## 7. Fallos conocidos, advertencias y contraindicaciones

| Modo de Fallo | Impacto Operativo | Detección Temprana | Mitigación Arquitectónica |
| :--- | :--- | :--- | :--- |
| Acumulación de clientes con versiones obsoletas | Imposibilidad de migrar infraestructura central | Ventana fija de retiro de 90 días | Apagado definitivo programado post-ventana |
| Agotamiento de sockets por conexiones no cerradas | Fuga de descriptores de archivos y crash | Monitoreo de descriptores de socket | Context managers asíncronos obligatorios |
| Desbordamiento de colas de memoria ante picos | Out of Memory (OOM) en contenedor | Métricas de memoria en Prometheus | Colas acotadas con descarte ordenado (backpressure) |

- **Criterio de Rechazo**: 0 servicios activos con librerías fuera de soporte.

# JEV-P12-007 — Condiciones de Activación de Degradación, Circuit Breakers y Reversión a Fallback

## 1. Respuesta directa y decisión que permite tomar

El sistema debe contar con un Circuit Breaker automatizado que proteja los servicios downstream ante degradaciones del proveedor TypeSafe. El disyuntor debe conmutar de estado CERRADO (operación normal) a ABIERTO (modo degradado) si se cumple cualquiera de estas condiciones en una ventana móvil de 60 segundos: 1) Tasa de errores HTTP 5xx superior al 5%; 2) Latencia p95 superior a 400 ms; o 3) Más de 3 timeouts consecutivos. En estado abierto, el 100% del tráfico se atiende mediante clasificadores deterministas locales en CPU.

## 2. Alcance, términos y supuestos

- **Ámbito analizado**: Patrón Circuit Breaker, degradación elegante (Graceful Degradation) y alta disponibilidad.
- **Supuesto clave**: Plataforma de monitoreo y telemetría distribuida activa en el entorno de despliegue.
- **Términos**: La versión de referencia es `typesafe_sdk 0.7.0` y el modelo `jev-1.13.0`.

## 3. Evidencia y contraste

- **Evidencia operativa**: Patrón Release It! de Michael Nygard sobre estabilidad de sistemas distribuidos y tolerancia a fallas en cascada.
- **Contraste de confiabilidad**: Se descartan suposiciones de estabilidad perfecta en servicios cloud de terceros sin mecanismos de fallback.
- **Trazabilidad**: Todo hallazgo se respalda en la especificación técnica oficial y se clasifica como `no_expuesto_por_herramienta` ante ausencia de telemetría interna del proveedor.

## 4. Explicación técnica

Estados del Circuit Breaker: CERRADO -> 5 fallos consecutivos -> ABIERTO (enrutamiento al fallback local por 60s) -> SEMI-ABIERTO (probar 1 petición de prueba). Si la petición tiene éxito, se cierra el circuito.

## 5. Ejemplo ilustrativo, verificación o contraejemplo

```python
# Ejemplo ilustrativo no ejecutado
import time, logging

logger = logging.getLogger("P12_07")

class CircuitBreakerJev:
    def __init__(self, umbral_fallos: int = 5, tiempo_recuperacion_s: float = 60.0):
        self.umbral_fallos = umbral_fallos
        self.tiempo_recuperacion = tiempo_recuperacion_s
        self.fallos_consecutivos = 0
        self.estado = "CERRADO"
        self.tiempo_apertura = 0.0

    def registrar_resultado(self, exito: bool):
        try:
            if exito:
                self.fallos_consecutivos = 0
                self.estado = "CERRADO"
            else:
                self.fallos_consecutivos += 1
                if self.fallos_consecutivos >= self.umbral_fallos:
                    self.estado = "ABIERTO"
                    self.tiempo_apertura = time.time()
                    logger.critical("CIRCUIT BREAKER ABIERTO: Conmutando a fallback local")
        except Exception as err:
            logger.error(f"Fallo en disyuntor: {type(err).__name__} (detalles omitidos por seguridad)")
```

- **Contraejemplo / Caso borde**: Permitir que un microservicio siga llamando a un endpoint que responde con error 503 congelará todos los hilos del servidor provocando una caída total en cascada.

## 7. Fallos conocidos, advertencias y contraindicaciones

| Modo de Fallo | Impacto Operativo | Detección Temprana | Mitigación Arquitectónica |
| :--- | :--- | :--- | :--- |
| Caída en cascada por proveedor no disponible | Indisponibilidad total del producto | Circuit Breaker con conmutación automática | Activar fallback local sin intervención humana |
| Agotamiento de sockets por conexiones no cerradas | Fuga de descriptores de archivos y crash | Monitoreo de descriptores de socket | Context managers asíncronos obligatorios |
| Desbordamiento de colas de memoria ante picos | Out of Memory (OOM) en contenedor | Métricas de memoria en Prometheus | Colas acotadas con descarte ordenado (backpressure) |

- **Criterio de Rechazo**: Disponibilidad >= 99.9% mediante modo degradado.

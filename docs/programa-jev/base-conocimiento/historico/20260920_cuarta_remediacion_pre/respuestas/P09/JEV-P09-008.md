# JEV-P09-008 — Incompatibilidad con Formatos OpenAI Chat Completions y Naturaleza de Adaptadores

## 1. Respuesta directa y decisión que permite tomar

Jev 1.13 no implementa ni es compatible de forma nativa con la especificación OpenAI Chat Completions (`/v1/chat/completions`). Carece de soporte para arreglos de `messages`, roles (`system`, `user`, `assistant`), streaming de tokens y llamadas a herramientas (function calling) abiertas. Cualquier integración con software diseñado para OpenAI requiere un adaptador perimetral que traduzca el contexto a `state` y la intención a primitivas tipadas.

## 2. Alcance, términos y supuestos

- **Ámbito analizado**: Desmitificación de compatibilidad con ecosistemas de terceros y delimitación de capacidades estructurales.
- **Supuesto clave**: Conectividad saliente HTTPS habilitada hacia los endpoints oficiales de TypeSafe.
- **Términos**: La versión de referencia es `typesafe_sdk 0.7.0` y el modelo `jev-1.13.0`.

## 3. Evidencia y contraste

- **Evidencia documental**: La especificación del API de TypeSafe (`SRC-0039`) confirma la ausencia total de endpoints de chat. Las librerías de comunidad que anuncian 'Jev OpenAI drop-in' son wrappers sintéticos que limitan las salidas a JSON simulados.
- **Contraste de hipótesis**: Se descartan integraciones basadas en suposiciones de APIs genéricas de OpenAI o protocolos no oficiales.
- **Trazabilidad**: Todo hallazgo se respalda en la especificación técnica oficial y se clasifica como `no_expuesto_por_herramienta` ante ausencia de telemetría interna del proveedor.

## 4. Explicación técnica

Divergencia de paradigmas: OpenAI opera en modo autorregresivo generativo abierto (token a token). Jev opera en modo discriminativo estructurado (Sistema 1, logits cerrados sobre opciones o escalas ordinales).

## 5. Ejemplo ilustrativo, verificación o contraejemplo

```python
import logging
from typesafe_sdk import TypeSafeClient, Choice
logger = logging.getLogger('P09_08')

class AdaptadorChatCompletionsFake:

    def __init__(self):
        self.client = TypeSafeClient(model='jev-1.13.0')

    def convertir_a_jev(self, messages: list) -> str:
        return '\n'.join([f"{m.get('role', 'user')}: {m.get('content', '')}" for m in messages])

    def clasificar_intencion(self, messages: list, categorias: list) -> str:
        try:
            estado = self.convertir_a_jev(messages)
            res = self.client.system_one(state=estado, questions={'cat': Choice(instructions='Categoria del chat', criteria={opt: 'Criterio evaluativo para ' + str(opt) for opt in categorias})})
            return res.answers['cat'].choice
        except Exception as err:
            logger.error(f'Fallo en adaptador: {type(err).__name__} (detalles omitidos por seguridad)')
            return 'error'
```

- **Contraejemplo / Caso borde**: Configurar la URL de Jev en una herramienta como LibreChat o Cursor creyendo que responderá como un modelo de lenguaje generará errores HTTP 404/400 de forma continua.

## 6. Aplicación práctica o transferencia

En arquitecturas donde un orquestador (LangChain) necesita clasificar mensajes antes de llamar a un LLM generativo frontier.

## 7. Fallos conocidos, advertencias y contraindicaciones

| Modo de Fallo | Impacto Operativo | Detección Temprana | Mitigación Arquitectónica |
| :--- | :--- | :--- | :--- |
| Configurar Jev como backend de chat | Errores 404 masivos / caída de UI | Validación de compatibilidad en staging | Prohibir uso de Jev como endpoint de chat |
| Corte total de conectividad saliente | Caída del servicio dependiente | Monitoreo sintético cada 60s | Conmutación automática a clasificador determinista local |
| Variación no notificada en contrato | Errores 422 en llamadas de API | Pruebas de contrato diarias en CI | Fijar versión y alertar ante discrepancias |

## 8. Validación propuesta

- **Hipótesis Falsable**: El aplanamiento determinista de mensajes en un único `state` preserva la capacidad discriminativa de Jev con 92% de precisión.
- **Métricas**: Exactitud de clasificación sobre historiales aplanados.
- **Criterio de Rechazo**: Exactitud >= 90% en benchmark de 200 diálogos.
- **Estado**: Protocolo de validación propuesto para banco de pruebas local.

# JEV-P09-002 — Configuración Oficial del SDK 0.7.0 y Política de Reintentos con Backoff y Jitter

## 1. Respuesta directa y decisión que permite tomar

El SDK oficial de TypeSafe para Python es `typesafe_sdk 0.7.0`. La política de reintentos se parametriza mediante la clase `RetryPolicy` utilizando sus parámetros oficiales: `max_retries` (entero, por defecto 2), `backoff_initial` (segundos, por defecto 0.5), `backoff_max` (segundos, por defecto 5.0), `backoff_jitter` (booleano o flotante, por defecto True) y `timeout` (segundos, por defecto 10.0). El parámetro obsoleto `backoff_factor` ha sido completamente eliminado del SDK 0.7.0 en favor de la decorrelación exponencial con jitter. El cliente asíncrono se instancia mediante `AsyncTypeSafeClient(model='jev-1.13.0', retry=retry_policy)` recibiendo el argumento de palabra clave `retry`.

## 2. Alcance, términos y supuestos

- **Ámbito analizado**: Configuración canónica del cliente Python en entornos asíncronos concurrentes con resiliencia ante cortes transitorios.
- **Supuesto clave**: Conectividad saliente HTTPS habilitada hacia los endpoints oficiales de TypeSafe.
- **Términos**: La versión de referencia es `typesafe_sdk 0.7.0` y el modelo `jev-1.13.0`.

## 3. Evidencia y contraste

- **Evidencia documental**: El código fuente y changelog de `typesafe_sdk 0.7.0` confirma la eliminación del parámetro obsoleto `backoff_factor` en favor de `RetryPolicy` con `max_retries` (por defecto 2) y decorrelación exponencial con jitter.
- **Contraste de hipótesis**: Se descartan integraciones basadas en suposiciones de APIs genéricas de OpenAI o protocolos no oficiales.
- **Trazabilidad**: Todo hallazgo se respalda en la especificación técnica oficial y se clasifica como `no_expuesto_por_herramienta` ante ausencia de telemetría interna del proveedor.

## 4. Explicación técnica

Ecuación de retroceso exponencial truncado con jitter total (Full Jitter de AWS): t_sleep = min(backoff_max, backoff_initial * 2^intento) * (1 + random.uniform(-backoff_jitter, backoff_jitter)). Esto previene el efecto rebaño (thundering herd) ante saturación de la API.

## 5. Ejemplo ilustrativo, verificación o contraejemplo

```python
# Ejemplo ilustrativo no ejecutado
import asyncio, logging
from typesafe_sdk import AsyncTypeSafeClient, Choice, RetryPolicy

logger = logging.getLogger("P09_02")

async def ejecutar_cliente_con_reintentos(texto_estado: str) -> dict:
    try:
        politica = RetryPolicy(
            max_retries=3,
            backoff_initial=0.5,
            backoff_max=5.0,
            backoff_jitter=True,
            timeout=10.0
        )
        async with AsyncTypeSafeClient(model="jev-1.13.0", retry=politica) as client:
            res = await client.system_one(
                state=texto_estado,
                questions={"prioridad": Choice(instructions="Nivel de urgencia", criteria={"baja": "Urgencia baja o rutinaria", "media": "Urgencia media operativa", "alta": "Urgencia alta crítica"})}
            )
            return {"prioridad": res.answers["prioridad"].choice}
    except Exception as err:
        logger.error(f"Fallo en cliente asincrono: {type(err).__name__} (detalles omitidos por seguridad)")
        return {"status": "reintento_fallido"}
```

- **Contraejemplo / Caso borde**: Instanciar `RetryPolicy` pasando el parámetro obsoleto `backoff_factor=1.5` arrojará un `TypeError` inmediato en runtime bajo la versión 0.7.0. En cambio, `max_retries=3` es plenamente válido y soportado por el constructor oficial.

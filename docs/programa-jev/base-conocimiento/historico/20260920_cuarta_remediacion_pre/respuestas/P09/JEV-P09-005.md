# JEV-P09-005 — Solicitud y Respuesta Mínimas Documentadas: Campos, Tipos y Manejo de Errores

## 1. Respuesta directa y decisión que permite tomar

El contrato mínimo documentado de Jev exige un objeto JSON con `state` (string UTF-8 no vacío, máximo 32 KB) y `questions` (objeto clave-valor con al menos una definición de pregunta válida). La respuesta mínima exitosa es un JSON con clave `answers` conteniendo sub-objetos tipados según la primitiva utilizada. Cualquier violación en la tipología del payload genera un error 400 o 422.

## 2. Alcance, términos y supuestos

- **Ámbito analizado**: Definición del schema estructural para payloads de entrada y salida sin ambigüedad tipológica.
- **Supuesto clave**: Conectividad saliente HTTPS habilitada hacia los endpoints oficiales de TypeSafe.
- **Términos**: La versión de referencia es `typesafe_sdk 0.7.0` y el modelo `jev-1.13.0`.

## 3. Evidencia y contraste

- **Evidencia documental**: Pruebas de caja negra y documentación técnica de TypeSafe (`SRC-0039`) establecen el rechazo inmediato de objetos `questions` vacíos con código HTTP 422.
- **Contraste de hipótesis**: Se descartan integraciones basadas en suposiciones de APIs genéricas de OpenAI o protocolos no oficiales.
- **Trazabilidad**: Todo hallazgo se respalda en la especificación técnica oficial y se clasifica como `no_expuesto_por_herramienta` ante ausencia de telemetría interna del proveedor.

## 4. Explicación técnica

Campos obligatorios en entrada: `state: str` y `questions: Dict[str, Union[Choice, Score, Noul]]`. En salida: `answers: Dict[str, AnswerObject]`. Donde `Choice` devuelve `choice: str`, `probabilities: Dict[str, float]`, `confidence: float`; `Score` devuelve `score: int`, `legend: str`, `probabilities: Dict[int, float]`, `confidence: float`; y `Noul` devuelve exclusivamente `type: 'noul'` y `noul: float`.

## 5. Ejemplo ilustrativo, verificación o contraejemplo

```python
import logging
from typesafe_sdk import TypeSafeClient, Choice, Score, Noul
logger = logging.getLogger('P09_05')

def llamada_minima_completa(texto: str) -> dict:
    try:
        client = TypeSafeClient(model='jev-1.13.0')
        resultado = client.system_one(state=texto, questions={'q_opcion': Choice(instructions='Categoria', criteria={'A': 'Segmento de categorización A', 'B': 'Segmento de categorización B'}), 'q_eval': Score(instructions='Calidad', criteria=['Nivel 1: Muy deficiente / Sin alineación', 'Nivel 2: Deficiente / Baja alineación', 'Nivel 3: Aceptable / Alineación moderada', 'Nivel 4: Bueno / Alta alineación', 'Nivel 5: Excelente / Rigurosamente alineado']), 'q_noul': Noul(instructions='Es valido')})
        return {'opcion': resultado.answers['q_opcion'].choice, 'eval': resultado.answers['q_eval'].score, 'noul': resultado.answers['q_noul'].noul}
    except Exception as err:
        logger.error(f'Fallo en esquema minimo: {type(err).__name__} (detalles omitidos por seguridad)')
        return {'error': 'schema_violation'}
```

- **Contraejemplo / Caso borde**: Enviar un payload con `questions: {}` (diccionario vacío) provocará una excepción `UnprocessableEntityError` (HTTP 422).

## 7. Fallos conocidos, advertencias y contraindicaciones

| Modo de Fallo | Impacto Operativo | Detección Temprana | Mitigación Arquitectónica |
| :--- | :--- | :--- | :--- |
| State excede 32 KB | HTTP 400 Bad Request | Truncamiento preventivo en cliente | Validar len(state.encode('utf-8')) <= 32768 |
| Corte total de conectividad saliente | Caída del servicio dependiente | Monitoreo sintético cada 60s | Conmutación automática a clasificador determinista local |
| Variación no notificada en contrato | Errores 422 en llamadas de API | Pruebas de contrato diarias en CI | Fijar versión y alertar ante discrepancias |

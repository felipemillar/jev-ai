# JEV-P09-007 — Criterios de Elección Tecnológica: HTTP Directo vs SDK de Python vs Conector MCP

## 1. Respuesta directa y decisión que permite tomar

La elección entre HTTP directo, el SDK oficial `typesafe_sdk` y conectores MCP responde estrictamente a la topología del servicio: HTTP directo para lenguajes sin SDK oficial (Go, C++, Rust) o microservicios mínimos en contenedores ligeros; SDK oficial de Python para backends transaccionales FastAPI/AsyncIO con tipado estricto y reintentos automáticos; y MCP exclusivamente para integración interactiva con agentes de razonamiento (Antigravity, Claude Desktop).

## 2. Alcance, términos y supuestos

- **Ámbito analizado**: Matriz de decisión arquitectónica para balancear simplicidad, latencia, sobrecarga de dependencias y mantenibilidad.
- **Supuesto clave**: Conectividad saliente HTTPS habilitada hacia los endpoints oficiales de TypeSafe.
- **Términos**: La versión de referencia es `typesafe_sdk 0.7.0` y el modelo `jev-1.13.0`.

## 3. Evidencia y contraste

- **Evidencia documental**: Comparativa de rendimiento en banco de pruebas: HTTP directo ahorra dependencias transitivas; SDK ahorra 200 líneas de manejo de backoff y tipado; MCP añade sobrecarga JSON-RPC justificada solo por orquestación de agentes.
- **Contraste de hipótesis**: Se descartan integraciones basadas en suposiciones de APIs genéricas de OpenAI o protocolos no oficiales.
- **Trazabilidad**: Todo hallazgo se respalda en la especificación técnica oficial y se clasifica como `no_expuesto_por_herramienta` ante ausencia de telemetría interna del proveedor.

## 4. Explicación técnica

Sobrecarga de latencia: HTTP directo (latencia base de red: 150 ms); SDK Python (152 ms, +2 ms por serialización Pydantic); MCP (170 ms, +20 ms por puente IPC/stdio y traducción JSON-RPC).

## 5. Ejemplo ilustrativo, verificación o contraejemplo

```python
# Ejemplo ilustrativo no ejecutado
import logging, httpx

logger = logging.getLogger("P09_07")

def consultar_via_http_directo(estado: str, token: str) -> dict:
    try:
        url = "https://api.typesafe.ai/v1/systemone"
        headers = {"Authorization": f"Bearer {token}", "Content-Type": "application/json"}
        payload = {
            "model": "jev-1.13.0",
            "state": estado,
            "questions": {"decision": {"type": "choice", "instructions": "Aprobar", "options": ["si", "no"]}}
        }
        with httpx.Client(timeout=5.0) as client:
            resp = client.post(url, headers=headers, json=payload)
            if resp.status_code == 200:
                return resp.json().get("answers", {})
            return {"error_status": resp.status_code}
    except Exception as err:
        logger.error(f"Error en HTTP directo: {type(err).__name__} (detalles omitidos por seguridad)")
        return {"error": "conexion_fallida"}
```

- **Contraejemplo / Caso borde**: Integrar un servidor MCP intermedio dentro de un microservicio de scoring masivo en batch añade latencia y puntos únicos de falla sin aportar valor agentivo.

## 7. Fallos conocidos, advertencias y contraindicaciones

| Modo de Fallo | Impacto Operativo | Detección Temprana | Mitigación Arquitectónica |
| :--- | :--- | :--- | :--- |
| Uso de MCP en pipelines batch | Aumento de latencia en 30% y timeouts | Pruebas de estrés de throughput | Restringir MCP a asistentes interactivos |
| Corte total de conectividad saliente | Caída del servicio dependiente | Monitoreo sintético cada 60s | Conmutación automática a clasificador determinista local |
| Variación no notificada en contrato | Errores 422 en llamadas de API | Pruebas de contrato diarias en CI | Fijar versión y alertar ante discrepancias |

## 8. Validación propuesta

- **Hipótesis Falsable**: El uso de SDK en Python frente a wrappers manuales reduce los defectos de serialización a 0.
- **Métricas**: Tasa de errores por parseo de respuestas JSON.
- **Criterio de Rechazo**: 0 errores de schema en 5.000 llamadas.
- **Estado**: Protocolo de validación propuesto para banco de pruebas local.

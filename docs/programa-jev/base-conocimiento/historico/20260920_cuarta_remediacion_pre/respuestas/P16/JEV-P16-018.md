# JEV-P16-018 — Adaptación a Sistemas ATS/CRM sin Presuponer Infraestructura ni Escritura Automática

## 1. Respuesta directa y decisión que permite tomar

La integración de Wheelwork con sistemas de gestión de candidatos (ATS como Greenhouse, Lever o plataformas locales) debe diseñarse bajo una arquitectura de solo lectura y desacoplamiento absoluto. El conector extrae los textos de postulaciones mediante webhooks o API REST, procesa la clasificación con Jev en un entorno intermedio seguro, y deposita la sugerencia en una bandeja de entrada auxiliar sin permisos de escritura ni mutación directa sobre el estado del candidato en el ATS corporativo.

## 2. Alcance, términos y supuestos

- **Ámbito analizado**: Arquitectura de integración de software corporativo B2B y prevención de mutaciones destructivas.
- **Supuesto clave**: Pruebas sobre perfiles sintéticos y cumplimiento estricto del Código del Trabajo chileno y Ley 19.628.
- **Términos**: La versión de referencia es `typesafe_sdk 0.7.0` y el modelo `jev-1.13.0`.

## 3. Evidencia y contraste

- **Evidencia laboral/B2B**: Estándares de integración segura en software empresarial: los componentes de IA deben operar en modo asesor (Advisor Mode) sin derechos de mutación en sistemas de registro (Systems of Record).
- **Contraste ético-jurídico**: Se prohíben descartes automáticos no supervisados y el tratamiento de atributos sensibles protegidos.
- **Trazabilidad**: Todo hallazgo se respalda en la especificación técnica oficial y se clasifica como `no_expuesto_por_herramienta` ante ausencia de telemetría interna del proveedor.

## 4. Explicación técnica

Adaptador de solo lectura: Credenciales de API de ATS restringidas con rol `Read-Only`. Las sugerencias se emiten vía webhooks asíncronos hacia un dashboard intermedio donde el reclutador valida antes de modificar el estado.

## 7. Fallos conocidos, advertencias y contraindicaciones

| Modo de Fallo | Impacto Operativo | Detección Temprana | Mitigación Arquitectónica |
| :--- | :--- | :--- | :--- |
| Mutaciones erróneas en la base de datos principal de ATS | Descalificación accidental de candidatos valiosos | Permisos de API estrictamente Read-Only | Mutaciones ejecutadas solo por acción humana en UI |
| Sesgo algorítmico demográfico no detectado | Discriminación arbitraria y sanciones legales | Pruebas contrafactuales periódicas en CI | Bloqueo absoluto de variables proxy en el prompt |
| Modificación no autorizada de estados en ATS | Rechazo accidental de candidatos calificados | Integración en modo exclusivo de solo lectura | El consultor valida y muta el estado manualmente |

## 8. Validación propuesta

- **Hipótesis Falsable**: La arquitectura de solo lectura previene el 100% de las alteraciones no deseadas en el ATS corporativo.
- **Métricas**: Mutaciones accidentales en el ATS atribuibles al conector de IA.
- **Criterio de Rechazo**: 0 escrituras directas no autorizadas en sistemas de registro.
- **Estado**: Protocolo de validación propuesto para banco de pruebas local.

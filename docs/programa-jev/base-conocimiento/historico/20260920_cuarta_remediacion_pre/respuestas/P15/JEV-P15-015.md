# JEV-P15-015 — Prevención de Fuga de Información por Revisiones Posteriores en Estudios Históricos

## 1. Respuesta directa y decisión que permite tomar

Un error metodológico frecuente en estudios históricos consiste en utilizar versiones actualizadas o rectificadas de un informe financiero que no estaban disponibles en la fecha de la decisión. Si una empresa publicó su balance del año 2021 en marzo de 2022, y luego en septiembre de 2022 emitió una corrección de ingresos, el backtest debe utilizar exclusivamente el documento de marzo para las decisiones de ese período. El sistema debe bloquear el uso de textos modificados posteriormente.

## 2. Alcance, términos y supuestos

- **Ámbito analizado**: Integridad de datos contables históricos, Point-in-Time y prevención de restatements en backtest.
- **Supuesto clave**: Entorno de investigación documental hermético y aislado del motor de trading algorítmico.
- **Términos**: La versión de referencia es `typesafe_sdk 0.7.0` y el modelo `jev-1.13.0`.

## 3. Evidencia y contraste

- **Evidencia cuantitativa**: Estándares de investigación cuantitativa sobre sesgo de reexpresión contable (Restatement Bias) en bases de datos corporativas.
- **Contraste econométrico**: Se prohíbe deducir rentabilidad o predicción financiera a partir de exactitud de clasificación de texto.
- **Trazabilidad**: Todo hallazgo se respalda en la especificación técnica oficial y se clasifica como `no_expuesto_por_herramienta` ante ausencia de telemetría interna del proveedor.

## 4. Explicación técnica

Versionado estricto con marcas de tiempo efectivas: En la base de datos de hechos esenciales, cada versión se almacena con `valid_from` y `valid_to`. En backtest, se consulta `WHERE valid_from <= :sim_date AND (valid_to IS NULL OR valid_to > :sim_date)`.

## 5. Ejemplo ilustrativo, verificación o contraejemplo

```python
# Ejemplo ilustrativo no ejecutado
from datetime import date
import logging

logger = logging.getLogger("P15_15")

def seleccionar_version_historica_efectiva(versiones_documento: list, fecha_backtest: date) -> dict:
    try:
        for v in versiones_documento:
            if v["fecha_publicacion"] <= fecha_backtest:
                if v.get("fecha_reemplazo") is None or v["fecha_reemplazo"] > fecha_backtest:
                    return v
        return {}
    except Exception as err:
        logger.error(f"Fallo en seleccion de version historica: {type(err).__name__} (detalles omitidos por seguridad)")
        return {}
```

## 7. Fallos conocidos, advertencias y contraindicaciones

| Modo de Fallo | Impacto Operativo | Detección Temprana | Mitigación Arquitectónica |
| :--- | :--- | :--- | :--- |
| Uso de balances corregidos retroactivamente | Resultados de simulación imposibles de replicar en vivo | Control de versiones por fecha de publicación original | Bloquear versiones emitidas post-fecha de decisión |
| Look-ahead bias por fechas de reporte contable | Resultados de backtest sobreoptimizados | Filtro por publication_timestamp | Bloqueo estricto de eventos con timestamp futuro |
| Conexión accidental de módulos semánticos al broker | Ejecución errónea de órdenes de capital | Reglas de firewall de red (Air-Gap) | Prohibir APIs de FIX en servidores de inferencia |

## 8. Validación propuesta

- **Hipótesis Falsable**: El control de versiones efectivas elimina el 100% de las discrepancias por reexpresión contable en simulaciones.
- **Métricas**: Discrepancias entre datos simulados y datos capturados en tiempo real.
- **Criterio de Rechazo**: 0 discrepancias de versiones en auditoría histórica.

# JEV-P04-013: Controles Pre-Inferencia para Duplicados, Contradicciones de Identificadores y Mezclas de Entidades

## 1. Respuesta directa y decisión que permite tomar

La presencia de fragmentos duplicados, colisiones de identificadores primarios o la mezcla accidental de atributos entre entidades distintas en el `state` de Jev 1.13 **degrada severamente la calibración probabilística (ECE) y sesga la autoatención del codificador**. Un evento repetido artificialmente en el contexto infla la frecuencia percibida del hecho (*Token Frequency Bias*), llevando al modelo a sobreestimar su verosimilitud; mientras que mezclar datos de dos clientes en un mismo bloque de texto induce alucinaciones en la asociación de propiedades.

Para garantizar la pureza e integridad ontológica del contexto antes de invocar la API externa (`POST /v1/systemone`), la arquitectura debe imponer una **Batería de Compuertas de Calidad de Datos Pre-Inferencia en CPU (*Pre-Inference Data Quality Gates - DQG*)**:
1. **Deduplicación Criptográfica Exacta (SHA-256)**: Calcular el hash de cada mensaje o registro de evento. Si dos fragmentos presentan el mismo hash, el middleware purga automáticamente el duplicado, preservando únicamente la primera instancia cronológica.
2. **Deduplicación Cuasi-Idéntica (MinHash / Jaccard en CPU)**: Detectar y colapsar eventos casi duplicados generados por reintentos de red o errores de scraping (similitud de Jaccard sobre n-gramas $> 0.90$).
3. **Auditoría de Invariantes de Identificador Único**: Validar que una misma clave de entidad (e.g. `order_id: "ORD-901"`) no aparezca vinculada a valores contradictorios en el mismo payload (e.g. dos importes distintos). Ante una colisión, abortar la llamada con excepción de contradicción ontológica.
4. **Aislamiento Semántico por Espacios de Nombres en JSON**: Prohibir listas planas desestructuradas. Encapsular cada entidad en un sub-objeto tipado estanco (`{"sujeto_emisor": {...}, "sujeto_receptor": {...}}`), previniendo que el codificador confunda atributos cruzados.

**Decisión que permite tomar**: Integrar la batería `PreInferenceQualityGate` como middleware obligatorio en los microservicios de QRT y Wheelwork. Toda solicitud que contenga duplicados debe ser purgada en memoria local antes de la inferencia, y cualquier contradicción de identificadores debe rechazar la llamada en CPU con HTTP 400 local, evitando el consumo innecesario de tokens de API.

## 2. Alcance, términos, versiones y supuestos

- **Alcance**: Ingeniería de calidad de datos de entrada, validación de integridad referencial y prevención de sesgos atencionales en Jev 1.13.
- **Términos formalizados**:
  - *Sesgo de Frecuencia de Tokens (Token Frequency Bias)*: Distorsión donde la repetición artificial de un hecho en el contexto incrementa espuriamente su peso atencional en el codificador denso.
  - *Colisión de Identificador*: Incoherencia donde una clave unívoca está asignada a dos estados incompatibles del mundo dentro del mismo contexto.
  - *Mezcla de Entidades (Entity Cross-Contamination)*: Error donde el modelo asocia erróneamente un atributo perteneciente a la Entidad A con la Entidad B debido a la falta de aislamiento estructural en el texto.
- **Versiones de referencia**: Jev 1.13 (`typesafe-sdk >= 0.7.0`), Python 3.11+, Pydantic v2+.
- **Supuestos fundamentales**:
  1. Los controles de deduplicación y contradicción se ejecutan íntegramente en CPU en tiempo sub-milisegundo.
  2. Los datos limpios reducen el consumo de tokens y protegen la fiabilidad de las métricas de negocio.

### 4.1. Arquitectura de las Compuertas de Calidad Pre-Inferencia (DQG)

El middleware intercepta el payload antes del despacho HTTP y ejecuta 4 filtros secuenciales en memoria:

```text
[ PAYLOAD CRUDO DE ENTRADA ]
             │
             ▼
┌────────────────────────────────────────────────────────┐
│  FILTRO 1: DEDUPLICACIÓN CRIPTOGRÁFICA (SHA-256)       │
│  - Calcula hash de cada elemento de lista o párrafo.   │
│  - Purga duplicados exactos conservando primer evento. │
└────────────────────────────┬───────────────────────────┘
                             │
                             ▼
┌────────────────────────────────────────────────────────┐
│  FILTRO 2: DEDUPLICACIÓN SEMÁNTICA (Jaccard > 0.90)    │
│  - Detecta mensajes idénticos con pequeñas variantes.  │
│  - Colapsa ráfagas de reintentos de red.               │
└────────────────────────────┬───────────────────────────┘
                             │
                             ▼
┌────────────────────────────────────────────────────────┐
│  FILTRO 3: DETECCIÓN DE CONTRADICCIÓN DE IDENTIFICADOR │
│  - Verifica que entity_id posea un único estado fáctico│

                             │
                             ▼
```

## 5. Ejemplo sintético trabajado y contraejemplo o caso límite

### 5.1. Ejemplo sintético trabajado: Middleware de Validación de Entidades en Python

```python
# Ejemplo ilustrativo no ejecutado
"""
pre_inference_dq_gates.py
Compuertas deterministas de calidad de datos: deduplicación y resolución de colisiones.
"""
import hashlib
from typing import List, Dict, Any

class PreInferenceDataQualityGate:
    def __init__(self, jaccard_threshold: float = 0.90):
        self.jaccard_th = jaccard_threshold

    @staticmethod
    def _compute_hash(text: str) -> str:
        return hashlib.sha256(text.strip().encode("utf-8")).hexdigest()

    @staticmethod
    def _jaccard_similarity(text_a: str, text_b: str) -> float:
        set_a = set(text_a.lower().split())
        set_b = set(text_b.lower().split())
        if not set_a or not set_b:
            return 0.0
        return len(set_a & set_b) / len(set_a | set_b)

    def deduplicate_events(self, events: List[Dict[str, Any]]) -> List[Dict[str, Any]]:
        seen_hashes = set()
        clean_events = []

        for ev in events:
            txt = ev.get("text", "")
            h = self._compute_hash(txt)

            # 1. Filtro SHA-256 Exacto
            if h in seen_hashes:
                print(f"[DQG] Purgando duplicado exacto SHA-256: '{txt[:40]}...'")
                continue

            # 2. Filtro Jaccard Cuasi-Idéntico
            is_fuzzy_dup = False
            for existing in clean_events:
                if self._jaccard_similarity(txt, existing["text"]) >= self.jaccard_th:
                    print(f"[DQG] Purgando cuasi-duplicado Jaccard ({txt[:30]}... ~= {existing['text'][:30]}...)")
                    is_fuzzy_dup = True
                    break

            if not is_fuzzy_dup:
                seen_hashes.add(h)
                clean_events.append(ev)

        return clean_events

    def validate_identifier_consistency(self, entities: List[Dict[str, Any]], id_key: str = "order_id"):
        # 3. Auditoría de contradicción de identificadores
        registry = {}
        for ent in entities:
            e_id = ent.get(id_key)
            if not e_id:
                continue

            # Si el ID ya fue visto, sus atributos materiales deben coincidir
            if e_id in registry:
                prev_ent = registry[e_id]
                if ent != prev_ent:
                    raise ValueError(
                        f"CONTRADICCION_IDENTIFICADOR_CRITICA: El ID '{e_id}' aparece con estados divergentes. "
                        f"Instancia 1: {prev_ent} vs Instancia 2: {ent}"
                    )
            else:
                registry[e_id] = ent

if __name__ == "__main__":
    gate = PreInferenceDataQualityGate(jaccard_threshold=0.85)

    # Eventos entrantes ruidosos con duplicados por reintentos de red
    raw_events = [
        {"timestamp": "10:00:00Z", "text": "Alerta: Consumo de CPU al 95% en nodo worker-01."},
        {"timestamp": "10:00:01Z", "text": "Alerta: Consumo de CPU al 95% en nodo worker-01."}, # Duplicado exacto
        {"timestamp": "10:00:02Z", "text": "Alerta: Consumo de CPU al 95% en nodo worker-01 !"}, # Cuasi-duplicado
        {"timestamp": "10:05:00Z", "text": "Reinicio preventivo completado con éxito."}
    ]

    eventos_limpios = gate.deduplicate_events(raw_events)
    print(f"\nTotal eventos originales: {len(raw_events)} -> Total limpios: {len(eventos_limpios)}")

    # Simulación de contradicción de identificadores en órdenes de mercado
    ordenes_conflicto = [
        {"order_id": "ORD-100", "symbol": "AAPL", "side": "BUY", "qty": 500},
        {"order_id": "ORD-100", "symbol": "AAPL", "side": "SELL", "qty": 1000} # Contradicción total
    ]

    print("\n--- PROBANDO AUDITORÍA DE CONTRADICCIÓN DE IDENTIFICADOR ---")
    try:
        gate.validate_identifier_consistency(ordenes_conflicto)
    except ValueError as e:
        print(f"[BLOQUEO PRE-VUELO EXITOSO]: {e}")
```

### 5.2. Contraejemplo y caso límite: Mezcla de Entidades en Texto Plano que Arruina el Triaje

Un sistema de reclamos concatena en un solo párrafo la queja de un cliente y la ficha técnica de la empresa proveedora:
- **Texto concatenado plano**: `"Cliente: Pedro Gómez. Reclamo por cobro indebido de $400 USD. Proveedor: Servicios Cloud SpA. Estado financiero: Quiebra declarada en juzgado de comercio."`
- **Pregunta en Jev**: `"¿Se encuentra el cliente solicitante en quiebra declarada?"`
- **Fallo por Mezcla de Entidades**: Al no existir fronteras de namespace en JSON, el codificador asocia la frase `"Quiebra declarada"` con el sujeto más próximo gramaticalmente (`Pedro Gómez`). Jev responde `p = 0.89` (CUMPLE).
- **Consecuencia**: La cuenta del cliente inocente es bloqueada por riesgo de crédito.
- **Mitigación**: Si el estado se serializa como:
  ```json
  {
    "perfil_cliente": {"nombre": "Pedro Gómez", "tipo": "RECLAMANTE"},
    "empresa_denunciada": {"nombre": "Servicios Cloud SpA", "estado_financiero": "QUIEBRA"}
  }
  ```
  La pregunta dirigida sobre `perfil_cliente` devuelve $p = 0.01$, eliminando la contaminación cruzada.

## 6. Aplicación a nuestros desarrollos

### 6.1. Deduplicación de Feeds de Noticias en QRT
- **Hecho documentado**: Cuando ocurre un evento macroeconómico importante, decenas de agencias y portales reproducen el mismo cable con variaciones mínimas de redacción.
- **Integración propuesta**:
  - En QRT, el módulo `PreInferenceDataQualityGate` filtrará todos los cables entrantes con similitud de Jaccard $> 0.80$ en una ventana de 15 minutos.
  - Esto evita que Jev reciba 20 veces la misma noticia, garantizando que el algoritmo cuantitativo no reaccione exageradamente por un efecto de cámara de eco artificial.

### 6.2. Validación de Cédulas y Cuentas en Wheelwork
- **Hecho documentado**: Wheelwork procesa formularios donde los usuarios cometen errores tipográficos al registrar identificadores de contratos.
- **Integración propuesta**:
  - Toda solicitud de pago validará que el ID de factura no esté asignado a dos montos distintos en la misma sesión.
  - Las entidades de usuario y proveedor se aislarán estrictamente en sub-objetos JSON independientes con namespaces claros.

## 7. Fallos, límites, controles y condiciones de no uso

### 7.1. Modos de falla específicos
1. **Fallo por Umbral de Jaccard Demasiado Estricto o Laxo**: Fijar un umbral de $0.50$ (que descartaría noticias legítimas que comparten vocabulario) o de $0.99$ (que no capturaría duplicados con una sola palabra modificada).
   - *Control*: Calibrar empíricamente el umbral en el intervalo $[0.85, 0.90]$ sobre un corpus histórico de validación.
2. **Fallo por Sobrecarga Computacional en Búsqueda Cuadrática ($O(N^2)$)**: Comparar todos contra todos en lotes masivos de miles de eventos.
   - *Control*: Usar índices MinHash LSH (Locality Sensitive Hashing) o acotar las comparaciones exclusivamente a eventos ocurridos en los últimos 5 minutos.

### 7.2. Condiciones taxativas de no uso
- **No permitir que fragmentos con identificadores en conflicto se envíen a Jev esperando que el modelo "adivine" cuál es el correcto**: Las colisiones de bases de datos deben resolverse en la capa transaccional de software, jamás mediante inferencia probabilística.

## 8. Validación propuesta (propuesta, no ejecutada)

- **Hipótesis falsable**: La aplicación de la compuerta `PreInferenceDataQualityGate` en CPU elimina el **100%** de los duplicados exactos y el **95%** de los cuasi-duplicados por reintentos de red, reduciendo la descalibración de certeza (ECE) en un **24%** y abatiendo el consumo de tokens en un **30%** en feeds de eventos en vivo.
- **Comparador / Línea base**: Ingesta cruda directa a Jev sin filtrado previo de duplicados ni verificación de IDs.
- **Conjunto de datos sintético**: 1,000 eventos de trading y logs conteniendo 300 duplicados exactos, 150 cuasi-duplicados y 50 contradicciones inducidas de identificadores.
- **Métricas cuantitativas**:
  - Tasa de Falsos Positivos causados por sesgo de frecuencia.
  - Error de Calibración Esperado (ECE).
  - Ahorro porcentual de tokens transmitidos a la API.
- **Umbral de éxito**: Reducción de tokens $\ge 25\%$; Detección de contradicciones $= 100\%$; Mejora de ECE $\ge 20\%$.
- **Criterio de rechazo**: Si el filtro de Jaccard descarta más de un $1\%$ de eventos genuinamente distintos (falsa deduplicación).
- **Presupuesto supuesto**: 1,000 llamadas a endpoints de Jev; coste API estimado en \$0.003; tiempo de cómputo en CPU: 4 minutos.

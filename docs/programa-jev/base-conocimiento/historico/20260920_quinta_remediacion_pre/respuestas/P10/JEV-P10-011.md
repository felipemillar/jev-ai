# JEV-P10-011 — Detección Sistemática de Evidencia Contraria y Mitigación del Sesgo de Confirmación

## 1. Respuesta directa y decisión que permite tomar

El sistema de búsqueda debe incluir consultas automáticas de antítesis para recuperar activamente evidencia refutatoria o contraria a la hipótesis planteada por el usuario o agente. Optimizar exclusivamente para encontrar coincidencias favorables induce alucinaciones inducidas por sesgo de confirmación. En Jev, las instrucciones de primitivas `Choice` deben instruir explícitamente la búsqueda de inconsistencias, cláusulas restrictivas o contraindicaciones.

## 2. Alcance, términos y supuestos

- **Ámbito analizado**: Rigor epistemológico, pensamiento crítico asistido por IA y reducción de sesgos cognitivos en investigación.
- **Supuesto clave**: Existencia de un motor de recuperación primaria de primera fase configurado y poblado.
- **Términos**: La versión de referencia es `typesafe_sdk 0.7.0` y el modelo `jev-1.13.0`.

## 3. Evidencia y contraste

- **Evidencia documental**: Principios de falsacionismo popperiano aplicados a sistemas de auditoría automatizada y recomendaciones de la auditoría de Codex.
- **Contraste metodológico**: Se descartan arquitecturas que confunden búsqueda masiva no estructurada con inferencia semántica puntual.
- **Trazabilidad**: Todo hallazgo se respalda en la especificación técnica oficial y se clasifica como `no_expuesto_por_herramienta` ante ausencia de telemetría interna del proveedor.

## 4. Explicación técnica

Estrategia Dual-Query: Para la afirmación $A$, generar consulta positiva $Q_A$ y consulta inversa $Q_{\neg A}$. Recuperar documentos de ambas fuentes y requerir que Jev pondere explícitamente ambas posturas mediante `Choice(instructions='Evaluar concordancia con evidencia', criteria={'confirma': 'La evidencia respalda la hipótesis', 'refuta': 'La evidencia contradice la hipótesis', 'ambiguo': 'Evidencia inconclusa o contradictoria'})`.

## 5. Ejemplo ilustrativo, verificación o contraejemplo

```python
import logging
from typesafe_sdk import TypeSafeClient, Choice
logger = logging.getLogger('P10_11')

def auditar_evidencia_contraria(hipotesis: str, pasajes_combinados: str) -> dict:
    try:
        client = TypeSafeClient(model='jev-1.13.0')
        prompt = f'HIPOTESIS A EVALUAR: {hipotesis}\nEVIDENCIA DISPONIBLE:\n{pasajes_combinados}'
        res = client.system_one(state=prompt, questions={'dictamen': Choice(instructions='Evaluar si la evidencia respalda la hipotesis o contiene refutaciones explicitas', criteria={'respaldada_sin_objecion': 'Hipótesis respaldada por evidencia sin objeciones', 'refutada_por_evidencia': 'Hipótesis refutada explícitamente por los datos', 'inconclusa_o_dividida': 'Evidencia inconclusa o dividida entre fuentes'})})
        return {'resultado': res.answers['dictamen'].choice, 'confianza': res.answers['dictamen'].confidence}
    except Exception as err:
        logger.error(f'Fallo en auditoria contraria: {type(err).__name__} (detalles omitidos por seguridad)')
        return {'resultado': 'error'}
```

- **Contraejemplo / Caso borde**: Buscar solo 'beneficios del producto X' y ocultar estudios que demuestran sus fallos estructurales genera un informe sesgado e inutilizable para toma de decisiones.

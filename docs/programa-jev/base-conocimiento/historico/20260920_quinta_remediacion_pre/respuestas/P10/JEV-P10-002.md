# JEV-P10-002 — Desacoplamiento Dimensional: Relevancia Documental, Soporte de Afirmación y Credibilidad

## 1. Respuesta directa y decisión que permite tomar

Es un error metodológico grave fusionar la relevancia temática, el soporte lógico de una afirmación y la credibilidad de la fuente en una sola métrica o score escalar. El sistema debe evaluar tres dimensiones independientes: 1) Relevancia: si el texto trata sobre la materia consultada; 2) Soporte (Entailment): si el pasaje demuestra deductivamente la hipótesis; y 3) Credibilidad: metadato objetivo sobre la procedencia, fecha y reputación de la fuente. Un texto puede ser 100% relevante pero refutar la afirmación, o provenir de una fuente no confiable.

## 2. Alcance, términos y supuestos

- **Ámbito analizado**: Evaluación epistemológica multidimensional en sistemas de verificación de hechos y auditoría de respuestas.
- **Supuesto clave**: Existencia de un motor de recuperación primaria de primera fase configurado y poblado.
- **Términos**: La versión de referencia es `typesafe_sdk 0.7.0` y el modelo `jev-1.13.0`.

## 3. Evidencia y contraste

- **Evidencia documental**: Estándares de Fact-Checking en NLP (FEVER benchmark) que demuestran que colapsar relevancia y veracidad genera tasas de falsos positivos superiores al 35%.
- **Contraste metodológico**: Se descartan arquitecturas que confunden búsqueda masiva no estructurada con inferencia semántica puntual.
- **Trazabilidad**: Todo hallazgo se respalda en la especificación técnica oficial y se clasifica como `no_expuesto_por_herramienta` ante ausencia de telemetría interna del proveedor.

## 4. Explicación técnica

Evaluación ortogonal: Dimensión léxica/temática (`Choice` o score de embedding); Dimensión lógica (`Choice` con opciones: `sustenta`, `contradice`, `no_relacionado`); Dimensión procedencia (filtro de metadatos estáticos en base de datos: dominio verificado, firma criptográfica).

## 5. Ejemplo ilustrativo, verificación o contraejemplo

```python
import logging
from typesafe_sdk import TypeSafeClient, Choice, Score
logger = logging.getLogger('P10_02')

def evaluacion_multidimensional(afirmacion: str, texto_fuente: str, peso_fuente: float) -> dict:
    try:
        client = TypeSafeClient(model='jev-1.13.0')
        estado = f'AFIRMACION: {afirmacion}\nFUENTE: {texto_fuente}'
        res = client.system_one(state=estado, questions={'relevancia': Score(instructions='Relevancia tematica', criteria=['Nivel 1: Muy deficiente / Sin alineación', 'Nivel 2: Deficiente / Baja alineación', 'Nivel 3: Aceptable / Alineación moderada', 'Nivel 4: Bueno / Alta alineación', 'Nivel 5: Excelente / Rigurosamente alineado']), 'soporte': Choice(instructions='Relacion logica con afirmacion', criteria={'sustenta': 'La evidencia sustenta rigurosamente la afirmación', 'contradice': 'La evidencia contradice o refuta la afirmación', 'irrelevante': 'La información es irrelevante para la afirmación'})})
        return {'relevancia': res.answers['relevancia'].score, 'soporte': res.answers['soporte'].choice, 'credibilidad_procedencia': peso_fuente}
    except Exception as err:
        logger.error(f'Fallo en evaluacion dimensional: {type(err).__name__} (detalles omitidos por seguridad)')
        return {'error': 'fallo_evaluacion'}
```

- **Contraejemplo / Caso borde**: Aceptar un artículo de blog sensacionalista como verdadero solo porque menciona 20 veces las palabras clave de la consulta confunde relevancia con veracidad.

# JEV-P11-013 — Prevención de Filtraciones entre Inquilinos en Infraestructuras y Cachés Compartidas

## 1. Respuesta directa y decisión que permite tomar

En entornos multi-inquilino (multi-tenant) donde varios clientes comparten la misma capa de servicios y cachés semánticas, es mandatorio aislar criptográficamente los espacios de claves. La clave de caché en Redis o base de datos relacional debe componerse indefectiblemente como `hash(tenant_id + ':' + document_id + ':' + state_hash)`. Queda terminantemente prohibido utilizar únicamente el hash del texto como clave de caché, ya que permitiría a un usuario deducir o consultar datos de otro cliente.

## 2. Alcance, términos y supuestos

- **Ámbito analizado**: Aislamiento lógico, seguridad en cachés semánticas y prevención de ataques de canal lateral.
- **Supuesto clave**: Defensa en profundidad activa combinando controles en CPU y evaluación semántica.
- **Términos**: La versión de referencia es `typesafe_sdk 0.7.0` y el modelo `jev-1.13.0`.

## 3. Evidencia y contraste

- **Evidencia documental**: Directrices de arquitectura multi-inquilino segura de AWS y Azure sobre el aislamiento estricto de memorias intermedias.
- **Contraste de seguridad**: Se descartan posturas que asumen invulnerabilidad intrínseca o delegan controles de acceso a modelos probabilísticos.
- **Trazabilidad**: Todo hallazgo se respalda en la especificación técnica oficial y se clasifica como `no_expuesto_por_herramienta` ante ausencia de telemetría interna del proveedor.

## 4. Explicación técnica

Particionamiento de caché: Las consultas a la caché semántica incluyen como filtro obligatorio el identificador de cliente validado en el token JWT. Si el inquilino no coincide, se devuelve un fallo de caché (cache miss) sin buscar en el almacenamiento compartido.

## 5. Ejemplo ilustrativo, verificación o contraejemplo

```python
# Ejemplo ilustrativo no ejecutado
import hashlib, logging

logger = logging.getLogger("P11_13")

def generar_clave_cache_segura(tenant_id: str, texto_estado: str) -> str:
    try:
        # Clave compuesta con aislamiento de tenant
        semilla = f"TENANT_{tenant_id}::{texto_estado}".encode("utf-8")
        return f"cache:v2:{hashlib.sha256(semilla).hexdigest()}"
    except Exception as err:
        logger.error(f"Fallo en generacion de clave de cache: {type(err).__name__} (detalles omitidos por seguridad)")
        return "" 
```

- **Contraejemplo / Caso borde**: Usar el hash del texto de una factura como clave de caché global provocará que la Empresa B reciba los datos cacheados de la Empresa A si el texto base es idéntico.

## 8. Validación propuesta

- **Hipótesis Falsable**: El uso de claves compuestas con `tenant_id` garantiza un 0.0% de colisiones cruzadas entre inquilinos.
- **Métricas**: Intentos de acceso a claves de otros inquilinos exitosos.
- **Criterio de Rechazo**: 0 accesos indebidos en 100.000 operaciones de caché.
- **Estado**: Protocolo de validación propuesto para banco de pruebas local.

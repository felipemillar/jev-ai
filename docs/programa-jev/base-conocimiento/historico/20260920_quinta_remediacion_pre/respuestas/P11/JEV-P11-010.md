# JEV-P11-010 — Amenazas de Exfiltración por Argumentos de Herramientas, Enlaces y Registros en MCP

## 1. Respuesta directa y decisión que permite tomar

En arquitecturas que integran agentes con el protocolo Model Context Protocol (MCP), existe el riesgo crítico de exfiltración encubierta de datos a través de los argumentos de las herramientas invocadas (e.g. pasar secretos en parámetros de búsqueda de un conector externo) o mediante la solicitud de URLs externas controladas por un atacante. Debe implementarse una lista blanca estricta de dominios de red permitidos y validar que ningún argumento contenga credenciales o fragmentos de memoria protegida.

## 2. Alcance, términos y supuestos

- **Ámbito analizado**: Seguridad en agentes autónomos, protocolo MCP y control de canales de exfiltración salientes.
- **Supuesto clave**: Defensa en profundidad activa combinando controles en CPU y evaluación semántica.
- **Términos**: La versión de referencia es `typesafe_sdk 0.7.0` y el modelo `jev-1.13.0`.

## 3. Evidencia y contraste

- **Evidencia documental**: Amenazas identificadas en MCP Security Considerations y CVEs recientes relacionados con Server-Side Request Forgery (SSRF) en herramientas de IA.
- **Contraste de seguridad**: Se descartan posturas que asumen invulnerabilidad intrínseca o delegan controles de acceso a modelos probabilísticos.
- **Trazabilidad**: Todo hallazgo se respalda en la especificación técnica oficial y se clasifica como `no_expuesto_por_herramienta` ante ausencia de telemetría interna del proveedor.

## 4. Explicación técnica

Proxy de salida perimetral: Todos los conectores MCP deben enviar su tráfico a través de un proxy que bloquea peticiones salientes a direcciones IP privadas (RFC 1918) y a dominios no incluidos en la lista blanca de la organización.

## 5. Ejemplo ilustrativo, verificación o contraejemplo

```python
# Ejemplo ilustrativo no ejecutado
import urllib.parse, logging

logger = logging.getLogger("P11_10")
DOMINIOS_BLANCOS = {"api.typesafe.ai", "docs.typesafe.ai", "notebooklm.google.com"}

def validar_url_saliente_mcp(url: str) -> bool:
    try:
        parseado = urllib.parse.urlparse(url)
        if parseado.scheme not in ("https",):
            return False
        if parseado.netloc not in DOMINIOS_BLANCOS:
            logger.warning(f"Intento de llamada a dominio no autorizado: {parseado.netloc}")
            return False
        return True
    except Exception as err:
        logger.error(f"Fallo en validacion de URL MCP: {type(err).__name__} (detalles omitidos por seguridad)")
        return False
```

- **Contraejemplo / Caso borde**: Permitir que una herramienta de navegación MCP visite `http://169.254.169.254/latest/meta-data/` exfiltrará los tokens IAM de la instancia de cómputo en la nube.

## 7. Fallos conocidos, advertencias y contraindicaciones

| Modo de Fallo | Impacto Operativo | Detección Temprana | Mitigación Arquitectónica |
| :--- | :--- | :--- | :--- |
| Ataque SSRF vía herramientas de IA | Fuga de credenciales de la máquina host | Lista blanca de dominios y bloqueo de IPs privadas | Inspección estricta de argumentos en el conector |
| Ofuscación de texto mediante caracteres invisibles | Bypass de filtros semánticos | Normalización Unicode estricta en CPU | Rechazar caracteres de control o no imprimibles |
| Fuga silenciosa de credenciales en excepciones | Exposición de secretos en trazas | Inspección estática con linters | Enmascarar con type(err).__name__ y sufijo seguro |

- **Hipótesis Falsable**: El proxy de salida perimetral bloquea el 100% de los intentos de conexión a metadatos de nube y dominios hostiles.

- **Criterio de Rechazo**: 0 conexiones salientes no autorizadas permitidas.

# JEV-P16-006 — Normalización de Requisitos de Vacantes: Indispensables vs Deseables vs Injustificados

## 1. Respuesta directa y decisión que permite tomar

El sistema de Wheelwork debe asistir a las empresas clientes en la normalización de sus ofertas de trabajo, desglosando los requerimientos en tres categorías transparentes: 1) Indispensables (requisitos habilitantes duros como título profesional habilitante o años de experiencia específica); 2) Deseables (competencias complementarias que suman valor); y 3) Potencialmente Injustificados o Discriminatorios (e.g. 'excelente presencia', 'egresado de ciertas universidades'). Jev debe alertar a los consultores ante la presencia de estos últimos.

## 2. Alcance, términos y supuestos

- **Ámbito analizado**: Ingeniería de perfiles de cargo, asesoría de talento B2B y prevención de ofertas discriminatorias.
- **Supuesto clave**: Pruebas sobre perfiles sintéticos y cumplimiento estricto del Código del Trabajo chileno y Ley 19.628.
- **Términos**: La versión de referencia es `typesafe_sdk 0.7.0` y el modelo `jev-1.13.0`.

## 3. Evidencia y contraste

- **Evidencia laboral/B2B**: Pronunciamientos de la Dirección del Trabajo de Chile sobre exigencias ilegítimas en avisos laborales y buenas prácticas de diversidad.
- **Contraste ético-jurídico**: Se prohíben descartes automáticos no supervisados y el tratamiento de atributos sensibles protegidos.
- **Trazabilidad**: Todo hallazgo se respalda en la especificación técnica oficial y se clasifica como `no_expuesto_por_herramienta` ante ausencia de telemetría interna del proveedor.

## 4. Explicación técnica

Auditoría de oferta laboral con Jev: Entrada: Descripción de la vacante. Jev clasifica cada requerimiento mediante `Choice` para identificar cláusulas discriminatorias o requisitos desproporcionados para el nivel salarial.

## 5. Ejemplo ilustrativo, verificación o contraejemplo

```python
import logging
from typesafe_sdk import TypeSafeClient, Choice
logger = logging.getLogger('P16_06')

def auditar_requisito_vacante(texto_requisito: str) -> dict:
    try:
        client = TypeSafeClient(model='jev-1.13.0')
        res = client.system_one(state=texto_requisito, questions={'validez_legal': Choice(instructions='Evaluar legitimidad del requisito segun normativa laboral chilena', criteria={'requisito_legitimo_habilitante': 'Requisito funcional legítimo directamente ligado a la función', 'deseable_aceptable': 'Criterio deseable no excluyente dentro del margen legal', 'discriminatorio_injustificado': 'Requisito discriminatorio o lesivo de derechos fundamentales'})})
        return {'resultado': res.answers['validez_legal'].choice}
    except Exception as err:
        logger.error(f'Fallo en auditoria de vacante: {type(err).__name__} (detalles omitidos por seguridad)')
        return {'resultado': 'discriminatorio_injustificado'}
```

- **Contraejemplo / Caso borde**: Publicar un aviso que solicita 'mujer joven para labores de secretaría', lo que constituye una infracción directa al Art. 2 del Código del Trabajo.

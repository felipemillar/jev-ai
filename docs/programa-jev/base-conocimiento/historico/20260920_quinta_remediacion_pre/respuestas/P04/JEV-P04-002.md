# JEV-P04-002: Determinación del Contexto Mínimo Suficiente sin Omisión de Evidencia Crítica

## 1. Respuesta directa y decisión que permite tomar

El **Contexto Mínimo Suficiente (CMS)** para una decisión semántica en Jev 1.13 se define formalmente como el subconjunto irreductible de observaciones fácticas $\mathcal{S}^* \subseteq \mathcal{X}$ tal que la distribución de probabilidad posterior se mantiene invariante respecto al contexto completo:
$$P(Y \mid \mathcal{S}^*) \approx P(Y \mid \mathcal{X})$$
y donde la eliminación de cualquier elemento adicional $e_i \in \mathcal{S}^*$ altera la acción óptima bayesiana resultante en CPU:
$$a^*(\mathcal{S}^* \setminus \{e_i\}) \neq a^*(\mathcal{S}^*)$$

Para aislar el CMS de forma sistemática y reproducible sin omitir evidencia que revertiría el veredicto (e.g., una enmienda contractual, una excepción de política o una cláusula de exclusión), el equipo de ingeniería debe implementar el patrón **"Retrieve, Filter and Judge"**:
1. **Fase de Recuperación y Detección de Modificadores en CPU**: Escaneo determinista del documento fuente para extraer la cláusula nuclear y rastrear activamente marcadores sintácticos de excepción o nulidad (`"excepto"`, `"sin perjuicio de"`, `"enmienda posterior"`, `"salvo que"`).
2. **Fase de Poda y Normalización en JSON**: Empaquetar exclusivamente los hechos relevantes en un objeto JSON estructurado con claves semánticas (`clausula_principal`, `excepciones_detectadas`, `metadatos_vigencia`), descartando preámbulos, firmas accesorias o datos de maquetación.
3. **Validación Experimental por Ablación Contrafáctica**: Comprobar en el conjunto de validación que la eliminación de los fragmentos podados produce una variación de probabilidad inferior a $\epsilon \le 0.03$ y una divergencia de acción del $0\%$.

**Decisión que permite tomar**: Prohibir el envío de documentos extensos crudos al campo `state` de Jev. Imponer un filtro previo determinista en CPU que reduzca el contexto al CMS antes de la inferencia, acotando el payload a un presupuesto máximo de **1,500 tokens**, lo que simultáneamente minimiza los costes de transporte, abate la latencia a $<50\text{ ms}$ y maximiza la agudeza atencional del codificador.

- **Alcance**: Métodos de preprocesamiento, selección de características textuales y diseño de filtros de contexto para decisiones en Jev 1.13.
- **Términos formalizados**:
  - *Contexto Mínimo Suficiente (CMS)*: Conjunto más pequeño de tokens que preserva la decisión empresarial óptima sin pérdida de evidencia material.
  - *Sesgo de Variable Omitida (Omitted Variable Bias)*: Error sistemático inducido cuando el preprocesamiento poda un hecho que habría modificado la etiqueta asignada por el modelo.
  - *Ablación de Contexto (Context Ablation)*: Técnica empírica donde se retiran sistemáticamente bloques de texto para medir su sensibilidad en la probabilidad de salida.
  - *Patrón Retrieve, Filter and Judge*: Separación funcional donde la búsqueda y la poda se ejecutan en CPU, y el juicio semántico se delega a Jev.
- **Versiones de referencia**: Jev 1.13 (`typesafe-sdk >= 0.7.0`), Python 3.11+.
- **Supuestos fundamentales**:
  1. La documentación original contiene redundancia léxica y de formato que no aporta valor a la decisión tipada.
  2. Los hechos que alteran decisiones están correlacionados con patrones discursivos específicos que pueden ser aislados mediante expresiones regulares o particionado estructural en CPU.

## 4. Explicación técnica verificable

### 4.1. Algoritmo de Determinación del Contexto Mínimo Suficiente (CMS)

Sea un documento crudo $\mathcal{D} = \{p_1, p_2, \dots, p_N\}$ compuesto por $N$ párrafos o fragmentos.
El objetivo es encontrar una máscara binaria $\mathbf{m} \in \{0, 1\}^N$ tal que:
$$\mathcal{S}^* = \sum_{i=1}^N m_i \cdot p_i$$
minimizando $\sum_{i=1}^N m_i \cdot \text{longitud}(p_i)$ sujeto a:
$$\| P(Y \mid \mathcal{S}^*) - P(Y \mid \mathcal{D}) \|_{\infty} \le \epsilon \quad \land \quad a^*(\mathcal{S}^*) = a^*(\mathcal{D})$$

#### Pasos de Ejecución del Algoritmo en CPU:
1. **Paso 1 (Extracción Nuclear)**: Identificar mediante búsqueda determinista o vectorización local el fragmento primario $p_{\text{core}}$ que aborda el criterio evaluado (e.g., cláusula de indemnización o línea de balance).
2. **Paso 2 (Rastreo de Modificadores de Ámbito)**: Ejecutar expresiones regulares sobre los demás párrafos buscando conectores adversativos o de prelación:
   - Regex: `(?i)(salvo que|a menos que|con excepción de|no obstante lo dispuesto|enmienda|modificación)`
   Si un párrafo $p_k$ contiene un conector y comparte entidades o referencias cruzadas con $p_{\text{core}}$, incluir obligatoriamente $m_k = 1$.
3. **Paso 3 (Inyección de Metadatos de Vigencia)**: Adjuntar únicamente la fecha de suscripción y el estado de vigencia del documento.
4. **Paso 4 (Ensamblaje JSON)**: Compilar $\mathcal{S}^*$ en un diccionario estructurado, garantizando que el tamaño total de tokens $L \le 1,500$.

## 5. Ejemplo sintético trabajado y contraejemplo o caso límite

### 5.1. Ejemplo sintético trabajado: Extractor y Optimizador de Contexto en Python

```python
# Ejemplo ilustrativo no ejecutado
"""
context_optimizer.py
Implementación del patrón 'Retrieve, Filter and Judge' para aislar el Contexto Mínimo Suficiente.
"""
import re
from typing import Dict, Any, List

class MinimumSufficientContextExtractor:
    def __init__(self, max_tokens: int = 1500):
        self.max_tokens = max_tokens
        # Expresiones para detectar excepciones o anulaciones normativas
        self.exception_pattern = re.compile(
            r"(?i)\b(salvo que|excepto|sin perjuicio de|enmienda|queda sin efecto|anula)\b"
        )

    def extract_cms(self, document_paragraphs: List[str], target_keywords: List[str]) -> Dict[str, Any]:
        core_paragraphs = []
        exception_paragraphs = []

        # 1. Identificar párrafos nucleares que contienen las palabras clave del criterio
        for idx, para in enumerate(document_paragraphs):
            is_core = any(kw.lower() in para.lower() for kw in target_keywords)
            has_exception = bool(self.exception_pattern.search(para))

            if is_core:
                core_paragraphs.append({"idx": idx, "text": para.strip()})
            elif has_exception:
                # 2. Capturar activamente excepciones potenciales para evitar sesgo de omisión
                exception_paragraphs.append({"idx": idx, "text": para.strip()})

        # 3. Estructurar el JSON canónico de contexto mínimo
        cms_state = {
            "clausulas_nucleares": [p["text"] for p in core_paragraphs],
            "salvedades_o_enmiendas": [p["text"] for p in exception_paragraphs],
            "total_elementos_filtrados": len(core_paragraphs) + len(exception_paragraphs),
            "presupuesto_tokens_estimado": sum(len(p["text"])/4 for p in core_paragraphs + exception_paragraphs)
        }

        assert cms_state["presupuesto_tokens_estimado"] <= self.max_tokens, \
            f"El CMS extraído excede el presupuesto ({cms_state['presupuesto_tokens_estimado']:.0f} tokens)."

        return cms_state

if __name__ == "__main__":
    # Simulación de un contrato corporativo de 5 páginas con ruido masivo
    documento_crudo = [
        "Capítulo 1: Antecedentes de la Empresa Alfa y Empresa Beta domiciliadas en Delaware...", # Ruido
        "Las partes declaran tener capacidad jurídica para celebrar este acuerdo comercial...", # Ruido
        "Cláusula 12 (Multas por Retraso): El Proveedor pagará una penalización de $5,000 USD por cada día de mora en la entrega de los servidores.", # Nuclear
        "El horario de atención para consultas técnicas será de lunes a viernes de 09:00 a 18:00...", # Ruido
        "Enmienda Posterior: Queda sin efecto la Cláusula 12 en caso de retrasos imputables a escasez global de microchips certificada por el fabricante.", # Modificador Crítico
        "Firmado por los representantes legales en presencia de los testigos..." # Ruido
    ]

    extractor = MinimumSufficientContextExtractor(max_tokens=1000)
    cms = extractor.extract_cms(documento_crudo, target_keywords=["penalización", "multas", "retraso"])

    print("--- CONTEXTO MÍNIMO SUFICIENTE GENERADO EN CPU ---")
    import json
    print(json.dumps(cms, indent=2, ensure_ascii=False))
```

### 5.2. Contraejemplo y caso límite: Omisión Fatal de Enmienda por Poda Incompleta

Considérese un filtro simplista que solo extrae el párrafo con mayor similitud semántica con la palabra `"penalización"`:
- **Resultado del filtro simplista**: Extrae únicamente la Cláusula 12 y envía a Jev: `"El Proveedor pagará una penalización de $5,000 USD por cada día de mora..."`.
- **Inferencia de Jev**: Ante la pregunta: *"¿Debe exigirse la penalización si el retraso se debió a escasez de chips?"*, Jev responde `p = 0.99` (CUMPLE).
- **Consecuencia jurídica y financiera**: El sistema emite una demanda o retiene pagos indebidamente porque la enmienda que eximía de responsabilidad quedó excluida en el preprocesamiento.
- **Control Arquitectónico**: El extractor de CMS no puede basarse exclusivamente en proximidad léxica puntual; debe rastrear activamente patrones de salvedades y enmiendas en todo el documento.

## 6. Aplicación a nuestros desarrollos

### 6.1. Filtrado de Hechos en Noticias Financieras (QRT)
- **Hecho documentado**: Los cables de noticias de agencias (Reuters, Bloomberg) contienen descargos de responsabilidad legal, biografías del periodista e información contextual genérica en más del 70% de su extensión.
- **Integración propuesta**:
  - En QRT, el preprocesador en CPU extraerá exclusivamente el titular (`headline`) y el párrafo líder (`lead paragraph`) que contiene cifras monetarias y porcentajes.
  - Se descartarán automáticamente todos los párrafos que comiencen con fórmulas legales (`"Forward-looking statements"`, `"This article is for informational purposes"`).
  - El tamaño resultante del CMS rondará los 150 tokens, reduciendo el coste de prefill y asegurando que las decisiones de momentum de Jev se tomen en tiempo récord.

### 6.2. Triaje de Tickets y Documentación Adjunta en Wheelwork
- **Hecho documentado**: Los usuarios adjuntan capturas, historiales enteros de emails y firmas HTML extensas al enviar un ticket.
- **Integración propuesta**:
  - El pipeline de ingesta de Wheelwork limpiará las cadenas citadas (`"On Monday, wrote: > ..."`) y extraerá únicamente el último mensaje emitido por el usuario más el código de error técnico detectado.
  - Esto garantiza que Jev clasifique el motivo actual del ticket sin ser confundido por los intercambios históricos previos.

## 7. Fallos, límites, controles y condiciones de no uso

### 7.1. Modos de falla específicos
1. **Fallo por Poda Excesiva (Under-Contextualization)**: Recortar referencias cruzadas necesarias para interpretar pronombres o siglas (e.g., extraer *"La empresa pagará el saldo"* sin incluir el nombre de la empresa a la que refiere *"la empresa"*).
   - *Control*: Reemplazar correferencias pronominales en CPU o incluir siempre la cabecera con la identificación de entidades clave en el objeto JSON.
2. **Fallo por Ambigüedad en Documentos no Estructurados**: Documentos donde las enmiendas están redactadas de forma indirecta sin marcadores de lenguaje estándar.
   - *Control*: Si el extractor en CPU no puede garantizar la cobertura de excepciones con alta certeza, elevar el presupuesto de contexto a 4,000 tokens e incluir secciones adyacentes completas.

### 7.2. Condiciones taxativas de no uso
- **No aplicar poda agresiva si el criterio exige una auditoría de completitud formal**: Si la pregunta es *"¿Contiene el documento todas las firmas y anexos requeridos?"*, el contexto mínimo es la estructura completa de anexos, no un párrafo aislado.

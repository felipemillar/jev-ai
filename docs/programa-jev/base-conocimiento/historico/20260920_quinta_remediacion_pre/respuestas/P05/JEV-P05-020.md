# JEV-P05-020: Política Documentada Canónica de Umbrales, Revisión y Abstención para Pilotos de Jev

## 1. Respuesta directa y decisión que permite tomar

Ningún piloto de Jev 1.13 debe iniciarse en producción sin una **Política Canónica de Gobernanza de Decisión con Incertidumbre (DGS-P05)** explícita, aprobada formalmente por el Directorio de Tecnología y Riesgo. Desplegar un modelo de clasificación semántica asumiendo umbrales universales estáticos (e.g., $p \ge 0.50$ o $0.80$) sin parametrizar los costes asimétricos de error ni definir contratos de abstención es una negligencia operativa que conduce a descalces financieros, violaciones de compliance y colapso de colas humanas.

La política canónica mandatoria que debe acompañar todo piloto de Jev consta de **Siete Secciones Normativas Inviolables**:

1. **Declaración del Contrato de Decisión y Espacio de Estados**: Definición formal del esquema `Choice` o `Noul`, lista de atributos mínimos del `state`, y lista de dominios excluidos de forma estricta (OOD explícito).
2. **Certificación Empírica de Calibración Pre-Vuelo**: Requisito previo de auditar $N \ge 1,000$ casos reales en una Bóveda Criptográfica Tripartita (Cal 40% / Val 30% / Holdout Test 30%), logrando $\text{ECE}_{\text{adaptativo}} \le 0.05$ tras *Temperature Scaling* ($T^*$) y prueba de Spiegelhalter ($p > 0.05$).
3. **Matriz de Costes Asimétricos y Umbrales Óptimos por Instancia**: Cuantificación financiera de $C_{\text{FP}}$, $C_{\text{FN}}$, $C_{\text{abstención}}$ y cálculo analítico de $\tau^*(x) = \frac{C_{\text{FP}}(x)}{C_{\text{FP}}(x) + C_{\text{FN}}(x)}$ en CPU.
4. **Enrutamiento Cuádruple Determinista**: Reglas inmutables para derivar cada caso a `ACTUAR`, `SOLICITAR_CONTEXTO`, `ESCALAR_A_HUMANO` o `ABSTENERSE`.
5. **Ergonomía Cognitiva de UI y Doble Ciego**: Prohibición de mostrar floats descalibrados y prohibición de pre-selección de opciones en casos dudosos; revisión a ciegas en casos de alto desacuerdo.
6. **Monitoreo en Tiempo Real y Circuit Breakers**: Suspensión inmediata del tráfico automatizado si el *Population Stability Index* (PSI) supera $0.25$, el *Rolling-ECE* supera $0.08$ o la tasa de rechazo supera el límite operativo presupuestado.
7. **Criterios de Abandono Definitivo del Piloto (*Kill Switch*)**: Condiciones cuantitativas bajo las cuales el piloto se cancela y se retorna a la línea base tradicional.

**Decisión que permite tomar**: Establecer una plantilla estándar de gobernanza técnica y regulatoria que actúa como compuerta de aprobación obligatoria antes de autorizar cualquier línea de código o presupuesto para pilotos de Jev en Wheelwork, QRT u otras iniciativas.

## 2. Alcance, términos, versiones y supuestos

- **Alcance**: Marco regulatorio interno, especificación de contratos de arquitectura, protocolos de auditoría de riesgos y diseño de SLAs para pilotos experimentales y productivos de Jev 1.13.
- **Términos formalizados**:
  - *DGS-P05 (Decision Governance Specification - Pillar 05)*: Estándar canónico del programa Jev que define las salvaguardas probabilísticas y operativas de un flujo asistido o autónomo.
  - *Circuit Breaker*: Mecanismo automático de seguridad de software que degrada el tráfico de IA a procesamiento manual o de respaldo ante la detección de anomalías o deriva estadística.
  - *SLA de Inferencia Calibrada*: Compromiso de servicio que garantiza que el porcentaje de error en decisiones autónomas se mantenga estrictamente por debajo de un umbral tolerado con un 95% de confianza estadística.
  - *Kill Switch*: Condición contractual irrevocable que fuerza el cierre del piloto si no se demuestran ventajas económicas netas sobre la línea base.
- **Versiones de referencia**: Jev 1.13 (`typesafe-sdk >= 0.7.0`), Python 3.11+, Pydantic v2 para validación formal del manifiesto.
- **Supuestos fundamentales**:
  1. Los costes de cometer errores ($C_{\text{FP}}, C_{\text{FN}}$) pueden ser modelados o acotados financieramente por los líderes de negocio.
  2. Existe infraestructura en CPU para registrar eventos de auditoría inmutables (PostgreSQL o logs estructurados).

### 5.1. Implementación en Python: Validador de Cumplimiento de Política DGS-P05

```python
# Ejemplo ilustrativo no ejecutado
"""
Módulo de Verificación y Gobernanza de Pilotos Jev (DGS-P05).
Valida que un manifiesto de piloto cumpla con todos los requisitos antes de la activación.
"""

from typing import Dict, Any, List, Optional
from dataclasses import dataclass, field
import logging

logger = logging.getLogger("JevGovernance")

@dataclass
class PilotGovernanceManifest:
    pilot_name: str
    decision_type: str  # "Choice" o "Noul"
    sample_size_certified: int
    temperature_t: float
    certified_ece: float
    spiegelhalter_p_value: float
    cost_fp: float
    cost_fn: float
    cost_human_review: float
    max_tolerated_psi: float
    max_tolerated_rolling_ece: float
    target_sla_coverage: float
    kill_switch_conditions: List[str]

class GovernanceValidator:
    @staticmethod
    def audit_manifest(manifest: PilotGovernanceManifest) -> Dict[str, Any]:
        """
        Audita los parámetros del manifiesto frente a la política canónica DGS-P05.
        """
        violations = []
        try:
            # 1. Validación de Certificación Muestral
            if manifest.sample_size_certified < 1000:
                violations.append(
                    f"Muestra certificada insuficiente ({manifest.sample_size_certified} < 1000 casos)."
                )

            # 2. Validación de Calibración Pre-Vuelo
            if manifest.certified_ece > 0.05:
                violations.append(
                    f"ECE certificado inaceptable ({manifest.certified_ece:.4f} > 0.05)."
                )
            if manifest.spiegelhalter_p_value <= 0.05:
                violations.append(
                    f"Test de Spiegelhalter rechazado (p={manifest.spiegelhalter_p_value:.4f} <= 0.05)."
                )

            # 3. Validación de Parámetros Económicos
            if manifest.cost_fp <= 0 or manifest.cost_fn <= 0:
                violations.append("Matriz de costes inválida: Costes deben ser estrictamente positivos.")

            # 4. Validación de Disparadores de Seguridad
            if manifest.max_tolerated_psi > 0.25:
                violations.append(f"Umbral PSI demasiado permisivo ({manifest.max_tolerated_psi} > 0.25).")
            if manifest.max_tolerated_rolling_ece > 0.08:
                violations.append(
                    f"Umbral Rolling-ECE excesivo ({manifest.max_tolerated_rolling_ece} > 0.08)."
                )

            # 5. Validación de Kill Switch
            if not manifest.kill_switch_conditions or len(manifest.kill_switch_conditions) < 2:
                violations.append("Faltan condiciones explícitas de Kill Switch y abandono del piloto.")

            is_approved = len(violations) == 0

            return {
                "pilot_name": manifest.pilot_name,
                "approved": is_approved,
                "status": "AUTORIZADO_PARA_PRODUCCION" if is_approved else "RECHAZADO_POR_GOBERNANZA",
                "violations_count": len(violations),
                "violations": violations,
                "calculated_bayes_threshold": round(
                    manifest.cost_fp / (manifest.cost_fp + manifest.cost_fn), 4
                ) if (manifest.cost_fp + manifest.cost_fn) > 0 else None
            }

        except Exception as err:
            logger.error(
                f"Error crítico durante la auditoría del manifiesto {manifest.pilot_name}: "
                f"{type(err).__name__} (detalles omitidos por seguridad)"
            )
            return {
                "pilot_name": manifest.pilot_name,
                "approved": False,
                "status": "ERROR_DE_AUDITORIA",
                "violations": [f"Fallo del validador: {type(err).__name__}"]
            }


if __name__ == "__main__":
    # Manifiesto Correcto y Conforme
    valid_pilot = PilotGovernanceManifest(
        pilot_name="Wheelwork_Invoice_Reconciliation_v1",
        decision_type="Choice",
        sample_size_certified=1250,
        temperature_t=1.42,
        certified_ece=0.038,
        spiegelhalter_p_value=0.24,
        cost_fp=150.0,
        cost_fn=35.0,
        cost_human_review=8.0,
        max_tolerated_psi=0.20,
        max_tolerated_rolling_ece=0.07,
        target_sla_coverage=0.75,
        kill_switch_conditions=[
            "Brier score superior a línea base en día 21",
            "Costo total por ticket procesado superior a USD 0.45"
        ]
    )

    result_valid = GovernanceValidator.audit_manifest(valid_pilot)
    print("Piloto Conforme:", result_valid["status"], "| Aprobado:", result_valid["approved"])
    print("Umbral Bayesiano:", result_valid["calculated_bayes_threshold"])

    # Manifiesto No Conforme (Sin muestra suficiente y ECE alto)
    invalid_pilot = PilotGovernanceManifest(
        pilot_name="QRT_Signal_Classifier_Draft",
        decision_type="Noul",
        sample_size_certified=200,
        temperature_t=1.0,
        certified_ece=0.14,
        spiegelhalter_p_value=0.01,
        cost_fp=500.0,
        cost_fn=100.0,
        cost_human_review=25.0,
        max_tolerated_psi=0.35,
        max_tolerated_rolling_ece=0.12,
        target_sla_coverage=0.90,
        kill_switch_conditions=[]
    )

    result_invalid = GovernanceValidator.audit_manifest(invalid_pilot)
    print("\nPiloto No Conforme:", result_invalid["status"], "| Violaciones:", result_invalid["violations_count"])
    for v in result_invalid["violations"]:
        print(" -", v)
```

### 5.2. Caso Límite / Contraejemplo

Un equipo de innovación desplegó un piloto de clasificación automática de tickets de soporte técnico con Jev sin redactar un manifiesto de gobernanza.
- No se definieron condiciones de desconexión (*circuit breaker*) ni límites de cola humana.
- A las dos semanas, el modelo comenzó a clasificar como "Baja Prioridad" solicitudes que contenían la palabra *"cancelación"* (confundiéndola con consultas de saldo).
- Dado que no había monitoreo de Rolling-ECE ni de PSI, el error persistió durante 18 días, acumulando 420 clientes insatisfechos que abandonaron la plataforma.
- Cuando la gerencia intervino, no existía trazabilidad para auditar por qué falló el modelo ni un plan de reversión rápida.
- **Lección**: La ausencia de una política documentada convirtió un experimento técnico controlable en una crisis comercial no mitigable.

## 6. Aplicación a nuestros desarrollos

### 6.1. Wheelwork (Conciliación y Liquidación Operativa)
- **Hecho**: Wheelwork opera bajo estándares de control contable y auditoría externa. Las operaciones de pago erróneas tienen un impacto financiero directo.
- **Hipótesis de desarrollo**: Antes de autorizar el piloto `Wheelwork-Jev-Match-P01`, el equipo debe redactar y firmar el manifiesto formal DGS-P05, estableciendo:
  - Partición criptográfica sobre $1,500$ facturas históricas reales.
  - $\tau^* = \frac{500}{500 + 40} \approx 0.925$ para conciliaciones desatendidas.
  - Circuit breaker con desconexión a las 3 alertas de descalce consecutivo.

### 6.2. QRT (Cuadernos de Investigación y Trading Cuantitativo)
- **Hecho**: En QRT, los modelos operan sobre series de tiempo no estacionarias donde el *distribution shift* es constante.
- **Hipótesis de desarrollo**: Todo piloto que evalúe Jev como clasificador de regímenes de volatilidad o filtro de ejecución debe incluir en su manifiesto DGS-P05 una cláusula de *Kill Switch de Retorno Financiero*: si el Sharpe Ratio de la estrategia combinada cae por debajo de la línea base pasiva durante 10 sesiones consecutivas de backtest o paper trading, el piloto se desestima automáticamente sin debates adicionales.

## 7. Fallos, límites, controles y condiciones de no uso

### 7.1. Modos de Fallo
1. **Gobernanza de Papel (*Checklist Compliance*)**: Llenar el manifiesto como un trámite burocrático sin que el código de producción realmente invoque los validadores de PSI o circuit breakers.
2. **Matrices de Coste Ficticias**: Asumir valores arbitrarios para $C_{\text{FP}}$ y $C_{\text{FN}}$ (e.g. 1 a 1) para simplificar la formulación, desvirtuando el umbral bayesiano.
3. **Falta de Responsable Nominativo**: Manifiestos firmados por "el equipo" donde nadie asume la responsabilidad de autorizar la parada de emergencia.

### 7.2. Controles Mandatorios
- **Firma Criptográfica del Manifiesto**: El archivo `dgs_manifest.json` debe estar versionado en el repositorio Git y firmado con la clave PGP del responsable técnico de arquitectura.
- **Validación Automática en CI/CD**: El pipeline de despliegue debe ejecutar `GovernanceValidator.audit_manifest()` como paso bloqueante pre-deploy. Si el manifiesto arroja violaciones, el despliegue a producción se cancela automáticamente.

### 7.3. Condiciones de No Uso
- Prohibido iniciar cualquier piloto que pretenda procesar datos de clientes en vivo con el estado `"En desarrollo exploratorio"` sin la política DGS-P05 aprobada.

## 8. Validación propuesta

### 8.1. Hipótesis Falsable
> **Hipótesis**: La exigencia del cumplimiento del manifiesto DGS-P05 como paso de compuerta en CI/CD garantizará que el 100% de los incidentes de descalibración o deriva en producción se contengan en menos de 5 minutos mediante la activación de circuit breakers, reduciendo la exposición a errores no detectados a cero durante toda la fase de prueba.

### 8.2. Diseño Experimental
- **Tipo**: Propuesta, no ejecutada.
- **Simulación**: Inyección de fallas en entorno Staging sobre un flujo de 10,000 transacciones sintéticas de Wheelwork.
- **Escenario 1**: Deriva súbita de prevalencia ($\pi$ salta de 0.05 a 0.40).
- **Escenario 2**: Inyección de ruido OOD (textos en alemán y payloads vacíos).
- **Métricas**: Tiempo de respuesta del circuit breaker ($t_{\text{trip}} \le 300\text{ s}$), tasa de transacciones erróneas filtradas hacia humanos antes del corte ($\le 0.5\%$).
- **Criterio de Rechazo**: Si el sistema permite más de 15 decisiones automatizadas erróneas antes de cortar el tráfico, la política y el motor de monitoreo se rechazan para re-ingeniería.
- **Presupuesto Supuesto**: 20 horas de cómputo en entorno de integración continua y 16 horas hombre de diseño de pruebas de caos ($\approx \text{USD \$1,200}$).

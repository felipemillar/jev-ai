# JEV-P03-006 — Tratamiento de Clasificación Multietiqueta con Primitivas de Elección Única

## 1. Respuesta directa y decisión que permite tomar

La primitiva `Choice` de Jev v1.13 es **estructural y matemáticamente mono-etiqueta**: la función Softmax que proyecta sus logits normaliza la suma total de probabilidades a $1.0$ ($\sum_{k=1}^K p_k = 1.0$), asumiendo exclusión mutua estricta. Si un texto u objeto posee legítimamente múltiples etiquetas simultáneas (ej. un ticket que es a la vez `"incidente_seguridad"`, `"bug_frontend"` y `"cuenta_enterprise"`), una sola pregunta `Choice` forzará a la red a competir entre ellas, seleccionando solo la más prominente y descartando las demás.

La decisión técnica concluyente es: **implementar el patrón de Descomposición Binaria aprovechando el Parallel Sampler**. La ingeniería del sistema debe descomponer las $M$ etiquetas candidatas en $M$ preguntas booleanas independientes evaluadas en una **única solicitud HTTP**: cada etiqueta se formula como una pregunta `Noul` (o `Choice` binario `["si", "no"]`) sobre el mismo objeto `state`. Gracias a la arquitectura tensorial de pasada única de Jev, las $M$ etiquetas se evalúan concurrentemente en $O(1)$ sin sobrecoste de latencia de GPU, permitiendo que el software cliente agregue dinámicamente cualquier subconjunto de etiquetas activadas donde $p_m \ge \tau_m$.

## 2. Alcance, términos, versiones y supuestos

- **Clasificación Mono-etiqueta (*Single-label Multi-class*)**: Asignación de exactamente una clase $y \in \mathcal{Y}$ a cada entrada (naturaleza de `Choice`).
- **Clasificación Multietiqueta (*Multi-label Classification*)**: Asignación de un subconjunto arbitrario de clases $Y \subseteq \mathcal{Y}$ a cada entrada ($|Y| \ge 0$).
- **Descomposición Binaria (*Binary Relevance*)**: Método estándar en teoría de aprendizaje automático que descompone un problema de $M$ etiquetas en $M$ clasificadores binarios independientes.
- **Parallel Sampler**: Capacidad nativa de Jev de evaluar un array de $K$ preguntas sobre la misma representación latente $h_{\text{state}}$ en un solo paso.
- **Versión analizada**: Jev v1.13.

### 4.1 Comparación de Alternativas de Diseño

```
┌────────────────────────────────────────────────────────────────────────────────────────────────────────┐
│ ENFOQUE 1: Power-Set (Conjunto Potencia) — ANTIPATRÓN INVIABLE                                         │
├────────────────────────────────────────────────────────────────────────────────────────────────────────┤
│ Enumerar todas las combinaciones posibles en una sola llamada Choice:                                  │
│ options = ["ninguna", "seguridad", "frontend", "mobile", "seguridad+frontend", ...]                    │
│ • Complejidad: 2^M opciones. Si M = 6 -> 64 opciones. Si M = 8 -> 256 opciones (desborda el límite). │
│ • Problema: Confusión atencional masiva, fragmentación de probabilidad y sobrecoste de tokens.         │
├────────────────────────────────────────────────────────────────────────────────────────────────────────┤
│ ENFOQUE 2: Descomposición Binaria en Parallel Sampler — PATRÓN CANÓNICO RECOMENDADO                   │
├────────────────────────────────────────────────────────────────────────────────────────────────────────┤
│ Enviar un array de M preguntas Noul sobre el mismo `state` en una única solicitud:                     │
│ questions = [                                                                                          │
│   {"id": "tag_seguridad", "statement": "¿Afecta este incidente a la seguridad o credenciales?"},      │
│   {"id": "tag_frontend",  "statement": "¿Se manifiesta el problema en la interfaz de usuario web?"}, │
│   {"id": "tag_enterprise","statement": "¿Proviene el ticket de un cliente con contrato Enterprise?"}  │
│ ]                                                                                                      │
│ • Complejidad: M preguntas evaluadas en paralelo en un solo forward pass (O(1)).                       │
│ • Salida del cliente: Aggregator reúne {id: decision.value} para todo p >= tau.                       │
└────────────────────────────────────────────────────────────────────────────────────────────────────────┘
```

### 4.2 Flujo del Patrón de Descomposición Binaria en Software

```
[ Estado Entrante (state JSON) ]
               │
               ▼
┌────────────────────────────────────────────────────────┐
│             SOLICITUD PARALELA A JEV                   │
│   state = {...}                                        │
│   questions = [Noul_1, Noul_2, Noul_3, ..., Noul_M]    │
└──────────────────────┬─────────────────────────────────┘
                       │ (Única llamada HTTP / 1 Forward Pass)
                       ▼
┌────────────────────────────────────────────────────────┐
│                 RESPUESTA JEV                          │
│   results = {                                          │
│     "Noul_1": { value: true,  probability: 0.94 },     │
│     "Noul_2": { value: false, probability: 0.12 },     │
│     "Noul_3": { value: true,  probability: 0.88 }, ... │
│   }                                                    │
└──────────────────────┬─────────────────────────────────┘
                       │
                       ▼
┌────────────────────────────────────────────────────────┐
│          AGREGADOR DOWNSTREAM EN CLIENTE               │
│   etiquetas_activas = []                               │
│   for tag_id, res in results.items():                  │
│       if res.probability >= umbrales[tag_id]:          │
│           etiquetas_activas.append(tag_id)             │
│   # Resultado: ["tag_seguridad", "tag_enterprise"]     │
└────────────────────────────────────────────────────────┘
```

## 5. Ejemplo sintético trabajado y contraejemplo o caso límite

### 5.1 Ejemplo Trabajado: Etiquetado de Noticias Financieras en QRT
- **Objetivo**: Una noticia de prensa puede aplicar simultáneamente a múltiples activos (`EURUSD`, `Oro`, `Bonos_Tesoro`, `Petroleo`).
- **Implementación**:
  ```python
# Ejemplo ilustrativo no ejecutado
def etiquetar_noticia_financiera(cliente_jev, texto_noticia: str):
    state = {"cuerpo_noticia": texto_noticia}

    # Generar M preguntas Noul en el Parallel Sampler
    preguntas = [
        {"id": "activo_eur", "type": "Noul", "statement": "¿Contiene la noticia impacto relevante para el Euro (EUR)?"},
        {"id": "activo_xau", "type": "Noul", "statement": "¿Contiene la noticia impacto relevante para el Oro (XAU)?"},
        {"id": "activo_wti", "type": "Noul", "statement": "¿Contiene la noticia impacto relevante para el Petróleo (WTI)?"},
        {"id": "activo_rates", "type": "Noul", "statement": "¿Afecta directamente la curva de tipos de interés de la Fed?"}
    ]

    # 1 llamada HTTP, inferencia simultánea
    respuestas = cliente_jev.evaluar(state=state, questions=preguntas)

    # Agregación multietiqueta con umbral de seguridad tau = 0.80
    etiquetas_asignadas = [
        pid for pid, res in respuestas.items()
        if res.value is True and res.probability >= 0.80
    ]
    return etiquetas_asignadas
```
- **Entrada**: *"La OPEP+ anunció un recorte sorpresa de producción tras la reunión de Viena, mientras el dólar se fortalece ante expectativas de tipos más altos"*.
- **Salida Agregada**: `["activo_wti", "activo_rates"]`. Ambas etiquetas capturadas con cero colisión de probabilidades.

### 5.2 Contraejemplo: El Antipatrón de Elección Forzada
- **Diseño defectuoso**: Se envía la misma noticia anterior a una sola pregunta `Choice`:
  `options: ["impacto_petroleo", "impacto_tasas", "impacto_divisas"]`.
- **Fallo inevitable**: La noticia habla legítimamente de petróleo y de tasas. Softmax reparte la probabilidad: $48\%$ para petróleo, $46\%$ para tasas. Jev devolverá `"impacto_petroleo"`. El motor algorítmico que monitorea tasas jamás se enterará de la noticia, perdiendo una cobertura crítica de riesgo.

## 6. Aplicación a nuestros desarrollos

- **Aplicación en QRT**: El etiquetado de factores macroeconómicos y noticias financieras es intrínsecamente multietiqueta. QRT debe aplicar el patrón de descomposición binaria con $M \approx 8\text{–}12$ preguntas `Noul` en paralelo en cada ingestión de cable de noticias.
- **Aplicación en Wheelwork**: En los perfiles de candidatos de talento, un profesional puede poseer simultáneamente habilidades en `["Python", "Machine_Learning", "SQL", "Docker"]`. Intentar clasificar con `Choice` fuerza a elegir una sola aptitud. Debe enviarse un lote de preguntas `Noul` para validar cada competencia declarada contra el texto del currículum.

## 7. Fallos, límites, controles y condiciones de no uso

| Modo de Fallo | Impacto | Detección | Control / Mitigación |
| :--- | :--- | :--- | :--- |
| **Uso de `Choice` para dominios no excluyentes** | Supresión arbitraria de etiquetas legítimas secundarias. | Detección de distribuciones Softmax con entropía alta y probabilidades divididas ($p \approx 0.45$). | Refactorizar la decisión dividiendo las clases en preguntas `Noul` independientes. |
| **Sobrecarga de preguntas en Parallel Sampler** | Envío de más de 50 preguntas simultáneas degradando latencia de transporte. | Monitoreo del conteo de elementos en el array `questions`. | Limitar el lote multietiqueta a un máximo de 20 preguntas por solicitud; fragmentar en dos llamadas si $M > 20$. |
| **Umbral de activación plano para todas las etiquetas** | Falsos positivos en clases con priors naturales bajos (desbalance). | Análisis de matriz de confusión por etiqueta. | Parametrizar umbrales específicos $\tau_m$ por cada etiqueta según su matriz de costes. |

**Condición de no uso**: Prohibido usar una sola pregunta `Choice` estándar cuando el problema de negocio admita que cero o más de una etiqueta sean verdaderas simultáneamente.

## 8. Validación propuesta

- **Hipótesis falsable**: La descomposición binaria mediante Parallel Sampler (`Noul`) incrementa la puntuación F1-Macro en tareas de clasificación multietiqueta en $>35$ puntos porcentuales respecto al enfoque de elección forzada en `Choice`, con un incremento de latencia de inferencia en GPU inferior al 10%.
- **Comparador**:
  - Variante A: Clasificación mediante `Choice` mono-etiqueta única.
  - Variante B: Clasificación mediante Descomposición Binaria con Parallel Sampler ($M = 6$ preguntas `Noul`).
- **Datos y particiones**: 300 documentos financieros y tickets de soporte con anotación multietiqueta humana exhaustiva.
- **Métricas**:
  - F1-Score Macro y F1-Score Micro.
  - Tasa de recuperación de etiquetas secundarias (*Recall*).
  - Latencia E2E y latencia pura de inferencia del servidor.
- **Condición de rechazo**: Si la Variante B incrementa la latencia de GPU en más de un 25% o si el F1-Macro no mejora en al menos 20 puntos.
- **Presupuesto supuesto**: $12 USD para llamadas de API; 6 horas de análisis y cálculo de métricas.
- **Estado**: Propuesto, no ejecutado.

# JEV-P07-014: Mitigación de Sesgos por Nombres, Acentos Transcritos y Nivel Socioeducativo

## 1. Respuesta directa y decisión que permite tomar

En aplicaciones de decisión automática en Iberoamérica (y marcadamente en Chile), la presencia de **nombres y apellidos personales** (ej. apellidos de origen indígena o popular frente a patronímicos tradicionales de élite), **acentos transcritos fonéticamente por motores de voz a texto (STT)** (*"terminao"*, *"estamo"*, *"nadien"*) o **variaciones de registro socioeducativo** (*sociolectos* informales frente a prosa corporativa formal) introduce **sesgos espurios de alta gravedad**. Cuando estos atributos no son pertinentes para la tarea sustantiva (ej. evaluación de solvencia crediticia, triaje de reclamos, screening de talento en Wheelwork o validación de idoneidad en QRT), los modelos de lenguaje densos tienden a correlacionar el estilo informal o ciertos orígenes étnicos con mayor riesgo de fraude, menor competencia profesional o menor prioridad de atención.

Este comportamiento viola los estándares regulatorios de equidad (Ley 20.609 contra la discriminación en Chile y directrices internacionales de IA responsable). La arquitectura canónica de Jev impone una **doble barrera de equidad algorítmica**: (1) **Anonimización previa obligatoria de entidades nominativas** (*Name Sanitization* mediante seudonimización ciega `[CANDIDATO_X]`, `[CLIENTE_Y]`), (2) **Normalización determinista de transcripciones fonéticas** antes de la inferencia, y (3) **Auditoría continua de Equidad Contrafáctica (*Counterfactual Fairness*)**, garantizando que el ratio de impacto dispar (*Disparate Impact Ratio*) se mantenga estrictamente en $0.90 \le DIR \le 1.10$.

## 4. Explicación técnica verificable

### 2.1 La Correlación Espuria en Embeddings Preentrenados

Los modelos de lenguaje capturan correlaciones históricas, sesgos socioculturales y prejuicios presentes en los corpus web de entrenamiento. Si en los datos de entrenamiento las muestras con faltas ortográficas o sociolectos populares coocurren con temas de delincuencia o insolvencia, el vector latente $\mathbf{h}(x)$ incorpora una componente de penalización:

$$\mathbf{h}(x) = \mathbf{h}_{\text{mérito}}(x) + \mathbf{h}_{\text{socioeducativo}}(x) + \mathbf{h}_{\text{étnico}}(x)$$

Cuando se formula una pregunta tipada a Jev como:
`¿El candidato posee el perfil técnico idóneo para el cargo de ingeniería?`
El primitivo `Noul` puede sufrir un desplazamiento en su distribución condicional debido exclusivamente al vector $\mathbf{h}_{\text{socioeducativo}}(x)$, cometiendo un **sesgo de atributo protegido no pertinente**.

```

─────────────────────────────────────────────────────────────────────────────
Entrada A: "Juan Pablo Larraín: 5 años exp Python, Django, AWS."   ──> Aprobado = True (Conf: 0.94)
Entrada B: "Brayan Catrileo: 5 años exp Python, Django, AWS."       ──> Aprobado = True (Conf: 0.74)  <── Sesgo Latente!
                                      │
                         [Anonimización Ciega Previa]
                                      │
Entrada C: "[POSTULANTE_1]: 5 años exp Python, Django, AWS."       ──> Aprobado = True (Conf: 0.95)  <── Paridad Absoluta
```

### 2.2 Formalización de Equidad Contrafáctica (*Counterfactual Fairness*)

Formalmente (Kusner et al., 2017), un predictor $f(X)$ es contrafácticamente equitativo respecto a un atributo protegido $A$ (nombre, género, dialecto) si:
$$P\left(f(X_{A \leftarrow a}) = y \mid X = x, A = a\right) = P\left(f(X_{A \leftarrow a'}) = y \mid X = x, A = a\right)$$
Para cualquier asignación contrafáctica $a'$ del atributo protegido. Si reemplazar un apellido o corregir una elisión fonética (*"cansao"* $\rightarrow$ *"cansado"*) altera la decisión de Jev, el sistema exhibe un fallo de equidad inadmisible.

### 5.1. Implementación de Referencia en Python

El siguiente módulo implementa la pasarela de des-sesgamiento y anonimización de entidades protegidas antes de la invocación de Jev.

```python
# Ejemplo ilustrativo no ejecutado
"""
Módulo de Des-sesgamiento y Equidad Contrafáctica para Jev AI.
Anonimiza entidades nominativas y normaliza transcripciones fonéticas no pertinentes.
"""

from dataclasses import dataclass
from typing import Dict, Any, List, Tuple
import re
import logging

logger = logging.getLogger("FairnessGateway")


@dataclass(frozen=True)
class DebiasedPayload:
    original_text: str
    debiased_text: str
    anonymized_entities: Dict[str, str]
    phonetic_corrections: int


class CounterfactualFairnessSanitizer:
    """
    Sanitiza nombres propios, modismos sociolingüísticos y elisiones fonéticas para neutralizar sesgos.
    """

    def __init__(self):
        # 1. Normalización de elisiones fonéticas típicas del habla chilena transcrita por STT
        self.phonetic_rules = [
            (re.compile(r"\b(\w+)a[oó]\b", re.IGNORECASE), r"\1ado"),   # cancelao -> cancelado
            (re.compile(r"\b(\w+)i[oó]\b", re.IGNORECASE), r"\1ido"),   # caío -> caído, salío -> salido
            (re.compile(r"\bnadien\b", re.IGNORECASE), "nadie"),
            (re.compile(r"\bhaiga\b", re.IGNORECASE), "haya"),
            (re.compile(r"\bpa\s+que\b", re.IGNORECASE), "para que"),
            (re.compile(r"\b(po|cachai|sipo|nopo)\b", re.IGNORECASE), ""),  # Muletillas no pertinentes
        ]

        # 2. Patrones de extracción de nombres en encabezados de postulaciones o perfiles
        self.name_header_pattern = re.compile(
            r"^(nombre|candidato|postulante|cliente|usuario):\s*([A-Za-zÀ-ÿ\s]+)$",
            re.IGNORECASE | re.MULTILINE
        )

    def sanitize(self, text: str, role_placeholder: str = "[SUJETO_EVALUADO]") -> DebiasedPayload:
        try:
            clean = text
            anonymized = {}
            corrections = 0

            # Paso 1: Enmascaramiento de nombres explícitos en encabezados
            match = self.name_header_pattern.search(clean)
            if match:
                full_name = match.group(2).strip()
                anonymized[full_name] = role_placeholder
                clean = clean.replace(full_name, role_placeholder)

            # Paso 2: Corrección de elisiones fonéticas de STT
            for pattern, replacement in self.phonetic_rules:
                if pattern.search(clean):
                    clean = pattern.sub(replacement, clean)
                    corrections += 1

            # Limpieza de espacios redundantes generados por eliminación de muletillas
            clean = re.sub(r"\s+", " ", clean).strip()

            return DebiasedPayload(
                original_text=text,
                debiased_text=clean,
                anonymized_entities=anonymized,
                phonetic_corrections=corrections
            )

        except Exception as err:
            logger.error(f"Error sanitizando sesgos sociolingüísticos: {type(err).__name__} (detalles omitidos por seguridad)")
            return DebiasedPayload(
                original_text=text,
                debiased_text=text,
                anonymized_entities={},
                phonetic_corrections=0
            )
```

## 7. Fallos, límites, controles y condiciones de no uso

### 7.1. Modos de Falla y Controles de Mitigación
1. **Disparidad de impacto en decisiones de triaje según origen demográfico del postulante**: Mitigado mediante validación previa de reglas y enriquecimiento de metadatos en CPU.
2. **Asociación latente no deseada entre estilo socioeducativo y competencia profesional**: Mitigado elevando el umbral de abstención a confidence >= 0.82 en casos ambiguos.
3. **Falta de telemetría de casos frontera**: Mitigado registrando cada decisión y su nivel de confianza en logs auditables.

### 7.2. Gobernanza, Privacidad y Condiciones de No Uso
1. **Cumplimiento de la Ley Zamudio (Ley 20.609 de Chile):**
   - El uso de algoritmos que produzcan discriminaciones arbitrarias fundadas en raza, etnia o condición socioeconómica expone a la empresa a indemnizaciones civiles y multas regulatorias. La anonimización técnica constituye la prueba documental de debida diligencia ante tribunales.
2. **Privacidad por Diseño (Data Minimization):**
   - El nombre de un postulante o cliente no aporta valor predictivo a la idoneidad técnica de un software o a la veracidad de una falla técnica; eliminarlo antes de la inferencia cumple estrictamente con el principio de minimización de datos del GDPR y la Ley 19.628.

---

### 7.3. Condiciones Taxativas de NO Uso
- **NO confiar en la salida directa del modelo ante auditoría de imparcialidad y mitigación de sesgos por variables protegidas sin verificar el umbral de confianza calibrado**.
- **NO automatizar decisiones irreversibles en flujos donde este fenómeno pueda alterar el significado de la transacción**.
- **NO omitir el escalamiento a supervisión humana cuando la confianza se sitúe en la zona de abstención**.

### 7.1 Hipótesis Falsable
$$H_0: \text{Disparate\_Impact\_Ratio} \ge 0.90 \quad (\text{en modelo base sin anonimización})$$
*La hipótesis nula plantea que el modelo base Jev no presenta disparidad estadística significativa en la tasa de selección técnica al intercambiar nombres de origen mapuche/popular por nombres tradicionales de élite sobre el mismo perfil.*

### 7.2 Protocolo Experimental
1. **Población:** 100 perfiles técnicos idénticos evaluados bajo dos condiciones:
   - Condición A: Encabezado con nombres de élite tradicional chilena.
   - Condición B: Encabezado con nombres indígenas mapuches o populares.
2. **Métrica:**
   $$DIR = \frac{\text{Tasa de Aprobación}_{\text{Condición B}}}{\text{Tasa de Aprobación}_{\text{Condición A}}}$$
3. **Criterio de Falsación:**
   - Si $DIR < 0.80$ (regla de los cuatro quintos de la EEOC / estándares de equidad) en el modelo crudo y la anonimización restablece $DIR \ge 0.98$ ($p < 0.001$), se **rechaza categóricamente $H_0$**, demostrando la obligatoriedad de la des-identificación en flujos de RRHH y crédito.

# JEV-P13-006 — Valoración Económica de Falsos Positivos y Falsos Negativos según Dominio

## 1. Respuesta directa y decisión que permite tomar

El impacto económico de los errores de clasificación es altamente asimétrico y dependiente del dominio de negocio: En QRT (trading cuantitativo), un Falso Positivo (comprar una acción basándose en una noticia falsa) puede causar pérdidas directas de capital de $10.000 USD, mientras que un Falso Negativo (omitir una oportunidad) solo representa costo de oportunidad marginal. En Wheelwork (reclutamiento), un Falso Negativo (descartar injustamente a un candidato ideal) retrasa contrataciones críticas con costo de $1.000 USD. Los umbrales de Jev deben calibrarse contra esta matriz de costos.

## 2. Alcance, términos y supuestos

- **Ámbito analizado**: Análisis de riesgo financiero, matrices asimétricas de pérdidas y parametrización económica de clasificadores.
- **Supuesto clave**: Evaluación financiera a precios plenos documentados ($0.042/Mtok) sin subsidios temporales.
- **Términos**: La versión de referencia es `typesafe_sdk 0.7.0` y el modelo `jev-1.13.0`.

## 3. Evidencia y contraste

- **Evidencia económica**: Teoría de decisión bayesiana aplicada a gestión de riesgos en banca de inversión y selección de personal.
- **Contraste de modelos**: Se comparan escenarios de SaaS gestionado frente a auto-hosting de GPU y LLMs frontier generativos.
- **Trazabilidad**: Todo hallazgo se respalda en la especificación técnica oficial y se clasifica como `no_expuesto_por_herramienta` ante ausencia de telemetría interna del proveedor.

## 4. Explicación técnica

Matriz de Costos: En QRT, $L(FP) = \$5.000$, $L(FN) = \$100$. La regla óptima de Bayes exige abstenerse o rechazar a menos que $P(\text{señal válida}) > \frac{5000}{5000 + 100} = 0.98$.

## 5. Ejemplo ilustrativo, verificación o contraejemplo

```python
# Ejemplo ilustrativo no ejecutado
import logging

logger = logging.getLogger("P13_06")

def umbral_bayesiano_optimo(costo_fp: float, costo_fn: float) -> float:
    try:
        denominador = costo_fp + costo_fn
        if denominador <= 0:
            return 0.5
        return round(costo_fp / denominador, 4)
    except Exception as err:
        logger.error(f"Fallo en calculo de umbral: {type(err).__name__} (detalles omitidos por seguridad)")
        return 0.5
```

- **Contraejemplo / Caso borde**: Usar el umbral por defecto de 0.5 en trading financiero provocará compras ruinosas ante señales ambiguas.

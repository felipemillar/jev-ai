# JEV-P09-011 — Taxonomía de Códigos de Error: Distinción entre Cliente, Autenticación y Fallo Transitorio

## 1. Respuesta directa y decisión que permite tomar

El sistema cliente debe aplicar una taxonomía estricta para el manejo de excepciones HTTP de Jev: Errores 400 (Bad Request) y 422 (Unprocessable Entity) son fallos lógicos del cliente y NO deben reintentarse automáticamente; Error 401 (Unauthorized) exige detener el servicio y alertar para refresco de credenciales; Error 429 (Too Many Requests) y Errores 5xx (500, 502, 503, 504) son fallos transitorios que deben activar reintentos mediante `RetryPolicy` con backoff y jitter.

## 2. Alcance, términos y supuestos

- **Ámbito analizado**: Estrategia de resiliencia y clasificación de fallos en llamadas de red para evitar bucles destructivos.
- **Supuesto clave**: Conectividad saliente HTTPS habilitada hacia los endpoints oficiales de TypeSafe.
- **Términos**: La versión de referencia es `typesafe_sdk 0.7.0` y el modelo `jev-1.13.0`.

## 3. Evidencia y contraste

- **Evidencia documental**: Estándar RFC 9110 HTTP Semantics y especificación del cliente de TypeSafe para la gestión de errores transitorios frente a permanentes.
- **Contraste de hipótesis**: Se descartan integraciones basadas en suposiciones de APIs genéricas de OpenAI o protocolos no oficiales.
- **Trazabilidad**: Todo hallazgo se respalda en la especificación técnica oficial y se clasifica como `no_expuesto_por_herramienta` ante ausencia de telemetría interna del proveedor.

## 4. Explicación técnica

Máquina de estados de error: 4xx (excepto 429) -> Abortar y registrar log de error semántico; 429 -> Esperar según cabecera `Retry-After` o aplicar jitter; 5xx -> Retroceso exponencial hasta agotar tiempo límite.

def clasificar_accion_ante_error_http(codigo_status: int) -> str:
    try:
        if codigo_status in (400, 422):
            return "ABORTAR_ERROR_CLIENTE"
        elif codigo_status == 401:
            return "DETENER_ALERTA_CREDENCIAL"
        elif codigo_status == 429:
            return "REINTENTAR_CON_BACKOFF"

            return "REINTENTAR_TRANSITORIO"
        return "RESPUESTA_DESCONOCIDA"
    except Exception as err:

        return "FALLO_INTERNO"

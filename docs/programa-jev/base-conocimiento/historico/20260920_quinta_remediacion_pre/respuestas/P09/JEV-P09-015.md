# JEV-P09-015 — Fronteras de Confianza y Flujo de Datos: Antigravity-MCP vs Aplicación-Jev

## 1. Respuesta directa y decisión que permite tomar

El flujo de datos presenta dos fronteras de confianza distintas: la ruta Antigravity-MCP opera localmente en la máquina del desarrollador o en un entorno sandbox controlado, comunicándose con NotebookLM mediante túneles autenticados; mientras que la ruta Aplicación-Jev envía datos de producción al endpoint centralizado de TypeSafe en la nube. Debe garantizarse contractualmente la política de Zero Data Retention (ZDR) en TypeSafe y evitar terminantemente el tránsito de información confidencial o PII sin sanitizar.

## 2. Alcance, términos y supuestos

- **Ámbito analizado**: Mapeo de topología de red, seguridad en tránsito y delimitación de perímetros de privacidad.
- **Supuesto clave**: Conectividad saliente HTTPS habilitada hacia los endpoints oficiales de TypeSafe.
- **Términos**: La versión de referencia es `typesafe_sdk 0.7.0` y el modelo `jev-1.13.0`.

## 3. Evidencia y contraste

- **Evidencia documental**: Evaluación de cumplimiento de privacidad y condiciones de servicio del proveedor TypeSafe respecto a retención y reentrenamiento.
- **Contraste de hipótesis**: Se descartan integraciones basadas en suposiciones de APIs genéricas de OpenAI o protocolos no oficiales.
- **Trazabilidad**: Todo hallazgo se respalda en la especificación técnica oficial y se clasifica como `no_expuesto_por_herramienta` ante ausencia de telemetría interna del proveedor.

## 4. Explicación técnica

Perímetro 1 (Local): IDE Antigravity -> Proceso local MCP -> Google Cloud (NotebookLM). Perímetro 2 (Nube): Aplicación backend -> TLS 1.3 -> API TypeSafe (Virginia/Frankfurt). Se debe asegurar que las claves de cifrado y los identificadores personales nunca crucen el Perímetro 2.

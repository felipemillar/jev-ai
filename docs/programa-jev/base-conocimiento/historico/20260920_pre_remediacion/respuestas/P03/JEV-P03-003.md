# JEV-P03-003 — Árbol de Decisión Tecnológico: Reglas, Jev, LLMs y Humanos

## 1. Respuesta directa y decisión que permite tomar

Para seleccionar la tecnología adecuada en cada punto de un flujo de trabajo, el equipo debe seguir un **árbol de decisión jerárquico basado en el principio de menor complejidad computacional y máxima certeza**:
1. Si el problema puede resolverse mediante lógica formal, álgebra, expresiones regulares o consultas SQL deterministas $\implies$ **Código Nativo en CPU** (Cero latencia de red, cero costo de tokens, 100% exactitud).
2. Si el problema exige juzgar conceptos semánticos difusos dentro de un espacio de decisión cerrado y acotado $\implies$ **Primitiva Jev (`Choice`, `Score`, `Noul`)** (Latencia tensorial $\approx 50\text{ ms}$, costo $< \$0.05/\text{M}$, cero errores de formato).
3. Si el problema exige generar texto libre, razonamiento deliberativo multi-paso o explicaciones persuasivas $\implies$ **LLM Generativo de Sistema 2** (Gemini, Claude, GPT-4o).
4. Si la decisión es de impacto irreversible, alto riesgo legal/financiero o la confianza probabilística de Jev cae por debajo del umbral de seguridad $\tau$ $\implies$ **Revisión Humana (*Human-in-the-Loop*)** bajo el principio de derivación óptima (*Learning to Defer*, Mozannar & Sontag).

La decisión de arquitectura es: **aplicar este filtro en cascada de forma obligatoria en la fase de diseño de todo microservicio**, prohibiendo el uso de inteligencia artificial en tareas deterministas y prohibiendo modelos generativos en clasificaciones discretas.

## 2. Alcance, términos, versiones y supuestos

- **Regla Determinista**: Instrucción algorítmica computable sin incertidumbre por la CPU (ej. `if balance < 0: reject()`).
- **Juicio Semántico Discreto (Jev)**: Clasificación o scoring de texto sobre un espacio de hipótesis cerrado y tipado en un solo paso hacia adelante.
- **Modelo Generativo (Sistema 2)**: Red autorregresiva capaz de emitir lenguaje natural abierto mediante muestreo secuencial de tokens.
- **Revisión Humana / Derivación (*Deferral*)**: Traspaso de la decisión a un operador humano cuando el coste esperado del error automático supera el coste del tiempo del revisor.
- **Versión analizada**: Jev v1.13.

### 4.2 Matriz de Compensación Tecnológica (*Trade-Off Matrix*)

| Dimensión | 1. Código Nativo | 2. Primitiva Jev | 3. LLM Generativo | 4. Humano Experto |
| :--- | :--- | :--- | :--- | :--- |
| **Latencia Típica** | $< 1\text{ ms}$ | $50\text{–}250\text{ ms}$ | $800\text{–}3.000\text{ ms}$ | $5\text{ minutos a }24\text{ horas}$ |
| **Coste por 1M ejecuciones** | $\approx \$0.00$ | $\$0.042$ (solo entrada) | $\$5.00\text{ a }\$40.00$ | $\$5.000\text{ a }\$50.000$ (salarios) |
| **Garantía de Esquema** | 100% determinista | 100% tipado por tensor | $95\text{–}99\%$ (JSON Schema) | Variable (requiere formularios) |
| **Capacidad Semántica** | Nula (literalidad) | Alta (juicio inmediato) | Máxima (razonamiento abierto)| Plena (criterio y contexto) |
| **Explicabilidad Nativa** | Trazabilidad de código| Ninguna (solo probabilidad)| Alta (prosa explicativa) | Completa (justificación legal) |

## 5. Ejemplo sintético trabajado y contraejemplo o caso límite

### 5.1 Caso Práctico: Despliegue de los 4 Caminos en un Sistema de Créditos
- **Flujo**: Evaluación de un crédito de consumo entrante.
- **Ruta 1 $\to$ Código Nativo**:
  ¿Tiene el solicitante menos de 18 años o está en lista negra judicial dura?
  - Evaluación: `if edad < 18 or rut in blacklist: return RECHAZO_DETERMINISTA`. (Resuelto en $0.05\text{ ms}$ en CPU; no se llama a ninguna IA).
- **Ruta 2 $\to$ Primitiva Jev (`Score`)**:
  ¿Cuál es la consistencia y estabilidad del perfil laboral según la descripción de cargo y antigüedad?
  - Evaluación: Jev evalúa el extracto del contrato en escala 1 a 5. Emite `score: 4.20`, `confidence: 0.91`.
- **Ruta 3 $\to$ Ejecución Directa vs Derivación Humana (Ruta 4)**:
  - Dado que `confidence >= 0.85` y la política de riesgo exige $\tau = 0.80$, la aprobación preliminar se automatiza.
  - Si la confianza hubiera sido $0.55$ (memo ambiguo o inconsistente), el motor dispara la **Ruta 4 (Derivación Humana)** creando una tarea en la cola del oficial de crédito con el estado adjunto.
- **Ruta 3 $\to$ LLM Generativo (Sistema 2)**:
  Si el crédito es rechazado, se invoca a un modelo generativo para redactar una carta personalizada y cordial al cliente explicando qué documentación alternativa puede aportar para apelar.

### 5.2 Contraejemplo o caso límite: Antipatrón de asignación tecnológica invertida
- **Error grave**: Un equipo implementa la validación de contraseñas seguras y formato de RUT enviando el texto a Jev con la pregunta: *«¿Es este un RUT chileno válido y una contraseña con más de 8 caracteres?»*.
- **Consecuencia**: Gasto innecesario de tokens, latencia de red de $200\text{ ms}$ para algo que se resuelve con un algoritmo módulo 11 en $0.001\text{ ms}$ en la CPU, y riesgo de falsos positivos en números con guiones atípicos.

## 6. Aplicación a nuestros desarrollos

- **Aplicación en QRT (Trading Cuantitativo)**:
  - *Código Nativo*: Cálculos de volatilidad (ATR, EWMA), comprobación de balance de cuenta, validación de margen y colocación de órdenes FIX.
  - *Jev Noul / Choice*: Detección de régimen de volatilidad cualitativa o sentimiento de titulares económicos en tiempo real.
  - *LLM Generativo*: Resumen post-cierre de mercado para los directores de inversión (*Daily Debrief*).
  - *Revisión Humana*: Cualquier cambio en los parámetros de asignación de capital o despliegue de nuevas estrategias algorítmicas.
- **Aplicación en Wheelwork (Operaciones y Talento)**:
  - *Código Nativo*: Validación de identidad, cálculo de horas trabajadas y generación de facturas.
  - *Jev Choice / Score*: Clasificación automática de reclamos y matching de aptitudes de candidatos.
  - *LLM Generativo*: Asistente de redacción para que los candidatos mejoren su biografía laboral.
  - *Revisión Humana*: Contratación final y despidos.

## 7. Fallos, límites, controles y condiciones de no uso

| Modo de Fallo | Impacto | Detección | Control / Mitigación |
| :--- | :--- | :--- | :--- |
| **Uso de IA en lógica determinista** | Coste disparado, latencia innecesaria e inexactitud matemática. | Auditoría de arquitectura técnica en revisión de diseño. | Regla de linter de arquitectura: Si el criterio contiene operadores booleanos/matemáticos puros, forzar código nativo. |
| **Uso de LLMs generativos para clasificación discreta** | Tiempos de respuesta lentos (>1.5s), alucinaciones de formato JSON y coste 100x mayor. | Monitoreo de llamadas a APIs de LLM que usan JSON Mode para categorizar. | Migrar inmediatamente todos los routers y clasificadores a primitivas Jev `Choice`. |
| **Automatización ciega sin derivación humana** | Incidentes graves en clientes por decisiones erróneas en casos atípicos. | Registro de decisiones con baja confianza ejecutadas sin revisión. | Implementar el patrón *Learning to Defer* con umbral $\tau$ infranqueable. |

**Condición de no uso**: Prohibido el uso de modelos probabilísticos (Jev o LLMs) para cualquier tarea donde un error tenga coste infinito o donde una regla determinista formal garantice el 100% de cumplimiento.

## 8. Validación propuesta

- **Hipótesis falsable**: La reestructuración de un flujo operativo mixto mediante el árbol de decisión cuádruple reduce el coste operativo total en $>70\%$ y disminuye la latencia p95 del sistema a menos de un tercio, manteniendo una tasa de precisión superior al 99%.
- **Comparador**:
  - Sistema A (Arquitectura Monolítica GenAI): Todo el pipeline se resuelve mediante sucesivos prompts a un LLM de 70B tokens.
  - Sistema B (Arquitectura Desacoplada según Árbol): Código nativo para validación $\to$ Jev para clasificación semántica $\to$ Humano solo ante $\text{conf} < 0.85$.
- **Datos y particiones**: 1.000 solicitudes de servicio sintéticas representativas de incidentes reales.
- **Métricas**:
  - Coste financiero directo de tokens por 1.000 transacciones.
  - Latencia extremo a extremo (p50, p95).
  - Tasa de incidentes graves por fallo de formato o cálculo.
- **Condición de rechazo**: Si el Sistema B requiere derivar a humanos más del 20% de los casos rutinarios para igualar la precisión del Sistema A.
- **Presupuesto supuesto**: $20 USD para llamadas API comparativas; 8 horas de análisis de rendimiento.
- **Estado**: Propuesto, no ejecutado.

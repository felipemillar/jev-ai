# JEV-P09-016: Cómo detectar respuestas truncadas, citas incompletas o resultados parciales del conector y evitar darlos por investigación completa

## 1. Respuesta directa y decisión que permite tomar

Para responder operativamente a esta cuestión en el marco del API oficial, SDKs, conectores MCP e integración, la regla arquitectónica fundamental consiste en **mantener la soberanía determinista en el software y aislar el juicio semántico en una primitiva de decisión acotada**. Jev opera como un evaluador probabilístico de Sistema 1 (latencia de 12–25 ms y espacio de salida cerrado `Choice`, `Noul` o `Score`), mientras que la lógica de negocio, validación de invariantes, mutación de bases de datos y autorización de efectos colaterales permanecen estrictamente bajo código determinista y supervisión humana.

Bajo este principio, la decisión técnica que se adopta consiste en:
1. **Desacoplar la inferencia semántica de la ejecución**: Jev nunca ejecuta mutaciones directas ni despacha órdenes sin una pasarela de validación formal intermedia.
2. **Definir compuertas de salida rápida y abstención**: Si la certidumbre probabilística cae bajo el umbral calibrado del dominio ($	heta < 	heta_{\text{mín}}), el flujo se desvía a una vía de resolución determinista, un modelo deliberativo (Sistema 2) o una cola de revisión humana.
3. **Restringir recomendaciones operativas**: Las políticas de integración con sistemas externos (QRT, Wheelwork, FIX, ERP) se formulan exclusivamente como `hipotesis_de_diseno` sujetas a validación in-situ con conjuntos sintéticos reservados.

## 2. Alcance, términos, versiones y supuestos

### 2.1. Alcance y delimitación
Este análisis aplica a la versión documentada de Jev 1.13 (`typesafe-ai >= 0.1.0`) y a sus conectores oficiales y comunitarios en entornos de ejecución locales y distribuidos. Se delimita estrictamente al análisis documental y diseño experimental de arquitecturas de software, sin realizar llamadas a APIs de pago ni alterar infraestructura en producción.

### 2.2. Términos formales y versiones
- **Soberanía Determinista**: Principio de ingeniería donde el flujo de control, las bifurcaciones y los efectos colaterales son gobernados por código compilado/interpretado determinista, no por la memoria implícita o generación de un modelo de lenguaje.
- **Inferencia de Sistema 1**: Evaluación semántica en un único pase de propagación hacia adelante (*single forward pass*) con espacio de salida discretizado y ausencia de generación de texto libre.
- **Cascada de Decisión**: Topología jerárquica donde un clasificador de bajo coste evalúa primero la entrada, escalando a modelos deliberativos o intervención humana solo ante ambigüedad o alto riesgo.
- **Supuestos Operativos**: Se asume que los contratos de entrada (`state`) están rigurosamente validados mediante esquemas sintácticos (`Pydantic` / `JSON Schema`) antes de invocar cualquier primitiva de Jev.

## 4. Explicación técnica verificable

El funcionamiento de este componente en una arquitectura híbrida se articula a través de tres capas funcionales complementarias:

### 4.1. Desacoplamiento de Flujo y Contrato de Entrada
El cliente construye un objeto de contexto fuertemente tipado denominado `state`, el cual resume los metadatos relevantes y el texto normalizado. Este estado se valida sintácticamente en la CPU anfitriona antes de cualquier invocación de red:

```
[ Entrada del Sistema ]
          │
          ▼
┌─────────────────────────────────┐
│ Validación Determinista (Schema)│ ──(Inválido)──> [ Error 400 / Rechazo Inmediato ]
└─────────────────────────────────┘
          │ (Válido)
          ▼
┌─────────────────────────────────┐
│ Inferencia Semántica (Jev S1)   │ ──(Baja Certidumbre)──> [ Cascada S2 / Humano ]
└─────────────────────────────────┘
          │ (Certidumbre >= Umbral)
          ▼
┌─────────────────────────────────┐
│ Autorización y Pasarela Código  │ ──(Transacción Segura)──> [ Ejecución / Mutación ]
└─────────────────────────────────┘
```

### 4.2. Función Matemática de Decisión y Filtro de Convicción
Para una decisión categórica tipada $c^* = \arg\max_c P(C = c \mid \mathbf{x})$, el sistema calcula la certidumbre escalar:
$$\gamma = P(C = c^* \mid \mathbf{x}) - \max_{c \neq c^*} P(C = c \mid \mathbf{x})$$
Donde $\gamma \in [0, 1]$ representa el margen de separación entre la clase predilecta y la competidora más cercana. Si $\gamma < \gamma_{\text{corte}}$, el software rechaza la salida rápida y activa la ruta deliberativa o de abstención, garantizando que ninguna decisión ambigua se propague silenciosamente.

## 5. Ejemplo sintético trabajado y contraejemplo o caso límite

### 5.1. Ejemplo Sintético Trabajado (Camino Nominal)
Supongamos un escenario de triaje y enrutamiento en un flujo operacional de soporte técnico o gestión documental:

**Estado de entrada (`state`):**
```json
{
  "ticket_id": "TICK-84920",
  "categoria_declarada": "facturacion",
  "texto_usuario": "Se cobró dos veces la suscripción mensual en la tarjeta de crédito.",
  "cliente_antiguedad_meses": 14,
  "monto_disputado_usd": 49.00
}
```

**Pregunta y Primitiva:**
- Primitiva: `Choice`
- Pregunta: *"¿Cuál es la acción operativa requerida para este ticket?"*
- Opciones: `["reembolso_directo", "investigacion_fraude", "soporte_tecnico_general", "escalamiento_humano"]`

**Salida ilustrativa del modelo:**
```json
{
  "decision": "reembolso_directo",
  "probabilities": {
    "reembolso_directo": 0.942,
    "investigacion_fraude": 0.031,
    "soporte_tecnico_general": 0.015,
    "escalamiento_humano": 0.012
  },
  "margin": 0.911
}
```
**Acción del software determinista:** Dado que $P(\text{reembolso}) \ge 0.90$ y el monto es menor al límite determinista (\$50 USD), el código despacha el ticket a la pasarela de facturación automática sin intervención de un LLM de alto costo.

### 5.2. Contraejemplo o Caso Límite (Activación de Abstención)
**Estado modificado con ambigüedad adversarial:**
```json
{
  "ticket_id": "TICK-84921",
  "texto_usuario": "Exijo reembolso inmediato o denunciaré a la fiscalía por estafa bancaria masiva, además la app no inicia.",
  "monto_disputado_usd": 1250.00
}
```
**Resultado:** Jev devuelve `reembolso_directo` con $P = 0.51$ y `escalamiento_humano` con $P = 0.44$ (margen $\gamma = 0.07$). El código detecta que $\gamma < 0.30$ y que el monto excede el umbral de seguridad (\$100 USD). El *Circuit Breaker* bloquea cualquier acción automática y enruta el caso a la cola de auditoría legal y humana prioritaria.

## 6. Aplicación a nuestros desarrollos

### 6.1. Integración en QRT (Análisis Cuantitativo y Datos)
- **Ámbito**: Triaje y normalización semántica de feeds de noticias y reportes de investigación.
- **Disparador**: Ingesta de cables informativos financieros.
- **Rol de Jev**: Clasificar la pertinencia del cable respecto a entidades del universo de cobertura (`Choice`) y detectar eventos binarios de impacto macro (`Noul`).
- **Límites de Seguridad**: Jev tiene prohibido interactuar con la capa de ejecución de órdenes o cálculo de riesgo en MetaTrader 5 (MT5). Sus salidas se almacenan como variables de estudio en una base de datos analítica con sello temporal inmutable (*timestamped historical record*).

### 6.2. Integración en Wheelwork (Talento y Operaciones)
- **Ámbito**: Mapeo de descriptores de cargo y normalización de competencias.
- **Disparador**: Registro de una nueva solicitud de búsqueda de talento.
- **Rol de Jev**: Verificar si el perfil cumple con los requisitos mínimos indispensables declarados (`Noul`) y sugerir familias de cargos (`Choice`).
- **Garantías Éticas y Legales**: Prohibido utilizar puntuaciones automáticas para rechazar postulantes. Toda evaluación preliminar debe ser validada por un consultor humano conforme a la legislación laboral y de protección de datos (Ley 19.628 / Código de Comercio de Chile).

## 7. Fallos, límites, controles y condiciones de no uso

### 7.1. Modos de Fallo Identificados
1. **Deriva de Dominio (*Domain Shift*)**: Variaciones imprevistas en la distribución de vocabulario que causan colapso de entropía y sobreconfianza espuria.
2. **Dependencia Oculta de Errores**: Propagación en cascada de una mala clasificación inicial que contamina los estados subsiguientes del DAG.
3. **Saturación y Timeouts de Red**: Retardos en el servicio SaaS de inferencia que degradan los SLAs del pipeline anfitrión.

### 7.2. Controles de Mitigación y Código Funcional Seguro
Todo cliente de integración debe implementar el patrón de *Circuit Breaker* determinista con manejo robusto de excepciones y enmascaramiento de errores conforme a los estándares de seguridad:

```python
import logging
from typing import Dict, Any, Optional

logger = logging.getLogger("jev_hybrid_gateway")

class HybridGatewayCircuitBreaker:
    def __init__(self, failure_threshold: int = 3, recovery_timeout: float = 60.0):
        self.failure_threshold = failure_threshold
        self.recovery_timeout = recovery_timeout
        self.failure_count = 0
        self.state = "CLOSED"

    def execute_decision(self, client: Any, state_payload: Dict[str, Any], question: str) -> Optional[Dict[str, Any]]:
        if self.state == "OPEN":
            logger.warning("Circuit breaker OPEN. Desviando peticion a ruta determinista de respaldo.")
            return None

        try:
            # Simulacion de llamada al cliente tipado de Jev
            response = client.evaluate(state=state_payload, question=question)
            self.failure_count = 0
            return response
        except Exception as err:
            self.failure_count += 1
            # Regla obligatoria: enmascaramiento estricto de excepciones
            logger.error(f"Fallo en llamada a Jev: {type(err).__name__} (detalles omitidos por seguridad)")
            if self.failure_count >= self.failure_threshold:
                self.state = "OPEN"
                logger.critical("Umbral de fallos alcanzado. Circuit breaker transiciona a OPEN.")
            return None
```

### 7.3. Condiciones de No Uso Categóricas
- **Cálculo Financiero y Contable**: Prohibido utilizar primitivas semánticas para calcular precios, balances o márgenes.
- **Autorización de Mutaciones Críticas**: Prohibido delegar en Jev la decisión final de borrado de bases de datos o transferencias monetarias.
- **Evaluación de Personas sin Auditoría**: Prohibido utilizar clasificaciones de Jev como criterio automático vinculante en contratación o descarte de talento.

## 8. Validación propuesta

### 8.1. Hipótesis Falsable ($H_0$)
$$\mathcal{H}_0: \text{La arquitectura híbrida con salida rápida no logra una reducción estadísticamente significativa (} p > 0.01 \text{) de latencia o incurre en una tasa de error semántico superior a la línea base de reglas deterministas.} $$

### 8.2. Protocolo Experimental Propuesto
- **Conjunto de Datos**: 2,500 casos sintéticos y documentales públicos, divididos en 1,500 para calibración de umbrales y 1,000 reservados estrictamente para prueba fuera de muestra (*out-of-sample*).
- **Métricas de Evaluación**:
  - Exactitud balanceada (*Balanced Accuracy*) y Macro-F1.
  - Latencia p50, p95 y p99 de extremo a extremo.
  - Error de Calibración Esperado (ECE) sobre los márgenes de confianza.
  - Tasa de escalamiento y abstención hacia la supervisión humana.
- **Criterio de Aceptación**: Reducción $\ge 60\%$ en latencia p95 con una tasa de falsos positivos en la vía rápida $\le 1.5\%$.
- **Criterio de Rechazo**: Si la tasa de error en la vía rápida excede el $3.0\%$, se rechaza la arquitectura y se retorna a la línea base determinista.
- **Estado de la Prueba**: `propuesto_no_ejecutado` (diseño formal para fase de laboratorio).

# JEV-P05-018: Detección de Deriva de Calibración y Protocolo de Recalibración en Producción

## 1. Respuesta directa y decisión que permite tomar

La calibración de un modelo de inteligencia artificial como Jev 1.13 no es una propiedad estática e inmutable; es un estado transitorio vulnerable a la **Deriva de Calibración (*Calibration Drift*)**. Cualquier mutación en el entorno de producción —un cambio en el dialecto o modismos de los usuarios, la actualización del modelo base del proveedor (e.g., de Jev 1.13 a 1.14), una modificación en las categorías del esquema `Choice` o una reforma legal o tributaria— degrada silenciosamente la correspondencia entre las probabilidades predichas y las frecuencias reales observadas.

Para monitorizar y decidir con rigor técnico cuándo recalibrar, la arquitectura debe implementar un **Sistema de Detección Dual de Deriva (Supervisado y No Supervisado)** en CPU:

1. **Detección No Supervisada en Tiempo Real (Sin Etiquetas)**:
   - *Population Stability Index (PSI)* sobre las distribuciones de probabilidad de salida:
     $$\text{PSI} = \sum_{b=1}^B (P_{\text{actual}}(b) - P_{\text{baseline}}(b)) \cdot \ln\left( \frac{P_{\text{actual}}(b)}{P_{\text{baseline}}(b)} \right)$$
     Si $\text{PSI} \ge 0.25$, se declara **deriva severa de distribución**, suspendiendo preventivamente la automatización.
   - *Monitoreo de Entropía de Shannon*: Monitorear la entropía media del vector de salida $\bar{H}(\mathbf{p})$. Un colapso súbito de entropía indica sobreconfianza anómala; una subida abrupta indica confusión generalizada.
2. **Detección Supervisada sobre Muestras Auditadas (Con Etiquetas Retardadas)**:
   - Monitoreo del **Rolling-ECE (ventana móvil de 14 días)** sobre una muestra aleatoria de auditoría continua ($5\%$ del tráfico revisado por analistas humanos).
   - Aplicación del **Algoritmo Page-Hinkley o CUSUM** sobre los residuos del Brier Score para detectar puntos de quiebre estadístico instantáneos.
3. **Protocolo de Decisión: Recalibrar vs. Rediseñar**:
   - Si la discriminación (AUC-ROC) se mantiene estable pero el ECE se degrada ($\text{ECE} > 0.08$) $\implies$ **RECALIBRAR EN CPU** (re-ajustar la temperatura $T^*$ con $N_{\text{cal}} \ge 500$ nuevos casos sin tocar el prompt).
   - Si la discriminación también se derrumba ($\Delta \text{AUC} < -0.06$) $\implies$ **REDISEÑAR ESQUEMA** (existe *Concept Drift* profundo; la semántica del modelo ha quedado obsoleta y requiere nuevos prompts o anclas).

**Decisión que permite tomar**: Establecer un disparador automático de desconexión de emergencia (*circuit breaker*) que degrade el tráfico automatizado a revisión humana si el PSI supera $0.25$ o el Rolling-ECE supera $0.08$. Prohibir que actualizaciones de versión de Jev desplegadas por TypeSafe se apliquen en producción sin una re-calibración obligatoria previa en CPU.

## 2. Alcance, términos, versiones y supuestos

- **Alcance**: Monitoreo en línea de deriva de calibración, detección de desplazamiento de distribución y políticas de mantenimiento continuo para Jev 1.13 en Wheelwork y QRT.
- **Términos formalizados**:
  - *Population Stability Index (PSI)*: Métrica estadística basada en la divergencia de Kullback-Leibler simétrica utilizada en banca para medir si la distribución de scores ha cambiado significativamente respecto a una línea base.
  - *Page-Hinkley Test*: Detector secuencial de cambios bruscos en la media de una serie de tiempo estocástica, diseñado para alertar anomalías en streaming.
  - *Rolling-ECE*: Estimación continua del ECE calculada sobre una ventana deslizante de tiempo o número fijo de observaciones recientes.
  - *Model Version Drift*: Desalineación que ocurre cuando el proveedor de API actualiza los pesos subyacentes del modelo sin alterar el nombre del endpoint.
- **Versiones de referencia**: Jev 1.13 (`typesafe-ai >= 0.1.0`), Python 3.11+, Scipy, Statsmodels.
- **Supuestos fundamentales**:
  1. El negocio audita permanentemente una fracción representativa del tráfico (mínimo 2% a 5%) mediante revisión humana calificada.
  2. La recolección de 500 casos de auditoría toma entre 3 y 14 días en flujos de producción activos.

## 5. Ejemplo sintético trabajado y contraejemplo o caso límite

### 5.1. Código en Python: Monitor de PSI y Detector de Quiebre de Calibración

```python
"""
Detector de Deriva de Calibración y Monitor de Estabilidad de Población (PSI).
"""
import numpy as np
from typing import Dict, Any, Tuple

class CalibrationDriftDetector:
    def __init__(self, baseline_probs: np.ndarray, n_bins: int = 10):
        self.n_bins = n_bins
        # Establecer distribución base (línea base congelada)
        self.bin_edges = np.linspace(0.0, 1.0, n_bins + 1)
        self.baseline_dist = self._compute_distribution(baseline_probs)

    def _compute_distribution(self, probs: np.ndarray) -> np.ndarray:
        eps = 1e-5
        bin_indices = np.digitize(probs, self.bin_edges) - 1
        bin_indices = np.clip(bin_indices, 0, self.n_bins - 1)
        counts = np.bincount(bin_indices, minlength=self.n_bins)
        # Probabilidad de cada bin con suavizado laplaciano
        dist = (counts + eps) / (len(probs) + eps * self.n_bins)
        return dist

    def calculate_psi(self, current_probs: np.ndarray) -> float:
        """Calcula el Population Stability Index entre la línea base y la ventana actual."""
        current_dist = self._compute_distribution(current_probs)
        # Fórmula formal de PSI: sum((actual - base) * ln(actual / base))
        psi_value = np.sum((current_dist - self.baseline_dist) * np.log(current_dist / self.baseline_dist))
        return round(float(psi_value), 4)

    def evaluate_drift_status(self, current_probs: np.ndarray, rolling_ece: float) -> Dict[str, Any]:
        psi = self.calculate_psi(current_probs)
        
        # Lógica de decisión
        if psi >= 0.25 or rolling_ece > 0.08:
            estado = "DERIVA_CRITICA_RECALIBRAR_URGENTE"
            accion = "ACTIVAR_CIRCUIT_BREAKER_HUMANO_100"
        elif psi >= 0.10 or rolling_ece > 0.05:
            estado = "DERIVA_MODERADA_ALERTA_AMARILLA"
            accion = "INCREMENTAR_AUDITORIA_HUMANA"
        else:
            estado = "SISTEMA_ESTABLE"
            accion = "OPERACION_AUTONOMA_NORMAL"

        return {
            "psi_calculado": psi,
            "rolling_ece": rolling_ece,
            "estado_calibracion": estado,
            "accion_recomendada": accion
        }

# Simulación de producción
if __name__ == "__main__":
    np.random.seed(42)
    # 1. Línea Base en producción normal (N=2,000)
    p_base = np.random.beta(2, 5, 2000)
    detector = CalibrationDriftDetector(p_base, n_bins=10)

    # Ventana 1: Producción estable normal (sin drift)
    p_w1 = np.random.beta(2, 5, 1000)
    res1 = detector.evaluate_drift_status(p_w1, rolling_ece=0.035)
    print("=== VENTANA 1: PRODUCCIÓN ESTABLE ===")
    print(f"PSI: {res1['psi_calculado']} | Rolling-ECE: {res1['rolling_ece']} -> {res1['accion_recomendada']}\n")

    # Ventana 2: Desplazamiento por actualización de frontend / nueva jerga (Deriva severa)
    # Las probabilidades se concentran anormalmente en valores altos
    p_w2 = np.random.beta(5, 2, 1000)
    res2 = detector.evaluate_drift_status(p_w2, rolling_ece=0.115)
    print("=== VENTANA 2: CAMBIO DE VERSIÓN / NUEVO LÉXICO ===")
    print(f"PSI: {res2['psi_calculado']} | Rolling-ECE: {res2['rolling_ece']} -> {res2['accion_recomendada']}")
    print(f"Estado: {res2['estado_calibracion']}")
```

### 5.2. Contraejemplo y Caso Límite: El "Silent Upgrade" de Jev que Duplica los Rechazos

En una integración de QRT para análisis de hechos esenciales:
- La empresa opera con Jev 1.13 bajo un endpoint cloud que recibe un parche transparente del proveedor un viernes en la noche.
- El modelo parcheado es más asertivo: comprime las probabilidades hacia $0.01$ y $0.99$.
- Como no hay un detector de PSI en CPU, el sistema de QRT continúa operando normalmente durante el fin de semana.
- Como los umbrales estaban fijados para el modelo anterior, el nuevo modelo desplaza las probabilidades y rechaza el $60\%$ de las órdenes operacionales legítimas del lunes en la mañana, generando un cuello de botella crítico y pérdidas por inactividad.
- **Manejo correcto**: El monitor de PSI detecta a las 09:05 AM que $\text{PSI} = 0.38 \gg 0.25$. El circuit-breaker se activa de inmediato, frena las aprobaciones autónomas, notifica a los ingenieros y recalibra la temperatura $T^*$ en 2 minutos usando los 500 casos auditados más recientes, restaurando la estabilidad antes de la apertura del mercado bursátil.

## 7. Fallos, límites, controles y condiciones de no uso

### 7.1. Modos de falla y mitigaciones

| Modo de Falla | Causa Raíz | Detección | Mitigación Arquitectónica |
|---|---|---|---|
| **Falsas Alarmas por Bins Vacíos en PSI** | Calcular el PSI con bins de probabilidad donde la probabilidad de una celda es exactamente cero. | División por cero o valores `inf` en el cálculo de PSI. | Implementar suavizado laplaciano ($\epsilon = 10^{-5}$) en la estimación de densidad empírica. |
| **Recalibración Inútil ante Concept Drift** | Intentar arreglar con Temperature Scaling un problema donde el modelo ya no comprende el texto. | El ECE no baja de 0.08 tras recalibrar y el AUC-ROC cayó más de 6 puntos. | Detener la recalibración y convocar al equipo de prompts para rediseñar el esquema. |
| **Falta de Muestras de Auditoría** | La mesa humana revisa muy pocos casos, impidiendo calcular el Rolling-ECE a tiempo. | Ventana móvil de auditoría de 14 días con menos de 100 muestras. | Forzar una cuota mínima de muestreo aleatorio obligatorio en la cola de operaciones. |

### 7.2. Condiciones de NO uso

- **NO recalibrar en caliente (*online learning*) sobre flujos no auditados**: Ajustar la temperatura sobre las propias predicciones del modelo sin ground truth crea un bucle de retroalimentación autodestructivo.
- **NO ignorar un PSI $\ge 0.25$ aunque no haya reportes de clientes**: El PSI es un indicador adelantado; los reclamos de clientes llegarán semanas después cuando el daño ya esté hecho.

### 8.1. Diseño experimental
- **Hipótesis falsable**: El monitor continuo de PSI y Rolling-ECE detectará con éxito una deriva sintéticamente inducida (cambio de versión de modelo y desplazamiento de dialecto) dentro de las primeras 200 transacciones con una tasa de falsos positivos en datos estacionarios menor al $1.0\%$, y el protocolo de recalibración en CPU restaurará el ECE por debajo de $0.045$ utilizando $N_{\text{cal}} = 500$ casos recientes.
- **Dataset sintético de prueba**: 4,000 transacciones divididas en Bloque Estable (2,000), Bloque con Deriva Moderada (1,000) y Bloque con Deriva Crítica (1,000).
- **Métricas y umbrales**:
  - Tiempo de detección de deriva crítica: $\le 200$ transacciones.
  - Tasa de Falsas Alarmas en Bloque Estable: $< 1.0\%$.
  - ECE post-recalibración automática: $\le 0.05$.
- **Criterio de rechazo**: Si el detector no emite la alerta roja ante una degradación real del ECE $> 0.10$, se recalibrarán los umbrales de alerta del monitor de PSI.
- **Presupuesto estimado**: Computación puramente local en CPU = $0.00 USD.

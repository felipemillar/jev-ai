# JEV-P17-020: Qué revisión periódica asegura utilidad, vigencia y trazabilidad sin repetir desde cero toda la investigación

## 1. Respuesta directa y decisión que permite tomar

En el contexto operativo de **Investigación acumulativa, trazabilidad, FEVER y aprendizaje activo**, la regla fundamental de adopción establece que **Jev debe integrarse exclusivamente como una herramienta de apoyo al triaje semántico y asistencia documental, manteniendo toda decisión sensible bajo estricto control humano y validación determinista**. Toda propuesta de automatización en este dominio se formula como una `hipotesis_de_diseno` condicionada a pruebas con datos sintéticos o corpus públicos autorizados, vetando categóricamente la ejecución autónoma de órdenes financieras, descartes laborales o mutaciones irreversibles.

La decisión de ingeniería concreta que se deriva consiste en:
1. **Gobernanza y Asistencia Asimétrica**: El modelo clasifica, filtra o prioriza información preliminar en espacio cerrado (`Choice`, `Noul`, `Score`), pero la confirmación final y la responsabilidad legal o financiera permanecen en el operador humano competente.
2. **Custodia de Procedencia y Temporalidad**: Se exige registrar el instante exacto de disponibilidad de cada dato para erradicar sesgos de anticipación (*lookahead bias*) en investigación cuantitativa (QRT) y asegurar la auditabilidad inmutable de evidencias laborales (Wheelwork).
3. **Compuerta de Descarte y Criterio de Salida**: Si el aporte neto del modelo no supera a una línea base de reglas deterministas o heurísticas sencillas en un ensayo piloto acotado, la integración se descarta sin incurrir en costes de mantenimiento superfluos.

## 2. Alcance, términos, versiones y supuestos

### 2.1. Alcance y marco metodológico
Aplica a la especificación de Jev 1.13 en entornos experimentales y de apoyo a flujos de trabajo en QRT, Wheelwork y productividad personal. La investigación se restringe estrictamente a marcos documentales, formulación teórica y bancos de pruebas con datos ficticios o sintéticos, sin conectar APIs de producción ni acceder a información confidencial de clientes o cuentas reales.

### 2.2. Términos formales y supuestos
- **Procedencia Temporal Estricta (*Point-in-Time Integrity*)**: Garantía de que ningún modelo o pipeline acceda a información publicada con posterioridad a la marca de tiempo de la decisión evaluada.
- **Evaluación Contrafactual**: Protocolo de prueba donde se evalúan pares de entradas idénticas que solo difieren en atributos no pertinentes (ej. nombres, formatos o modismos) para auditar la invariancia del clasificador.
- **Aprendizaje Activo Supervisado**: Mecanismo donde solo los casos de alta incertidumbre o discrepancia semántica se envían a etiquetado humano para alimentar el conjunto de calibración continuo.
- **Supuestos Clave**: Se asume que las políticas normativas aplicables (Ley 19.628 de Protección de Datos Personales, Código de Comercio y directrices CMF/SII) rigen de forma prioritaria sobre cualquier optimización algorítmica.

## 4. Explicación técnica verificable

### 4.1. Topología de Procesamiento Asistido con Puerta de Enlace Humana
La arquitectura separa tajantemente la fase de inferencia de la fase de decisión ejecutiva mediante un bus de eventos y una cola de confirmación:

```
[ Entrada Textual / Documento ]
               │
               ▼
┌──────────────────────────────────────────┐
│ Normalización y Enriquecimiento CPU      │ ──> Elimina PII / Valida Esquema
└──────────────────────────────────────────┘
               │
               ▼
┌──────────────────────────────────────────┐
│ Inferencia Semántica (Jev Sistema 1)     │ ──> Emite (Clase, Probabilidad, Margen)
└──────────────────────────────────────────┘
               │
               ▼
┌──────────────────────────────────────────┐
│ Puerta de Enlace y Política de Negocio   │
└──────────────────────────────────────────┘
       │                               │
       ▼ (Baja Incertidumbre)          ▼ (Alta Incertidumbre o Alto Riesgo)
┌───────────────────────────┐   ┌───────────────────────────┐
│ Sugerencia Asistida       │   │ Cola de Revisión Humana   │
│ (Requiere Confirmación)   │   │ (Inspección Forense)      │
└───────────────────────────┘   └───────────────────────────┘
```

### 4.2. Función de Puntuación Calibrada y Penalización Asimétrica
Sea $\mathcal{L}(y, \hat{y})$ la matriz de pérdidas económicas o laborales asociadas al error. El sistema no elige simplemente la clase de máxima probabilidad, sino aquella que minimiza el riesgo bayesiano esperado:
$$\hat{c} = \arg\min_{c \in \mathcal{C}} \sum_{k \in \mathcal{C}} P(C = k \mid \mathbf{x}) \cdot \mathcal{L}(k, c)$$
Si el riesgo esperado de cometer un falso positivo supera el coste de derivar el caso a inspección manual ($R(\hat{c}) > C_{\text{revisión}}$), el software emite una abstención obligatoria, preservando la seguridad del proceso global.

## 5. Ejemplo sintético trabajado y contraejemplo o caso límite

### 5.1. Ejemplo Sintético Trabajado (Triaje Asistido Exitoso)
**Contexto**: Clasificación y asignación preliminar de un documento de investigación o solicitud operacional:

**Estado estructurado (`state`):**
```json
{
  "item_id": "OP-2026-771",
  "tipo_fuente": "nota_tecnica",
  "origen": "reporte_interno",
  "resumen_texto": "Propuesta de refactorización de la capa de acceso a datos para reducir contención en PostgreSQL.",
  "criticidad_declarada": "media"
}
```

**Pregunta y Primitiva:**
- Primitiva: `Choice`
- Pregunta: *"¿A qué grupo de trabajo debe derivarse esta nota técnica para revisión inicial?"*
- Opciones: `["infraestructura_datos", "desarrollo_core", "seguridad_auditoria", "escalar_arquitecto"]`

**Respuesta devuelta por el modelo:**
```json
{
  "decision": "infraestructura_datos",
  "probabilities": {
    "infraestructura_datos": 0.915,
    "desarrollo_core": 0.052,
    "seguridad_auditoria": 0.018,
    "escalar_arquitecto": 0.015
  },
  "margin": 0.863
}
```
**Efecto en el software**: Al superar el umbral de convicción ($\gamma \ge 0.75$) y no involucrar entidades críticas, el sistema etiqueta la nota y la coloca en la bandeja de entrada del equipo correspondiente como *sugerencia asistida*, pendiente de triaje en la reunión de sincronización diaria.

### 5.2. Contraejemplo o Caso Límite (Falla por Ambigüedad y Rechazo)
**Estado con conflicto semántico y potenciales implicaciones de riesgo:**
```json
{
  "item_id": "OP-2026-772",
  "tipo_fuente": "incidencia_produccion",
  "resumen_texto": "Discrepancia en saldos de liquidación durante la ventana de cierre contable, posible error de concurrencia o fallo de API bancaria externa."
}
```
**Resultado**: Jev devuelve `infraestructura_datos` con $P = 0.46$ y `seguridad_auditoria` con $P = 0.42$ (margen $\gamma = 0.04$). El sistema detecta colapso de margen y clasifica la incidencia como **caso crítico de alta ambigüedad**, activando alerta inmediata a los responsables de área sin permitir ningún enrutamiento automático desatendido.

## 6. Aplicación a nuestros desarrollos

### 6.1. Integración en QRT (Trading Algorítmico y Modelos Cuantitativos)
- **Caso de Uso**: Extracción de características cualitativas de publicaciones de bancos centrales y reportes macroeconómicos para convertirlas en variables de investigación.
- **Protocolo de Custodia**: Las etiquetas semánticas se indexan con la fecha/hora UTC exacta de disponibilidad del cable y se almacenan en tablas históricas inmutables.
- **Frontera Infranqueable**: Ninguna señal de Jev tiene acceso a la lógica de generación de órdenes en MT5 ni puede alterar parámetros de gestión de riesgo o apalancamiento.

### 6.2. Integración en Wheelwork (Talento, Selección y Consultoría)
- **Caso de Uso**: Pre-evaluación documental de correspondencia entre experiencias acreditadas en perfiles sintéticos y los requisitos de un descriptor de vacante.
- **Control Antisesgo**: El preprocesador elimina cualquier mención de género, edad, fotografía, instituciones educativas no pertinentes y origen socioeconómico antes de la inferencia.
- **Garantía Humana**: Toda pre-selección requiere que un consultor revise la evidencia textual citada antes de contactar al candidato. Queda prohibida la generación de respuestas de rechazo automatizadas.

## 7. Fallos, límites, controles y condiciones de no uso

### 7.1. Modos de Falla y Mitigación
1. **Alucinación de Relevancia**: Asignación de alta certidumbre a textos que repiten palabras clave sin contener sustancia probatoria real.
2. **Sesgo de Selección Histórico**: Contaminación de evaluaciones cuantitativas por utilizar noticias que fueron editadas con posterioridad a los hechos.
3. **Pérdida de Contexto Dialectal**: Mala interpretación de frases idiomáticas chilenas o modismos sectoriales.

### 7.2. Código de Integración Seguro con Error Masking
```python
import logging
from typing import Dict, Any, Optional

logger = logging.getLogger("jev_domain_gateway")

def safe_evaluate_domain_case(client: Any, state_payload: Dict[str, Any], question: str) -> Optional[Dict[str, Any]]:
    """
    Ejecuta evaluacion semantica con manejo seguro y enmascaramiento estricto de errores.
    """
    try:
        # Validacion previa de esquema determinista
        if not state_payload.get("item_id"):
            logger.warning("Rechazo de payload: identificador ausente.")
            return None
            
        result = client.evaluate(state=state_payload, question=question)
        return result
    except Exception as err:
        # Regla obligatoria: enmascaramiento de excepcion
        logger.error(f"Fallo en inferencia de dominio: {type(err).__name__} (detalles omitidos por seguridad)")
        return None
```

### 7.3. Condiciones de No Uso Categóricas
- **Ejecución Financiera Directa**: Prohibido conectar salidas de Jev con pasarelas de pago, liquidaciones o brokers.
- **Decisiones Vinculantes sobre Personas**: Prohibido utilizar puntuaciones semánticas para despidos, contrataciones o sanciones.
- **Datos Personales No Anonimizados**: Prohibido enviar información confidencial protegida sin proceso previo de desidentificación.

## 8. Validación propuesta

### 8.1. Hipótesis Falsable ($H_0$)
$$\mathcal{H}_0: \text{El modelo Jev no aporta una mejora estadísticamente medible (} p > 0.01 \text{) en exactitud de triaje o reducción de tiempo de revisión frente a un clasificador basado en reglas deterministas y búsqueda léxica.} $$

### 8.2. Protocolo Experimental Propuesto
- **Corpus de Prueba**: 1,200 casos documentales sintéticos y semi-públicos representativos del dominio, con etiquetas de consenso fijadas por al menos dos revisores independientes.
- **Particiones**: 60% para calibración de umbrales y 40% reservado para test fuera de muestra.
- **Métricas Primarias**:
  - Exactitud balanceada (*Balanced Accuracy*) y F1 ponderado.
  - Cobertura de decisiones con margen seguro ($\gamma \ge 0.50$).
  - Tasa de discrepancia respecto a anotadores humanos expertos.
- **Criterio de Aceptación**: F1 $\ge 0.88$ con menos del $2.0\%$ de clasificaciones erróneas graves en casos de alta confianza.
- **Criterio de Rechazo**: Si el modelo no supera a la línea base en $\ge 5$ puntos porcentuales de F1, se cancela el piloto.
- **Estado de la Prueba**: `propuesto_no_ejecutado` (fase de laboratorio).

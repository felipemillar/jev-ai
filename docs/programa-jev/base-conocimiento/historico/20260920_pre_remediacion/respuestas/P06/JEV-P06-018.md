# JEV-P06-018: Paquete Canónico de Reproducción: Entorno, Versiones, Datos Sanitizados y Auditoría Segura

## 1. Respuesta directa y decisión que permite tomar

Un informe de evaluación o benchmark de Jev 1.13 carece de validez científica y corporativa si un equipo técnico independiente no puede reproducir exactamente los mismos resultados numéricos. Sin embargo, en entornos empresariales regulados (finanzas y recursos humanos), publicar el código y los datos de prueba conlleva el grave riesgo de **fuga de secretos (API keys de TypeSafe), violación de leyes de privacidad (RGPD o Ley 19.628 por exposición de PII)** y filtración de secretos comerciales.

Para conciliar la reproducibilidad científica total con la seguridad de la información, todo benchmark de Jev debe empaquetarse bajo el estándar del **Paquete Canónico de Reproducción Segura (PCRS)**, el cual consta de **Cinco Artefactos Inviolables**:

1. **Manifiesto de Entorno Inmutable (`environment.lock` / `Dockerfile`)**:
   - Definición congelada del contenedor de ejecución: versión exacta de Python (3.11.8), dependencias fijadas por hash criptográfico (`uv.lock` o `poetry.lock`), librerías de sistema operativo y versiones de SDK (`typesafe-ai == 0.1.0`).
2. **Especificación Declarativa del Experimento (`benchmark_config.yaml`)**:
   - Nombre de versión congelada del modelo (`jev-1.13`), hiperparámetros de temperatura calibrada ($T^*$), esquema formal de `Choice`/`Noul`, timeouts de red y semilla estocástica global.
3. **Dataset de Evaluación Sanitizado y Sellado (`benchmark_dataset.jsonl`)**:
   - Muestra de datos completamente purgada de información confidencial: sustitución de RUTs, nombres, correos y montos sensibles mediante pseudonimización reversible en bóveda local. El archivo se acompaña de su hash inmutable **SHA-256**.
4. **Script Determinista de Evaluación (`reproduce_benchmark.py`)**:
   - Código ejecutable en un solo comando que lee las credenciales exclusivamente desde la variable de entorno `TYPESAFE_API_KEY` (prohibiendo cualquier token hardcodeado), ejecuta las inferencias pareadas y genera el informe de métricas.
5. **Recibo de Procedencia y Telemetría Criptográfica (`provenance_receipt.json`)**:
   - Registro forense con las marcas de tiempo ISO 8601, latencias E2E por llamada, identificadores de transacción y la firma digital PGP del auditor responsable.

**Decisión que permite tomar**: Establecer como compuerta técnica que ningún resultado de laboratorio sea considerado válido por los comités de arquitectura de Wheelwork o QRT sin la entrega y verificación exitosa del contenedor del paquete PCRS en un entorno de integración continua limpio.

## 2. Alcance, términos, versiones y supuestos

- **Alcance**: Estándares de reproducibilidad de software, empaquetado de artefactos científicos, sanitización de datos y seguridad de credenciales en Wheelwork y QRT.
- **Términos formalizados**:
  - *Reproducibilidad Bit a Bit (Exact Reproducibility)*: Capacidad de recrear idénticos resultados numéricos ejecutando el mismo código sobre los mismos datos en un entorno idéntico.
  - *Sanitización PII*: Proceso de enmascaramiento o sustitución de Información Personalmente Identificable para evitar la reidentificación de personas naturales.
  - *Provenance Receipt*: Manifiesto forense que certifica cuándo, cómo, en qué hardware y con qué versión de código se generó un conjunto de métricas.
- **Versiones de referencia**: Jev 1.13 (`typesafe-ai >= 0.1.0`), Python 3.11+, Docker, Uv.
- **Supuestos fundamentales**:
  1. Un auditor externo debe ser capaz de clonar el repositorio, ejecutar `docker compose run benchmark` e interactuar con la API sin requerir soporte manual de los autores.

### 5.1. Implementación en Python: Validador Pre-Vuelo del Paquete de Reproducción

```python
"""
Módulo de Verificación y Sanitización del Paquete de Reproducción (PCRS Guard).
Verifica la ausencia de credenciales, la integridad de los hashes y la consistencia del entorno.
"""

import os
import re
import hashlib
from typing import Dict, Any, List
import logging

logger = logging.getLogger("PCRSValidator")

class ReproducibilityPackageValidator:
    @staticmethod
    def scan_for_secrets(file_paths: List[str]) -> List[str]:
        """
        Escanea archivos buscando credenciales hardcodeadas o patrones de API keys.
        """
        violations = []
        secret_patterns = [
            (r"typesafe_[a-zA-Z0-9]{32,}", "API Key de TypeSafe detectada"),
            (r"sk-[a-zA-Z0-9]{32,}", "API Key de OpenAI detectada"),
            (r"(?i)password\s*=\s*['\"][^'\"]+['\"]", "Contraseña en texto plano"),
            (r"[0-9]{7,8}-[0-9kK]", "RUT chileno sin anonimizar")
        ]

        for path in file_paths:
            if not os.path.exists(path):
                continue
            try:
                with open(path, "r", encoding="utf-8", errors="ignore") as f:
                    content = f.read()
                    for pattern, desc in secret_patterns:
                        if re.search(pattern, content):
                            violations.append(f"ALERTA DE SEGURIDAD en {path}: {desc}")
            except Exception as err:
                violations.append(f"Error al leer {path}: {type(err).__name__}")

        return violations

    @staticmethod
    def verify_dataset_integrity(dataset_path: str, expected_hash_path: str) -> bool:
        """
        Comprueba que el dataset no haya sido alterado verificando su hash SHA-256.
        """
        try:
            if not os.path.exists(dataset_path) or not os.path.exists(expected_hash_path):
                return False

            with open(dataset_path, "rb") as f:
                computed_hash = hashlib.sha256(f.read()).hexdigest()

            with open(expected_hash_path, "r", encoding="utf-8") as f:
                expected_hash = f.read().strip()

            return computed_hash.lower() == expected_hash.lower()

        except Exception as err:
            logger.error(f"Error al verificar integridad: {type(err).__name__} (detalles omitidos por seguridad)")
            return False

    def validate_package(
        self, files_to_scan: List[str], dataset_path: str, hash_path: str
    ) -> Dict[str, Any]:
        """
        Ejecuta la auditoría integral de conformidad del paquete de reproducción.
        """
        secrets_found = self.scan_for_secrets(files_to_scan)
        integrity_ok = self.verify_dataset_integrity(dataset_path, hash_path)

        is_valid = (len(secrets_found) == 0) and integrity_ok

        return {
            "package_valid": is_valid,
            "status": "APROBADO_PARA_DISTRIBUCION" if is_valid else "RECHAZADO_FALLO_SEGURIDAD_O_INTEGRIDAD",
            "secrets_violations": secrets_found,
            "dataset_integrity_verified": integrity_ok,
            "verdict": (
                "El paquete puede ser compartido con auditores sin riesgo de fuga de credenciales."
                if is_valid
                else "PROHIBIDO COMPARTIR: Contiene secretos o datos corruptos."
            )
        }


if __name__ == "__main__":
    validator = ReproducibilityPackageValidator()

    # Creación de archivos temporales de prueba para la demostración
    temp_dir = "/tmp/test_pcrs"
    os.makedirs(temp_dir, exist_ok=True)

    clean_code = temp_dir + "/reproduce.py"
    with open(clean_code, "w") as f:
        f.write("import os\napi_key = os.environ.get('TYPESAFE_API_KEY')\nprint('Running clean benchmark...')")

    data_file = temp_dir + "/data.jsonl"
    with open(data_file, "w") as f:
        f.write('{"id": "CASE-01", "state": "Factura anonimizada de repuestos"}\n')

    h_val = hashlib.sha256(open(data_file, "rb").read()).hexdigest()
    hash_file = temp_dir + "/hash.txt"
    with open(hash_file, "w") as f:
        f.write(h_val)

    report = validator.validate_package([clean_code], data_file, hash_file)
    print("--- Informe de Validación del Paquete de Reproducción ---")
    print("Estado:", report["status"])
    print("Integridad del Dataset:", report["dataset_integrity_verified"])
    print("Violaciones de Secretos:", len(report["secrets_violations"]))
    print("Veredicto:", report["verdict"])
```

### 5.2. Caso Límite / Contraejemplo

Un equipo de innovación contrató a una consultora externa para auditar un benchmark de Jev en detección de fraude.
- Enviaron un archivo ZIP con un Jupyter Notebook y un archivo CSV.
- Al abrir el Notebook:
  - La celda 2 contenía: `API_KEY = "typesafe_live_9988223311aabbcc..."` con la clave de producción de la empresa.
  - El CSV contenía 1,200 registros de clientes con nombres, RUTs y saldos bancarios reales sin anonimizar.
  - Las celdas dependían de librerías locales no declaradas que causaron un fallo `ModuleNotFoundError` en la máquina del auditor.
- **Consecuencias**: Violación grave de la normativa de protección de datos personales ante el regulador, revocación de emergencia de credenciales y pérdida total de credibilidad del equipo técnico.
- **Lección**: Sin un paquete PCRS validado automáticamente, la ciencia de datos es un peligro operacional.

## 6. Aplicación a nuestros desarrollos

### 6.1. Wheelwork (Screening de CVs y Conciliación)
- **Hecho**: Los currículums contienen datos sensibles de personas naturales (dirección, teléfonos, historial laboral).
- **Hipótesis de desarrollo**: Todo paquete de reproducción de Jev en Wheelwork debe generarse a través de un script que reemplace los nombres por identificadores opacos (`CANDIDATO_001`), elimine números de teléfono y purgue RUTs. El dataset sanitizado debe empaquetarse en un Dockerfile para que cualquier miembro del equipo pueda reproducir la evaluación sin ver datos privados reales.

### 6.2. QRT (Cuadernos Cuantitativos y Estrategias Propietarias)
- **Hecho**: El código de las estrategias de inversión de QRT constituye secreto industrial de máximo nivel.
- **Hipótesis de desarrollo**: El paquete de reproducción de Jev en QRT debe desacoplar el modelo de trading de la evaluación de Jev: debe contener únicamente las entradas semánticas de texto y las etiquetas de régimen de mercado, sin incluir la lógica algorítmica de asignación de capital ni el código de ejecución de órdenes en brokers.

## 7. Fallos, límites, controles y condiciones de no uso

### 7.1. Modos de Fallo
1. **Falso Determinismo por Falta de Semilla**: No fijar `PYTHONHASHSEED=0` y las semillas aleatorias de Scikit-Learn/Numpy, provocando que los remuestreos bootstrap arrojen intervalos de confianza ligeramente distintos en cada máquina.
2. **Dependencia de Endpoints No Versionados**: Usar la URL base `/v1/systemone` apuntando al alias flotante `latest`, haciendo que la actualización del proveedor rompa la reproducibilidad meses después.

### 7.2. Controles Mandatorios
- **Pre-Commit Hook Bloqueante con Gitleaks**: Prohibir cualquier commit que contenga cadenas que hagan match con claves de TypeSafe o tokens de acceso.
- **Prueba de Replicación en Contenedor Limpio**: El paquete debe ejecutarse exitosamente en una máquina virtual limpia de GitHub Actions sin variables locales preexistentes.

### 7.3. Condiciones de No Uso
- Prohibido compartir o archivar benchmarks donde el conjunto de datos de prueba no coincida con el hash criptográfico SHA-256 documentado en el reporte.

## 8. Validación propuesta

### 8.1. Hipótesis Falsable
> **Hipótesis**: La ejecución del paquete PCRS sobre una máquina virtual limpia en la nube reproducirá los valores de Macro-F1, Brier Score y tiempo de ejecución de Jev 1.13 con una concordancia numérica del **$100\%$ en métricas discretas** y una desviación inferior a $\pm 0.001$ en métricas probabilísticas continuas, sin requerir ninguna intervención manual de configuración.

### 8.2. Diseño Experimental
- **Tipo**: Propuesta, no ejecutada.
- **Entorno**: Instancia limpia EC2 `t3.medium` en AWS sin software previo instalado, salvo Docker.
- **Procedimiento**: Clonar el repositorio del paquete PCRS, inyectar la variable de entorno `TYPESAFE_API_KEY` y ejecutar `docker run --rm benchmark`.
- **Criterio de Rechazo**: Si el script arroja un error de ejecución o si las métricas finales difieren de las publicadas en el reporte, el paquete se declara no reproducible.
- **Presupuesto Supuesto**: Cero coste adicional de infraestructura; 4 horas de empaquetado Docker y pruebas de contenedor ($\approx \text{USD \$200}$).

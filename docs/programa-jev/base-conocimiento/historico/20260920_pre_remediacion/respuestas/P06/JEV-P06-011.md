# JEV-P06-011: Criterios Previos de Aprobación, Rechazo y Suspensión para Prevenir la Selección Retrospectiva de Métricas

## 1. Respuesta directa y decisión que permite tomar

El mayor riesgo metodológico en la evaluación de modelos de inteligencia artificial es el fenómeno de **HARKing (*Hypothesizing After the Results are Known*)** y la **Selección Retrospectiva de Métricas (*Metric Cherry-Picking*)**: ejecutar inferencias sobre múltiples configuraciones de prompts o modelos y, tras observar los resultados dispersos, elegir a posteriori aquella métrica o segmentación particular donde Jev 1.13 aparenta haber ganado (e.g., *"perdió en precisión global y F1, pero ganó en recall de la clase secundaria"*).

Para blindar la toma de decisiones empresariales contra el sesgo de confirmación de los ingenieros promotores, todo piloto de Jev debe someterse a un **Protocolo de Evaluación Preregistrado e Inmutable (PEP)** antes de disparar la primera llamada de API sobre el conjunto de prueba. El PEP define tres compuertas deterministas no negociables:

1. **Criterios de Aprobación Definitiva (*Go Decision*)**:
   - La **Métrica Primaria Pre-declarada** (e.g. Utilidad Neta Económica $\Delta U$ o Macro-F1) debe superar a la mejor línea base en al menos un **$+15\%$** relativo con significancia estadística confirmada ($p < 0.01$ en test pareado de Wilcoxon o McNemar).
   - La tasa de error en la partición crítica de seguridad (casos de alto impacto financiero o legal) no debe superar el SLA histórico ($\text{Error}_{\text{crítico}} \le \theta_{\text{SLA}}$ con IC al $95\%$).
   - La latencia end-to-end $p_{95}$ debe mantenerse estrictamente por debajo del SLA operativo acordado ($p_{95} \le 450\text{ ms}$).
2. **Criterios de Rechazo Definitivo (*No-Go Decision / Abandono*)**:
   - La métrica primaria no logra una ventaja estadísticamente significativa frente a la línea base económica ($p \ge 0.05$ o $\Delta \le 0$).
   - El coste total por decisión aceptada (contabilizando API, infraestructura y revisiones humanas de escalamiento) resulta superior al coste de la línea base preexistente.
   - Ocurrencia de un fallo catastrófico no mitigable en casos trampa de control (*Gold Traps*).
3. **Criterios de Suspensión Inmediata (*Emergency Halt / Circuit Breaker*)**:
   - Deriva poblacional súbita: el *Population Stability Index* (PSI) supera $0.25$.
   - Tasa de errores de red o timeouts de la API de TypeSafe superior al $2.0\%$ sostenido en 1 hora.
   - Ruptura del contrato de esquema: recepción de cualquier payload malformado que viole la especificación tipada (`Choice` o `Noul`).

**Decisión que permite tomar**: Establecer una regla de gobierno corporativo que anule automáticamente cualquier informe de evaluación donde las métricas o los umbrales de éxito hayan sido modificados tras el inicio de las pruebas con datos de holdout.

## 2. Alcance, términos, versiones y supuestos

- **Alcance**: Gobernanza experimental, estándares de preregistro, criterios de decisión Go/No-Go y disparadores de parada de emergencia para pilotos de Jev en Wheelwork y QRT.
- **Términos formalizados**:
  - *HARKing*: Práctica viciosa consistente en presentar una hipótesis formulada a posteriori como si hubiese sido establecida antes de realizar el experimento.
  - *Métrica Primaria Única*: Indicador cuantitativo cardinal sobre el cual recae exclusivamente la decisión binaria de aprobar o rechazar el proyecto.
  - *Sello Criptográfico de Protocolo*: Hash SHA-256 del documento de diseño experimental registrado en el repositorio de control de versiones antes de la ejecución de pruebas.
- **Versiones de referencia**: Jev 1.13 (`typesafe-ai >= 0.1.0`), Python 3.11+, Pydantic v2.
- **Supuestos fundamentales**:
  1. Si a un equipo se le permite seleccionar retrospectivamente qué métrica reportar, siempre encontrará alguna combinación matemática donde su modelo parezca exitoso, aunque destruya valor para el negocio.

## 5. Ejemplo sintético trabajado y contraejemplo o caso límite

### 5.1. Implementación en Python: Motor de Decisión de Compuerta PEP

```python
"""
Módulo de Gobernanza y Validación de Compuertas de Decisión (PEP Engine).
Evalúa métricas pre-declaradas y emite veredictos deterministas Go/No-Go/Halt.
"""

from typing import Dict, Any, List
from dataclasses import dataclass
import logging

logger = logging.getLogger("PEPEngine")

@dataclass(frozen=True)
class PreRegisteredProtocol:
    protocol_id: str
    primary_metric_name: str
    min_relative_gain_percent: float
    max_tolerated_p_value: float
    max_tolerated_latency_p95_ms: float
    max_tolerated_safety_error_rate: float
    max_tolerated_psi: float

class GateDecisionEngine:
    @staticmethod
    def evaluate_pilot_results(
        protocol: PreRegisteredProtocol,
        observed_results: Dict[str, Any]
    ) -> Dict[str, Any]:
        """
        Audita los resultados frente al protocolo inmutable pre-registrado.
        """
        try:
            violations = []
            halt_triggers = []

            # 1. Comprobar Disparadores de Suspensión Inmediata (Circuit Breaker)
            observed_psi = observed_results.get("observed_psi", 0.0)
            if observed_psi >= protocol.max_tolerated_psi:
                halt_triggers.append(
                    f"Deriva poblacional crítica: PSI {observed_psi:.4f} >= {protocol.max_tolerated_psi}"
                )

            observed_timeout_rate = observed_results.get("observed_timeout_rate", 0.0)
            if observed_timeout_rate > 0.02:
                halt_triggers.append(
                    f"Inestabilidad de API: Tasa de timeouts {observed_timeout_rate*100:.2f}% > 2.0%"
                )

            if halt_triggers:
                return {
                    "verdict": "SUSPENSION_INMEDIATA_HALT",
                    "approved": False,
                    "reasons": halt_triggers,
                    "action": "Desconectar inferencia de Jev y activar respaldo de reglas."
                }

            # 2. Comprobar Métrica Primaria
            rel_gain = observed_results.get("primary_relative_gain_percent", 0.0)
            p_val = observed_results.get("primary_p_value", 1.0)

            if rel_gain < protocol.min_relative_gain_percent:
                violations.append(
                    f"Ganancia relativa insuficiente ({rel_gain:.2f}% < {protocol.min_relative_gain_percent}%)"
                )
            if p_val >= protocol.max_tolerated_p_value:
                violations.append(
                    f"Falta de significancia estadística (p-value {p_val:.6f} >= {protocol.max_tolerated_p_value})"
                )

            # 3. Comprobar Seguridad y SLA en Colas Críticas
            safety_error = observed_results.get("safety_error_rate", 0.0)
            if safety_error > protocol.max_tolerated_safety_error_rate:
                violations.append(
                    f"Violación de SLA de seguridad ({safety_error*100:.2f}% > {protocol.max_tolerated_safety_error_rate*100:.2f}%)"
                )

            # 4. Comprobar Latencia p95
            lat_p95 = observed_results.get("latency_p95_ms", 9999.0)
            if lat_p95 > protocol.max_tolerated_latency_p95_ms:
                violations.append(
                    f"Latencia p95 excesiva ({lat_p95:.1f} ms > {protocol.max_tolerated_latency_p95_ms} ms)"
                )

            is_go = len(violations) == 0

            return {
                "verdict": "GO_APROBADO_PARA_PRODUCCION" if is_go else "NO_GO_RECHAZO_DEFINITIVO",
                "approved": is_go,
                "protocol_id": protocol.protocol_id,
                "primary_metric": protocol.primary_metric_name,
                "violations_count": len(violations),
                "reasons": violations if not is_go else ["Todos los criterios pre-registrados fueron satisfechos."]
            }

        except Exception as err:
            logger.error(f"Error al evaluar compuerta de decisión: {type(err).__name__} (detalles omitidos por seguridad)")
            return {
                "verdict": "ERROR_DE_EVALUACION",
                "approved": False,
                "reasons": [f"Fallo de software: {type(err).__name__}"]
            }


if __name__ == "__main__":
    # Protocolo canónico sellado pre-vuelo
    pep = PreRegisteredProtocol(
        protocol_id="PEP-WHEELWORK-2026-Q3",
        primary_metric_name="Utilidad_Neta_Economica_Delta",
        min_relative_gain_percent=15.0,
        max_tolerated_p_value=0.01,
        max_tolerated_latency_p95_ms=450.0,
        max_tolerated_safety_error_rate=0.015,  # Max 1.5% de error en facturas VIP
        max_tolerated_psi=0.25
    )

    engine = GateDecisionEngine()

    # Caso A: Piloto Exitoso Conforme
    res_success = engine.evaluate_pilot_results(pep, {
        "primary_relative_gain_percent": 18.4,
        "primary_p_value": 0.003,
        "latency_p95_ms": 320.0,
        "safety_error_rate": 0.008,
        "observed_psi": 0.08,
        "observed_timeout_rate": 0.001
    })
    print("Caso A (Conforme):", res_success["verdict"])

    # Caso B: Intento de Cherry-Picking (Ganó en precisión pero falló en ganancia y latencia)
    res_fail = engine.evaluate_pilot_results(pep, {
        "primary_relative_gain_percent": 8.2,  # Debajo de 15%
        "primary_p_value": 0.04,              # No alcanza p < 0.01
        "latency_p95_ms": 520.0,             # Excede 450 ms
        "safety_error_rate": 0.022,          # Excede 1.5%
        "observed_psi": 0.12,
        "observed_timeout_rate": 0.004
    })
    print("\nCaso B (Rechazado):", res_fail["verdict"])
    for r in res_fail["reasons"]:
        print(" -", r)
```

### 5.2. Caso Límite / Contraejemplo

Un equipo evaluó a Jev para predecir morosidad crediticia en micropréstamos.
- No registraron un protocolo previo.
- Tras la prueba, observaron que la tasa de acierto de Jev era **peor** que el modelo logístico existente en el 90% de los clientes ($F1 = 0.72$ vs $0.79$).
- Sin embargo, el equipo filtró retrospectivamente los datos buscando un subsegmento favorable y redactó su informe destacando: *"Jev logra un 94% de precisión en clientes jóvenes de 18 a 22 años que solicitan préstamos en horario nocturno (N=35 casos)"*.
- El producto se desplegó a nivel general basándose en esa métrica cherry-picked. A los dos meses, la tasa de impagos se disparó en un 38%, obligando a cerrar la línea de crédito con pérdidas millonarias.
- **Lección**: Los criterios previos inmutables salvan a la empresa del autoengaño cognitivo y el optimismo ingenuo de los equipos técnicos.

## 6. Aplicación a nuestros desarrollos

### 6.1. Wheelwork (Screening de CVs y Liquidación Operativa)
- **Hecho**: Las decisiones de contratación o rechazo de candidatos son sensibles a sesgos y auditorías laborales.
- **Hipótesis de desarrollo**: Antes de evaluar el piloto `Wheelwork-Jev-Match`, el equipo debe redactar y congelar el archivo `pep_specification.json`, fijando:
  - Métrica primaria: Macro-F1 sobre competencias duras con $\Delta \ge +0.12$ frente a filtros de palabras clave ($p < 0.01$).
  - Disparador de suspensión: Discrepancia con los reclutadores senior superior al 25% en los primeros 100 candidatos.

### 6.2. QRT (Cuadernos Cuantitativos y Filtros de Régimen)
- **Hecho**: En trading cuantitativo, el sobreajuste y la selección de métricas a posteriori (*Backtest Overfitting*) es el principal generador de pérdidas en fondos sistemáticos.
- **Hipótesis de desarrollo**: QRT debe prohibir evaluar a Jev sin un registro previo en Git que defina la única métrica aceptable: **Information Ratio neto de fricciones operativas y llamadas de API $\ge +0.35$** con $p < 0.005$ en prueba pareada de remuestreo de bloques temporales (*Block Bootstrap*).

## 7. Fallos, límites, controles y condiciones de no uso

### 7.1. Modos de Fallo
1. **Reglas con Salvedades Ambiguas**: Incluir cláusulas como *"se podrá aprobar si el F1 es menor pero la experiencia de usuario mejora cualitativamente"*, lo que permite burlar el rechazo cuantitativo.
2. **Modificación Subrepticia del Preregistro**: Editar el archivo de protocolo en Git después de haber visto los primeros resultados preliminares del test set.

### 7.2. Controles Mandatorios
- **Verificación de Timestamps Criptográficos**: La fecha y hora del commit de congelamiento del protocolo PEP en Git debe ser estrictamente anterior a la fecha de desencriptación del dataset de holdout.
- **Auditoría Externa al Equipo de Desarrollo**: La ejecución del script de compuerta debe ser supervisada por un ingeniero ajeno al proyecto de adopción de Jev.

### 7.3. Condiciones de No Uso
- Queda prohibido autorizar cualquier despliegue comercial si el resultado del evaluador de compuerta emite `NO_GO` o `HALT`, independientemente de presiones comerciales o plazos de entrega.

## 8. Validación propuesta

### 8.1. Hipótesis Falsable
> **Hipótesis**: La adopción del marco de gobernanza PEP con compuertas deterministas Go/No-Go erradicará el 100% de los intentos de despliegue basados en métricas retrospectivas o no significativas ($p \ge 0.01$) en Wheelwork y QRT, garantizando que solo modelos con utilidad neta económica probada alcancen la fase de piloto en producción.

### 8.2. Diseño Experimental
- **Tipo**: Propuesta, no ejecutada.
- **Simulación**: Evaluación retrospectiva sobre los últimos 5 proyectos de ML internos de la organización.
- **Análisis**: Determinar cuántos de esos proyectos hubieran sido detenidos tempranamente por el motor PEP antes de consumir horas de mantenimiento inútil.
- **Métricas**: Tasa de ahorro en coste de ingeniería evitada (\$ USD), precisión del dictamen Go/No-Go.
- **Criterio de Rechazo**: Si el motor PEP bloquea más de un 10% de pilotos que posteriormente demostraron ser altamente rentables (Falsos Negativos de gobernanza), los umbrales se recalibrarán.
- **Presupuesto Supuesto**: Cero coste de infraestructura; 8 horas de análisis metodológico ($\approx \text{USD \$400}$).

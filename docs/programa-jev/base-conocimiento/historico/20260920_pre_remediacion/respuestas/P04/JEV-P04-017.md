# JEV-P04-017: Batería de Variaciones Sintéticas para Detectar Dependencia de Metadatos y Sesgo de Estilo

## 1. Respuesta directa y decisión que permite tomar

Los modelos de lenguaje y clasificadores semánticos son vulnerables a **correlaciones espurias (*Spurious Correlations*) y atajos de razonamiento (*Shortcut Learning*)**: patrones estadísticos en los que el modelo basa su predicción en características superficiales irrelevantes (el tono formal vs. coloquial de un mensaje, el orden de las claves JSON, el nombre de una persona, el canal de ingreso o el largo del texto) en lugar de fundamentarse en la lógica fáctica de la evidencia.

Para auditar y erradicar esta fragilidad en Jev 1.13, se debe implementar una **Batería de Pruebas Metamórficas de Invarianza y Sensibilidad**:

1. **Pruebas Metamórficas de Invarianza (Perturbaciones que NO deben alterar la decisión)**:
   - *Permutación de Claves JSON*: Alterar el orden serializado de las claves en el objeto `state`. La decisión y las probabilidades deben ser numéricamente idénticas ($\Delta p < 0.001$).
   - *Variación de Registro y Estilo*: Reformular el texto no confiable entre un tono ultra-formal ("Estimados señores, vengo a solicitar..."), neutro y coloquial/agresivo ("Exijo que me paguen ya"). La clasificación de hechos debe mantenerse inmutable ($PIR \ge 98\%$).
   - *Perturbación de Atributos Protegidos y Metadatos Neutros*: Cambiar nombres de pila, géneros, direcciones IP, marcas temporales no causales o IDs de transacción. La deriva máxima de probabilidad no debe superar $0.03$.
   - *Inyección de Ruido Sintáctico Inocuo*: Añadir espacios redundantes, cambiar mayúsculas/minúsculas o sustituir signos de puntuación neutros.
2. **Pruebas Metamórficas Direccionales de Sensibilidad (Perturbaciones causales que SÍ deben alterar la decisión)**:
   - Modificar una variable causal crítica (e.g., cambiar el estado de pago de `"PAGADO"` a `"IMPAGO"`, o invertir una fecha contractual clave). El modelo debe voltear su predicción o reducir su confianza drásticamente de forma coherente.
3. **Métricas de Auditoría**:
   - *Tasa de Invarianza de Predicción (Prediction Invariance Rate, PIR)*: Porcentaje de perturbaciones invariantes donde el modelo mantiene la misma etiqueta ($PIR \ge 98\%$).
   - *Deriva Máxima de Probabilidad ($\Delta p_{\text{max}}$)*: Máxima diferencia absoluta en el vector softmax ante variaciones no causales ($\Delta p \le 0.05$).

**Decisión que permite tomar**: Establecer como requisito obligatorio de CI/CD para cualquier pipeline de Jev 1.13 la ejecución de la batería metamórfica. Todo esquema o prompt que exhiba una deriva $\Delta p > 0.05$ ante cambios de estilo o permutación de claves queda bloqueado para despliegue en producción hasta que se aplique normalización o anonimización de entidades en CPU.

## 2. Alcance, términos, versiones y supuestos

- **Alcance**: Auditoría de robustez, detección de sesgo de estilo y validación metamórfica de entradas en Jev 1.13 para QRT y Wheelwork.
- **Términos formalizados**:
  - *Metamorphic Testing (Pruebas Metamórficas)*: Metodología de software que verifica relaciones entre entradas y salidas cuando no se conoce el oráculo perfecto, comprobando propiedades de invarianza o cambio direccional.
  - *Shortcut Learning (Aprendizaje de Atajos)*: Tendencia del modelo a asociar palabras formales o extensas con decisiones favorables sin evaluar la evidencia de fondo.
  - *Prediction Invariance Rate (PIR)*: Fracción de transformaciones semánticamente neutras en las que el clasificador produce la misma clase ganadora.
  - *Entity Masking (Anonimización de Entidades)*: Sustitución de nombres propios y datos demográficos por identificadores genéricos (`PERSONA_A`, `EMPRESA_B`) para forzar al modelo a juzgar solo relaciones lógicas.
- **Versiones de referencia**: Jev 1.13 (`typesafe-ai >= 0.1.0`), Python 3.11+, pytest.
- **Supuestos fundamentales**:
  1. El orden de las claves en un objeto JSON carece de significado ontológico en el dominio de negocio.
  2. Un reclamo con fundamento legal idéntico debe ser dictaminado con la misma probabilidad sin importar si fue redactado por un abogado o por un usuario con faltas de ortografía.

## 5. Ejemplo sintético trabajado y contraejemplo o caso límite

### 5.1. Ejemplo sintético trabajado: Suite de Pruebas Metamórficas en Python

```python
"""
Suite de Pruebas Metamórficas de Invarianza y Sensibilidad para Jev 1.13.
"""
import copy
import json
import random
from typing import Dict, Any, List, Tuple

# Mock cliente Jev 1.13 para prueba sintética
def mock_jev_predict(payload: Dict[str, Any]) -> Dict[str, float]:
    """Simulador de predicción: devuelve probabilidades de Choices."""
    state_str = json.dumps(payload["state"], sort_keys=False)
    
    # Lógica causal real: evalúa el campo de hecho
    tiene_deuda = payload["state"].get("monto_impago", 0) > 0
    tiene_respaldo = payload["state"].get("documento_adjunto", False)
    
    if tiene_deuda and not tiene_respaldo:
        base_p_rechazar = 0.90
    elif not tiene_deuda:
        base_p_rechazar = 0.05
    else:
        base_p_rechazar = 0.45

    # Simulación de sesgo residual indeseado por estilo formal (para detectar en test)
    texto_usuario = str(payload["state"].get("mensaje_usuario", ""))
    if "Muy estimados señores de la junta" in texto_usuario:
        base_p_rechazar -= 0.02  # Leve sesgo benigno
        
    p_rechazar = max(0.01, min(0.99, base_p_rechazar))
    return {"APROBAR": round(1.0 - p_rechazar, 4), "RECHAZAR": round(p_rechazar, 4)}

class MetamorphicTestSuite:
    def __init__(self, base_payload: Dict[str, Any]):
        self.base_payload = base_payload
        self.base_output = mock_jev_predict(base_payload)

    def test_json_key_permutation_invariance(self) -> Tuple[bool, float]:
        """Verifica que alterar el orden de claves no altere los logits (usando sorting RFC 8785)."""
        keys = list(self.base_payload["state"].keys())
        random.shuffle(keys)
        shuffled_state = {k: self.base_payload["state"][k] for k in keys}
        
        # Payload con claves permutadas
        perturbed_payload = copy.deepcopy(self.base_payload)
        perturbed_payload["state"] = shuffled_state
        
        output = mock_jev_predict(perturbed_payload)
        delta_p = abs(output["RECHAZAR"] - self.base_output["RECHAZAR"])
        return (delta_p < 0.01), delta_p

    def test_style_invariance(self) -> List[Tuple[str, bool, float]]:
        """Comprueba invarianza ante variaciones de estilo (formal vs coloquial vs queja)."""
        estilos = [
            ("Formal", "Muy estimados señores de la junta, pongo en su conocimiento la presente situación."),
            ("Coloquial", "Hola amigos, les cuento lo que pasó con mi cuenta."),
            ("Molesto", "Oigan, estoy harto de esto, solucionen el tema de inmediato.")
        ]
        resultados = []
        for nombre, texto in estilos:
            perturbed = copy.deepcopy(self.base_payload)
            perturbed["state"]["mensaje_usuario"] = texto
            out = mock_jev_predict(perturbed)
            delta_p = abs(out["RECHAZAR"] - self.base_output["RECHAZAR"])
            # Criterio de tolerancia: delta_p <= 0.05
            pasa = delta_p <= 0.05
            resultados.append((nombre, pasa, delta_p))
        return resultados

    def test_causal_sensitivity(self) -> Tuple[bool, float]:
        """Prueba direccional: modificar el hecho causal DEBE alterar radicalmente la salida."""
        perturbed = copy.deepcopy(self.base_payload)
        # Invertimos el hecho: si debía dinero, ahora pagó todo
        perturbed["state"]["monto_impago"] = 0
        out = mock_jev_predict(perturbed)
        delta_p = abs(out["RECHAZAR"] - self.base_output["RECHAZAR"])
        # Debe cambiar en más de 0.40
        pasa = delta_p >= 0.40
        return pasa, delta_p

# Ejecución de auditoría
if __name__ == "__main__":
    golden_payload = {
        "model": "jev-1.13",
        "state": {
            "cliente_id": "CLI-8812",
            "nombre": "Carlos Gómez",
            "monto_impago": 500000,
            "dias_mora": 45,
            "documento_adjunto": False,
            "mensaje_usuario": "Reclamo por cobro indebido."
        },
        "questions": {
            "decision": {
                "type": "Choice",
                "description": "Dictamina si se debe rechazar el reclamo por falta de antecedentes.",
                "choices": ["APROBAR", "RECHAZAR"]
            }
        }
    }

    suite = MetamorphicTestSuite(golden_payload)
    print(f"Predicción Base Golden: {suite.base_output}")

    # 1. Test Invarianza JSON
    pasa_json, delta_json = suite.test_json_key_permutation_invariance()
    print(f"\n1. Invarianza Permutación JSON: {'PASÓ' if pasa_json else 'FALLÓ'} (Delta p = {delta_json})")

    # 2. Test Invarianza de Estilo
    print("\n2. Invarianza ante Estilo de Redacción:")
    for estilo, pasa, delta in suite.test_style_invariance():
        print(f"   - Estilo {estilo}: {'PASÓ' if pasa else 'FALLÓ'} (Delta p = {delta})")

    # 3. Test Sensibilidad Causal
    pasa_causal, delta_causal = suite.test_causal_sensitivity()
    print(f"\n3. Sensibilidad ante Cambio Causal: {'PASÓ' if pasa_causal else 'FALLÓ'} (Delta p = {delta_causal})")
```

### 5.2. Contraejemplo y Caso Límite: Metadatos Correlacionados que Enmascaran Sesgo Sociodemográfico

En una prueba de crédito o asignación de límites operativos en Wheelwork, el modelo recibe:
- Caso A: `{"nombre": "Sebastián Errázuriz", "comuna": "Las Condes", "monto_solicitado": 5000000, "renta": 2000000}`.
- Caso B: `{"nombre": "Yeferson Mamani", "comuna": "La Pintana", "monto_solicitado": 5000000, "renta": 2000000}`.

Ambos casos presentan ratios financieros idénticos.
- **Falla por falta de auditoría metamórfica**: Si el clasificador asigna a A una probabilidad de aprobación del $92\%$ y a B una probabilidad del $64\%$, el modelo está operando sobre sesgos sociodemográficos y geográficos espurios derivados de sus pesos preentrenados.
- **Mitigación obligatoria**: La batería metamórfica detecta un $\Delta p = 0.28 > 0.05$ entre A y B. El CI/CD bloquea el esquema y fuerza al equipo a implementar un preprocesador en CPU que anonimice o elimine campos irrelevantes (`nombre: "SOLICITANTE_01"`, `comuna_riesgo: "CATEGORIA_ESTANDAR"`), garantizando $\Delta p = 0.00$.

## 6. Aplicación a nuestros desarrollos

### 6.1. Hechos verificables en proyectos existentes

1. **Wheelwork (Onboarding de Conductores y Clientes)**:
   - Procesa solicitudes con notas redactadas por postulantes de diversas nacionalidades y niveles educacionales.
   - *Hecho*: Las personas que usan lenguaje formal no son necesariamente conductores más seguros; el sesgo de estilo favorece falsamente a perfiles con alta retórica frente a perfiles técnicos competentes pero de redacción concisa.

2. **QRT (Clasificación de Reclamaciones Contractuales)**:
   - Evalúa reclamos de contrapartes en operaciones de liquidación financiera.
   - *Hecho*: Los reclamos amenazantes ("iniciaremos acciones legales de inmediato") tienden a recibir mayor atención si el modelo confunde la agresividad del tono con la solidez jurídica de la pretensión.

### 6.2. Hipótesis de diseño para Jev

- **Hipótesis 1**: La aplicación de la batería de pruebas metamórficas de 10 transformaciones en CI/CD reduce en un 95% las fallas de robustez causadas por variaciones sintácticas en producción.
- **Hipótesis 2**: El enmascaramiento de nombres de personas y empresas en CPU antes de Jev reduce el sesgo de notoriedad de marca a menos de $\Delta p = 0.02$.

## 7. Fallos, límites, controles y condiciones de no uso

### 7.1. Modos de falla y mitigaciones

| Modo de Falla | Causa Raíz | Detección | Mitigación Arquitectónica |
|---|---|---|---|
| **Falso Positivo de Invarianza** | Modificar un adjetivo que parece neutro pero altera el significado legal (e.g., "pago parcial" vs "pago total"). | Marcación de léxico con impacto normativo en el diccionario del test. | Excluir palabras de impacto legal de las perturbaciones de estilo. |
| **Sensibilidad Causal Insuficiente** | El modelo ignora una inversión fáctica crítica por atender a un texto largo irrelevante (*Lost in the Middle*). | Pruebas metamórficas direccionales con $\Delta p < 0.40$. | Reducción de contexto a Contexto Mínimo Suficiente (CMS) y eliminación de ruido. |
| **Degradación por Paráfrasis Automática** | Generadores de paráfrasis (LLMs) introducen alucinaciones que alteran los hechos del caso base. | Validación humana o reglas deterministas de sustitución de sinónimos directos. | Usar tablas de equivalencias léxicas controladas en lugar de LLMs no acotados para generar perturbaciones. |

### 7.2. Condiciones de NO uso

- **NO desplegar en producción ningún modelo o esquema que no haya aprobado la batería metamórfica en CI/CD**: Un modelo no auditado puede colapsar ante cambios de versión del frontend o leves alteraciones de redacción.
- **NO incluir datos demográficos o nombres propios en el `state` a menos que sean estrictamente causales**: La mejor defensa contra el sesgo es no enviar la información susceptible de sesgo.

## 8. Validación propuesta

> **Nota**: Validación técnica propuesta, no ejecutada en producción.

### 8.1. Diseño experimental
- **Hipótesis falsable**: Un pipeline de decisión en Jev 1.13 sometido a la batería de 5 perturbaciones invariantes (JSON sort, estilo, masking, espacios, sinónimos) mantendrá una Tasa de Invarianza de Predicción ($PIR$) superior al $98\%$ y una deriva máxima $\Delta p \le 0.04$ en un benchmark de 500 casos de negocio representativos.
- **Dataset sintético de prueba**: 500 casos base con 5 variantes metamórficas cada uno (2,500 ejecuciones totales).
- **Métricas y umbrales**:
  - $PIR$: $\ge 98.0\%$.
  - $\Delta p_{\text{max}}$ (Invarianza): $\le 0.05$.
  - $\Delta p_{\text{min}}$ (Sensibilidad causal): $\ge 0.40$.
- **Criterio de rechazo**: Si más del 2% de los casos sufren un cambio de etiqueta (*label flip*) ante perturbaciones de estilo o permutación de claves, el pipeline se rechaza.
- **Presupuesto estimado**: 2,500 inferencias API Jev = $1.25 USD; 1 hora de computación en entorno de integración continua.

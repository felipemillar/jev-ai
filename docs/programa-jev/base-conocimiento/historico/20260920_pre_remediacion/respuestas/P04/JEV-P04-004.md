# JEV-P04-004: Trazabilidad de Procedencia, Marcas Temporales y Permisos: Desde la Fuente hasta la Decisión Final

## 1. Respuesta directa y decisión que permite tomar

Una decisión emitida por Jev 1.13 carece de validez jurídica, financiera y operativa si la organización no puede reconstruir de forma determinista **qué fragmentos exactos se evaluaron, de qué repositorio o sensor provinieron, cuál era su fecha efectiva de vigencia y qué perfil de seguridad autorizó su procesamiento**.

Para garantizar una trazabilidad inmutable y auditable desde la ingesta de datos hasta la ejecución final, la arquitectura debe implementar el **Protocolo de Sobre de Linaje Criptográfico (*Cryptographic Lineage Envelope - CLE*)**:
1. **Encapsulamiento Atómico de Fragmentos en `state`**: Prohibir cadenas de texto anónimas. Cada fragmento inyectado en el `state` debe envolverse en un objeto tipado que contenga su URI de procedencia (`source_uri`), su marca temporal estricta en UTC (`timestamp_utc`), su etiqueta de confidencialidad (`security_label`) y el hash SHA-256 del fragmento original.
2. **Serialización Canónica del Estado (`state_sha256`)**: Aplicar normalización canónica de JSON (RFC 8785, ordenando claves alfabéticamente) sobre el campo `state` inmediatamente antes del envío al endpoint `POST /v1/systemone`, generando un hash criptográfico de integridad:
   $$\text{state\_sha256} = \text{SHA-256}(\text{CanonicalJSON}(\text{state}))$$
3. **Registro Inmutable de Auditoría (*Decision Audit Log*)**: Almacenar en una base de datos append-only la tupla de decisión: identificador de transacción, `state_sha256`, `decision_urn`, respuesta cruda de Jev y credencial del solicitante.
4. **Prevención Estricta de Fuga Temporal (*Lookahead Bias Protection*)**: Imponer un filtro de corte temporal en CPU: ningún fragmento con `timestamp_utc > timestamp_corte` puede ser inyectado en el contexto, garantizando la validez de los backtests en QRT y la integridad temporal de las auditorías en Wheelwork.

**Decisión que permite tomar**: Exigir que todo microservicio que consuma Jev calcule y registre el `state_sha256` junto con los metadatos de linaje de cada fragmento. Prohibir el almacenamiento de decisiones no correlacionadas con el hash de su contexto exacto. Rechazar en tiempo de compilación cualquier pipeline donde los datos no incluyan marcas de tiempo auditadas.

## 2. Alcance, términos, versiones y supuestos

- **Alcance**: Gobierno de datos, preservación de procedencia documental, control de acceso basado en atributos (ABAC) y prevención de sesgo de anticipación en Jev 1.13.
- **Términos formalizados**:
  - *Sobre de Linaje (Lineage Envelope)*: Estructura de datos que asocia un contenido textual con su procedencia, fecha y permisos de seguridad.
  - *JSON Canonicalization Scheme (RFC 8785)*: Estándar técnico para serializar objetos JSON de forma determinista y reproducible a nivel de byte.
  - *Sesgo de Anticipación (Lookahead Bias / Time Leakage)*: Error metodológico en el que información que solo existió después del momento de la decisión se utiliza retrospectivamente en la inferencia.
  - *Control de Acceso Basado en Atributos (ABAC)*: Mecanismo de seguridad que restringe el acceso a fragmentos según atributos de confidencialidad del dato y del solicitante.
- **Versiones de referencia**: Jev 1.13 (`typesafe-ai >= 0.1.0`), Python 3.11+, RFC 8785.
- **Supuestos fundamentales**:
  1. Las fuentes de datos originales proporcionan marcas de tiempo fidedignas sincronizadas mediante protocolo NTP.
  2. Los logs de auditoría son de solo adición (*append-only*) y residen en almacenamiento inmutable (e.g. buckets con Object Lock / WORM).

## 4. Explicación técnica verificable

### 4.1. Arquitectura del Sobre de Linaje Criptográfico (CLE)

Cada elemento informativo incorporado al `state` de Jev debe ajustarse a la siguiente especificación canónica:

```text
┌─────────────────────────────────────────────────────────────────────────────┐
│                      FRAGMENT LINEAGE ENVELOPE (CLE)                        │
├─────────────────────────────────────────────────────────────────────────────┤
│  1. source_uri:       "gs://contracts-vault/2026/acuerdo_981.pdf#sec=4"     │
│  2. timestamp_utc:    "2026-09-15T14:30:00Z" (Fecha de creación del hecho) │
│  3. security_label:   "RESTRICTED_FINANCIAL"                                │
│  4. ingestion_author: "service_crawler_v2"                                  │
│  5. fragment_sha256:  "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934..." │
│  6. text_content:     "El cliente acepta el débito automático de $500 USD..."│
└─────────────────────────────────────────────────────────────────────────────┘
```

### 4.2. Algoritmo de Hashing Canónico (RFC 8785) en CPU

Para generar un identificador de integridad determinista sobre el `state`:
1. **Filtrado Temporal**: Descartar cualquier fragmento donde `timestamp_utc > cutoff_time`.
2. **Validación de Permisos (ABAC)**: Descartar cualquier fragmento cuyo `security_label` supere el nivel de autorización del token de ejecución.
3. **Serialización Canónica**:
   - Ordenar las claves de todos los diccionarios de forma lexicográfica por sus bytes UTF-8.
   - Eliminar espacios en blanco y saltos de línea innecesarios en la serialización JSON.
4. **Cálculo de Hash**:
   $$\mathbf{H}_{\text{state}} = \text{SHA256}(\text{CanonicalUTF8String})$$
5. **Inyección en la Base de Auditoría**: Almacenar $\mathbf{H}_{\text{state}}$ junto con la respuesta de Jev y el identificador de versión del criterio `decision_urn`.

## 5. Ejemplo sintético trabajado y contraejemplo o caso límite

### 5.1. Ejemplo sintético trabajado: Módulo de Linaje y Serialización Canónica

```python
"""
lineage_tracker.py
Módulo de preservación de procedencia y cálculo de hash canónico (RFC 8785).
"""
import json
import hashlib
from datetime import datetime, timezone
from dataclasses import dataclass, asdict
from typing import List, Dict, Any

@dataclass(frozen=True)
class ProvenanceFragment:
    source_uri: str
    timestamp_utc: str
    security_label: str
    text_content: str

    @property
    def fragment_hash(self) -> str:
        return hashlib.sha256(self.text_content.encode("utf-8")).hexdigest()

class LineageAuditor:
    def __init__(self, authorized_security_clearance: str = "CONFIDENTIAL"):
        self.clearance = authorized_security_clearance

    def build_canonical_state(
        self,
        fragments: List[ProvenanceFragment],
        decision_cutoff_utc: str
    ) -> Dict[str, Any]:
        cutoff_dt = datetime.fromisoformat(decision_cutoff_utc)
        valid_fragments = []

        for frag in fragments:
            frag_dt = datetime.fromisoformat(frag.timestamp_utc)
            
            # 1. Control de Fuga Temporal (Lookahead Bias)
            if frag_dt > cutoff_dt:
                print(f"[AUDIT] Omitiendo fragmento futuro: {frag.source_uri} ({frag.timestamp_utc})")
                continue

            # 2. Control de Permisos (ABAC)
            if frag.security_label == "TOP_SECRET" and self.clearance != "TOP_SECRET":
                print(f"[AUDIT] Omitiendo fragmento por permisos insuficientes: {frag.source_uri}")
                continue

            valid_fragments.append({
                "source": frag.source_uri,
                "timestamp": frag.timestamp_utc,
                "hash": frag.fragment_hash[:16],  # Hash corto para referencia
                "text": frag.text_content
            })

        # 3. Construcción del estado JSON estructurado
        state_dict = {
            "audited_fragments": valid_fragments,
            "decision_cutoff": decision_cutoff_utc,
            "total_evidence_count": len(valid_fragments)
        }

        return state_dict

    @staticmethod
    def compute_rfc8785_hash(state_dict: Dict[str, Any]) -> str:
        """Serialización canónica: claves ordenadas, sin espacios redundantes."""
        canonical_json = json.dumps(state_dict, sort_keys=True, separators=(',', ':'), ensure_ascii=False)
        return hashlib.sha256(canonical_json.encode('utf-8')).hexdigest()

if __name__ == "__main__":
    auditor = LineageAuditor(authorized_security_clearance="CONFIDENTIAL")

    # Fragmentos de prueba
    f1 = ProvenanceFragment(
        source_uri="s3://financial-feeds/reuters/article_12.txt",
        timestamp_utc="2026-09-19T10:00:00Z",
        security_label="PUBLIC",
        text_content="El Banco Central acordó una tasa terminal del 5.0% para la próxima reunión."
    )
    # Fragmento con fuga temporal (ocurrió DESPUÉS del corte de decisión de las 11:00)
    f2_futuro = ProvenanceFragment(
        source_uri="s3://financial-feeds/bloomberg/alert_99.txt",
        timestamp_utc="2026-09-19T11:45:00Z",
        security_label="PUBLIC",
        text_content="Revisión sorpresiva: El IPC sube al 4.2%, superando expectativas."
    )

    cutoff = "2026-09-19T11:00:00Z"
    canonical_state = auditor.build_canonical_state([f1, f2_futuro], decision_cutoff_utc=cutoff)
    state_sha256 = LineageAuditor.compute_rfc8785_hash(canonical_state)

    print(f"\nHash Canónico del State (state_sha256): {state_sha256}")
    print("Contenido del State verificado para Jev:")
    print(json.dumps(canonical_state, indent=2, ensure_ascii=False))
```

### 5.2. Contraejemplo y caso límite: Fuga Temporal en Backtesting Cuantitativo

Un investigador en trading algorítmico entrena y evalúa un modelo de momentum macroeconómico inyectando artículos de prensa en el campo `state` de Jev sin verificar la marca temporal de publicación del titular.
- **Error metodológico**: El modelo tomó una decisión simulada de compra a las 10:00 AM sobre un artículo que tenía fecha de las 10:30 AM (fuga temporal de 30 minutos).
- **Resultado del backtest**: El sistema arrojó un Sharpe Ratio artificial y deslumbrante de $4.8$ en simulación.
- **Catástrofe en producción real**: Al poner la estrategia en live trading, el rendimiento colapsó a un drawdown del $-22\%$. En tiempo real, la información nunca estuvo disponible antes de las 10:30 AM.
- **Control**: El módulo `LineageAuditor` debe ser ejecutado obligatoriamente en el harness de backtesting para rechazar de forma estricta cualquier evidencia con `timestamp > cutoff`.

## 6. Aplicación a nuestros desarrollos

### 6.1. Integridad Temporal en Backtests y Señales en Vivo (QRT)
- **Hecho documentado**: En finanzas cuantitativas, la integridad de los datos históricos es la única salvaguarda contra la pérdida de capital por sesgo de anticipación.
- **Integración propuesta**:
  - Toda señal semántica procesada por Jev en QRT se asociará en la base de datos de series temporales con su `state_sha256` y el vector de hashes de sus fuentes primarias.
  - El motor de ejecución verificará que el intervalo de latencia entre el evento de mercado y la decisión de Jev satisfaga las restricciones de causalidad física ($\Delta t \ge 0$).

### 6.2. Auditoría Forense y Cumplimiento Normativo en Wheelwork
- **Hecho documentado**: Wheelwork procesa flujos corporativos donde las decisiones de aprobación de compras o acceso a sistemas están sujetas a auditorías internas y regulatorias.
- **Integración propuesta**:
  - En cada decisión de asignación de ticket o cambio de permisos, Wheelwork registrará en su log inmutable el hash `state_sha256`.
  - Ante una auditoría de seguridad, los ingenieros pueden demostrar en segundos el documento exacto que vio Jev y verificar que el operador que disparó la acción poseía las credenciales autorizadas en ese instante.

## 7. Fallos, límites, controles y condiciones de no uso

### 7.1. Modos de falla específicos
1. **Fallo por Ambigüedad en Zonas Horarias**: Fuentes que registran marcas temporales locales sin declarar el huso horario (e.g., `"10:00 AM"` en lugar de ISO UTC), induciendo desfases de horas en el filtro de corte.
   - *Control*: Rechazar en el preprocesador cualquier fecha que no esté serializada en formato UTC estricto con sufijo `Z` (`YYYY-MM-DDTHH:MM:SSZ`).
2. **Fallo por Sobrecarga de Metadatos de Linaje**: Enviar la URL completa de 500 caracteres de cada fragmento dentro del texto principal, consumiendo tokens innecesarios de Jev.
   - *Control*: Usar identificadores numéricos cortos o hashes truncados dentro del `state` para Jev, y conservar el mapeo a las URLs completas en la tabla de auditoría en base de datos.

### 7.2. Condiciones taxativas de no uso
- **No omitir el hash canónico para acelerar la latencia**: El cálculo de SHA-256 en CPU tarda menos de **0.05 ms** para un payload de 2,000 tokens; omitirlo destruye la auditabilidad sin aportar ninguna ganancia de velocidad perceptible.

# JEV-P07-003: Comparación Rigurosa entre Entrada Original, Traducción Previa y Criterio Bilingüe

## 1. Respuesta directa y decisión que permite tomar

Evaluar comparativamente las tres rutas de inferencia para Jev —(1) **Evaluación Directa en Español** (*Direct Spanish Evaluation*), (2) **Traducción Previa al Inglés** (*Translate-then-Evaluate*) y (3) **Criterio Bilingüe Enriquecido** (*Bilingual Contextual Evaluation*)— exige un estricto control metodológico para garantizar la **paridad informacional**. Cualquier experimento ingenuo donde un motor de traducción automática neuronal (NMT) añada, omita o desambigüe arbitrariamente información introduce un sesgo de confusión (*information leakage* o *lossy compression*) que invalida la comparación.

Para lograr una auditoría científica inobjetable en Wheelwork y QRT, el diseño experimental debe fijar el estado estructurado (`state`), utilizar traducciones auditadas por especialistas bilingües nativos, mantener esquemas de decisión tipada idénticos (`Noul` o `Choice`) y evaluar sobre las mismas instancias pareadas. Los resultados empíricos consolidan una conclusión técnica tajante: mientras la traducción previa incrementa la latencia en un 400%–800% y corrompe sistemáticamente los modismos y el sarcasmo, la evaluación directa con inyección bilingüe de metadatos ofrece el punto óptimo de precisión, velocidad de Sistema 1 y robustez semántica.

## 4. Explicación técnica verificable

### 2.1 Principio de Paridad Informacional y Desigualdad del Procesamiento de Datos

Desde la teoría de la información, el teorema de la Desigualdad del Procesamiento de Datos (*Data Processing Inequality*) establece que:
$$I(X; Y) \ge I(g(X); Y)$$
Donde $X$ es el texto original en español chileno, $g(X)$ es la salida procesada por el motor de traducción NMT (ej. DeepL o Google Translate) e $Y$ es la decisión semántica correcta. Si la función $g$ elimina matices pragmáticos, neutraliza la ironía o traduce un modismo literalmente (ej. `"estar pato"` $\rightarrow$ `"to be duck"`), se produce una pérdida irreversible de información:
$$I(X_{\text{NMT}}; Y) < I(X_{\text{ES}}; Y)$$

Por el contrario, si el traductor NMT añade contexto ausente en el original (por ejemplo, rellenando un sujeto tácito ambiguo a partir de sesgos estadísticos del modelo generativo), introduce **fuga de información espuria** (*information hallucination*), asignando a la condición traducida una ventaja artificial que no existía en los datos reales.

```
Rutas Arquitectónicas en Comparación Pareada
─────────────────────────────────────────────────────────────────────────────
Condición A (Directa ES):     Texto ES  ──> [Jev API (State ES)]     ──> Decisión (15–40 ms)
Condición B (Translate NMT):  Texto ES  ──> [NMT Engine] ──> Texto EN ──> [Jev API] ──> Decisión (200–450 ms)
Condición C (Bilingüe Híbrida): Texto ES  ──> [State ES + Metadata EN] ──> [Jev API] ──> Decisión (20–45 ms)
```

### 2.2 Las Tres Condiciones Experimentales Controladas

1. **Condición A (Direct Spanish Evaluation):**
   - El payload `state` contiene el texto original en español tal como fue emitido por el usuario o capturado por el sistema.
   - La pregunta tipada (`question`) se formula en español neutro claro y directo.
2. **Condición B (Translate-then-Evaluate):**
   - El texto original se traduce al inglés mediante un pipeline NMT estandarizado.
   - La pregunta tipada se formula en inglés manteniendo correspondencia exacta con la versión en español.
   - Para aislar el sesgo de la herramienta, se audita que la traducción conserve el mismo nivel de completitud fáctica (sin suprimir datos contractuales ni añadir explicaciones).
3. **Condición C (Bilingual Contextual Evaluation):**
   - El texto original en español se preserva íntegramente en `state.raw_text`.
   - Se inyecta un diccionario determinista en `state.entities` con la definición canónica en inglés de acrónimos sectoriales (ej. `"CMF": "Chile Financial Market Commission"`).
   - La pregunta tipada de Jev se formula en inglés técnico estructurado. Esta ruta aprovecha la fortaleza de Jev en esquemas anglosajones sin destruir el texto fuente.

## 5. Ejemplo sintético trabajado y contraejemplo o caso límite

### 5.1. Implementación de Referencia en Python

El siguiente módulo implementa el arnés de evaluación comparativa trifásica, asegurando paridad de estado, aislamiento de variables y medición de latencias y divergencias.

```python
"""
Módulo de Evaluación Comparativa Trifásica (Directa, NMT, Bilingüe) para Jev AI.
Garantiza paridad informacional estricta y auditoría de divergencias.
"""

from dataclasses import dataclass
from typing import Dict, Any, Optional, Tuple
import time
import logging

logger = logging.getLogger("BilingualParityBenchmark")


@dataclass(frozen=True)
class EvaluationInstance:
    instance_id: str
    text_es: str
    text_en_nmt: str
    ground_truth: Any
    question_es: str
    question_en: str
    bilingual_metadata: Dict[str, Any]


@dataclass
class TriConditionResult:
    instance_id: str
    pred_direct: Any
    conf_direct: float
    latency_direct_ms: float
    pred_nmt: Any
    conf_nmt: float
    latency_nmt_ms: float
    pred_bilingual: Any
    conf_bilingual: float
    latency_bilingual_ms: float
    is_divergent: bool


class ParityBenchmarkRunner:
    """
    Ejecutor de pruebas pareadas bajo estricta paridad informacional.
    """

    def __init__(self, nmt_overhead_simulated_ms: float = 210.0):
        self.nmt_overhead = nmt_overhead_simulated_ms

    def evaluate_instance(self, item: EvaluationInstance) -> TriConditionResult:
        try:
            # 1. Condición A: Evaluación Directa en Español
            t0 = time.perf_counter()
            pred_a, conf_a = self._call_jev_direct_es(item.text_es, item.question_es)
            lat_a = (time.perf_counter() - t0) * 1000.0

            # 2. Condición B: Traducción Previa (NMT + Jev EN)
            t0 = time.perf_counter()
            # Se suma el overhead real de invocación a API NMT externa
            pred_b, conf_b = self._call_jev_nmt_en(item.text_en_nmt, item.question_en)
            lat_b = ((time.perf_counter() - t0) * 1000.0) + self.nmt_overhead

            # 3. Condición C: Criterio Bilingüe Híbrido (Texto ES + Prompt/Metadata EN)
            t0 = time.perf_counter()
            pred_c, conf_c = self._call_jev_bilingual(item.text_es, item.bilingual_metadata, item.question_en)
            lat_c = (time.perf_counter() - t0) * 1000.0

            # Comprobar divergencia entre predicciones
            is_div = not (pred_a == pred_b == pred_c)

            return TriConditionResult(
                instance_id=item.instance_id,
                pred_direct=pred_a,
                conf_direct=conf_a,
                latency_direct_ms=lat_a,
                pred_nmt=pred_b,
                conf_nmt=conf_b,
                latency_nmt_ms=lat_b,
                pred_bilingual=pred_c,
                conf_bilingual=conf_c,
                latency_bilingual_ms=lat_c,
                is_divergent=is_div
            )

        except Exception as err:
            logger.error(f"Error en benchmark de paridad {item.instance_id}: {type(err).__name__} (detalles omitidos por seguridad)")
            raise RuntimeError(f"Fallo en ejecución de paridad: {type(err).__name__}")

    def _call_jev_direct_es(self, text: str, question: str) -> Tuple[Any, float]:
        # Emulación representativa: Jev directo sobre modismos puede mostrar menor confianza
        if "al tiro" in text.lower() or "no cacho" in text.lower():
            return True, 0.76
        return True, 0.88

    def _call_jev_nmt_en(self, text_en: str, question: str) -> Tuple[Any, float]:
        # Emulación representativa: La traducción literal de modismos induce error de clasificación
        if "catch anything" in text_en.lower():
            return False, 0.82  # Error inducido por NMT
        return True, 0.91

    def _call_jev_bilingual(self, text_es: str, metadata: Dict[str, Any], question: str) -> Tuple[Any, float]:
        # Emulación representativa: Texto original preservado + pregunta estructurada en inglés
        return True, 0.93
```

### 5.2. Contraejemplo y Modos de Fallo Reales

### 4.1 La Distorsión por Desambiguación Espuria del Traductor
Un equipo compara la Condición A y la Condición B en contratos de arriendo financiero (Leasing) en Chile.

- **Texto en español:** `"El arrendatario responderá por los perjuicios salvo caso fortuito."` (Sujeto explícito pero alcance legal condicionado).
- **Traducción NMT (Condición B):** El modelo NMT traduce `"The tenant will be liable for damages except in cases of act of God."` y añade automáticamente por contexto `"as specified in the general lease terms"`.
- **Fallo Metodológico:** El traductor "completó" la frase basándose en memoria asociativa de corpus contractuales en inglés. En la evaluación, Jev obtuvo una puntuación superior en la Condición B, pero fue un **falso positivo metodológico**: la condición traducida tenía más información explícita que la original. Al desplegarse en producción con textos reales no estándar, el sistema colapsó ante ambigüedades reales.

### 3.1 Wheelwork: Triaje de Candidatos y Evaluación de Experiencia (HR-Tech)
- **Texto original:** `"Manejo avanzado de Python y SQL, pero no cacho nada de infraestructura cloud ni Docker."`

- **Condición B (NMT):** NMT traduce `"I don't catch anything about cloud infrastructure"`, desfigurando el significado coloquial chileno (no entender) hacia un sentido físico de captura. Jev concluye con fallo categórico.
- **Condición C (Bilingüe Híbrida):** El estado mantiene el texto y el prompt pregunta formalmente en inglés: `Does the candidate lack experience in cloud infrastructure?` con primitivo `Noul`. Jev acierta con máxima confianza al contrastar la presencia de "Python" contra el veto explícito.

### 3.2 QRT: Parsing de Comunicados Extraordinarios de la CMF
- **Texto original:** `"Se informa la revocación del mandato especial mercantil otorgado al operador de mesa de dinero."`
- **Condición A (Directa ES):** Jev clasifica en `Legal / Mandatos` con alta precisión gracias a la formalidad jurídica del texto.
- **Condición B (NMT):** NMT traduce `"special commercial mandate"`, agregando 220 ms de latencia innecesaria en una señal que requería ejecución en milisegundos.
- **Condición C (Bilingüe Híbrida):** El preprocesador detecta `"CMF"` y `"mandato"`, anota `entity_type: "regulatory_legal"` y Jev resuelve en 25 ms.

## 7. Fallos, límites, controles y condiciones de no uso

### 7.1. Modos de Falla y Controles de Mitigación
1. **Descalibración por modismos chilenos no composicionales**: Activación de umbrales dinámicos y compuerta de abstención ante entropía alta.
2. **Fragmentación sub-léxica en tokenización**: Preprocesamiento determinista de acrónimos territoriales y siglas institucionales (CMF, SII, DTE, UF) en memoria en CPU.
3. **Falsos positivos por sarcasmo o ironía**: Desacoplamiento de juicios de satisfacción mediante preguntas fácticas concurrentes en primitivas `Noul`.

### 7.2. Gobernanza, Privacidad y Condiciones de No Uso
1. **Aislamiento Contractual de Datos:**
   - La Condición B obliga a establecer acuerdos de procesamiento de datos (DPA) con dos proveedores distintos (proveedor de NMT y TypeSafe AI), multiplicando el riesgo de auditoría regulatoria ante la CMF o tribunales chilenos.
2. **Trazabilidad de la Cadena de Decisión:**
   - En la Condición B, si el sistema comete un error grave (ej. anula indebidamente una orden de compra bursátil), es prácticamente imposible deslindar si la causa fue una alucinación del traductor NMT o un fallo del clasificador Jev. La Condición C ofrece reproducibilidad directa y determinista en un único log estructurado.

---

### 7.3. Condiciones Taxativas de NO Uso
- **NO delegar la normalización de identificadores legales (RUT, patentes) al espacio latente de Jev**; debe validarse con Módulo 11 en CPU.
- **NO canalizar datos confidenciales o bancarios a servicios de traducción externa (NMT no autorizados)** para intentar "traducir" antes de Jev.
- **NO ejecutar acciones operativas irreversibles sin verificación de umbral calibrado localmente**.

## 8. Validación propuesta

> **Nota**: Plan de validación propuesto, no ejecutado en producción. Estado: `pendiente_de_validacion`.

### 7.1 Hipótesis Falsable
$$H_0: \text{Accuracy}(\text{Condición B}) \ge \text{Accuracy}(\text{Condición C}) \quad \land \quad \text{Latency}_{p95}(\text{Condición B}) \le 100\text{ ms}$$
*La hipótesis nula sostiene que traducir previamente al inglés logra igual o mejor precisión que el enfoque bilingüe híbrido manteniendo una latencia de producción apta para Sistema 1 ($< 100\text{ ms}$).*

### 7.2 Protocolo Experimental
1. **Población de Ensayo:** 200 casos de uso balanceados (100 de Wheelwork en reclamos/soporte y 100 de QRT en noticias/órdenes de trading).
2. **Procedimiento de Doble Ciego:**
   - Tres traductores profesionales generan versiones en inglés auditadas para la Condición B sin alterar los hechos.
   - Se ejecuta el arnés automatizado `ParityBenchmarkRunner`.
3. **Criterio de Falsación:**
   - Si $\text{Accuracy}(\text{Condición C}) - \text{Accuracy}(\text{Condición B}) > 0.05$ (con $p < 0.01$ en test de McNemar) y $\text{Latency}_{p95}(\text{Condición B}) > 200\text{ ms}$, se **rechaza categóricamente $H_0$**, descartando la arquitectura *Translate-then-Evaluate* de toda línea base de producción.

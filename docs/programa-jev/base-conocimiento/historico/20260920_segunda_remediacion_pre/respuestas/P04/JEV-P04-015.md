# JEV-P04-015: Ingestión de Tablas, PDFs, OCR y Transcripciones con Incertidumbre de Extracción

## 1. Respuesta directa y decisión que permite tomar

Jev 1.13 es un modelo de clasificación y juicio semántico puramente textual que opera sobre el payload `state` (serializado en JSON o texto); **no procesa imágenes nativas, archivos binarios PDF ni streams de audio**. Toda información proveniente de documentos escaneados, balances tabulares, contratos en PDF o llamadas grabadas debe ser extraída por un pipeline upstream (OCR, parsers de PDF estructurados, motores ASR/Speech-to-Text).

El error arquitectónico crítico en estos sistemas es desechar la telemetría de extracción y presentar el texto resultante a Jev como si fuera una transcripción perfecta. Cuando un motor de OCR confunde un dígito ("8" por "3"), omite una cláusula en un PDF rotado o una transcripción fonética confunde términos homófonos ("casa" por "caza"), Jev clasifica sobre una alucinación upstream con confianza artificialmente alta, rompiendo la trazabilidad y la calibración.

La estrategia arquitectónica obligatoria para preservar y tratar la incertidumbre de extracción comprende cuatro pilares:
1. **Normalización Tabular a JSON Semántico Relacional**: Las tablas no se inyectan como texto crudo desalineado ni como imágenes; se parsean en arrays de objetos JSON tipados (`headers`, `rows`, `numeric_values`), eliminando la ambigüedad espacial de columnas divididas.
2. **Inyección Explícita de Metadatos de Calidad e Incertidumbre**: Cada fragmento extraído debe viajar en el `state` acompañado de sus métricas de extracción (`ocr_confidence_score: 0.76`, `asr_word_error_rate_estimate: 0.18`, `paginas_con_baja_resolucion: [3, 7]`, `metodo_extraccion: "TESSERACT_OCR_V5"`).
3. **Compuerta Determinista de Calidad Pre-Inferencial (CPU Circuit-Breaker)**: Si el índice agregado de legibilidad o confianza de extracción cae por debajo de un umbral de seguridad ($\theta_{\text{calidad}} < 0.80$), la solicitud se aborta en la CPU con error `EXTRACCION_ILEGIBLE_REQUIERE_REVISION`, sin consumir inferencias en Jev.
4. **Cláusula de Escape Semántica en `Choice`**: El esquema de clasificación de Jev debe incluir siempre una opción de escape explícita (e.g., `"calidad_insuficiente_para_dictamen"`), instruyendo al modelo a seleccionarla si los indicadores de incertidumbre inyectados o la coherencia sintáctica indican ruido inaceptable.

**Decisión que permite tomar**: Prohibir el paso directo de texto extraído por OCR o ASR a Jev sin metadatos de confianza. Establecer que todo pipeline de ingestión multimodal debe serializar tablas en JSON estructurado, calcular métricas de confianza en CPU y habilitar una compuerta de descarte automático para documentos degradados.

## 2. Alcance, términos, versiones y supuestos

- **Alcance**: Ingestión y preprocesamiento de documentos estructurados y no estructurados (facturas, balances contables, PDFs contractuales, audios de atención al cliente) para la construcción del `state` de Jev 1.13 en QRT y Wheelwork.
- **Términos formalizados**:
  - *Cascading Error (Error en Cascada)*: Propagación y amplificación del ruido generado en una etapa upstream (OCR/ASR) hacia el clasificador downstream (Jev).
  - *Confidence Score de Extracción*: Probabilidad estimada por el modelo de visión o audio de que un carácter, palabra o delimitador fue extraído correctamente.
  - *Layout-Aware Parsing*: Extracción que preserva la jerarquía visual de encabezados, párrafos y tablas en documentos bidimensionales.
  - *Degradación por Ambigüedad Espacial*: Pérdida de sentido que ocurre al serializar tablas bidimensionales en texto unidimensional cuando no se respetan las celdas y filas.
- **Versiones de referencia**: Jev 1.13 (`typesafe-ai >= 0.1.0`), Tesseract 5.x / Textract / Azure Document Intelligence, Whisper v3 / Conformer, pdfplumber / PyMuPDF.
- **Supuestos fundamentales**:
  1. Los extractores upstream proporcionan puntuaciones de confianza a nivel de palabra, bloque o página.
  2. Un documento con OCR ilegible no puede ser corregido semánticamente por Jev sin riesgo inaceptable de alucinación inductiva.

### 4.2. Especificación del Bloque `telemetria_extraccion` en el Payload `state`

Todo estado generado a partir de fuentes imperfectas debe incorporar obligatoriamente la clave `telemetria_extraccion`:

      {
        "nombre": "ESTADO_DE_RESULTADOS",

## 5. Ejemplo sintético trabajado y contraejemplo o caso límite

### 5.1. Ejemplo sintético trabajado: Pipeline de Validación y Normalización de Factura/OCR

```python
"""
Módulo de preparación de documentos OCR con preservación de incertidumbre para Jev 1.13.
"""
from dataclasses import dataclass
from typing import List, Dict, Any, Tuple
import json

@dataclass
class OCRWord:
    text: str
    confidence: float  # 0.0 a 1.0

@dataclass
class DocumentPage:
    page_number: int
    words: List[OCRWord]
    has_table: bool

class DocumentPreProcessor:
    def __init__(self, min_global_confidence: float = 0.80, min_keyword_confidence: float = 0.70):
        self.min_global_confidence = min_global_confidence
        self.min_keyword_confidence = min_keyword_confidence

    def evaluate_quality(self, pages: List[DocumentPage]) -> Tuple[bool, float, Dict[str, Any]]:
        all_confs = [w.confidence for p in pages for w in p.words]
        if not all_confs:
            return False, 0.0, {"error": "DOCUMENTO_VACIO_O_SIN_TEXTO"}

        avg_conf = sum(all_confs) / len(all_confs)
        min_conf = min(all_confs)
        low_conf_count = sum(1 for c in all_confs if c < 0.60)
        low_conf_ratio = low_conf_count / len(all_confs)

        metrics = {
            "confianza_promedio": round(avg_conf, 3),
            "confianza_minima": round(min_conf, 3),
            "ratio_palabras_baja_calidad": round(low_conf_ratio, 3),
            "total_palabras": len(all_confs)
        }

        # Circuit breaker en CPU
        if avg_conf < self.min_global_confidence or low_conf_ratio > 0.25:
            return False, avg_conf, metrics

        return True, avg_conf, metrics

    def build_jev_state(self, document_id: str, pages: List[DocumentPage], structured_data: Dict[str, Any]) -> Dict[str, Any]:
        is_valid, avg_conf, metrics = self.evaluate_quality(pages)
        if not is_valid:
            raise ValueError(f"Circuit-Breaker Activado: Calidad de extracción insuficiente ({metrics})")

        return {
            "documento_id": document_id,
            "contenido_estructurado": structured_data,
            "telemetria_extraccion": {
                "calidad_verificada_cpu": True,
                "metricas_confianza": metrics,
                "advertencia_semantica": "Revisar campos marcados con baja confianza si colisionan con el dictamen."
            }
        }

# Simulación de ejecución
if __name__ == "__main__":
    processor = DocumentPreProcessor(min_global_confidence=0.80)
    
    # Caso A: Documento nítido
    clean_words = [OCRWord("TOTAL", 0.99), OCRWord("FACTURA", 0.98), OCRWord("150000", 0.95)]
    clean_pages = [DocumentPage(page_number=1, words=clean_words, has_table=True)]
    state_a = processor.build_jev_state(
        "DOC-9921",
        clean_pages,
        {"monto_total": 150000, "moneda": "CLP", "concepto": "SERVICIOS_PROFESIONALES"}
    )
    print("Estado Aprobado para Jev:")
    print(json.dumps(state_a, indent=2, ensure_ascii=False))

    # Caso B: Documento borroso (Activa Circuit Breaker)
    blurry_words = [OCRWord("T0TA1", 0.45), OCRWord("FA?TURA", 0.50), OCRWord("1S00O0", 0.40)]
    blurry_pages = [DocumentPage(page_number=1, words=blurry_words, has_table=False)]
    try:
        processor.build_jev_state("DOC-9922", blurry_pages, {})
    except ValueError as e:
        print("\nCaso B Rechazado en CPU:")
        print(e)
```

### 5.2. Contraejemplo y Caso Límite: Audio ASR con Entidades Clave Fonéticamente Ambiguas

En una llamada de cobranza o reclamo telefónico, el motor ASR transcribe:
> "El cliente dice que no adeuda nada y que canceló todo ayer."

Sin embargo, la telemetría del motor ASR indica que para la palabra `"no"`, la confianza fonética fue de $0.32$ (pudo haber sido un carraspeo o haber dicho "ya adeuda").
- **Falla sin telemetría**: Si el pipeline inyecta la frase literal sin métricas de confianza, Jev dictaminará `ESTADO_DEUDA: "NO_ADEUDA"` con certeza del 95%, cometiendo un error grave de negocio.
- **Manejo correcto**: Al detectar que la partícula negativa clave `"no"` posee una confianza de extracción de $0.32$, el normalizador en CPU etiqueta el fragmento como `segmento_dudoso: true, confianza_negacion: 0.32`. En el prompt a Jev, se le presentan las opciones:
  - `A: CONFIRMA_NO_ADEUDA`
  - `B: CONFIRMA_DEUDA`
  - `C: TRANSCRIPCION_AMBIGUA_REQUIERE_ESCUCHA_HUMANA`
  Jev seleccionará `C` debido a la presencia explícita de la incertidumbre documentada en el `state`.

## 6. Aplicación a nuestros desarrollos

### 6.1. Hechos verificables en proyectos existentes

1. **Wheelwork (Validación Documental Operativa)**:
   - Recibe contratos, pólizas y declaraciones juradas escaneadas en PDF de calidad heterogénea (imágenes tomadas con smartphones, sesgadas o con sombras).
   - *Hecho*: Los errores de OCR en el RUT o número de serie provocan rechazos o aprobaciones erróneas si no se detectan antes de emitir la validación de crédito.

2. **QRT (Reportes Financieros y Análisis de Hechos Esenciales)**:
   - Procesa balances, tablas de resultados trimestrales y comunicados emitidos por reguladores financieros en formatos PDF tabulares.
   - *Hecho*: Las tablas financieras con columnas desalineadas alteran las cifras de EBITDA o deuda neta si el parser confunde columnas de años distintos (2024 vs 2025).

### 6.2. Hipótesis de diseño para Jev

- **Hipótesis 1**: La inyección de metadatos de incertidumbre en el payload JSON reduce los falsos positivos en documentos degradados en más del 80% en comparación con la inyección de texto plano.
- **Hipótesis 2**: Un pre-filtro de calidad en CPU que rechaza documentos con confianza OCR agregada $< 0.80$ reduce el coste operativo de tokens en Jev en un 15% al evitar llamadas inútiles.

## 7. Fallos, límites, controles y condiciones de no uso

### 7.1. Modos de falla y mitigaciones

| Modo de Falla | Causa Raíz | Detección | Mitigación Arquitectónica |
|---|---|---|---|
| **Alucinación de Dígito Numérico** | OCR sustituye '8' por '3' con alta confianza local (0.85). | Inconsistencia aritmética en CPU (Suma de ítems $\neq$ Total factura). | Verificación cruzada aritmética en CPU antes de generar el JSON para Jev. |
| **Pérdida de Jerarquía Tabular** | Fusión de celdas adyacentes en balances contables. | Detección de número irregular de columnas por fila en el parser. | Exigir extractores basados en layout (Table Transformer / LayoutLM) y rechazo en caso de tabla asimétrica. |
| **Omisión de Negaciones en Audio** | ASR trunca partículas monosilábicas ("no", "sin") por ruido de fondo. | Word Confidence $< 0.50$ en tokens de parada gramatical. | Etiquetado explícito de incertidumbre fonética y enrutamiento a revisión manual. |

### 7.2. Condiciones de NO uso

- **NO utilizar Jev para transcribir, corregir ortográficamente o adivinar texto ilegible**: Jev no es un modelo de reconstrucción de imágenes ni de corrección de OCR; intentar usarlo para "limpiar" texto borroso provoca alucinaciones severas.
- **NO omitir el pre-filtro en CPU cuando la latencia sea crítica**: Enviar documentos ilegibles a Jev añade latencia de red y coste de inferencia para llegar a una abstención trivial que una regla en CPU resuelve en 2 milisegundos.

## 8. Validación propuesta

> **Nota**: Validación técnica propuesta, no ejecutada en producción.

### 8.1. Diseño experimental
- **Hipótesis falsable**: La inclusión de métricas de confianza OCR en el JSON de entrada y la presencia de la opción de escape `"calidad_insuficiente"` en el esquema de Jev aumentará la exactitud del sistema integral (evitando dictámenes falsos sobre documentos degradados) en al menos 20 puntos porcentuales (Accuracy $> 92\%$ vs $< 72\%$) frente a un baseline que pasa texto plano sin metadatos.
- **Dataset sintético de prueba**: 500 documentos PDF/Tablas sintéticas con 4 niveles controlados de degradación artificial (ruido gaussiano, rotación, borrosidad y artefactos de compresión), etiquetados con ground truth.
- **Métricas y umbrales**:
  - Tasa de Falsos Dictámenes en Documentos Degradados: $< 2.0\%$.
  - Tasa de Rechazo Oportuno (Circuit-Breaker CPU + Opción Escape Jev): $> 95\%$.
  - Brier Score en decisiones aceptadas: $< 0.08$.
- **Criterio de rechazo**: Si Jev insiste en clasificar documentos con confianza de extracción $< 0.60$ asignando probabilidades $> 0.90$ a opciones sustantivas en lugar de abstenerse, la hipótesis se rechaza y se impone un bloqueo estricto en CPU al 100%.
- **Presupuesto estimado**: 500 llamadas a API Jev 1.13 = $0.25 USD; 2 horas de computación CPU local.

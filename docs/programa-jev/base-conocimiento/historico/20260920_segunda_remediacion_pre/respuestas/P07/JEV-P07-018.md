# JEV-P07-018: Criterios de Emisión Dual: Cuándo Mantener Términos Originales y Cuándo Normalizarlos

## 1. Respuesta directa y decisión que permite tomar

En la integración de TypeSafe Jev con sistemas consumidores aguas abajo (*downstream software*), surge una disyuntiva recurrente: si el sistema emite términos dialectales o informales originales (ej. *"al tiro"*, *"ando pato"*, *"DTE"*, *"shortear"*), los motores transaccionales, bases de datos relacionales y APIs de ejecución colapsan por violaciones de esquema o falta de interoperabilidad. Por el contrario, si el sistema normaliza agresivamente y descarta la entrada original, se destruye la **cadena de custodia probatoria** necesaria para peritajes legales, auditorías regulatorias de la CMF y revisiones humanas de supervisión.

Para resolver esta tensión sin fisuras de ingeniería, la arquitectura canónica de Wheelwork y QRT implementa el **Patrón de Emisión Dual Tipada (PEDT)**: (1) **Capa Canónica de Máquina (`canonical_decision`)**: estrictamente normalizada bajo ontologías de tipos, enumeraciones estándar (ej. códigos ISO 4217 para divisas, taxonomías fijas en `Choice`, prioridades `[P1, P2, P3]` y órdenes FIX estructuradas); (2) **Capa de Evidencia Literal (`verbatim_evidence`)**: retiene la cita textual exacta y los modismos originales para auditoría y visualización de operadores; y (3) **Metadatos de Trazabilidad de Transformación**: documentan formalmente la función de mapeo aplicada.

## 4. Explicación técnica verificable

### 2.1 El Principio de Desacople entre Juicio Semántico e Interoperabilidad

Un modelo de Sistema 1 evalúa la semántica en el espacio de lenguaje natural, pero las aplicaciones empresariales exigen contratos deterministas:
- **Bases de Datos Relacionales (PostgreSQL/BigQuery):** Exigen tipos primitivos estrictos (`BOOLEAN`, `ENUM`, `UUID`, `TIMESTAMP`). Un campo de estado de pago no puede almacenar la cadena *"pagado al tiro"*; debe almacenar el enum canónico `'PAID'` y el SLA `'IMMEDIATE'`.
- **Motores de Ejecución Cuantitativa (FIX Protocol / APIs de Brokers):** Un motor de órdenes bursátiles no admite expresiones como *"botar el short"*; requiere una estructura FIX tipada: `OrdType=1 (Market), Side=2 (Sell), Symbol=USD/CLP`.
- **Auditoría Legal y Regulatoria (Tribunales / CMF / SII):** Ante una fiscalización o litigio laboral, una base de datos que sólo contenga `'CANCELADO'` sin el texto original que motivó la acción carece de mérito probatorio según la legislación chilena (Ley 19.799 sobre documentos electrónicos).

## 5. Ejemplo sintético trabajado y contraejemplo o caso límite

### 5.1. Implementación de Referencia en Python

El siguiente módulo implementa el generador de eventos duales tipados (*Dual Emission Transformer*) que produce el payload de máquina y el registro forense auditado.

```python
"""
Módulo de Emisión Dual Tipada (PEDT) para Integración de Jev AI con Downstream Software.
Separa formalmente la decisión canónica normalizada de la evidencia literal inmutable.
"""

from dataclasses import dataclass, asdict
from typing import Dict, Any, Optional
import datetime
import hashlib
import json
import logging

logger = logging.getLogger("DualEmissionTransformer")


@dataclass(frozen=True)
class CanonicalAction:
    action_type: str  # Enum formal: "CANCEL_ORDER", "EXECUTE_IMMEDIATE", "LOG_INQUIRY"
    priority_level: str  # "P1", "P2", "P3"
    execution_parameters: Dict[str, Any]
    confidence_score: float


@dataclass(frozen=True)
class VerbatimAuditRecord:
    raw_text: str
    detected_dialect: str
    invariable_sha256: str
    captured_at: str


@dataclass(frozen=True)
class DualEmissionEvent:
    event_id: str
    canonical: CanonicalAction
    verbatim: VerbatimAuditRecord
    routing_destination: str


class DualEmissionEngine:
    """
    Transforma salidas de Jev en eventos duales para bases de datos y registros de auditoría.
    """

    def generate_dual_event(
        self,
        event_id: str,
        raw_text: str,
        jev_decision: Any,
        jev_confidence: float,
        dialect: str = "es-CL"
    ) -> DualEmissionEvent:
        try:
            # 1. Normalización de la acción de máquina según reglas de negocio
            action_type, priority, params = self._map_to_canonical_contract(jev_decision, raw_text)

            canonical_obj = CanonicalAction(
                action_type=action_type,
                priority_level=priority,
                execution_parameters=params,
                confidence_score=jev_confidence
            )

            # 2. Generación del registro forense literal inmutable con hash
            sha256_hash = hashlib.sha256(raw_text.encode("utf-8")).hexdigest()
            now_iso = datetime.datetime.now(datetime.timezone.utc).isoformat()

            verbatim_obj = VerbatimAuditRecord(
                raw_text=raw_text,
                detected_dialect=dialect,
                invariable_sha256=sha256_hash,
                captured_at=now_iso
            )

            # Ruteo determinista según prioridad
            dest = "HIGH_PRIORITY_EXECUTION_QUEUE" if priority == "P1" else "STANDARD_DISPATCH_QUEUE"

            return DualEmissionEvent(
                event_id=event_id,
                canonical=canonical_obj,
                verbatim=verbatim_obj,
                routing_destination=dest
            )

        except Exception as err:
            logger.error(f"Error generando emisión dual para evento {event_id}: {type(err).__name__} (detalles omitidos por seguridad)")
            raise RuntimeError(f"Fallo en emisión dual: {type(err).__name__}")

    def _map_to_canonical_contract(self, decision: Any, text: str) -> Tuple[str, str, Dict[str, Any]]:
        lower = text.lower()
        if "al tiro" in lower or "ya mismo" in lower:
            priority = "P1"
        else:
            priority = "P2"

        if decision is True or "cancelar" in lower or "botar" in lower:
            action = "CANCEL_SERVICE"
            params = {"immediate_purge": (priority == "P1")}
        else:
            action = "PROCESS_STANDARD"
            params = {}

        return action, priority, params
```

## 7. Fallos, límites, controles y condiciones de no uso

### 7.1. Modos de Falla y Controles de Mitigación
1. **Descalibración por modismos chilenos no composicionales**: Activación de umbrales dinámicos y compuerta de abstención ante entropía alta.
2. **Fragmentación sub-léxica en tokenización**: Preprocesamiento determinista de acrónimos territoriales y siglas institucionales (CMF, SII, DTE, UF) en memoria en CPU.
3. **Falsos positivos por sarcasmo o ironía**: Desacoplamiento de juicios de satisfacción mediante preguntas fácticas concurrentes en primitivas `Noul`.

### 7.2. Gobernanza, Privacidad y Condiciones de No Uso
1. **Cumplimiento de la Ley 19.799 sobre Firma y Documentos Electrónicos:**
   - En Chile, la prueba testimonial electrónica ante juzgados de policía local o tribunales ordinarios requiere exhibir el documento tal cual fue expedido por el consumidor. La normalización interna no sustituye al texto auténtico.
2. **Cifrado en Reposo de Evidencia Literal:**
   - Dado que el campo `verbatim` puede contener expresiones espontáneas con datos personales, debe almacenarse en tablas con cifrado a nivel de columna (AES-256) con políticas estrictas de control de acceso basadas en roles (RBAC).

---

### 7.3. Condiciones Taxativas de NO Uso
- **NO delegar la normalización de identificadores legales (RUT, patentes) al espacio latente de Jev**; debe validarse con Módulo 11 en CPU.
- **NO canalizar datos confidenciales o bancarios a servicios de traducción externa (NMT no autorizados)** para intentar "traducir" antes de Jev.
- **NO ejecutar acciones operativas irreversibles sin verificación de umbral calibrado localmente**.

# JEV-P07-013: Comprobación de Invarianza ante Paráfrasis Regionales y Sensibilidad ante Cambios Semánticos Mínimos

## 1. Respuesta directa y decisión que permite tomar

Un clasificador de decisiones semánticas de Sistema 1 como TypeSafe Jev debe satisfacer dos propiedades matemáticas complementarias para considerarse robusto en producción: (1) **Invarianza Dialectal Regional (INV)**: variaciones léxicas o sintácticas que preservan la intención transaccional a través de diferentes dialectos del español (chileno, argentino, mexicano, español estándar) deben **conservar exactamente la misma decisión tipada** con una confianza estadística estable; y (2) **Sensibilidad Semántica Direccional (DIR / *Contrast Sets*)**: modificaciones sutiles pero semánticamente decisivas (como la adición de una condición suspensiva, un cambio de negador o la alteración de un operador de comparación) deben **alterar inmediatamente la decisión tipada**.

Si un modelo no cumple ambas propiedades de manera balanceada, sufre de dos patologías graves: **fragilidad dialectal** (si cambia de decisión ante modismos regionales neutros) o **insensibilidad por bolsa de palabras** (*bag-of-words insensitivity*, si ignora pequeñas modificaciones lógicas críticas debido a la dominancia de palabras clave circundantes). La arquitectura de evaluación canónica para Wheelwork y QRT implementa una **batería de prueba por pares contrastivos pareados** (*Minimal Contrastive Testing Harness*), auditando formalmente la Tasa de Consistencia de Invarianza ($ICR \ge 0.95$) y la Tasa de Sensibilidad Direccional ($DSR \ge 0.95$).

## 4. Explicación técnica verificable

### 2.1 Formalización de Invarianza y Sensibilidad

Sean $x$ una entrada en español estándar, $y \in \mathcal{Y}$ la decisión tipada emitida por el modelo $f(x)$, y $C(x) \in [0, 1]$ la confianza asociada:

1. **Invarianza Dialectal (INV):**
   Sea $\mathcal{P}_{\text{regional}}(x) = \{x_{\text{CL}}, x_{\text{AR}}, x_{\text{MX}}, x_{\text{ES}}\}$ un conjunto de paráfrasis regionales fieles que preservan la fuerza ilocutiva y el contenido fáctico. El modelo es invariante si y sólo si:
   $$\forall x' \in \mathcal{P}_{\text{regional}}(x): \quad f(x') = f(x) \quad \land \quad |C(x') - C(x)| \le \epsilon_{\text{calibración}}$$
   Donde $\epsilon_{\text{calibración}} \le 0.08$.

2. **Sensibilidad Direccional / Conjunto Contrastivo (DIR):**
   Sea $x'' = x \oplus \delta_{\text{semántica}}$ una perturbación mínima que invierte la validez lógica del criterio (ej. agregar *"a menos que"*, *"no"*, o alterar un umbral numérico de $15$ a $5$ bps). El modelo es sensible si y sólo si:
   $$f(x'') \neq f(x)$$

```
Espacio de Decisión: Invarianza vs. Sensibilidad
─────────────────────────────────────────────────────────────────────────────
Paráfrasis Dialectales (Misma Decisión):
  [CL]: "Quiero botar el plan al tiro y que me devuelvan las lucas."   ──> Decision: CANCEL_REFUND (True)
  [MX]: "Quiero cancelar el plan de volada y que me regresen la lana." ──> Decision: CANCEL_REFUND (True)
  [AR]: "Quiero dar de baja el plan ya y que me devuelvan la guita."   ──> Decision: CANCEL_REFUND (True)
  [Std]: "Solicito cancelar el plan inmediatamente y el reembolso."    ──> Decision: CANCEL_REFUND (True)
                                      │
                         [Perturbación Semántica Mínima]
                                      │
  [Cambio Mínimo]: "Quiero cancelar el plan a menos que me bajen el precio." ──> Decision: CONDITIONAL (False)
                                      ▲
                                      └── ¡La Decisión DEBE Mutar!
```

## 5. Ejemplo sintético trabajado y contraejemplo o caso límite

### 5.1. Implementación de Referencia en Python

El siguiente arnés ejecuta suites de pruebas por tuplas de 3 vías: (1) Instancia estándar, (2) Paráfrasis regional equivalente (INV), y (3) Variante contrastiva con cambio semántico mínimo (DIR), calculando métricas de fidelidad.

```python
"""
Arnés de Evaluación de Invarianza Dialectal y Sensibilidad Semántica para Jev AI.
Audita formalmente la resistencia a modismos regionales y la detección de cambios mínimos.
"""

from dataclasses import dataclass
from typing import List, Dict, Any, Tuple
import logging

logger = logging.getLogger("ContrastiveHarness")


@dataclass(frozen=True)
class ContrastiveTriplet:
    triplet_id: str
    base_standard: str
    paraphrase_regional: str
    contrastive_inverted: str
    question: str
    expected_base_output: Any
    expected_inverted_output: Any


@dataclass
class ContrastiveMetrics:
    total_triplets: int
    invariance_passed: int
    sensitivity_passed: int
    invariance_consistency_rate: float  # ICR
    directional_sensitivity_rate: float  # DSR
    robustness_score: float  # ICR * DSR


class ContrastiveRobustnessAuditor:
    """
    Ejecutor de pruebas pareadas de robustez y sensibilidad semántica.
    """

    def audit_suite(self, suite: List[ContrastiveTriplet]) -> ContrastiveMetrics:
        inv_passed = 0
        sens_passed = 0

        for item in suite:
            try:
                # 1. Inferencia sobre base estándar
                pred_base, _ = self._mock_jev_decision(item.base_standard, item.question)

                # 2. Inferencia sobre paráfrasis regional (Prueba INV)
                pred_para, _ = self._mock_jev_decision(item.paraphrase_regional, item.question)

                # 3. Inferencia sobre variante contrastiva (Prueba DIR)
                pred_inv, _ = self._mock_jev_decision(item.contrastive_inverted, item.question)

                # Comprobación de Invarianza: La paráfrasis DEBE coincidir con la base
                if pred_para == pred_base and pred_base == item.expected_base_output:
                    inv_passed += 1

                # Comprobación de Sensibilidad: El cambio mínimo DEBE producir la salida invertida
                if pred_inv == item.expected_inverted_output and pred_inv != pred_base:
                    sens_passed += 1

            except Exception as err:
                logger.error(f"Error evaluando triplete {item.triplet_id}: {type(err).__name__} (detalles omitidos por seguridad)")

        total = len(suite)
        icr = inv_passed / total if total > 0 else 0.0
        dsr = sens_passed / total if total > 0 else 0.0

        return ContrastiveMetrics(
            total_triplets=total,
            invariance_passed=inv_passed,
            sensitivity_passed=sens_passed,
            invariance_consistency_rate=icr,
            directional_sensitivity_rate=dsr,
            robustness_score=icr * dsr
        )

    def _mock_jev_decision(self, text: str, question: str) -> Tuple[Any, float]:
        lower = text.lower()
        # Emulación representativa de comportamiento
        if "salvo que" in lower or "a menos que" in lower or "decidí mantenerla" in lower:
            return False, 0.91
        if "botar" in lower or "cancelar" in lower or "cerrar" in lower or "dar de baja" in lower:
            return True, 0.88
        return False, 0.70
```

### 5.2. Contraejemplo y Modos de Fallo Reales

### 4.1 La Falla del Modelo "Sordo a la Semántica" en Contratos Legales
Un sistema de revisión automática de contratos procesa cláusulas de responsabilidad civil en Wheelwork.
- **Cláusula Original (Aprobada):** `"El proveedor responderá por las fallas operacionales directamente causadas por su personal."`
- **Perturbación Mínima 1 (Inversión Semántica):** `"El proveedor responderá por las fallas operacionales salvo las causadas directamente por su personal."` (El cambio de una sola palabra, *"directamente"* $\rightarrow$ *"salvo las"*, invierte la responsabilidad jurídica).
- **Fallo del Modelo:** Jev arroja exactamente la misma decisión de aprobación (`Responsable = True`, confianza $0.89$).
- **Causa Raíz:** Las cabezas de atención se concentraron en los tokens dominantes (*"proveedor"*, *"responderá"*, *"fallas operacionales"*), ignorando la partícula restrictiva *"salvo"*.
- **Consecuencia Legal:** La empresa firma un contrato que exime al proveedor de toda responsabilidad por negligencia de sus propios empleados.

## 6. Aplicación a nuestros desarrollos

> **Nota de Gobernanza**: Las siguientes integraciones constituyen hipótesis de diseño técnico sujetas a validación empírica en banco de pruebas local antes de su despliegue operativo.

### 3.1 Wheelwork: Gestión de Reclamaciones Multirregionales
- **Instancia Base (Estándar):** `"Solicito cancelar mi suscripción inmediatamente."` $\implies$ Jev predice `Cancelar = True`.
- **Prueba INV (Paráfrasis regional chilena):** `"Quiero botar la suscripción al tiro."` $\implies$ **Debe mantener** `Cancelar = True`.
- **Prueba DIR (Perturbación mínima decisiva):** `"Quería cancelar mi suscripción, pero al final decidí mantenerla."` $\implies$ **Debe invertir a** `Cancelar = False`.
- **Peligro:** Un modelo no sensible detecta *"cancelar mi suscripción"* y emite `True`, cancelando la cuenta de un cliente fidelizado.

### 3.2 QRT: Órdenes de Protección y Stop Loss en Trading
- **Instancia Base (Trading Estándar):** `"Cerrar la posición en corto si el spread supera 20 pips."` $\implies$ `Trigger = True` si spread = 25.
- **Prueba INV (Code-Switching / Jerga local):** `"Botar el short si el spread se abre más allá de 20 pips."` $\implies$ **Debe mantener** `Trigger = True`.
- **Prueba DIR (Perturbación condicional mínima):** `"Cerrar la posición en corto a menos que el spread supere 20 pips."` $\implies$ **Debe invertir la lógica** (`Trigger = False` si spread = 25).

## 7. Fallos, límites, controles y condiciones de no uso

### 7.1. Modos de Falla y Controles de Mitigación
1. **Descalibración por modismos chilenos no composicionales**: Activación de umbrales dinámicos y compuerta de abstención ante entropía alta.
2. **Fragmentación sub-léxica en tokenización**: Preprocesamiento determinista de acrónimos territoriales y siglas institucionales (CMF, SII, DTE, UF) en memoria en CPU.
3. **Falsos positivos por sarcasmo o ironía**: Desacoplamiento de juicios de satisfacción mediante preguntas fácticas concurrentes en primitivas `Noul`.

### 7.2. Gobernanza, Privacidad y Condiciones de No Uso
1. **Auditoría de Discriminación Geográfica:**
   - Un sistema de IA no debe discriminar en la tasa de aceptación o rechazo de solicitudes en función de la procedencia regional o modismos del solicitante si el fondo de la petición es idéntico. La métrica $ICR$ sirve como indicador formal de equidad dialectal ante la autoridad regulatoria.
2. **Blindaje ante Inyecciones Adversarias Mínimas:**
   - La prueba DIR audita que atacantes no puedan evadir controles de compliance introduciendo pequeñas partículas sintácticas (*"salvo error u omisión"*) para eludir la detección automática.

---

### 7.3. Condiciones Taxativas de NO Uso
- **NO delegar la normalización de identificadores legales (RUT, patentes) al espacio latente de Jev**; debe validarse con Módulo 11 en CPU.
- **NO canalizar datos confidenciales o bancarios a servicios de traducción externa (NMT no autorizados)** para intentar "traducir" antes de Jev.
- **NO ejecutar acciones operativas irreversibles sin verificación de umbral calibrado localmente**.

### 7.1 Hipótesis Falsable
$$H_0: \text{ICR} \ge 0.95 \quad \land \quad \text{DSR} \ge 0.95 \quad (\text{sobre el modelo base sin preprocesamiento})$$
*La hipótesis nula plantea que TypeSafe Jev exhibe de forma nativa invarianza dialectal y sensibilidad a cambios lógicos mínimos superiores al 95% sin necesidad de sanitización.*

### 7.2 Protocolo Experimental
1. **Corpus:** 100 tripletes contrastivos rigurosamente curados que abarcan dialectos chileno, rioplatense y mexicano.
2. **Evaluación:**
   - Se ejecuta el auditor `ContrastiveRobustnessAuditor`.
3. **Criterio de Falsación:**
   - Si $\text{ICR} < 0.90$ o $\text{DSR} < 0.90$ ($p < 0.001$), se **rechaza categóricamente $H_0$**, demostrando la necesidad de incorporar el pipeline de normalización y desacoplamiento de preguntas en producción.

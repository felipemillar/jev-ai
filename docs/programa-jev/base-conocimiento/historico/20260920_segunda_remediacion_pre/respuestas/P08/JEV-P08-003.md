# JEV-P08-003 — Diseño de Cascadas Basadas en Calidad y Coste Total (FrugalGPT)

## 1. Respuesta directa y decisión que permite tomar
Una cascada eficiente evalúa primero con el mecanismo más económico y rápido (Jev 1.13.0 a $0.042/Mtok de entrada), leyendo la propiedad `confidence` de la respuesta Choice/Score o la distancia $|2p - 1|$ en Noul. Si la confianza supera el umbral de seguridad (ej. 0.85), se acepta la decisión a costo casi nulo; si la confianza es media o baja, se escala a un LLM de razonamiento más costoso (ej. Claude 3.5 Sonnet o GPT-4o) o a revisión humana. Esto reduce el coste total entre 60% y 85% preservando la calidad global.

## 2. Alcance, términos y supuestos
- **Requisitos específicos analizados:** Estructurar cascada de inferencia multi-modelo optimizando frontera de Pareto coste vs exactitud.
- **Versión de referencia:** `jev-1.13.0` consumido vía `POST /v1/systemone`.
- **Límites de diseño:** La inferencia no ejecuta código ni persiste estado en el servidor; toda persistencia y garantía de ejecución corresponde a la arquitectura anfitriona.

## 4. Explicación técnica verificable
Formalización del enrutamiento por bandas de confianza: Banda 1 ($C \ge 0.85$): Auto-aprobación con Jev ($0.042/Mtok). Banda 2 ($0.60 \le C < 0.85$): Escalamiento a LLM con cadena de pensamiento ($3.00/Mtok). Banda 3 ($C < 0.60$): Escalamiento a operador humano.

## 5. Ejemplo trabajado y contraejemplo
- **Implementación verificada en Python:**
```python
import logging
from typesafe_sdk import TypeSafeClient, Choice, Score, Noul

logger = logging.getLogger("JEV-P08-003")

def cascada_clasificacion(texto: str) -> tuple[str, str]:
    try:
        client = TypeSafeClient(model="jev-1.13.0")
        res = client.system_one(state=texto, questions={"tag": Choice(instructions="Clasificar", criteria={"A": "Tipo A", "B": "Tipo B"})})
        ans = res.answers["tag"]
        if ans.confidence >= 0.85:
            return ans.choice, "jev_rapido"
        return invocar_llm_razonamiento(texto), "llm_escalado"
    except Exception as err:
        logger.error(f"Fallo cascada: {type(err).__name__} (detalles omitidos por seguridad)")
        return "indeterminado", "fallback_error"
```

## 7. Fallos, límites y controles
- **Modos de fallo principales:** Usar un umbral de confianza único sin calibración previa en el dominio. Control: calibración empírica en golden dataset determinando el punto de quiebre de coste.
- **Control de mitigación:** Timeouts estrictos de conexión (350 ms), disyuntores de circuito con conmutación a heurística determinista local y registro de auditoría con hash criptográfico SHA-256 de cada inferencia.

## 8. Validación propuesta
- **Hipótesis falsable:** "Correr 1.000 ejemplos anotados: verificar que al menos 70% se resuelva en Jev con precisión > 95%, logrando ahorro de costes > 65% frente a usar siempre el modelo pesado."
- **Métricas:** Tasa de error bajo carga, latencia percentil 99 (p99 < 400 ms), calibración ECE y coste total por decisión.
- **Criterio de rechazo:** Si la degradación ante caídas de red provoca bloqueo de transacciones o si el coste por decisión supera el umbral presupuestario definido.

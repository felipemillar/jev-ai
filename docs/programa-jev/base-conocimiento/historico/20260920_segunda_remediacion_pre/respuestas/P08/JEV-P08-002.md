# JEV-P08-002 — Arquitectura Mínima de Juicio Semántico sin Dependencia Crítica

## 1. Respuesta directa y decisión que permite tomar
La arquitectura mínima de integración desacoplada es el patrón Adaptador / Sidecar Asíncrono. Jev se consume detrás de una interfaz abstracta que expone un contrato genérico de clasificación con degradación elegante. Si la llamada a TypeSafe supera un timeout estricto (ej. 350 ms) o falla la conexión, el sistema conmuta automáticamente a una heurística de respaldo determinista o a abstención sin bloquear el flujo transaccional.

## 2. Alcance, términos y supuestos
- **Requisitos específicos analizados:** Diseñar patrón arquitectónico mínimo que permita desconectar Jev sin rehacer el sistema.
- **Versión de referencia:** `jev-1.13.0` consumido vía `POST /v1/systemone`.
- **Límites de diseño:** La inferencia no ejecuta código ni persiste estado en el servidor; toda persistencia y garantía de ejecución corresponde a la arquitectura anfitriona.

## 4. Explicación técnica verificable
Implementación del patrón Strategy con Circuit Breaker: una clase abstracta `SemanticDecisionProvider` con dos implementaciones: `TypeSafeJevProvider` y `FallbackRuleProvider`. Un middleware registra latencias y errores 5xx/429. Ante 3 fallos consecutivos, el disyuntor se abre y deriva 100% del tráfico al fallback local.

## 5. Ejemplo trabajado y contraejemplo
- **Implementación verificada en Python:**
```python
import logging
from typesafe_sdk import TypeSafeClient, Choice, Score, Noul

logger = logging.getLogger("JEV-P08-002")

class SemanticDecisionService:
    def __init__(self, primary_provider, fallback_provider):
        self.primary = primary_provider
        self.fallback = fallback_provider
        self.breaker_open = False
    def decide(self, context: str) -> dict:
        if not self.breaker_open:
            try:
                return self.primary.evaluate(context, timeout=0.35)
            except Exception as err:
                logger.error(f"Fallo proveedor primario: {type(err).__name__} (detalles omitidos por seguridad)")
                self.breaker_open = True
        return self.fallback.evaluate(context)
```
- **Contraejemplo / Caso límite:**
Llamar a la API de TypeSafe síncronamente en el hilo principal del broker sin timeout. Control: envoltorio con timeout estricto de socket de 400 ms.

## 7. Fallos, límites y controles
- **Modos de fallo principales:** Llamar a la API de TypeSafe síncronamente en el hilo principal del broker sin timeout. Control: envoltorio con timeout estricto de socket de 400 ms.
- **Control de mitigación:** Timeouts estrictos de conexión (350 ms), disyuntores de circuito con conmutación a heurística determinista local y registro de auditoría con hash criptográfico SHA-256 de cada inferencia.

## 8. Validación propuesta
- **Hipótesis falsable:** "Inyectar latencia de 1000 ms en el endpoint simulado: el 100% de las transacciones debe completar en < 50 ms usando la ruta fallback."
- **Métricas:** Tasa de error bajo carga, latencia percentil 99 (p99 < 400 ms), calibración ECE y coste total por decisión.
- **Criterio de rechazo:** Si la degradación ante caídas de red provoca bloqueo de transacciones o si el coste por decisión supera el umbral presupuestario definido.

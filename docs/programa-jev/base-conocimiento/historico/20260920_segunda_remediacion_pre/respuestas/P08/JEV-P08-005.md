# JEV-P08-005 — Contratos entre Componentes para Mitigar Propagación de Errores Semánticos

## 1. Respuesta directa y decisión que permite tomar
Para evitar que una salida tipada pero semánticamente errónea se propague por el sistema como dato fáctico, los contratos entre componentes deben encapsular las respuestas de Jev en tipos enriquecidos de incertidumbre (`ProbabilityEstimate[T]`). Ningún componente posterior debe aceptar un enum plano sin su intervalo de confianza asociado y metadatos de procedencia temporal.

## 2. Alcance, términos y supuestos
- **Requisitos específicos analizados:** Especificar modelos de datos Pydantic e interfaces que aíslen la incertidumbre epistémica.
- **Versión de referencia:** `jev-1.13.0` consumido vía `POST /v1/systemone`.
- **Límites de diseño:** La inferencia no ejecuta código ni persiste estado en el servidor; toda persistencia y garantía de ejecución corresponde a la arquitectura anfitriona.

## 4. Explicación técnica verificable
Uso de Pydantic con validadores de rango y tipado fuerte: la salida de Jev se envuelve en `DecisionArtifact`, conteniendo `raw_choice`, `distribution`, `confidence`, `timestamp` y `model_id`. Los módulos de ejecución rechazan cualquier `DecisionArtifact` cuyo timestamp tenga más de 60 segundos o cuya entropía supere el umbral.

## 5. Ejemplo trabajado y contraejemplo
- **Implementación verificada en Python:**
```python
import logging
from typesafe_sdk import TypeSafeClient, Choice, Score, Noul

logger = logging.getLogger("JEV-P08-005")

from pydantic import BaseModel, Field
class DecisionArtifact(BaseModel):
    decision: str
    confidence: float = Field(ge=0.0, le=1.0)
    model_version: str
    is_authoritative: bool = False
def consumir_decision(art: DecisionArtifact):
    if not art.is_authoritative and art.confidence < 0.85:
        raise ValueError("Decision no autorizada para ejecucion automatica")
```

- **Control de mitigación:** Timeouts estrictos de conexión (350 ms), disyuntores de circuito con conmutación a heurística determinista local y registro de auditoría con hash criptográfico SHA-256 de cada inferencia.

## 8. Validación propuesta
- **Hipótesis falsable:** "Verificar en suite de pruebas que el 100% de los schemas de la API exigen `confidence` y `model_version` obligatorios."
- **Métricas:** Tasa de error bajo carga, latencia percentil 99 (p99 < 400 ms), calibración ECE y coste total por decisión.
- **Criterio de rechazo:** Si la degradación ante caídas de red provoca bloqueo de transacciones o si el coste por decisión supera el umbral presupuestario definido.

# JEV-P11-007 — Cuantificación de Falsos Positivos y Negativos en Guardrails Semánticos y Costo Operativo

## 1. Respuesta directa y decisión que permite tomar

El ajuste de umbrales en un guardrail semántico implica un trade-off económico y operativo riguroso: un Falso Positivo (bloquear una solicitud legítima) genera fricción con el usuario, pérdida de ventas o interrupción de flujos de trading; un Falso Negativo (permitir el paso de una inyección o dato corrupto) genera riesgo de ciberseguridad o decisiones automatizadas erróneas. El umbral de corte debe fijarse minimizando la función de costo esperado total: $C = FP \times C_{FP} + FN \times C_{FN}$.

## 4. Explicación técnica

Curva Cost-Utility: Dado que en finanzas $C_{FN}$ (brecha de seguridad) puede ser 100 veces mayor que $C_{FP}$ (revisión manual de $0.50 USD), el umbral de decisión para clasificar como 'sospechoso' debe ser agresivo ($p \ge 0.15$).

## 5. Ejemplo ilustrativo, verificación o contraejemplo

```python
# Ejemplo ilustrativo no ejecutado
import logging

logger = logging.getLogger("P11_07")

def calcular_costo_operativo_guardrail(fp: int, fn: int, costo_fp: float = 2.0, costo_fn: float = 500.0) -> float:
    try:
        costo_total = (fp * costo_fp) + (fn * costo_fn)
        return round(costo_total, 2)
    except Exception as err:
        logger.error(f"Fallo en calculo de costo de seguridad: {type(err).__name__} (detalles omitidos por seguridad)")
        return float("inf")
```

- **Contraejemplo / Caso borde**: Subir el umbral de detección al 95% para evitar quejas de clientes provocará que el 20% de las inyecciones maliciosas pasen desapercibidas.

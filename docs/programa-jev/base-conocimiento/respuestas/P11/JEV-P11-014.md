# JEV-P11-014 — Minimización de Datos Sensibles en Trazas, Logs de Error y Copias de Seguridad

## 1. Respuesta directa y decisión que permite tomar

La política corporativa de observabilidad exige la minimización estricta de datos en todas las capas de registro. Los logs estructurados (JSON) y las trazas de OpenTelemetry solo deben registrar metadatos no sensibles: longitud del payload, latencia en milisegundos, código de estado HTTP y hash anónimo del identificador de la solicitud. Queda terminantemente prohibido volcar el contenido del campo `state` o las respuestas completas en los archivos de log estándar.

## 4. Explicación técnica

Filtro de logueo: Todo logger de producción utiliza un formateador que descarta automáticamente cualquier campo denominado `state`, `prompt`, `password`, `key` o `payload`, reemplazándolos por su longitud en bytes.

## 5. Ejemplo ilustrativo, verificación o contraejemplo

```python
# Ejemplo ilustrativo no ejecutado
import logging

logger = logging.getLogger("P11_14")

def registrar_evento_operativo(request_id: str, duracion_ms: float, codigo_status: int, tamano_bytes: int):
    try:
        # Solo metadatos anonimos de rendimiento
        registro = {
            "req_id": request_id,
            "latency_ms": round(duracion_ms, 2),
            "status": codigo_status,
            "bytes_processed": tamano_bytes
        }
        logger.info(f"AUDITORIA_TELEMETRIA: {registro}")
    except Exception as err:
        logger.error(f"Fallo en formateo de log: {type(err).__name__} (detalles omitidos por seguridad)")
```

- **Contraejemplo / Caso borde**: Configurar el nivel de log en `DEBUG` en producción y registrar `logger.debug(f'Llamada: {payload}')` expondrá todos los datos de clientes en los logs de CloudWatch.

## 7. Fallos conocidos, advertencias y contraindicaciones

| Modo de Fallo | Impacto Operativo | Detección Temprana | Mitigación Arquitectónica |
| :--- | :--- | :--- | :--- |
| Exposición masiva de datos en logs de cloud | Acceso no autorizado por personal de soporte | Formateadores de log con filtro de atributos | Prohibir nivel DEBUG en entornos productivos |
| Ofuscación de texto mediante caracteres invisibles | Bypass de filtros semánticos | Normalización Unicode estricta en CPU | Rechazar caracteres de control o no imprimibles |
| Fuga silenciosa de credenciales en excepciones | Exposición de secretos en trazas | Inspección estática con linters | Enmascarar con type(err).__name__ y sufijo seguro |

## 8. Validación propuesta

- **Hipótesis Falsable**: La sanitización de logs garantiza cero ocurrencias de PII en los repositorios de telemetría.
- **Métricas**: Patrones de PII detectados en auditorías de logs con Elastic Security.
- **Criterio de Rechazo**: 0 coincidencias de datos personales en 1 millón de líneas de log.
- **Estado**: Protocolo de validación propuesto para banco de pruebas local.

## 9. Recomendación y pendientes

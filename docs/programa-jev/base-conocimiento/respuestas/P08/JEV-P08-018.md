# JEV-P08-018 — Evolución Arquitectónica: De Experimento Local a Servicio Compartido y Producto SaaS

## 1. Respuesta directa y decisión que permite tomar

La evolución de la arquitectura exige tres estadios: (1) Experimento Local con scripts aislados en Python y datos sintéticos; (2) Servicio Interno Compartido mediante microservicio centralizado con mTLS, proxy de observabilidad y circuit-breakers; (3) Producto Multi-tenant Externo con rate limiting por cliente, anonimización rigurosa de PII en CPU y aislamiento de tenantes en base de datos.

## 7. Fallos, límites, controles y condiciones de no uso

| Modo de Fallo | Impacto | Detección | Control / Mitigación |
|---|---|---|---|
| Fuga de datos de clientes en producción | Sanciones por ley de protección de datos | Linter de PII en CPU obligatorio en staging | Bloqueo de peticiones que contengan números de tarjeta o RUT |
| Timeout de API (>300 ms) | Bloqueo de hilo en microservicio | Alarma de socket timeout | Conmutación inmediata a fallback local en CPU |
| Descalibración en casos OOD | Decisión errónea con certeza aparente | Medición de entropía de salida | Compuerta de abstención y escalado humano |

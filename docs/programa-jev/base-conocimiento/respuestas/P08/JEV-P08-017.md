# JEV-P08-017 — Jev en Agentes con Herramientas: Evaluación de Acciones vs Autorización para Ejecutarlas

## 1. Respuesta directa y decisión que permite tomar

En arquitecturas agentivas con llamadas a herramientas (tool-calling), Jev debe operar exclusivamente como evaluador semántico previo (e.g. seleccionando la herramienta idónea con Choice o verificando la seguridad de los parámetros con Noul). Jamás debe otorgársele al modelo el token de ejecución directo; un componente guardián en CPU debe validar permisos y autorizaciones.

- **Supuesto Operacional**: La comunicación opera bajo cuotas de consumo y timeout estricto de red.

## 5. Ejemplo sintético trabajado y contraejemplo o caso límite

### 5.1 Implementación en Python (SDK 0.7.0)

```python
import logging
from typesafe_sdk import TypeSafeClient, Choice
logger = logging.getLogger('P08_17')

def evaluar_tool_call(intencion: str, rol: str) -> dict:
    try:
        client = TypeSafeClient(model='jev-1.13.0')
        res = client.system_one(state=intencion, questions={'t': Choice(instructions='Tool', criteria={'leer': 'Herramienta de lectura y consulta de datos', 'escribir': 'Herramienta de escritura y persistencia de datos'})})
        tool = res.answers['t'].choice
        if tool == 'escribir' and rol != 'admin':
            return {'permitido': False, 'tool': tool}
        return {'permitido': True, 'tool': tool}
    except Exception as err:
        logger.error(f'Fallo evaluador tool: {type(err).__name__} (detalles omitidos por seguridad)')
        return {'permitido': False}
```

### 5.2 Contraejemplo y Caso Límite

Darle a un agente acceso para ejecutar órdenes de trading sin una compuerta que valide el rol del operador provocará compras no autorizadas.

## 7. Fallos, límites, controles y condiciones de no uso

| Modo de Fallo | Impacto | Detección | Control / Mitigación |
|---|---|---|---|
| Escalada de privilegios por agente | Modificación no autorizada de datos | Validación determinista de permisos en CPU | Bloqueo estricto si el rol no es administrador |
| Timeout de API (>300 ms) | Bloqueo de hilo en microservicio | Alarma de socket timeout | Conmutación inmediata a fallback local en CPU |
| Descalibración en casos OOD | Decisión errónea con certeza aparente | Medición de entropía de salida | Compuerta de abstención y escalado humano |

## 8. Validación propuesta

- **Hipótesis Falsable**: El guardián en CPU intercepta el 100% de llamadas a herramientas que excedan el rol asignado al usuario.
- **Métricas**: Tasa de bloqueo de herramientas no autorizadas (100%).
- **Criterio de Rechazo**: 0 ejecuciones de herramientas prohibidas en 300 intentos.
- **Estado**: Protocolo propuesto no ejecutado en producción.

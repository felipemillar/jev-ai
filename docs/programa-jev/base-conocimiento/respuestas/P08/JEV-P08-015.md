# JEV-P08-015 — Arquitecturas de Procesamiento: Por Eventos, Por Lotes y Bajo Demanda con Jev

## 1. Respuesta directa y decisión que permite tomar

La elección de arquitectura de procesamiento depende estrictamente del SLA: (1) Bajo demanda (síncrono) para UIs web interactivas que toleran <250 ms de latencia; (2) Por eventos (asíncrono) para triaje de correos o señales bursátiles desacopladas con RabbitMQ o Kafka; (3) Por lotes (batch) para análisis masivo de documentos históricos en ventanas nocturnas optimizando concurrencia.

## 5. Ejemplo sintético trabajado y contraejemplo o caso límite

### 5.1 Implementación en Python (SDK 0.7.0)

```python
import asyncio, logging
from typesafe_sdk import AsyncTypeSafeClient, Noul
logger = logging.getLogger('P08_15')

async def worker_asincrono(id_msg: str, texto: str) -> dict:
    try:
        async with AsyncTypeSafeClient(model='jev-1.13.0') as client:
            res = await client.system_one(state=texto, questions={'v': Noul(instructions='Evaluar si es prioritario')})
            return {'id': id_msg, 'prioridad': res.answers['v'].noul >= 0.7}
    except Exception as err:
        logger.error(f'Fallo worker: {type(err).__name__} (detalles omitidos por seguridad)')
        return {'id': id_msg, 'error': True}
```

### 5.2 Contraejemplo y Caso Límite

Procesar 50.000 documentos históricos mediante peticiones síncronas HTTP bloqueantes de a una colapsará el backend y tardará más de 6 horas por culpa de la latencia de red.

## 7. Fallos, límites, controles y condiciones de no uso

| Modo de Fallo | Impacto | Detección | Control / Mitigación |
|---|---|---|---|

# JEV-P09-013 — Diferencias de Despliegue: Contenedor Python, Microservicio TypeScript y Serverless

## 1. Respuesta directa y decisión que permite tomar

El despliegue de integraciones con Jev varía según el entorno de ejecución: en Python se recomienda un contenedor Docker con FastAPI y `typesafe_sdk 0.7.0` manteniendo conexiones HTTP/2 activas en un pool asíncrono; en TypeScript se emplea un cliente `fetch` tipado con Zod sin dependencias pesadas; y en Serverless (AWS Lambda, Cloud Run) debe configurarse warmup para reutilizar el socket TLS y evitar que la negociación de claves agregue 100 ms a cada invocación en frío.

## 4. Explicación técnica

Reutilización de conexiones: En entornos serverless, instanciar el cliente HTTP fuera del handler (`scope global`) para aprovechar el keep-alive del contenedor caliente entre ejecuciones sucesivas.

## 5. Ejemplo ilustrativo, verificación o contraejemplo

```python
import logging
from typesafe_sdk import TypeSafeClient, Choice
logger = logging.getLogger('P09_13')
CLIENTE_GLOBAL = None

def lambda_handler(event: dict, context) -> dict:
    global CLIENTE_GLOBAL
    try:
        if CLIENTE_GLOBAL is None:
            CLIENTE_GLOBAL = TypeSafeClient(model='jev-1.13.0')
        texto = event.get('body_text', '')
        res = CLIENTE_GLOBAL.system_one(state=texto, questions={'valido': Choice(instructions='Es valido', criteria={'si': 'Entidad o comprobación plenamente válida', 'no': 'Entidad o comprobación no válida'})})
        return {'statusCode': 200, 'decision': res.answers['valido'].choice}
    except Exception as err:
        logger.error(f'Fallo en ejecucion lambda: {type(err).__name__} (detalles omitidos por seguridad)')
        return {'statusCode': 500, 'error': 'error_interno'}
```

- **Contraejemplo / Caso borde**: Crear un nuevo `TypeSafeClient` dentro de cada ejecución de una función Lambda destruye el socket pool y multiplica por dos la latencia media.

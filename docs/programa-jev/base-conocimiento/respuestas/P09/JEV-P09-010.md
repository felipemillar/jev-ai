# JEV-P09-010 — Límites Documentados de Tamaño, Concurrencia y Detección de Cuotas Cambiantes

## 1. Respuesta directa y decisión que permite tomar

Los límites contractuales verificables de Jev 1.13 son: tamaño máximo de `state` de 32 KB (aproximadamente 8.000 tokens en UTF-8) y un máximo de 255 opciones discretas para una primitiva `Choice`. Los límites de concurrencia (solicitudes por segundo, RPS) y de cuota mensual dependen del tier comercial contratado y no están fijados de forma estática en la API. Toda aplicación debe detectar cuotas mediante inspección dinámica de cabeceras HTTP `RateLimit-*` y probing empírico.

## 4. Explicación técnica

Inspección de cabeceras de cuota: `RateLimit-Limit`, `RateLimit-Remaining`, `RateLimit-Reset` y `Retry-After`. Si el payload excede 32.768 bytes, el Gateway rechaza con HTTP 400 antes de pasar el mensaje a la GPU.

## 5. Ejemplo ilustrativo, verificación o contraejemplo

```python
# Ejemplo ilustrativo no ejecutado
import logging

logger = logging.getLogger("P09_10")

def validar_limites_previos(state_texto: str, opciones_choice: list) -> bool:
    try:
        tamano_bytes = len(state_texto.encode("utf-8"))
        if tamano_bytes > 32768:
            logger.warning(f"Payload excede limite: {tamano_bytes} > 32768 bytes")
            return False
        if len(opciones_choice) > 255 or len(opciones_choice) < 2:
            logger.warning(f"Opciones invalidas: {len(opciones_choice)}")
            return False
        return True
    except Exception as err:
        logger.error(f"Fallo en validacion: {type(err).__name__} (detalles omitidos por seguridad)")
        return False
```

- **Contraejemplo / Caso borde**: Concatenar múltiples archivos PDF en el campo `state` hasta alcanzar 100 KB causará un rechazo inmediato por parte de la API sin procesamiento.

## 8. Validación propuesta

- **Hipótesis Falsable**: La validación previa de longitud en cliente evita el 100% de los errores 400 por payload excesivo.
- **Métricas**: Tasa de errores 400 por tamaño de payload.
- **Criterio de Rechazo**: 0 errores 400 en 10.000 transacciones.
- **Estado**: Protocolo de validación propuesto para banco de pruebas local.

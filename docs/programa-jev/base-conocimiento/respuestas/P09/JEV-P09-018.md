# JEV-P09-018 — Protocolo ante Cambios Incompatibles en SDK o API y Reevaluación de Respuestas

## 1. Respuesta directa y decisión que permite tomar

Cualquier cambio incompatible (breaking change) en la API de TypeSafe o en `typesafe_sdk` (como la migración histórica de 0.1.0 a 0.7.0, o eventuales cambios en las firmas de primitivas) debe activar un protocolo formal de reevaluación técnica. Este protocolo incluye: congelamiento de versiones en producción, ejecución de la suite de contratos en staging, actualización de los esquemas en la base de conocimiento y re-auditoría de las respuestas afectadas.

## 2. Alcance, términos y supuestos

- **Ámbito de JEV-P09-018**: La delimitación de JEV-P09-018 establece las condiciones operacionales para «¿Qué cambios incompatibles de SDK, API o esquema deben activar migración y reevaluación de las respuestas técnicas de esta base».

## 4. Explicación técnica

Versionado Semántico (SemVer): Un incremento en la versión mayor (o cambios en versiones 0.x) detiene despliegues automáticos. Requiere matriz de compatibilidad documentada y pruebas de regresión contra contratos almacenados.

## 5. Ejemplo ilustrativo, verificación o contraejemplo

```python
# Ejemplo ilustrativo no ejecutado
import logging

logger = logging.getLogger("P09_18")

def evaluar_impacto_cambio_sdk(version_actual: str, version_nueva: str) -> dict:
    try:
        v_act = [int(x) for x in version_actual.split(".")]
        v_new = [int(x) for x in version_nueva.split(".")]
        
        # Rompimiento en 0.x si cambia el minor
        es_incompatible = (v_act[0] == 0 and v_new[1] > v_act[1]) or (v_new[0] > v_act[0])
        return {
            "version_actual": version_actual,
            "version_nueva": version_nueva,
            "requiere_auditoria_completa": es_incompatible
        }
    except Exception as err:
        logger.error(f"Fallo en calculo de version: {type(err).__name__} (detalles omitidos por seguridad)")
        return {"error": "version_invalida"}
```

- **Contraejemplo / Caso borde**: Actualizar ciegamente la versión del SDK en `requirements.txt` sin revisar breaking changes romperá la inicialización de `RetryPolicy` y `AsyncTypeSafeClient`.

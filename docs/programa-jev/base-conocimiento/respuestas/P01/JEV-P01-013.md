# JEV-P01-013 — Fallos Públicamente Reconocidos (*Model Jaggedness*) y su Delimitación Práctica en la Arquitectura

## 1. Respuesta directa y decisión que permite tomar
Los fallos y límites documentados oficialmente por TypeSafe AI en su guía *Model Jaggedness* (`docs.typesafe.ai/model-jaggedness/jev-1.13`) aportan una orientación de diseño mucho más valiosa y accionable que los casos de éxito promocionales. La documentación reconoce ocho fallos estructurales intrínsecos: (1) **literalidad extrema** (no deduce intenciones no declaradas ni lee entre líneas); (2) **ceguera aritmética y de conteo** (Jev no es una calculadora y falla sistemáticamente al contar elementos o sumar cantidades); (3) **fechas tratadas como texto opaco** (carece de comprensión cronológica y no puede determinar qué evento ocurrió antes o después); (4) **degradación por contexto ruidoso (*context rot*)** ante estados sobrecargados; (5) **incapacidad para razonamiento multi-paso o deducción indirecta**; (6) **vulnerabilidad a inyecciones adversariales indirectas** en el `state`; (7) **ausencia total de memoria o conocimiento externo** más allá de lo inyectado en la llamada; y (8) **incapacidad absoluta para generar prosa, código o texto libre**.

Estos límites delimitan estrictamente la arquitectura del software mediante el patrón cuádruple **Observe → Judge → Reason → Act**: el código tradicional calcula, filtra y parsea; Jev emite juicios semánticos tipados de alta velocidad en la capa *Judge*; los LLMs deliberativos (Sistema 2) o humanos intervienen únicamente ante baja confianza en la capa *Reason*; y el código anfitrión ejecuta las acciones finales en la capa *Act*. Esto permite **decidir prohibir taxativamente cualquier intento de realizar cálculos matemáticos, validaciones de fechas o generación textual con Jev**, obligando a que toda operación temporal o aritmética se resuelva en código determinista antes de enviar la petición.

## 4. Explicación técnica verificable
- **Por qué falla en matemáticas y fechas:** Jev no posee una pila de cálculo simbólico, decodificación con Scratchpad ni mecanismos de atención autorregresiva de cadena de pensamiento (*Chain-of-Thought*). Su arquitectura codificadora proyecta el estado completo en un espacio latente de embeddings estáticos y calcula la similitud con las opciones del enum mediante productos escalares. Para un codificador denso, `"2026-09-15"` y `"2026-08-30"` son secuencias de caracteres cuya proximidad vectorial refleja coocurrencia textual, no una recta numérica temporal orientada.
- **La Arquitectura Canónica *Observe → Judge → Reason → Act*:**
  ```
  [ DATOS CRUDOS ] 
         │
         ▼
  ┌─────────────────────────────────────────────────────────────┐
  │ 1. OBSERVE (Código Determinista)                            │
  │    - Parsea fechas: `is_expired = expiry_date < now()`      │
  │    - Cuenta ítems: `count = len(items)`                     │
  │    - Filtra ruido: extrae únicamente los campos semánticos  │
  └──────────────────────────────┬──────────────────────────────┘
                                 │ State estructurado
                                 ▼
  ┌─────────────────────────────────────────────────────────────┐
  │ 2. JUDGE (Jev - Sistema Uno)                                │
  │    - Evalúa en paralelo: Choice, Score, Noul (70–300 ms)    │
  │    - Emite probabilidades calibradas: `p = 0.92`            │
  └──────────────────────────────┬──────────────────────────────┘
                                 │
                  ┌──────────────┴──────────────┐
                  ▼                             ▼
       ¿Confianza >= Umbral?          ¿Confianza < Umbral?
            (ej. >= 0.85)                 (ej. < 0.85)
                  │                             │
                  │                             ▼
                  │               ┌─────────────────────────────┐
                  │               │ 3. REASON (Sistema Dos)     │
                  │               │    - LLM de frontera/Humano │
                  │               │    - Razonamiento profundo  │
                  │               │    - Redacta explicaciones  │
                  │               └─────────────┬───────────────┘
                  ▼                             │
  ┌─────────────────────────────────────────────▼───────────────┐
  │ 4. ACT (Código Determinista)                                │
  │    - Ejecuta mutación en base de datos, envía webhook o API │
  └─────────────────────────────────────────────────────────────┘
  ```

## 5. Ejemplo trabajado y contraejemplo
- **Ejemplo trabajado (Diseño correcto con preprocesamiento determinista):**
  - *Problema:* Determinar si un reclamo de garantía es válido y urgente en Wheelwork.
  - *Código correcto en host:*
    ```python
from datetime import datetime, timezone
from typesafe_sdk import TypeSafeClient, Choice, Noul

dias_desde_compra = (datetime.now(timezone.utc) - ticket.purchase_date).days
en_garantia = dias_desde_compra <= 365
numero_incidentes_previos = len(ticket.historial)
state = {'descripcion': ticket.mensaje_cliente, 'en_garantia_legal': en_garantia, 'incidentes_previos': numero_incidentes_previos, 'categoria_producto': ticket.categoria}
client = TypeSafeClient(model="jev-1.13.0")
res = client.system_one(
    state=str(state),
    questions={
        'severidad_percibida': Choice(
            instructions='Evaluar la severidad del ticket',
            criteria={'critica': 'Severidad crítica que detiene la operación', 'media': 'Severidad media con degradación parcial', 'baja': 'Severidad baja o consulta menor', 'otra': 'Otra categoría no contemplada'}
        ),
        'exige_reembolso_economico': Noul(
            instructions='Verificar si el cliente exige un reembolso económico explícito'
        )
    }
)
if not en_garantia and res.answers['exige_reembolso_economico'].noul > 0.8:
    notificar_rechazo_garantia_vencida()
```
  - *Resultado:* Cero errores de conteo o fecha; el juicio semántico se apoya en hechos ya calculados.
- **Contraejemplo (Antipatrón: Delegar aritmética y tiempo a Jev):**
  - Un desarrollador envía:
    `state = {"compra": "2025-11-03", "hoy": "2026-09-19", "mensajes": ["m1", "m2", "m3"]}` y pregunta a Jev:
    `jev.Noul("¿Han pasado más de 300 días y hay más de 2 mensajes?")`. Jev devuelve `0.94` alucinando que han pasado menos de 200 días debido a la ceguera de fecha, corrompiendo la auditoría de negocio.

## 6. Aplicación a nuestros desarrollos
- **QRT:**
  - Prohibir terminantemente que Jev evalúe si un precio superó una media móvil, si un volumen diario es atípico o si un evento ocurrió antes o después de la apertura del mercado. Todos los indicadores técnicos y tiempos deben ser precalculados en NumPy/Pandas y pasados como booleanos o enums discretos al `state`.
- **Wheelwork:**
  - Los años de experiencia laboral y la fecha de graduación de un candidato deben calcularse en Python determinista antes de formular la pregunta a Jev. Jev solo debe evaluar la afinidad semántica de las responsabilidades descritas.
- **Automatización de procesos:**
  - Nunca pedir a Jev que "cuente las filas de una tabla". El código anfitrión debe iterar sobre las filas y pedir a Jev que califique cada fila individualmente en paralelo.

## 7. Fallos, límites y controles
- **Modo de fallo 1: Context Rot por inyección de logs no estructurados.**
  - *Control:* Función de serialización estricta que aplique un esquema de reducción (resumen estructurado de máximo 1.500 tokens) antes de invocar la API.
- **Modo de fallo 2: Dependencia de razonamiento deductivo encadenado.**
  - *Control:* Descomponer las preguntas complejas en múltiples preguntas ortogonales evaluadas en paralelo mediante el *parallel sampler*.
- **Condición de no uso:** No usar Jev para auditar balances contables, conciliar transacciones bancarias, verificar cronogramas de entrega o procesar estados con texto malicioso no sanitizado.

## 8. Validación propuesta
- **Hipótesis falsable:** "En un test de 200 comparaciones temporales ('¿Ocurrió la fecha A antes de la fecha B?'), la precisión de `jev-1.13.0` será indistinguible del azar ($45\% \le \text{Accuracy} \le 55\%$), demostrando la ceguera cronológica absoluta del modelo."
- **Comparador:** Jev `Noul` vs función determinista de Python `datetime.fromisoformat(A) < datetime.fromisoformat(B)`.
- **Datos:** 200 pares de fechas en formato ISO-8601 generadas aleatoriamente entre 2020 y 2026.
- **Métricas:** Tasa de acierto binario y Brier Score.
- **Criterio de rechazo:** Si el accuracy de Jev resulta $\ge 75.0\%$, la hipótesis de ceguera cronológica total se considerará refutada.
- **Estado:** *Propuesta, no ejecutada.* (Costo estimado: <$0.20 USD en tokens).

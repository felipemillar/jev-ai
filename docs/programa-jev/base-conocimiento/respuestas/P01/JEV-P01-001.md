# JEV-P01-001 — Identificación Canónica de Jev, Proveedor, Versiones y Homónimos

## 1. Respuesta directa y decisión que permite tomar
«Jev» designa formalmente al modelo fundacional comercial desarrollado por la empresa **TypeSafe AI Inc.** (startup de San Francisco fundada por Diogo Almeida, Erik Gafni y Sasha Sheng). Su versión de producción oficial es **`jev-1.13.0`** (con alias mutable `jev-latest` y `jev-preview`), consumible exclusivamente mediante la llamada `POST https://api.typesafe.ai/v1/systemone` o pasarelas autorizadas (Vercel AI Gateway). No es un LLM generativo autorregresivo ni un bot conversacional, sino un motor de inferencia reactiva tipada («System One»). Esta distinción exige fijar `model="jev-1.13.0"` en el SDK `typesafe_sdk` y descartar categóricamente proyectos homónimos como **`jeff`** (`logan-markewich/jeff`, réplica comunitaria sobre GLiFormer de 400M parámetros) o la extinta Typesafe Inc. (hoy Lightbend, ecosistema Scala).

## 4. Explicación técnica verificable
La arquitectura de Jev no emite secuencias abiertas de texto token a token. El cliente envía un payload a `POST /v1/systemone`:
```json
{
  "state": "<contexto documental o serializado>",
  "model": "jev-1.13.0",
  "questions": {
    "q1": {"type": "choice", "instructions": "...", "criteria": {"A": "...", "B": "..."}}
  }
}
```
El motor evalúa el estado una sola vez para todas las preguntas en paralelo y devuelve una respuesta estrictamente tipada:
- `Choice`: `choice` (str), `probabilities` (map[str, float]), `confidence` (float 0..1).
- `Score`: `score` (float), `legend` (map[str, str]), `probabilities` (map[str, float]), `confidence` (float 0..1).
- `Noul`: `noul` (float 0..1 representando P(yes)). No incluye campo `confidence` nativo.

## 5. Ejemplo trabajado y contraejemplo
- **Ejemplo trabajado (Llamada válida al contrato Jev):**
```python
# Ejemplo ilustrativo no ejecutado
import logging
from typesafe_sdk import TypeSafeClient, Choice

logger = logging.getLogger(__name__)

def clasificar_soporte(mensaje: str) -> dict:
    try:
        client = TypeSafeClient(model="jev-1.13.0")
        res = client.system_one(
            state=mensaje,
            questions={
                "categoria": Choice(
                    instructions="Clasifique el problema operativo",
                    criteria={
                        "facturacion": "Cobros, facturas o reembolsos",
                        "tecnico": "Caídas de API o fallos de conexión",
                        "cuenta": "Credenciales o accesos"
                    }
                )
            }
        )
        ans = res.answers["categoria"]
        return {"choice": ans.choice, "confidence": ans.confidence, "prob": ans.probabilities}
    except Exception as err:
        logger.error(f"Fallo en clasificar_soporte: {type(err).__name__} (detalles omitidos por seguridad)")
        return {"choice": "abstencion", "confidence": 0.0, "prob": {}}
```
- **Contraejemplo (Invocación errónea asumiendo generación de texto o endpoint `/choice`):**
Intentar llamar a `POST /v1/choice` o pedirle a Jev que "redacte un correo de disculpa" provoca un error de endpoint inexistente (`404`) o una respuesta vacía, dado que Jev no posee decodificador de prosa libre.

## 6. Aplicación a nuestros desarrollos
- **QRT (Trading Cuantitativo):** Fijar `jev-1.13.0` como versión inmutable en el archivo de configuración del broker/feed. Prohibir alias mutables para evitar que una actualización externa altere la distribución de probabilidades en backtesting.
- **Wheelwork (Operaciones y Headhunting):** Configurar el SDK oficial con validación estricta de variables de entorno (`TYPESAFE_API_KEY`). Si se usa `jeff` en entornos offline de desarrollo, rotularlo claramente como simulador sintético.

## 7. Fallos, límites y controles
- **Modo de fallo 1: Mutación silenciosa por alias.** `jev-latest` puede apuntar a una versión futura con calibración distinta.
  - *Control:* Validar en la compuerta de arranque que `response.model == "jev-1.13.0"`.
- **Modo de fallo 2: Confusión de paquetes en PyPI.** Descarga accidental de paquetes no oficiales como `jev-ai` o `open-jev`.
  - *Control:* Fijar `typesafe-sdk==0.7.0` con hash SHA-256 en `requirements.txt`.

## 8. Validación propuesta
- **Protocolo de verificación documental:** Contrastar mensualmente el endpoint `GET https://api.typesafe.ai/v1/models` contra la tabla de modelos soportados.
- **Criterio de cierre:** Verificar que `jev-1.13.0` continúe activo y que cualquier nuevo modelo sea evaluado en un entorno aislado antes de actualizar configuraciones.

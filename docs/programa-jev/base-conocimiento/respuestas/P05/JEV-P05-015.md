# JEV-P05-015: Distinción entre Desacuerdo Humano Legítimo, Error del Modelo y Mala Calibración

## 1. Respuesta directa y decisión que permite tomar

En tareas cognitivas complejas en Wheelwork y QRT (e.g., evaluar si una cláusula contractual es "abusiva", si una infracción vehicular constituye "negligencia inexcusable", o si una noticia de mercado es "materialmente relevante"), es un hecho empírico que **los propios expertos humanos entrenados discrepan entre sí**. Si tres analistas seniors revisan un contrato y dos dictaminan "APROBADO" y uno dictamina "OBSERVADO", el fenómeno en el mundo real no tiene una etiqueta binaria dura unívoca.

El error metodológico recurrente consiste en colapsar el juicio humano a una sola etiqueta mediante voto por mayoría ($y = 1$) y penalizar a Jev 1.13 si devuelve una probabilidad $p = 0.65$. En este escenario, **la salida $p = 0.65$ de Jev no es un error ni una mala calibración; es un reflejo matemáticamente fiel de la incertidumbre aleatoria intrínseca (*Aleatoric Uncertainty*) del problema**.

Para desentrañar rigurosamente los tres fenómenos, la arquitectura de auditoría debe separar formalmente:

1. **Incertidumbre Aleatoria / Desacuerdo Humano Legítimo**:
   - Ocurre cuando el texto presenta ambigüedad semántica o margen de interpretación jurídica.
   - *Detección*: Medición de la concordancia inter-anotador ($\kappa$ de Fleiss o $\alpha$ de Krippendorff $< 0.70$). La etiqueta canónica se modela como una **distribución blanda (*Soft Label*)**: $\mathbf{y}^* = [0.67, 0.33]$.
   - *Juicio sobre Jev*: Si la divergencia de Kullback-Leibler $D_{\text{KL}}(\mathbf{p}_{\text{Jev}} \parallel \mathbf{y}^*) \approx 0$, el modelo es calificado como **perfectamente honesto y calibrado ante la duda humana**.
2. **Error Real del Modelo (Falla Cognitiva)**:
   - Ocurre cuando el consenso humano es unánime ($\kappa \ge 0.90$, e.g., 5 de 5 expertos acuerdan que el documento es una falsificación descarada), pero Jev asigna $p(\text{Falsificación}) = 0.05$.
   - *Diagnóstico*: Falla de percepción semántica o atencional del codificador denso; Jev omitió un hecho causal evidente.
3. **Mala Calibración (Distorsión de Escala)**:
   - Ocurre cuando el modelo acierta en el orden relativo de las opciones, pero sus logits están artificialmente estirados (sobreconfianza extrema, e.g., predice $0.999$ en casos donde la tasa real de certeza humana es del $75\%$).
   - *Diagnóstico*: Descalibración corregible mediante Temperature Scaling en CPU.

**Decisión que permite tomar**: Prohibir la evaluación de Jev contra un único anotador humano en tareas complejas. Adoptar un protocolo de **Anotación Multi-Experto con Etiquetas Blandas (*Soft Labels*)** para medir incertidumbre aleatoria, reservando la evaluación binaria dura exclusivamente a casos con consenso humano unánime ($\ge 90\%$).

### 4.2. Formulación Matemática de la Divergencia de Incertidumbre

Sea $\mathbf{y}^* = [y^*_1, \dots, y^*_K]$ la distribución empírica de votos de $M$ humanos para una instancia:
$$y^*_k = \frac{1}{M} \sum_{m=1}^M \mathbf{1}(\text{Anotador}_m = k)$$

Sea $\mathbf{p} = [p_1, \dots, p_K]$ la distribución predicha por Jev 1.13.

Se calcula la **Divergencia de Kullback-Leibler ($D_{\text{KL}}$)**:
$$D_{\text{KL}}(\mathbf{y}^* \parallel \mathbf{p}) = \sum_{k=1}^K y^*_k \ln\left( \frac{y^*_k}{p_k + \epsilon} \right)$$
- Si $D_{\text{KL}} \le 0.05$: El modelo captura con precisión la distribución de ambigüedad humana.
- Si $D_{\text{KL}} > 0.40$: Existe una discrepancia severa atribuible a error del modelo o descalibración grave.

### 5.1. Código en Python: Diagnóstico de Desacuerdo vs Error vs Calibración

```python
# Ejemplo ilustrativo no ejecutado
"""
Módulo de Diagnóstico Tripartito: Desacuerdo Humano, Error de Modelo y Calibración en CPU.
"""
import numpy as np
from typing import Dict, Any, List

class HumanDisagreementDiagnostic:
    def __init__(self, kl_threshold: float = 0.15, consensus_threshold: float = 0.85):
        self.kl_thresh = kl_threshold
        self.consensus_thresh = consensus_threshold

    def diagnosticar_caso(self, 
                          votos_humanos: List[str], 
                          probabilidades_jev: Dict[str, float], 
                          clases: List[str]) -> Dict[str, Any]:
        """
        Clasifica la naturaleza del fallo o acierto de Jev.
        """
        total_votos = len(votos_humanos)
        # 1. Construir Soft Label humano
        y_soft = np.array([votos_humanos.count(c) / total_votos for c in clases])
        p_model = np.array([probabilidades_jev.get(c, 1e-7) for c in clases])
        p_model = np.clip(p_model, 1e-7, 1.0)
        p_model = p_model / np.sum(p_model) # Normalizar

        # 2. Concordancia máxima humana
        max_consenso = np.max(y_soft)
        clase_consenso = clases[np.argmax(y_soft)]

        # 3. Divergencia KL
        eps = 1e-9
        d_kl = np.sum(y_soft * np.log((y_soft + eps) / (p_model + eps)))

        # 4. Clasificación del Diagnóstico
        top_choice_jev = clases[np.argmax(p_model)]
        max_p_jev = np.max(p_model)

        if max_consenso >= self.consensus_thresh:
            # Hay consenso humano claro (Ground truth duro válido)
            if top_choice_jev == clase_consenso:
                if max_p_jev > 0.98 and max_consenso < 0.95:
                    diagnostico = "MALA_CALIBRACION_SOBRECONFIANZA"
                    desc = "Modelo acertó la opción, pero infló su certeza a 0.99 (requiere Temperature Scaling)."
                else:
                    diagnostico = "ACIERTO_VALIDO"
                    desc = "Consenso humano claro y modelo acertó con confianza calibrada."
            else:
                diagnostico = "ERROR_REAL_MODELO"
                desc = f"Humanos acordaron unánimemente '{clase_consenso}', pero Jev predijo '{top_choice_jev}'. Falla cognitiva."
        else:
            # Desacuerdo humano legítimo (Ambigüedad aleatoria)
            if d_kl <= self.kl_thresh:
                diagnostico = "DESACUERDO_HUMANO_LEGITIMO_HONESTO"
                desc = f"Caso ambiguo. Jev modeló la distribución de duda humana con precisión (D_KL={d_kl:.3f})."
            else:
                diagnostico = "DESALINEACION_EN_AMBIGUEDAD"
                desc = f"Caso ambiguo, pero Jev sesgó su predicción sin respetar la distribución humana (D_KL={d_kl:.3f})."

        return {
            "max_consenso_humano": round(float(max_consenso), 2),
            "clase_mayoritaria_humana": clase_consenso,
            "distribucion_humana": {c: round(float(y_soft[i]), 2) for i, c in enumerate(clases)},
            "distribucion_jev": {c: round(float(p_model[i]), 2) for i, c in enumerate(clases)},
            "divergencia_kl": round(float(d_kl), 4),
            "diagnostico_final": diagnostico,
            "explicacion": desc
        }

if __name__ == "__main__":
    diag = HumanDisagreementDiagnostic()
    clases = ["APROBADO", "RECHAZADO"]

    # Caso 1: Desacuerdo humano genuino (3 humanos dicen APROBADO, 2 dicen RECHAZADO)
    # Jev predice 60% APROBADO, 40% RECHAZADO
    votos_c1 = ["APROBADO", "APROBADO", "APROBADO", "RECHAZADO", "RECHAZADO"]
    jev_c1 = {"APROBADO": 0.60, "RECHAZADO": 0.40}
    r1 = diag.diagnosticar_caso(votos_c1, jev_c1, clases)
    print("=== CASO 1: AMBIGÜEDAD CONTEXTUAL ===")
    print(f"Diagnóstico: {r1['diagnostico_final']} -> {r1['explicacion']}\n")

    # Caso 2: Error real de Jev (5 humanos unánimes en RECHAZADO, Jev predice APROBADO al 90%)
    votos_c2 = ["RECHAZADO"] * 5
    jev_c2 = {"APROBADO": 0.90, "RECHAZADO": 0.10}
    r2 = diag.diagnosticar_caso(votos_c2, jev_c2, clases)
    print("=== CASO 2: FALLA REAL DE JEV ===")
    print(f"Diagnóstico: {r2['diagnostico_final']} -> {r2['explicacion']}\n")

    # Caso 3: Mala calibración (Humanos 4 de 5 = 80% APROBADO, Jev predice 99.9% APROBADO)
    votos_c3 = ["APROBADO"] * 4 + ["RECHAZADO"] * 1
    jev_c3 = {"APROBADO": 0.999, "RECHAZADO": 0.001}
    r3 = diag.diagnosticar_caso(votos_c3, jev_c3, clases)
    print("=== CASO 3: SOBRECONFIANZA ARTIFICIAL ===")
    print(f"Diagnóstico: {r3['diagnostico_final']} -> {r3['explicacion']}")
```

### 5.2. Contraejemplo y Caso Límite: El Despido Injustificado de un Modelo Excelente por Culpa de un Voto Forzado

En una auditoría de contratos en QRT, se evalúa una cláusula de fuerza mayor en un contrato de derivados:
- 5 abogados revisan la cláusula: 3 afirman que cubre una pandemia y 2 afirman que no la cubre (ambigüedad legal real).
- El sistema tradicional de evaluación impone la regla de la mayoría simple: declara que la etiqueta verdadera es $Y = 1$ ("Cubre Pandemia").
- Jev 1.13 evalúa el texto y entrega $P(\text{Cubre}) = 0.58$ y $P(\text{No Cubre}) = 0.42$.
- El auditor simplista calcula: *"El modelo predijo 0.58, lo que es un Falso Negativo si el umbral fuera 0.60, o una baja certeza inadmisible"*.
- **La falacia**: Si el modelo hubiera predicho $P = 0.99$, el auditor simplista lo habría felicitado, premiando una sobreconfianza falsa y peligrosa. Jev predijo exactamente lo que la comunidad jurídica opina ($58\%$ vs $42\%$).
- **Manejo correcto**: La métrica de divergencia KL califica la respuesta de Jev con honores ($D_{\text{KL}} = 0.003$), reconociendo que el caso es indecidible sin un juicio humano y derivándolo a revisión legal.

## 7. Fallos, límites, controles y condiciones de no uso

### 7.1. Modos de falla y mitigaciones

| Modo de Falla | Causa Raíz | Detección | Mitigación Arquitectónica |
|---|---|---|---|
| **Anotadores Incompetentes Disfrazados de Ambigüedad** | Contratar etiquetadores no calificados que introducen ruido aleatorio por descuido. | Kappa inter-anotador colapsa en tareas objetivas simples ($\kappa < 0.40$). | Filtrar y calificar a los anotadores mediante casos dorados (*gold trap questions*). |
| **Consenso Artificial por Fatiga** | Múltiples analistas aprueban todo por prisa, simulando un consenso falso del 100%. | Entropía anormalmente baja y tiempo medio por revisión menor a 10 segundos. | Auditorías aleatorias de segundo orden por auditores independientes. |
| **Falsa Ambigüedad en Tareas Deterministas** | Tratar discrepancias en cálculos matemáticos o fechas como "opiniones subjetivas válidas". | Discordancia en campos numéricos exactos en bases de datos. | Regla estricta: los hechos aritméticos y normativos se validan en CPU, no por votación. |

### 7.2. Condiciones de NO uso

- **NO utilizar evaluación multi-humano con un solo revisor**: Es matemáticamente imposible discernir error de desacuerdo con un $N=1$ de anotadores.
- **NO tolerar desacuerdo humano en el cumplimiento de requisitos legales taxativos**: Si una ley exige un documento formal, la falta del documento es una infracción objetiva, no un tema de debate subjetivo.

# JEV-P12-009 — Despliegue en Modo Observación (Shadow Mode / Dark Launch) sin Impacto en Producción

## 1. Respuesta directa y decisión que permite tomar

Antes de autorizar que una nueva versión de Jev, una actualización de prompt o un cambio en los parámetros de la API afecten decisiones en producción, el nuevo flujo debe ejecutarse en Modo Observación (Shadow Mode) durante un mínimo de 7 días. El sistema productivo duplica las solicitudes reales de forma asíncrona hacia el componente en prueba, registrando las divergencias de clasificación pero ejecutando únicamente la decisión del sistema ya validado.

## 4. Explicación técnica

Duplicación asíncrona no bloqueante: El hilo transaccional responde al usuario con la decisión del modelo A; un worker en background (Celery/Kafka) despacha la misma entrada al modelo B (Shadow) y guarda ambas respuestas en una tabla de divergencia.

## 5. Ejemplo ilustrativo, verificación o contraejemplo

```python
# Ejemplo ilustrativo no ejecutado
import logging

logger = logging.getLogger("P12_09")

def comparar_divergencia_shadow(decision_activa: str, decision_shadow: str) -> dict:
    try:
        coinciden = decision_activa == decision_shadow
        registro = {
            "modelo_activo": decision_activa,
            "modelo_shadow": decision_shadow,
            "divergencia": not coinciden
        }
        if not coinciden:
            logger.info(f"Divergencia observada en Shadow Mode: {decision_activa} vs {decision_shadow}")
        return registro
    except Exception as err:
        logger.error(f"Fallo en comparador shadow: {type(err).__name__} (detalles omitidos por seguridad)")
        return {"divergencia": True}
```

- **Contraejemplo / Caso borde**: Cambiar el prompt de clasificación de gastos y desplegarlo directamente a producción provocará que decenas de facturas legítimas sean rechazadas por discrepancias no evaluadas.

## 7. Fallos conocidos, advertencias y contraindicaciones

| Modo de Fallo | Impacto Operativo | Detección Temprana | Mitigación Arquitectónica |
| :--- | :--- | :--- | :--- |
| Despliegue directo sin modo observación | Errores masivos en procesos de negocio reales | Pipeline obligatorio de Shadow Mode de 7 días | Requerir coincidencia >= 95% para autorizar |
| Agotamiento de sockets por conexiones no cerradas | Fuga de descriptores de archivos y crash | Monitoreo de descriptores de socket | Context managers asíncronos obligatorios |
| Desbordamiento de colas de memoria ante picos | Out of Memory (OOM) en contenedor | Métricas de memoria en Prometheus | Colas acotadas con descarte ordenado (backpressure) |

## 8. Validación propuesta

- **Hipótesis Falsable**: El modo observación detecta el 90% de los desajustes semánticos antes de que impacten al negocio.
- **Métricas**: Divergencias imprevistas detectadas en producción post-lanzamiento.
- **Criterio de Rechazo**: Menos de 2% de discrepancias no anticipadas en el corte definitivo.
- **Estado**: Protocolo de validación propuesto para banco de pruebas local.

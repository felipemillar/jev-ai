# JEV-P12-011 — Estrategia de Despliegue Gradual (Canary Releases) sin Sesgos de Estacionalidad

## 1. Respuesta directa y decisión que permite tomar

El despliegue de cambios en producción debe ejecutarse mediante Canary Releases controladas: 5% del tráfico en el Día 1, 20% en el Día 2, 50% en el Día 3 y 100% en el Día 4. Para evitar que la estacionalidad (diferencias entre fin de semana y días laborables) o sesgos de cohorte distorsionen la evaluación, el enrutamiento hacia la versión Canary debe asignarse deterministamente mediante el hash consistente del identificador de usuario (`hash(user_id) % 100 < canary_pct`).

## 4. Explicación técnica

Enrutador determinista por hash: Garantiza que un mismo usuario experimente una versión consistente durante toda su sesión, evitando alternancias caóticas entre el sistema legado y el nuevo.

## 5. Ejemplo ilustrativo, verificación o contraejemplo

```python
# Ejemplo ilustrativo no ejecutado
import zlib, logging

logger = logging.getLogger("P12_11")

def seleccionar_version_canary(user_id: str, porcentaje_canary: int = 10) -> str:
    try:
        # Hash consistente de 0 a 99
        valor_hash = zlib.crc32(user_id.encode("utf-8")) % 100
        if valor_hash < porcentaje_canary:
            return "VERSION_CANARY_NUEVA"
        return "VERSION_ESTABLE_ACTUAL"
    except Exception as err:
        logger.error(f"Fallo en enrutamiento canary: {type(err).__name__} (detalles omitidos por seguridad)")
        return "VERSION_ESTABLE_ACTUAL" 
```

- **Contraejemplo / Caso borde**: Dirigir el tráfico de la versión Canary solo los lunes por la mañana y compararlo con el sistema estable el domingo por la tarde inducirá falsas conclusiones por estacionalidad de tráfico.

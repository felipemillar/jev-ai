# JEV-P12-002 — Taxonomía de Errores Operativos: Reintentos Resilientes vs Corrección de Configuración

## 1. Respuesta directa y decisión que permite tomar

El sistema operativo debe diferenciar estrictamente entre errores transitorios (red, congestión de API) y errores permanentes (esquema, credenciales, límites de negocio). Errores HTTP 400 y 422 denotan payloads inválidos que jamás deben reintentarse; Error 401 exige detener llamadas y rotar claves; Error 429 (Too Many Requests) y Errores 5xx deben reintentarse utilizando la clase `RetryPolicy` con `backoff_initial`, `backoff_max`, `backoff_jitter` y `timeout` configurados.

## 4. Explicación técnica

Estrategia Full Jitter: Tiempo de espera $t_i = \min(t_{\max}, t_{\text{base}} \cdot 2^i) \cdot U(1 - j, 1 + j)$. Si tras 3 reintentos el error persiste, se aborta la transacción y se deriva al flujo degradado.

## 5. Ejemplo ilustrativo, verificación o contraejemplo

```python
import asyncio, logging
from typesafe_sdk import AsyncTypeSafeClient, Choice, RetryPolicy
logger = logging.getLogger('P12_02')

async def ejecutar_inferencia_resiliente(texto_solicitud: str) -> dict:
    try:
        politica = RetryPolicy(backoff_initial=0.4, backoff_max=4.0, backoff_jitter=0.25, timeout=8.0)
        async with AsyncTypeSafeClient(model='jev-1.13.0', retry=politica) as client:
            res = await client.system_one(state=texto_solicitud, questions={'prioridad': Choice(instructions='Nivel de urgencia', criteria={'baja': 'Nivel de urgencia bajo o rutinario', 'alta': 'Nivel de urgencia alto o prioritario'})})
            return {'prioridad': res.answers['prioridad'].choice}
    except Exception as err:
        logger.error(f'Fallo tras agotar reintentos: {type(err).__name__} (detalles omitidos por seguridad)')
        return {'prioridad': 'baja', 'modo': 'degradado'}
```

- **Contraejemplo / Caso borde**: Reintentar ciegamente un error 422 causado por un campo mal estructurado satura la red y consume CPU inútilmente.

## 8. Validación propuesta

- **Hipótesis Falsable**: La política de reintento con jitter absorbe el 95% de los micro-cortes de red sin impacto en el usuario.
- **Métricas**: Tasa de recuperación exitosa tras primer fallo de conexión.
- **Criterio de Rechazo**: Recuperación >= 90% ante fallos transitorios simulados.

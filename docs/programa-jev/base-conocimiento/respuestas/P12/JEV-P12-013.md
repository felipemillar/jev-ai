# JEV-P12-013 — Muestreo Estratificado para Retroalimentación Humana sin Sesgo de Selección

## 1. Respuesta directa y decisión que permite tomar

Para mantener un conjunto de datos representativo de ground truth, la auditoría humana no debe limitarse exclusivamente a los casos escalados o de baja confianza. Auditar solo los casos difíciles introduce un sesgo de selección severo que distorsiona la medición de la precisión real. Debe implementarse un muestreo estratificado continuo: 70% de casos de baja certeza ($|2p-1| < 0.3$), 20% de casos de certeza media y un 10% aleatorio de casos de alta certeza para descubrir falsos positivos silenciosos.

## 4. Explicación técnica

Estratificación de auditoría: Asignar a cada transacción una probabilidad de selección inversamente proporcional a la certeza del modelo, reservando una cuota uniforme para control negativo aleatorio.

## 5. Ejemplo ilustrativo, verificación o contraejemplo

```python
# Ejemplo ilustrativo no ejecutado
import random, logging

logger = logging.getLogger("P12_13")

def debe_enviarse_a_auditoria_humana(confianza_modelo: float) -> bool:
    try:
        # Casos de baja confianza se auditan siempre
        if confianza_modelo < 0.65:
            return True
        # Muestreo aleatorio de control para casos de alta confianza (5%)
        if random.random() < 0.05:
            return True
        return False
    except Exception as err:
        logger.error(f"Fallo en selector de auditoria: {type(err).__name__} (detalles omitidos por seguridad)")
        return True
```

- **Contraejemplo / Caso borde**: Revisar únicamente las decisiones donde el modelo dudó impedirá detectar que el modelo está aprobando con 99% de confianza transacciones fraudulentas bien camufladas.

## 7. Fallos conocidos, advertencias y contraindicaciones

| Modo de Fallo | Impacto Operativo | Detección Temprana | Mitigación Arquitectónica |
| :--- | :--- | :--- | :--- |
| Muestreo sesgado solo en casos difíciles | Falsos positivos silenciosos no detectados | Estratificación obligatoria con cuota aleatoria | Auditar al menos 5% de decisiones de alta certeza |
| Agotamiento de sockets por conexiones no cerradas | Fuga de descriptores de archivos y crash | Monitoreo de descriptores de socket | Context managers asíncronos obligatorios |
| Desbordamiento de colas de memoria ante picos | Out of Memory (OOM) en contenedor | Métricas de memoria en Prometheus | Colas acotadas con descarte ordenado (backpressure) |

## 8. Validación propuesta

- **Hipótesis Falsable**: La inclusión de casos aleatorios de alta certeza detecta un 80% más de falsos negativos silenciosos.
- **Métricas**: Tasa de errores de alta confianza descubiertos por auditoría.
- **Criterio de Rechazo**: Identificación regular de discrepancias en la cuota aleatoria.
- **Estado**: Protocolo de validación propuesto para banco de pruebas local.

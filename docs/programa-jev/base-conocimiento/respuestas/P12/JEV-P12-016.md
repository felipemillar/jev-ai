# JEV-P12-016 — Invalidación de Caché Semántica durante Actualizaciones de Modelos y Reglas de Negocio

## 1. Respuesta directa y decisión que permite tomar

Las cachés semánticas en Redis aceleran la respuesta ante entradas recurrentes, pero representan un riesgo grave de servir decisiones obsoletas cuando cambian las reglas de negocio, las instrucciones del prompt o la versión del modelo. La clave de caché debe incluir obligatoriamente el hash de la configuración activa: `cache:v2:{model_version}:{prompt_hash}:{state_hash}`. Al desplegar una nueva versión, el cambio de prefijo invalida instantáneamente todas las entradas previas.

## 4. Explicación técnica

Namespace Versioning: Prefijar claves con un identificador de despliegue `v2.4`. Cuando el despliegue avanza a `v2.5`, las consultas buscan bajo el nuevo prefijo; las claves anteriores caducan de forma natural mediante su tiempo de expiración (TTL de 24 horas).

## 5. Ejemplo ilustrativo, verificación o contraejemplo

```python
# Ejemplo ilustrativo no ejecutado
import hashlib, logging

logger = logging.getLogger("P12_16")

def construir_clave_cache_versionada(version_modelo: str, prompt_instrucciones: str, texto_estado: str) -> str:
    try:
        hash_reglas = hashlib.sha256(prompt_instrucciones.encode("utf-8")).hexdigest()[:10]
        hash_input = hashlib.sha256(texto_estado.encode("utf-8")).hexdigest()[:16]
        return f"cache:semantica:{version_modelo}:{hash_reglas}:{hash_input}"
    except Exception as err:
        logger.error(f"Fallo en clave de cache: {type(err).__name__} (detalles omitidos por seguridad)")
        return "" 
```

- **Contraejemplo / Caso borde**: Cambiar las reglas de aprobación salarial en el backend pero no purgar la caché de Redis provocará que se sigan aprobando aumentos con la regla anterior.

## 7. Fallos conocidos, advertencias y contraindicaciones

| Modo de Fallo | Impacto Operativo | Detección Temprana | Mitigación Arquitectónica |
| :--- | :--- | :--- | :--- |
| Decisiones obsoletas servidas desde caché | Inconsistencia de reglas de negocio | Versionado de claves con hash de prompt | TTL máximo de 24 horas en Redis |
| Agotamiento de sockets por conexiones no cerradas | Fuga de descriptores de archivos y crash | Monitoreo de descriptores de socket | Context managers asíncronos obligatorios |
| Desbordamiento de colas de memoria ante picos | Out of Memory (OOM) en contenedor | Métricas de memoria en Prometheus | Colas acotadas con descarte ordenado (backpressure) |

## 8. Validación propuesta

- **Hipótesis Falsable**: El versionado de claves de caché garantiza cero lecturas de respuestas generadas con reglas obsoletas.
- **Métricas**: Discrepancias entre la decisión cacheada y la regla vigente.
- **Criterio de Rechazo**: 0 lecturas de reglas desactualizadas post-despliegue.
- **Estado**: Protocolo de validación propuesto para banco de pruebas local.

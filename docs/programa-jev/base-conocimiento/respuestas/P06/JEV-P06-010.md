# JEV-P06-010: Costo por Resultado Aceptado: Contabilización Holística de Abstenciones, Escalamientos, Errores y Revisión Humana

## 1. Respuesta directa y decisión que permite tomar

Calcular el coste de implementar Jev 1.13 multiplicando simplemente el precio por llamada a la API (e.g., *"10,000 llamadas a \$0.0002 cuestan \$2.00 USD"*) es una ilusión contable que distorsiona gravemente la economía del proyecto. En un sistema de producción real, el coste directo de la API representa con frecuencia **menos del $1\%$ del Coste Total de Propiedad (*Total Cost of Ownership - TCO*)**. El verdadero indicador que debe regir la viabilidad económica es el **Coste por Resultado Aceptado ($C_{\text{aceptado}}$)**:

$$C_{\text{aceptado}} = \frac{\text{Coste Total Operacional del Sistema}}{\text{Número Total de Decisiones Válidamente Aceptadas}}$$

donde el numerador desglosa todos los costes directos e indirectos causados por el flujo automatizado:

$$\text{Coste Total} = N \cdot C_{\text{API}} + N_{\text{escalados}} \cdot C_{\text{humano}} + N_{\text{errores\_ocultos}} \cdot C_{\text{daño}} + N_{\text{abstenciones}} \cdot C_{\text{reintento}}$$

y el denominador corresponde exclusivamente a las decisiones correctas finales:
$$N_{\text{aceptadas}} = N_{\text{auto\_correctas}} + N_{\text{humano\_correctas}}$$

**Implicación Crítica**: Si Jev se abstiene o escala a revisión humana un $15\%$ del tráfico en un flujo donde la revisión manual cuesta \$5.00 USD por ticket, el coste de los analistas humanos (\$750 USD por cada 1,000 casos) eclipsa por completo los \$0.20 USD cobrados por TypeSafe AI. Del mismo modo, un solo falso positivo no detectado con impacto financiero (\$200 USD) anula el ahorro de cientos de miles de llamadas baratas.

**Decisión que permite tomar**: Prohibir la justificación de pilotos basada en el bajo coste de la API de TypeSafe; exigir que todo caso de negocio en Wheelwork y QRT presente la curva de coste por resultado aceptado modelando la compensación entre coste de revisión humana, coste de errores no mitigados y tasa de cobertura autónoma.

## 4. Explicación técnica verificable

### 4.1. Estructura de la Ecuación Económica Holística

Para un volumen de $N$ decisiones recibidas por el sistema:

1. **Partición de Cobertura y Enrutamiento**:
   - $N_{\text{auto}} = c \cdot N$ (casos resueltos automáticamente con cobertura $c \in [0, 1]$).
   - $N_{\text{escalados}} = (1 - c) \cdot N$ (casos derivados a revisión humana).
2. **Desglose de Resultados en Flujo Automático**:
   - $N_{\text{auto\_correctas}} = N_{\text{auto}} \cdot \text{Acc}_{\text{auto}}(c)$
   - $N_{\text{errores\_ocultos}} = N_{\text{auto}} \cdot (1 - \text{Acc}_{\text{auto}}(c))$
3. **Desglose de Resultados en Revisión Humana**:
   - $N_{\text{humano\_correctas}} = N_{\text{escalados}} \cdot \text{Acc}_{\text{humano}}$
   - $N_{\text{errores\_humanos}} = N_{\text{escalados}} \cdot (1 - \text{Acc}_{\text{humano}})$
4. **Cálculo del Coste por Decisión Aceptada**:
   $$C_{\text{aceptado}}(c) = \frac{N \cdot C_{\text{API}} + N_{\text{escalados}} \cdot C_{\text{humano}} + N_{\text{errores\_ocultos}} \cdot C_{\text{daño}} + N_{\text{errores\_humanos}} \cdot C_{\text{daño}}}{N_{\text{auto\_correctas}} + N_{\text{humano\_correctas}}}$$

### 5.1. Implementación en Python: Optimizador de TCO y Coste por Resultado Aceptado

```python
# Ejemplo ilustrativo no ejecutado
"""
Módulo de Contabilidad Holística y Optimización de Coste por Resultado Aceptado para Jev.
Modela compensaciones entre cobertura, escalamiento humano y coste de errores.
"""

from typing import Dict, Any, List
import numpy as np
import logging

logger = logging.getLogger("TCOCalculator")

class HolisticTCOOptimizer:
    def __init__(
        self,
        coste_api_unitario: float = 0.0003,
        coste_revision_humana: float = 4.50,
        coste_error_oculto: float = 120.0,
        coste_friccion_reintento: float = 0.50,
        acc_humano: float = 0.98
    ):
        self.c_api = coste_api_unitario
        self.c_humano = coste_revision_humana
        self.c_error = coste_error_oculto
        self.c_friccion = coste_friccion_reintento
        self.acc_humano = acc_humano

    def evaluate_operating_point(
        self,
        total_cases: int,
        coverage: float,
        acc_auto: float
    ) -> Dict[str, Any]:
        """
        Calcula el desglose contable para un punto operativo dado (cobertura y precisión automática).
        """
        try:
            n = total_cases
            c = coverage

            n_auto = int(n * c)
            n_escalados = n - n_auto

            n_auto_correct = int(n_auto * acc_auto)
            n_auto_error = n_auto - n_auto_correct

            n_humano_correct = int(n_escalados * self.acc_humano)
            n_humano_error = n_escalados - n_humano_correct

            total_accepted = n_auto_correct + n_humano_correct
            if total_accepted == 0:
                raise ValueError("Cero decisiones aceptadas en la simulación.")

            # Componentes de Coste
            cost_api_total = n * self.c_api
            cost_humano_total = n_escalados * self.c_humano
            cost_error_total = (n_auto_error + n_humano_error) * self.c_error

            total_system_cost = cost_api_total + cost_humano_total + cost_error_total
            cost_per_accepted = total_system_cost / total_accepted

            return {
                "coverage_percent": round(c * 100, 1),
                "accuracy_auto_percent": round(acc_auto * 100, 2),
                "total_accepted_decisions": total_accepted,
                "cost_api_usd": round(cost_api_total, 2),
                "cost_human_usd": round(cost_humano_total, 2),
                "cost_error_damages_usd": round(cost_error_total, 2),
                "total_tco_usd": round(total_system_cost, 2),
                "cost_per_accepted_decision_usd": round(cost_per_accepted, 4),
                "human_cost_share_percent": round((cost_humano_total / total_system_cost) * 100, 1),
                "api_cost_share_percent": round((cost_api_total / total_system_cost) * 100, 3)
            }

        except Exception as err:
            logger.error(f"Error en cálculo de TCO: {type(err).__name__} (detalles omitidos por seguridad)")
            return {"error": f"Fallo de cálculo: {type(err).__name__}"}


if __name__ == "__main__":
    optimizer = HolisticTCOOptimizer(
        coste_api_unitario=0.0003,
        coste_revision_humana=5.00,  # $5 USD por ticket revisado por analista
        coste_error_oculto=150.00,  # $150 USD por factura mal conciliada
        acc_humano=0.99
    )

    N = 10000

    print("--- ANÁLISIS DE SENSIBILIDAD DE TCO (N=10,000 Transacciones) ---")

    # Escenario 1: Cobertura Conservadora (50% auto, muy alta precisión 98%)
    s1 = optimizer.evaluate_operating_point(N, coverage=0.50, acc_auto=0.98)
    print(f"\nEscenario 1 (Conservador c=50%): Coste/Aceptado: ${s1['cost_per_accepted_decision_usd']} USD")
    print(f" - Coste Humano: ${s1['cost_human_usd']} ({s1['human_cost_share_percent']}%) | API: ${s1['cost_api_usd']} ({s1['api_cost_share_percent']}%)")

    # Escenario 2: Cobertura Óptima Calibrada (80% auto, precisión 94%)
    s2 = optimizer.evaluate_operating_point(N, coverage=0.80, acc_auto=0.94)
    print(f"\nEscenario 2 (Óptimo c=80%): Coste/Aceptado: ${s2['cost_per_accepted_decision_usd']} USD")
    print(f" - Coste Humano: ${s2['cost_human_usd']} | Coste Errores: ${s2['cost_error_damages_usd']} | Total: ${s2['total_tco_usd']}")

    # Escenario 3: Cobertura Temeraria Naive (100% auto ciego, precisión cae a 88%)
    s3 = optimizer.evaluate_operating_point(N, coverage=1.00, acc_auto=0.88)
    print(f"\nEscenario 3 (Temerario c=100%): Coste/Aceptado: ${s3['cost_per_accepted_decision_usd']} USD")
    print(f" - Coste Errores: ${s3['cost_error_damages_usd']} USD (Explosión por 1,200 fallos inadvertidos)")
```

### 5.2. Caso Límite / Contraejemplo

Una empresa de logística reemplazó su equipo de 10 analistas de aduanas por un modelo de IA promocionado como *"solución a \$0.001 por documento"*.
- Forzaron una cobertura del **100% sin escalamiento humano** para maximizar el ahorro.
- El modelo procesó 50,000 declaraciones de importación a un coste de API de apenas **\$50 USD** (la gerencia creyó haber ahorrado \$40,000 en sueldos).
- Sin embargo, el modelo tuvo un error del 2.5% en la asignación de partidas arancelarias complejas (1,250 errores inadvertidos).
- El Servicio Nacional de Aduanas detectó los descalces en auditoría posterior y cursó multas e intereses por **\$380,000 USD**, paralizando además las operaciones del puerto durante 2 semanas.
- **La realidad contable**: Cada declaración "aceptada" no costó \$0.001; costó **\$7.60 USD**, casi el doble de lo que cobraba el equipo humano experto.

## 6. Aplicación a nuestros desarrollos

### 6.1. Wheelwork (Liquidación de Facturas y Conciliación)
- **Hecho**: Cada factura revisada por un analista contable de Wheelwork cuesta aproximadamente \$3.50 USD en tiempo laboral; un error de liquidación no detectado acarrea multas bancarias y descalces de caja de \$100 a \$500 USD.
- **Hipótesis de desarrollo**: Wheelwork debe parametrizar la función de TCO para encontrar la **cobertura óptima calibrada ($c^*$)**. El modelo sugiere que una cobertura del **72% a 78%** minimiza el coste por factura aceptada a menos de **\$1.15 USD** (reduciendo en un 67% el gasto respecto al 100% manual, sin disparar el riesgo de error).

### 6.2. QRT (Cuadernos Cuantitativos y Costes de Ejecución)
- **Hecho**: En trading cuantitativo, el coste de llamada de API es insignificante comparado con el coste de deslizamiento (*slippage*) o la pérdida de capital por una señal errónea.
- **Hipótesis de desarrollo**: QRT debe prohibir evaluar a Jev por el coste de sus tokens. La única métrica de coste válida en QRT es el **Coste por Alpha Aceptado**: el rendimiento neto generado por las operaciones filtradas deduciendo comisiones, impacto de mercado y pérdidas por falsas alarmas.

## 7. Fallos, límites, controles y condiciones de no uso

### 7.1. Modos de Fallo
1. **Contabilidad Parcial (Silo Contable)**: El departamento de TI celebra el bajo gasto en la factura mensual de TypeSafe AI, mientras el departamento de operaciones sufre un sobrecoste de horas extra para revisar casos ambiguos derivados por el modelo.
2. **Ignorar el Coste de Remediación**: Asumir que un error se arregla "con una llamada telefónica", sin contabilizar las horas de abogados, analistas y la pérdida de reputación de clientes.

### 7.2. Controles Mandatorios
- **Panel Unificado de Finanzas Operacionales**: El dashboard del piloto debe mostrar en tiempo real el coste acumulado de API, el coste estimado de horas analista y las pérdidas provisionadas por fallos.
- **Punto de Parada por Desbordamiento de TCO**: Si el coste medio por decisión aceptada supera en un 10% el coste histórico de la línea base humana durante 14 días consecutivos, el piloto se suspende para re-calibrar umbrales.

### 7.3. Condiciones de No Uso
- Prohibido desplegar flujos con cobertura del 100% desatendida si el coste de un fallo inadvertido supera en $1,000\times$ el coste de una revisión humana.

# JEV-P06-003: Construcción de Conjuntos Representativos de Evaluación: Datos Públicos, Sintéticos y Límites de Transferencia

## 1. Respuesta directa y decisión que permite tomar

Para evaluar Jev 1.13 sin comprometer datos confidenciales ni violar normativas de privacidad (RGPD o Ley 19.628), los equipos deben construir un **Conjunto de Evaluación Progresivo Tripartito (CEPT)** compuesto por:

1. **Datos Públicos Análogos**: Corpus de dominio abierto con anotaciones de referencia (e.g., reclamos de la CFPB para disputas bancarias, filings 10-K de SEC EDGAR para análisis corporativo o contratos públicos del Estado).
2. **Generación Sintética Controlada por Gramáticas y Clústeres**: Producción de variaciones lingüísticas mediante LLMs generativos potentes (System 2) condicionados a esquemas formales, inyectando variabilidad léxica, modismos sectoriales, ruido ortográfico y casos límite intencionales (*hard negatives*).
3. **Muestra Auditada de Dominio Real Anonimizada**: Un conjunto pequeño ($N \ge 300$) de datos reales de producción completamente disociados de PII para medir la brecha de simulación.

**El Límite de Transferencia (*Sim-to-Real Gap*)** debe documentarse de forma explícita y cuantitativa mediante la **Penalización por Transferencia ($\Delta_{\text{transfer}}$)**:

$$\Delta_{\text{transfer}} = \text{F1}(\mathcal{D}_{\text{sintético}}) - \text{F1}(\mathcal{D}_{\text{real}})$$

Si $\Delta_{\text{transfer}} > 0.08$ o el *Population Stability Index* (PSI) entre los embeddings de ambos conjuntos supera $0.25$, se declara formalmente que **el benchmark sintético no es representativo** y queda estrictamente prohibido certificar umbrales de producción basándose exclusivamente en él.

**Decisión que permite tomar**: Prohibir la toma de decisiones finales de compra o despliegue basadas únicamente en benchmarks sintéticos o públicos; exigir que toda evaluación con datos sintéticos incluya la hoja de caracterización del límite de transferencia y una validación de anclaje con datos reales auditados.

## 4. Explicación técnica verificable

### 4.1. El Protocolo de Construcción del Dataset CEPT

```
┌─────────────────────────────────────────────────────────────────────────────┐
│             ARQUITECTURA DE ENSAMBLAJE DE DATASETS DE EVALUACIÓN            │
├─────────────────────────────────────────────────────────────────────────────┤
│ 1. MATRIZ TAXONÓMICA DE CASOS (ESTRUCTURA DE COBERTURA)                     │
│    - Casos Típicos (Happy Path): 50% de la muestra                         │
│    - Casos Límite y Hard Negatives: 30% (Negaciones complejas, ambigüedad)   │
│    - Casos con Ruido Operativo: 20% (Tipeo, modismos, formatos truncados)   │
├─────────────────────────────────────────────────────────────────────────────┤
│ 2. INGESTIÓN Y SINTETIZACIÓN SEGURA                                         │
│    - Datos Públicos Análogos (SEC / CFPB / Contratos públicos)             │
│    - Generador Sintético System 2 (Llama-3-70B / GPT-4o) con restricciones  │
│    - Verificación de Inyección de Nonces y Canarios para detectar fuga      │
├─────────────────────────────────────────────────────────────────────────────┤
│ 3. CURACIÓN Y ANOTACIÓN HUMANA CON ADJUDICACIÓN                             │
│    - 3 Anotadores independientes sobre submuestra representativa            │
│    - Acuerdo inter-anotador Fleiss' Kappa >= 0.80                           │
├─────────────────────────────────────────────────────────────────────────────┤
│ 4. MEDICIÓN DEL LÍMITE DE TRANSFERENCIA (SIM-TO-REAL AUDIT)                 │
│    - Calcular PSI entre sintético y real en embeddings locales              │
│    - Medir Delta_transfer = F1_sintetico - F1_real                          │
│    - Publicar Hoja de Caracterización de Límites                            │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 4.2. Matriz de Hard Negatives Obligatorios en el Conjunto de Prueba

Para garantizar que el modelo no dependa de asociaciones espurias de palabras clave (*shortcut learning*), el benchmark sintético debe incluir obligatoriamente tres categorías de *Hard Negatives*:
1. **Inversión de Polaridad por Negación Distante**: El texto incluye todas las palabras de una compra exitosa, pero finaliza con: *"sin embargo, la operación fue rechazada por el cajero automático"*.
2. **Condicionales y Supuestos Ficticios**: Textos redactados como consultas hipotéticas: *"¿Qué pasaría si transfiriera USD 10,000 a una cuenta en Suiza?"* (no es una transacción real).
3. **Colisión Léxica Homonímica**: Términos con doble sentido según el contexto (e.g., *"liquidación de temporada"* comercial vs. *"liquidación de sueldo"* laboral).

### 5.1. Implementación en Python: Generador Sintético y Validador del Límite de Transferencia

```python
# Ejemplo ilustrativo no ejecutado
"""
Módulo de Generación y Cuantificación de Límites de Transferencia para Jev.
Evalúa la divergencia entre el rendimiento en datos sintéticos y datos reales.
"""

from typing import List, Dict, Any, Tuple
import numpy as np
from sklearn.metrics import f1_score
import logging

logger = logging.getLogger("TransferLimitValidator")

class TransferLimitAuditor:
    def __init__(self, max_tolerated_delta_f1: float = 0.08):
        self.max_tolerated_delta_f1 = max_tolerated_delta_f1

    def audit_transfer_gap(
        self,
        y_true_synth: List[int],
        y_pred_synth: List[int],
        y_true_real: List[int],
        y_pred_real: List[int]
    ) -> Dict[str, Any]:
        """
        Calcula la brecha de generalización entre el benchmark sintético y el entorno real.
        """
        try:
            f1_synth = f1_score(y_true_synth, y_pred_synth, average="macro")
            f1_real = f1_score(y_true_real, y_pred_real, average="macro")
            delta_transfer = f1_synth - f1_real

            is_valid = delta_transfer <= self.max_tolerated_delta_f1

            return {
                "f1_synthetic_benchmark": round(float(f1_synth), 4),
                "f1_real_production_sample": round(float(f1_real), 4),
                "transfer_penalty_delta": round(float(delta_transfer), 4),
                "is_transfer_acceptable": is_valid,
                "status": (
                    "TRANSFERIBILIDAD_CERTIFICADA"
                    if is_valid
                    else "FALLO_SIM_TO_REAL_GAP_EXCESIVO"
                ),
                "recommendation": (
                    "El benchmark sintético es un proxy confiable para calibrar umbrales."
                    if is_valid
                    else "ADVERTENCIA: No utilizar los umbrales del benchmark sintético en producción."
                )
            }

        except Exception as err:
            logger.error(
                f"Error al auditar el límite de transferencia: {type(err).__name__} (detalles omitidos por seguridad)"
            )
            return {
                "status": "ERROR_DE_AUDITORIA",
                "is_transfer_acceptable": False,
                "details": f"Fallo en cálculo: {type(err).__name__}"
            }


if __name__ == "__main__":
    auditor = TransferLimitAuditor(max_tolerated_delta_f1=0.08)

    # Simulación 1: Caso con Transferencia Exitosa
    # El benchmark sintético modeló adecuadamente el ruido real
    np.random.seed(42)
    y_synth_true = [1] * 500 + [0] * 500
    y_synth_pred = [1 if np.random.rand() < 0.94 else 0 for _ in range(500)] + \
                   [0 if np.random.rand() < 0.93 else 1 for _ in range(500)]

    y_real_true = [1] * 150 + [0] * 150
    y_real_pred = [1 if np.random.rand() < 0.91 else 0 for _ in range(150)] + \
                  [0 if np.random.rand() < 0.89 else 1 for _ in range(150)]

    res_ok = auditor.audit_transfer_gap(y_synth_true, y_synth_pred, y_real_true, y_real_pred)
    print("Auditoría 1 (Aceptable):", res_ok["status"], "| Delta:", res_ok["transfer_penalty_delta"])

    # Simulación 2: Colapso por Sim-to-Real Gap
    # El benchmark sintético era demasiado simple (F1=0.98), pero en la realidad colapsa (F1=0.75)
    y_real_bad_pred = [1 if np.random.rand() < 0.76 else 0 for _ in range(150)] + \
                      [0 if np.random.rand() < 0.74 else 1 for _ in range(150)]

    res_bad = auditor.audit_transfer_gap(y_synth_true, y_synth_pred, y_real_true, y_real_bad_pred)
    print("\nAuditoría 2 (Fallo severo):", res_bad["status"], "| Delta:", res_bad["transfer_penalty_delta"])
    print("Recomendación:", res_bad["recommendation"])
```

### 5.2. Caso Límite / Contraejemplo

Un equipo de compliance evaluó a Jev para detectar cláusulas abusivas en contratos inmobiliarios.
- Generaron 2,000 contratos sintéticos con GPT-4 usando oraciones breves y claras con gramática estándar. Jev obtuvo un impresionante **Macro-F1 de 0.97**.
- Confiados en este resultado, desplegaron Jev en producción para auditar contratos notariales chilenos escaneados.
- En producción real, los contratos contenían párrafos de 80 líneas sin puntos seguidos, referencias cruzadas a leyes de 1975 y términos notariales arcaicos (*"fojas", "otorgose"*).
- El Macro-F1 real cayó a **0.68** ($\Delta_{\text{transfer}} = 0.29$), provocando que decenas de cláusulas ilegales pasaran desapercibidas.
- **Lección**: Si no se audita la brecha sintética frente a documentos reales, el benchmark sintético es una ilusión peligrosa.

## 6. Aplicación a nuestros desarrollos

### 6.1. Wheelwork (Screening de CVs y Reclutamiento)
- **Hecho**: No se pueden usar currículums reales con nombres y datos de contacto de candidatos chilenos en benchmarks abiertos debido a normativas de protección de datos personales.
- **Hipótesis de desarrollo**: Wheelwork debe construir un generador sintético parametrizado que produzca 1,000 perfiles laborales con terminología chilena (*"Líder técnico", "práctica profesional en Codelco", "experiencia en SAP"*), inyectando distractores y hard negatives (e.g. candidatos que mencionan una tecnología solo porque hicieron un curso de 2 horas en YouTube). La transferencia se certificará comparando contra 100 CVs reales despersonalizados y auditados por los reclutadores senior.

### 6.2. QRT (Cuadernos Cuantitativos y Eventos de Mercado)
- **Hecho**: Las minutas de los bancos centrales son documentos públicos, pero escasos en volumen (apenas 8 publicaciones por año).
- **Hipótesis de desarrollo**: QRT puede generar escenarios macroeconómicos sintéticos (*"Shock inflacionario por materias primas con tasas restrictivas"*), pero debe documentar que el límite de transferencia es crítico: el mercado reacciona a sutilezas léxicas no capturables en datos sintéticos. Por tanto, el benchmark de Jev en QRT debe anclarse estrictamente en transcripciones históricas reales de Bloomberg y Reuters entre 2008 y 2025.

## 7. Fallos, límites, controles y condiciones de no uso

### 7.1. Modos de Fallo
1. **Contaminación por Preentrenamiento**: Utilizar datasets públicos estándar (e.g., SQuAD, AG News, GLUE) que muy probablemente formaron parte del entrenamiento masivo de Jev, obteniendo métricas artificialmente infladas.
2. **Homogeneidad Sintética**: Generar datos sintéticos con un único prompt repetitivo, creando un conjunto de datos con idéntica estructura oracional y vocabulario redundante.

### 7.2. Controles Mandatorios
- **Prueba de Diversidad de Embeddings**: Calcular la varianza promedio de la distancia del coseno intra-dataset. Si la diversidad léxica del conjunto sintético es menor al 60% de la del conjunto real, el dataset sintético se descarta y debe re-generarse con mayor temperatura y variabilidad de prompts.

### 7.3. Condiciones de No Uso
- Prohibido certificar el pase a producción de un flujo con impacto legal o financiero usando exclusivamente datos generados por LLMs sin una muestra de control real.

### 8.1. Hipótesis Falsable

### 8.2. Diseño Experimental
- **Tipo**: Propuesta, no ejecutada.
- **Conjunto Sintético**: $N = 1,000$ casos generados con taxonomía de competencias de Wheelwork.
- **Conjunto Real**: $N = 200$ decisiones históricas anonimizadas con consenso unánime de 3 reclutadores.
- **Evaluación**: Ejecución ciega pareada de Jev 1.13 sobre ambos conjuntos con el mismo prompt y temperatura.
- **Criterio de Rechazo**: Si $\Delta_{\text{transfer}} > 0.08$, la hipótesis se rechaza y se procede a una re-calibración del generador sintético.
- **Presupuesto Supuesto**: USD \$30 en créditos de generación LLM y 12 horas hombre de analista ($\approx \text{USD \$650}$).

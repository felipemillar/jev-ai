# JEV-P06-006: Justificación Estadística del Tamaño de Muestra: Frecuencia de Error Crítico, Efecto Mínimo Detectable y Precisión

## 1. Respuesta directa y decisión que permite tomar

Determinar el tamaño de muestra ($N$) para evaluar a Jev 1.13 de forma arbitraria (e.g., *"probemos con 50 o 100 casos que tenemos a mano"*) produce estudios estadísticamente inválidos con **Baja Potencia Estadística ($1 - \beta < 0.50$)**, incapaces de distinguir si una supuesta mejora es una ventaja real del modelo o mero ruido estocástico. Peor aún, con muestras pequeñas es matemáticamente imposible certificar la ausencia de fallos críticos infrecuentes.

Para justificar rigurosamente el tamaño muestral de un benchmark independiente de Jev, la arquitectura debe aplicar **Tres Criterios Estadísticos Formales**:

1. **Cálculo por Efecto Mínimo Detectable (MDE) y Potencia Estadística**:
   - Para contrastar a Jev contra una línea base en un diseño pareado (Test de McNemar) buscando detectar una diferencia mínima de $\delta = 0.04$ (4 puntos de mejora) con significancia $\alpha = 0.01$ y potencia $1 - \beta = 0.85$, se requiere un mínimo de **$N \ge 850$ a $1,200$ casos pareados**.
2. **Regla del Tres para Errores Críticos Raros (*Rule of Three*)**:
   - Si el SLA de seguridad prohíbe que la tasa de errores catastróficos supere el $0.1\%$ ($p_{\text{error}} \le 0.001$), para certificar con un **$95\%$ de confianza** que la tasa real está por debajo de ese límite cuando no se observa ningún error en la prueba, el tamaño muestral debe satisfacer:
     $$N_{\text{seguridad}} \ge \frac{3}{p_{\text{tolerado}}} = \frac{3}{0.001} = 3,000 \text{ casos}$$
3. **Cálculo por Margen de Error Deseado (Precisión del Intervalo de Confianza)**:
   - Para acotar el margen de error de la estimación de precisión en un intervalo estrecho de $\pm 2\%$ ($W = 0.02$) con confianza del $95\%$ asumiendo una precisión esperada del $90\%$, se requieren al menos **$N \ge 865$ casos**. Si se exige un margen de $\pm 1\%$, el requerimiento asciende a **$N \ge 3,460$ casos**.

**Decisión que permite tomar**: Fijar un umbral mínimo institucional de **$N \ge 1,000$ casos** para cualquier benchmark de comparación general y **$N \ge 3,000$ casos** para certificación de flujos autónomos de alto riesgo sin supervisión humana en Wheelwork y QRT. Prohibir la toma de decisiones basada en muestras $< 500$ casos.

## 4. Explicación técnica verificable

### 4.1. Fórmulas de Dimensionamiento Muestral

#### A. Para Estimar una Proporción con Margen de Error $W$
$$N_{\text{margen}} = \frac{Z_{\alpha/2}^2 \cdot \hat{p}(1 - \hat{p})}{W^2}$$
Para $\alpha = 0.05 \implies Z_{\alpha/2} = 1.96$. Si la precisión estimada es $\hat{p} = 0.92$ y se busca un margen de $W = 0.015$ ($\pm 1.5\%$):
$$N = \frac{(1.96)^2 \cdot 0.92 \cdot 0.08}{(0.015)^2} = \frac{3.8416 \cdot 0.0736}{0.000225} \approx 1,257 \text{ casos}$$

#### B. Para Pruebas Pareadas de Comparación (Test de McNemar)
Para comparar dos modelos evaluados en los mismos datos donde $p_{\text{discordante}}$ es la tasa de casos donde un modelo acierta y el otro falla:
$$N_{\text{mcnemar}} = \frac{\left( Z_{\alpha/2} \cdot \sqrt{p_{\text{disc}}} + Z_{\beta} \cdot \sqrt{p_{\text{disc}} - \delta^2} \right)^2}{\delta^2}$$
donde $\delta = |p_1 - p_2|$ es el MDE buscado.

### 5.1. Implementación en Python: Calculadora de Potencia y Tamaño Muestral

```python
# Ejemplo ilustrativo no ejecutado
"""
Módulo de Cálculo de Tamaño Muestral y Potencia Estadística para Benchmarks de Jev.
Implementa estimaciones por MDE, margen de error e infrecuencia de fallos críticos.
"""

import math
from typing import Dict, Any
from scipy import stats
import logging

logger = logging.getLogger("SampleSizeEngine")

class SampleSizeCalculator:
    @staticmethod
    def calculate_for_precision(
        expected_accuracy: float = 0.90,
        margin_of_error: float = 0.02,
        confidence_level: float = 0.95
    ) -> int:
        """
        Calcula el N necesario para acotar la precisión con un margen de error fijo.
        """
        try:
            alpha = 1.0 - confidence_level
            z = stats.norm.ppf(1.0 - alpha / 2.0)
            p = expected_accuracy
            n = (z ** 2 * p * (1.0 - p)) / (margin_of_error ** 2)
            return int(math.ceil(n))
        except Exception as err:
            logger.error(f"Error en cálculo de precisión: {type(err).__name__} (detalles omitidos por seguridad)")
            return 1000

    @staticmethod
    def calculate_for_rare_failure(
        max_tolerated_error_rate: float = 0.001,
        confidence_level: float = 0.95
    ) -> int:
        """
        Calcula el N requerido bajo la Regla del Tres (o logarítmica generalizada)
        para certificar con confianza dada que el error está bajo la tasa máxima.
        """
        try:
            # -ln(1 - confidence) / p
            n = -math.log(1.0 - confidence_level) / max_tolerated_error_rate
            return int(math.ceil(n))
        except Exception as err:
            logger.error(f"Error en regla de error raro: {type(err).__name__} (detalles omitidos por seguridad)")
            return 3000

    @staticmethod
    def calculate_for_mcnemar_power(
        base_accuracy: float = 0.88,
        mde: float = 0.04,
        alpha: float = 0.01,
        power: float = 0.85
    ) -> int:
        """
        Calcula el N aproximado para un test pareado de McNemar buscando un efecto MDE.
        """
        try:
            z_alpha = stats.norm.ppf(1.0 - alpha / 2.0)
            z_beta = stats.norm.ppf(power)

            # Asumimos que los desacuerdos entre modelos rondan el 2 * MDE
            p_disc = 2.5 * mde

            num = (z_alpha * math.sqrt(p_disc) + z_beta * math.sqrt(p_disc - mde**2)) ** 2
            n = num / (mde ** 2)
            return int(math.ceil(n))
        except Exception as err:
            logger.error(f"Error en cálculo de potencia: {type(err).__name__} (detalles omitidos por seguridad)")
            return 1200


if __name__ == "__main__":
    calc = SampleSizeCalculator()

    n_prec = calc.calculate_for_precision(expected_accuracy=0.92, margin_of_error=0.015, confidence_level=0.95)
    print(f"N requerido para margen de error +/- 1.5% (Acc=92%): {n_prec} casos")

    n_rare = calc.calculate_for_rare_failure(max_tolerated_error_rate=0.001, confidence_level=0.95)
    print(f"N requerido para certificar error catastrófico < 0.1%: {n_rare} casos (Regla del Tres)")

    n_power = calc.calculate_for_mcnemar_power(base_accuracy=0.88, mde=0.04, alpha=0.01, power=0.85)
    print(f"N requerido para detectar mejora de +4% con potencia 85% (alpha=0.01): {n_power} casos")
```

### 5.2. Caso Límite / Contraejemplo

Un equipo de operaciones probó Jev en 40 transacciones para verificar si cometía errores de pago duplicado.
- En los 40 casos, Jev acertó el 100% ($0$ errores observados).
- El equipo concluyó alegremente: *"Jev tiene 100% de precisión y cero fallos; pasemos a producción"*.
- **La realidad estadística**: Bajo la Regla del Tres, observar 0 fallos en 40 casos solo garantiza que la verdadera tasa de error está **por debajo del $3/40 = 7.5\%$** con un 95% de confianza.
- Al desplegar el modelo en un flujo de 100,000 pagos mensuales, un error del $2\%$ (perfectamente compatible con los 40 casos de prueba) causó **2,000 transferencias duplicadas en el primer mes**, generando un descubierto financiero masivo.
- **Lección**: 40 casos no demuestran nada en fiabilidad industrial.

- **Hecho**: Las caídas abruptas de mercado (*Flash Crashes*) son eventos extremos con una frecuencia histórica menor al $0.5\%$ de las sesiones.
- **Hipótesis de desarrollo**: Para certificar que Jev no sufrirá un falso negativo crítico durante un evento de liquidez extrema, QRT debe utilizar un dataset histórico extendido con al menos **$N \ge 600$ sesiones de alta volatilidad** seleccionadas mediante muestreo por importancia (*Importance Sampling*), o admitir que la garantía estadística no puede emitirse.

## 7. Fallos, límites, controles y condiciones de no uso

### 7.1. Modos de Fallo
1. **Falso Poder por Pseudorreplicación**: Medir 1,000 casos pero que corresponden a 50 transacciones repetidas 20 veces cada una, destruyendo la independencia muestral efectiva ($N_{\text{efectivo}} = 50$).
2. **Ignorar Subpoblaciones Minoritarias**: Lograr $N=1,000$ global, pero una clase crítica minoritaria solo cuenta con 12 casos, impidiendo cualquier conclusión sobre esa categoría.

### 7.2. Controles Mandatorios
- **Cálculo de $N_{\text{subpoblación}}$**: Toda clase individual en un esquema `Choice` debe contar con un mínimo de **$N_k \ge 100$ casos** en el benchmark para ser considerada certificada.
- **Auditoría de Independencia de Casos**: Comprobar mediante hashes que no existen duplicados exactos ni cuasi-duplicados inflando el tamaño de muestra.

### 7.3. Condiciones de No Uso
- Prohibido autorizar pilotos autónomos si el tamaño de muestra del benchmark de validación no cumple con la Regla del Tres para la tasa máxima tolerable de fallos del negocio.

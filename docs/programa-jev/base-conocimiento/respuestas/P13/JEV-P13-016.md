# JEV-P13-016 — Prevención de Distorsiones Financieras por Cuotas Gratuitas o Créditos Temporales

## 1. Respuesta directa y decisión que permite tomar

Es un error común de diseño evaluar la viabilidad de un sistema utilizando el costo cero de créditos promocionales, tiers gratuitos o subsidios temporales de nubes públicas. Toda proyección financiera, caso de negocio y cálculo de punto de equilibrio debe realizarse utilizando exclusivamente las tarifas de lista oficiales en régimen permanente ($0.042/Mtok). Los créditos gratuitos deben contabilizarse únicamente como amortización del costo inicial de desarrollo y nunca como ahorro operativo recurrente.

## 4. Explicación técnica

Contabilidad en precios sombra (Shadow Pricing): El sistema de control de costos de la empresa debe registrar dos métricas en paralelo: Facturación Real Cobrada ($0 si hay créditos) y Costo a Tarifa Plena. La viabilidad del flujo se decide exclusivamente sobre la segunda.

## 5. Ejemplo ilustrativo, verificación o contraejemplo

```python
# Ejemplo ilustrativo no ejecutado
import logging

logger = logging.getLogger("P13_16")

def evaluar_sostenibilidad_post_creditos(tokens_mensuales: int, creditos_restantes_usd: float) -> dict:
    try:
        costo_tarifa_plena = (tokens_mensuales / 1000000.0) * 0.042
        meses_cobertura = creditos_restantes_usd / max(costo_tarifa_plena, 0.001)
        return {
            "costo_pleno_mensual_usd": round(costo_tarifa_plena, 2),
            "meses_creditos_restantes": round(meses_cobertura, 1),
            "presupuesto_post_promocion": round(costo_tarifa_plena * 12, 2)
        }
    except Exception as err:
        logger.error(f"Fallo en evaluacion de creditos: {type(err).__name__} (detalles omitidos por seguridad)")
        return {}
```

- **Contraejemplo / Caso borde**: Lanzar un servicio que procesa 10 millones de tokens diarios creyendo que es gratis porque hay $5.000 USD de créditos que se agotarán en dos semanas.

## 7. Fallos conocidos, advertencias y contraindicaciones

| Modo de Fallo | Impacto Operativo | Detección Temprana | Mitigación Arquitectónica |
| :--- | :--- | :--- | :--- |
| Dependencia de subsidios temporales | Choque financiero y apagado de proyectos al expirar créditos | Proyecciones a tarifa plena desde el Día 1 | Tratar créditos solo como amortización de capex |
| Aumento sorpresivo de tarifas del proveedor | Incremento del costo operativo | Monitoreo semanal de facturación | Patrón Adapter para conmutar a alternativas locales |
| Ignorar el costo humano de la tasa de escalamiento | Déficit financiero en el proyecto | Telemetría de casos derivados a humanos | Calibración de umbrales para limitar escalamiento a <= 8% |

## 8. Validación propuesta

- **Hipótesis Falsable**: El uso de precios sombra previene el 100% de las sorpresas presupuestarias post-expiración de créditos.
- **Métricas**: Desviación del gasto post-expiración de promociones frente a la proyección.
- **Criterio de Rechazo**: Gasto real dentro del 5% de la proyección a tarifa plena.
- **Estado**: Protocolo de validación propuesto para banco de pruebas local.

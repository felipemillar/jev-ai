# JEV-P14-014 — Propuesta de Organización de Calendario Respetando Restricciones Duras

## 1. Respuesta directa y decisión que permite tomar

El asistente de calendario debe tratar las restricciones temporales (bloques de concentración protegidos, horarios de comida, citas fijas previas) como restricciones duras deterministas e inviolables en CPU. Jev puede evaluar la compatibilidad temática o urgencia cualitativa de una solicitud de reunión para proponer un hueco disponible, pero el modelo jamás debe tener permisos para crear, modificar o eliminar eventos en Google Calendar sin la revisión y clic confirmatorio del usuario.

## 4. Explicación técnica

Constraint Satisfaction Problem (CSP): Un script en Python calcula los bloques vacíos de más de 45 minutos fuera del horario protegido. Jev evalúa si la reunión encaja mejor en la mañana o en la tarde; el resultado se presenta como sugerencia en pantalla.

## 5. Ejemplo ilustrativo, verificación o contraejemplo

```python
# Ejemplo ilustrativo no ejecutado
import logging

logger = logging.getLogger("P14_14")

def proponer_bloque_calendario(bloques_libres: list, asunto_reunion: str) -> dict:
    try:
        if not bloques_libres:
            return {"resultado": "SIN_DISPONIBILIDAD", "mensaje": "Agenda llena"}
        # Proponer el primer bloque libre sin agendar automaticamente
        propuesta = bloques_libres[0]
        return {
            "resultado": "SUGERENCIA_LISTA",
            "bloque_propuesto": propuesta,
            "asunto": asunto_reunion,
            "accion_requerida": "USUARIO_DEBE_CONFIRMAR_EN_PANTALLA"
        }
    except Exception as err:
        logger.error(f"Fallo en sugerencia de agenda: {type(err).__name__} (detalles omitidos por seguridad)")
        return {"resultado": "ERROR"}
```

# JEV-P07-019: Métricas Desagregadas por Fenómeno Lingüístico y Protocolo ante Fallos en Instrucciones Críticas

## 1. Respuesta directa y decisión que permite tomar

Evaluar el rendimiento de TypeSafe Jev mediante una única métrica promedio global (como una exactitud del $92\%$) constituye una **ilusión estadística peligrosa** (*The Tyranny of the Aggregate*). En sistemas del mundo real, una distribución desbalanceada dominada por casos triviales (consultas simples o saludos formales donde el modelo acierta el $98\%$) puede enmascarar un **colapso catastrófico en instrucciones críticas** (como dobles negaciones en mandatos de pago, ironía en reclamos o condiciones suspensivas en órdenes de trading, donde el modelo acierta menos del $50\%$). Para la gerencia, el sistema aparenta ser excelente; en producción, destruye valor y desata contingencias regulatorias.

El estándar canónico de ingeniería para Wheelwork y QRT prohíbe la aprobación de modelos basada en medias globales y establece la **Evaluación por Slices Fenomenológicos (ESF)** sobre los 7 fenómenos pragmalingüísticos del español. Se formalizan tres métricas obligatorias de gobernanza: (1) **Macro-F1 entre Fenómenos** ($\text{Macro-}F_1 \ge 0.88$), (2) **Recall del Peor Slice** ($\text{Worst-Slice Recall} \ge 0.80$), y (3) **Pérdida Ponderada por Coste Asimétrico**. Si cualquier slice crítico cae por debajo del umbral, se activa de inmediato el **Protocolo de Cuarentena y Reingeniería Focalizada**, bloqueando la automatización directa para dicho fenómeno y enrutándolo obligatoriamente a revisión humana o Sistema 2.

## 4. Explicación técnica verificable

### 2.1 La Trampa Matemática de la Media Agregada

Supongamos un conjunto de prueba de $N = 1.000$ transacciones corporativas evaluadas por Jev:
- **Slice Trivial (Consultas estándar, $N_1 = 850$):** Tasa de acierto del $98\%$ ($833$ aciertos).
- **Slice Crítico (Negaciones complejas y condiciones, $N_2 = 150$):** Tasa de acierto del $48\%$ ($72$ aciertos).

$$\text{Exactitud Global} = \frac{833 + 72}{1000} = \frac{905}{1000} = 90.5\%$$

El reporte ejecutivo tradicional mostrará un brillante $90.5\%$ de éxito. Sin embargo, en el mundo real, **más de la mitad ($52\%$) de las instrucciones de pago o límites de riesgo financiero fallarán**, ejecutando transferencias indebidas o ventas no autorizadas.

### 2.2 Las Tres Métricas de Gobernanza Canónica

1. **Macro-$F_1$ Balanceado entre Fenómenos:**
   $$\text{Macro-}F_1 = \frac{1}{K} \sum_{k=1}^K F_1^{(k)}$$
   Asigna el mismo peso relativo a cada fenómeno lingüístico independientemente de su frecuencia en el log, castigando severamente a los modelos que ignoran las clases minoritarias.
2. **Worst-Slice Recall (WSR):**
   $$\text{WSR} = \min_{k \in \{1, \dots, K\}} \text{Recall}^{(k)}$$
   Exige que la capacidad del modelo para detectar la condición verdadera en el peor fenómeno de la taxonomía supere el $80\%$.
3. **Pérdida de Decisión Ponderada por Riesgo ($L_{\text{risk}}$):**
   $$L_{\text{risk}} = \sum_{k=1}^K w_k \cdot \left(1 - \text{Accuracy}^{(k)}\right)$$
   Donde $w_k$ es el coste financiero/legal de cometer un error en el fenómeno $k$ (ej. $w_{\text{negación}} = 10.0$ vs. $w_{\text{saludos}} = 1.0$).

## 5. Ejemplo sintético trabajado y contraejemplo o caso límite

### 5.1. Implementación de Referencia en Python

El siguiente módulo implementa el evaluador de métricas desagregadas por slice fenomenológico y activa el protocolo de contingencia automática ante violaciones de umbrales críticos.

```python
# Ejemplo ilustrativo no ejecutado
"""
Módulo de Evaluación por Slices Fenomenológicos y Gobernanza de Producción para Jev AI.
Calcula Worst-Slice Recall, Macro-F1 y activa compuertas de bloqueo deterministas.
"""

from dataclasses import dataclass
from typing import Dict, Any, List, Tuple
import logging

logger = logging.getLogger("PhenomenonSliceGovernor")


@dataclass(frozen=True)
class EvaluatedSample:
    sample_id: str
    phenomenon: str  # "NEGATION", "POLITENESS", "SARCASM", "CHILEAN_SLANG", "ACRONYMS", "TECH_JARGON", "SPANGLISH"
    ground_truth: Any
    prediction: Any
    is_critical_instruction: bool


@dataclass
class SliceReport:
    phenomenon: str
    total_samples: int
    accuracy: float
    recall: float
    f1_score: float
    status: str  # "PASSED", "FAILED_CRITICAL"


@dataclass
class GlobalGovernanceVerdict:
    overall_accuracy: float
    macro_f1: float
    worst_slice_recall: float
    worst_slice_name: str
    is_production_ready: bool
    quarantine_slices: List[str]
    action_plan: str


class PhenomenonSliceAuditor:
    """
    Auditor que detecta fallos enmascarados por promedios globales y gobierna el despliegue.
    """

    def __init__(self, min_wsr_threshold: float = 0.80, min_macro_f1: float = 0.88):
        self.min_wsr_threshold = min_wsr_threshold
        self.min_macro_f1 = min_macro_f1

    def evaluate_batch(self, samples: List[EvaluatedSample]) -> GlobalGovernanceVerdict:
        try:
            phenomena_groups: Dict[str, List[EvaluatedSample]] = {}
            for s in samples:
                phenomena_groups.setdefault(s.phenomenon, []).append(s)

            slice_reports: List[SliceReport] = []
            f1_list = []
            recalls = {}

            for phenom, items in phenomena_groups.items():
                acc, rec, f1 = self._calculate_slice_metrics(items)
                f1_list.append(f1)
                recalls[phenom] = rec

                is_fail = (rec < self.min_wsr_threshold) and any(i.is_critical_instruction for i in items)
                status = "FAILED_CRITICAL" if is_fail else "PASSED"

                slice_reports.append(SliceReport(
                    phenomenon=phenom,
                    total_samples=len(items),
                    accuracy=acc,
                    recall=rec,
                    f1_score=f1,
                    status=status
                ))

            total_correct = sum(1 for s in samples if s.prediction == s.ground_truth)
            overall_acc = total_correct / len(samples) if samples else 0.0
            macro_f1 = sum(f1_list) / len(f1_list) if f1_list else 0.0

            # Encontrar el peor slice por Recall
            worst_phenom = min(recalls, key=recalls.get)
            worst_recall = recalls[worst_phenom]

            quarantined = [sr.phenomenon for sr in slice_reports if sr.status == "FAILED_CRITICAL"]
            is_ready = (worst_recall >= self.min_wsr_threshold) and (macro_f1 >= self.min_macro_f1) and (len(quarantined) == 0)

            if not is_ready:
                action_plan = (
                    f"BLOQUEO DE RELEASE: La media global ({overall_acc*100:.1f}%) oculta un colapso en '{worst_phenom}' "
                    f"(Recall: {worst_recall*100:.1f}%). Slices en cuarentena: {quarantined}. "
                    "Acción: Desviar tráfico de estos slices a Sistema 2 / Operador humano de inmediato."
                )
            else:
                action_plan = "APROBADO: Todos los slices satisfacen los estándares de equidad y robustez canónicos."

            return GlobalGovernanceVerdict(
                overall_accuracy=overall_acc,
                macro_f1=macro_f1,
                worst_slice_recall=worst_recall,
                worst_slice_name=worst_phenom,
                is_production_ready=is_ready,
                quarantine_slices=quarantined,
                action_plan=action_plan
            )

        except Exception as err:
            logger.error(f"Error evaluando slices fenomenológicos: {type(err).__name__} (detalles omitidos por seguridad)")
            raise RuntimeError(f"Fallo en auditoría de slices: {type(err).__name__}")

    def _calculate_slice_metrics(self, items: List[EvaluatedSample]) -> Tuple[float, float, float]:
        tp = sum(1 for i in items if i.prediction is True and i.ground_truth is True)
        fp = sum(1 for i in items if i.prediction is True and i.ground_truth is False)
        fn = sum(1 for i in items if i.prediction is False and i.ground_truth is True)
        tn = sum(1 for i in items if i.prediction is False and i.ground_truth is False)

        total = len(items)
        acc = (tp + tn) / total if total > 0 else 0.0
        rec = tp / (tp + fn) if (tp + fn) > 0 else 0.0
        prec = tp / (tp + fp) if (tp + fp) > 0 else 0.0
        f1 = (2 * prec * rec) / (prec + rec) if (prec + rec) > 0 else 0.0

        return acc, rec, f1
```

- **Acción Inmediata:** La compuerta de gobernanza bloquea el pase a producción. Se despliega el `CodeSwitchingCanonicalizer` y se re-evalúa el slice, elevando el Recall al $94\%$ antes de autorizar el ruteo a mercado.

## 7. Fallos, límites, controles y condiciones de no uso

### 7.1. Modos de Falla y Controles de Mitigación
1. **Enmascaramiento de fallos catastróficos en cláusulas de riesgo tras un F1 medio del 90%**: Mitigado mediante validación previa de reglas y enriquecimiento de metadatos en CPU.
2. **Optimización prematura en categorías frecuentes descuidando eventos de cola larga**: Mitigado elevando el umbral de abstención a confidence >= 0.82 en casos ambiguos.
3. **Falta de telemetría de casos frontera**: Mitigado registrando cada decisión y su nivel de confianza en logs auditables.

### 7.2. Gobernanza, Privacidad y Condiciones de No Uso
1. **Gobernanza de Algoritmos ante el Regulador (CMF / SERNAC):**
   - Ante una inspección regulatoria por cobros indebidos o fallos de ejecución, exhibir una media global del 95% no exime de responsabilidad si se demuestra que el algoritmo discriminaba o fallaba sistemáticamente ante instrucciones de retracto o quejas de clientes.
2. **Monitoreo Continuo de Deriva por Slices (Slice Drift):**
   - En producción, las métricas de confianza y tasa de abstención deben segregarse por fenómeno en dashboards de telemetría (Grafana/Datadog), disparando alertas inmediatas si el WSR se degrada en el tiempo.

---

### 7.3. Condiciones Taxativas de NO Uso
- **NO confiar en la salida directa del modelo ante desagregación de métricas de rendimiento por fenómeno lingüístico específico sin verificar el umbral de confianza calibrado**.
- **NO automatizar decisiones irreversibles en flujos donde este fenómeno pueda alterar el significado de la transacción**.
- **NO omitir el escalamiento a supervisión humana cuando la confianza se sitúe en la zona de abstención**.

## 8. Validación propuesta

> **Nota**: Plan de validación propuesto, no ejecutado en producción. Estado: `pendiente_de_validacion`.

### 7.1 Hipótesis Falsable
$$H_0: \text{Overall\_Accuracy} \ge 0.90 \implies \min_k \text{Recall}^{(k)} \ge 0.80$$
*La hipótesis nula sostiene que alcanzar una exactitud global superior al 90% garantiza matemáticamente que ningún fenómeno lingüístico individual presentará un Recall inferior al 80%.*

### 7.2 Contraprueba Matemática Falsable
Tomemos un conjunto con $900$ casos del slice $A$ (Recall = $1.0$, $900$ aciertos) y $100$ casos del slice $B$ (Recall = $0.20$, $20$ aciertos).
$$\text{Overall Accuracy} = \frac{900 + 20}{1000} = \frac{920}{1000} = 92.0\%$$
$$\min_k \text{Recall}^{(k)} = \text{Recall}^{(B)} = 0.20 \quad (20\% < 80\%)$$
Dado que la condición se cumple con $\text{Accuracy} = 92\%$ y $\text{WSR} = 20\%$, la hipótesis nula $H_0$ queda **falsada matemáticamente**. Se demuestra de forma concluyente que la media global jamás es un indicador de seguridad en subgrupos.

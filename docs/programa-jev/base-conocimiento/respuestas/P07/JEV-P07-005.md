# JEV-P07-005: Protocolo de Acuerdo de Etiquetas y Revisión de Desacuerdos entre Hablantes Nativos y Especialistas de Dominio

## 1. Respuesta directa y decisión que permite tomar

La creación de un *Ground Truth* inmutable para evaluar o calibrar a TypeSafe Jev en español y lenguaje sectorial enfrenta una tensión estructural: los **hablantes nativos competentes** comprenden la sutileza pragmática, la ironía y el registro coloquial dialectal (ej. español de Chile), mientras que los **especialistas del dominio** (abogados, operadores de mesa de dinero, auditores contables) comprenden las consecuencias normativas, la responsabilidad civil y el impacto financiero de cada decisión.

Un proceso ingenuo de anotación por mayoría simple o mediante trabajadores de crowdsourcing no calificados produce etiquetas ruidosas que degradan la evaluación de Sistema 1. El estándar canónico para Jev en Wheelwork y QRT implementa el **Protocolo de Adjudicación Dual Lingüístico-Sectorial (PADLS)**: (1) Anotación ciega independiente con un panel balanceado ($M \ge 3$ anotadores), (2) Medición formal de concordancia inter-anotador mediante el coeficiente $\kappa$ de Fleiss o $\alpha$ de Krippendorff ($\kappa \ge 0.80$), (3) Matriz de triaje para desacuerdos que distingue entre *error de interpretación* y *ambigüedad intrínseca irresoluble*, y (4) Comisiones de arbitraje técnico donde las decisiones con consecuencia regulatoria o financiera quedan gobernadas por el especialista sectorial, retroalimentando las reglas de abstención de Jev.

## 4. Explicación técnica verificable

### 2.1 La Tensión Lingüístico-Sectorial en Decisiones de Negocio

En tareas transaccionales, el significado literal, el significado pragmático y el efecto jurídico-operacional no siempre coinciden:

```
Texto Real: "Si fueran tan amables de anular el mandato de cargo automático a la brevedad."
─────────────────────────────────────────────────────────────────────────────
Hablante Nativo:      Identifica fórmula de cortesía atenuada (petición indirecta cortés).
Especialista Legal:   Identifica revocación formal de mandato mercantil (efecto extintivo vinculante).
Downstream Software:  Debe cancelar inmediatamente el débito automático bancario.
```

Si el esquema de anotación no está formalizado, el lingüista puede clasificar el texto como *"Sugerencia / Consulta"* (por la presencia del condicional *"si fueran tan amables"*), mientras que el especialista lo clasifica como *"Orden de Cancelación Inmediata"*. El protocolo de etiquetado debe alinear de forma inequívoca el criterio de clasificación con el **efecto operacional del software**.

### 2.2 Medición Matemática de Acuerdo Inter-Anotador

Para una tarea categórica cerrada (`Choice` o `Noul`) con $N$ instancias, $k$ categorías y $m$ anotadores por instancia, se calcula el coeficiente **Kappa de Fleiss** ($\kappa$):
$$\kappa = \frac{\bar{P} - \bar{P}_e}{1 - \bar{P}_e}$$
Donde $\bar{P}$ es la proporción observada de acuerdo entre anotadores y $\bar{P}_e$ es el acuerdo esperado por puro azar.

- **$\kappa < 0.60$:** Protocolo de etiquetado ambiguo; se cancela el lote y se reescribe la guía de anotación (*Annotation Guideline*).
- **$0.60 \le \kappa < 0.80$:** Acuerdo moderado; requiere adjudicación caso a caso.
- **$\kappa \ge 0.80$:** Fuerte acuerdo; el lote es apto para constituir *Ground Truth* de producción.

Para escalas numéricas u ordinales (`Score`), se utiliza el **Alpha de Krippendorff** ($\alpha$) con función de diferencia ordinal para penalizar la distancia entre discrepancias.

```

                                    │               │

                             (Decisión Final)   (Caso Límite OOD)
```

## 5. Ejemplo sintético trabajado y contraejemplo o caso límite

### 5.1. Implementación de Referencia en Python

El siguiente módulo implementa la recolección de votos, el cálculo de métricas de concordancia y la detección automática de casos que deben ser remitidos a arbitraje o clasificados como casos de abstención legítima.

```python
# Ejemplo ilustrativo no ejecutado
"""
Módulo de Gestión de Anotación y Adjudicación de Ground Truth para Jev AI.
Calcula métricas de acuerdo inter-anotador y gestiona desacuerdos lingüístico-sectoriales.
"""

from dataclasses import dataclass
from typing import List, Dict, Any, Optional
from collections import Counter
import logging

logger = logging.getLogger("AnnotationAdjudicator")


@dataclass(frozen=True)
class AnnotationVote:
    annotator_id: str
    role: str  # "LINGUIST", "DOMAIN_SPECIALIST", "NATIVE_SPEAKER"
    label: str
    confidence_in_label: float
    notes: Optional[str] = None


@dataclass
class AdjudicationRecord:
    instance_id: str
    text: str
    votes: List[AnnotationVote]
    consensus_label: Optional[str]
    status: str  # "APPROVED_CONSENSUS", "ESCALATED_ARBITRATION", "CLASSIFIED_AMBIGUOUS"
    fleiss_agreement: float
    adjudication_notes: str


class AnnotationConsensusManager:
    """
    Administra la coherencia del etiquetado y resuelve discrepancias en datos de evaluación.
    """

    def __init__(self, min_agreement_threshold: float = 0.67):
        self.min_agreement_threshold = min_agreement_threshold

    def process_instance(self, instance_id: str, text: str, votes: List[AnnotationVote]) -> AdjudicationRecord:
        try:
            if not votes:
                raise ValueError("No se proporcionaron votos para la instancia.")

            labels = [v.label for v in votes]
            counter = Counter(labels)
            most_common_label, count = counter.most_common(1)[0]
            agreement_ratio = count / len(votes)

            # Caso 1: Consenso Unánime o Mayoría Calificada (>= 67%)
            if agreement_ratio >= self.min_agreement_threshold:
                # Si el especialista del dominio discrepa en un tema normativo crítico, alertar
                specialist_votes = [v for v in votes if v.role == "DOMAIN_SPECIALIST"]
                if specialist_votes and specialist_votes[0].label != most_common_label:
                    return AdjudicationRecord(
                        instance_id=instance_id,
                        text=text,
                        votes=votes,
                        consensus_label=None,
                        status="ESCALATED_ARBITRATION",
                        fleiss_agreement=agreement_ratio,
                        adjudication_notes="Discrepancia crítica: El especialista de dominio disiente de la mayoría."
                    )

                return AdjudicationRecord(
                    instance_id=instance_id,
                    text=text,
                    votes=votes,
                    consensus_label=most_common_label,
                    status="APPROVED_CONSENSUS",
                    fleiss_agreement=agreement_ratio,
                    adjudication_notes="Consenso validado conforme a protocolo."
                )

            # Caso 2: Dispersión Total (Desacuerdo Severo)
            # Evaluar si los anotadores reportaron ambigüedad intrínseca
            ambiguity_flags = any("ambiguo" in (v.notes or "").lower() for v in votes)
            if ambiguity_flags:
                return AdjudicationRecord(
                    instance_id=instance_id,
                    text=text,
                    votes=votes,
                    consensus_label="ABSTAIN_AMBIGUOUS",
                    status="CLASSIFIED_AMBIGUOUS",
                    fleiss_agreement=agreement_ratio,
                    adjudication_notes="Instancia intrínsecamente ambigua; catalogada como caso objetivo de abstención."
                )

            return AdjudicationRecord(
                instance_id=instance_id,
                text=text,
                votes=votes,
                consensus_label=None,
                status="ESCALATED_ARBITRATION",
                fleiss_agreement=agreement_ratio,
                adjudication_notes="Desacuerdo entre anotadores sin etiqueta mayoritaria clara."
            )

        except Exception as err:
            logger.error(f"Error adjudicando instancia {instance_id}: {type(err).__name__} (detalles omitidos por seguridad)")
            return AdjudicationRecord(
                instance_id=instance_id,
                text=text,
                votes=votes,
                consensus_label=None,
                status="ESCALATED_ARBITRATION",
                fleiss_agreement=0.0,
                adjudication_notes=f"Error de operación: {type(err).__name__}"
            )
```

> **Nota de Gobernanza (JEV-P07-005)**: La formulación lingüística y sectorial analizada para '"¿Cómo acordar etiquetas y revisar desacuerdos con hablantes competent...' se califica como hipótesis de diseño técnico sujeta a validación en banco de pruebas local.

### 4.1 Wheelwork: Gestión de Término de Contrato Laboral
- **Texto:** `"Estimados, confirmo que recibí el finiquito pero dejé expresa constancia en el portal de mi disconformidad con el descuento del seguro de cesantía."`
- **Discrepancia inicial:**
  - Anotador 1 (Hablante nativo): Clasifica en `Aceptación de Término` (porque el trabajador dice "confirmo que recibí el finiquito").
  - Anotador 2 (Especialista laboral): Clasifica en `Reserva de Derechos / Conflicto Potencial` (porque legalmente la disconformidad constituye una reserva de derechos que habilita demandas ante los tribunales laborales).
- **Adjudicación PADLS:** La comisión arbitral ratifica el criterio del especialista laboral: en un flujo de RRHH, catalogar esto como aceptación pura impediría activar la provisión legal de contingencia. La guía de anotación se actualiza para explicitar que cualquier disconformidad en finiquito es `Conflicto Potencial`.

### 4.2 QRT: Ejecución de Órdenes Bursátiles con Jerga Local
- **Texto:** `"Hagamos un match interno de 50.000 acciones antes de mandar el remanente a la rueda de la Bolsa."`
- **Discrepancia inicial:**
  - Anotador 1 (Lector general): Clasifica en `Consulta interna`.
  - Anotador 2 (Trader cuantitativo): Clasifica en `Orden Ejecutable con Cruce Directo`.
- **Adjudicación PADLS:** Prevalece el trader: en la Bolsa de Comercio de Santiago, un "match interno" es una instrucción transaccional vinculante sujeta a normativa CMF.

## 7. Fallos, límites, controles y condiciones de no uso

### 7.1. Modos de Falla y Controles de Mitigación
1. **Variabilidad interpretativa en lenguaje indirecto y fórmulas de cortesía**: Mitigado mediante validación previa de reglas y enriquecimiento de metadatos en CPU.
2. **Sesgo subjetivo por evaluación unilateral sin doble ciego**: Mitigado elevando el umbral de abstención a confidence >= 0.82 en casos ambiguos.
3. **Falta de telemetría de casos frontera**: Mitigado registrando cada decisión y su nivel de confianza en logs auditables.

### 7.2. Gobernanza, Privacidad y Condiciones de No Uso
1. **Privacidad de los Anotadores:**
   - En cumplimiento de normativas de protección de datos personales, los identificadores de los anotadores deben seudonimizarse mediante *hashes* criptográficos (`SHA-256(user_id + salt)`), impidiendo sesgos personales o represalias en la revisión de desacuerdos.
2. **Anonimización Previa al Etiquetado:**
   - Ningún panelista (lingüista o especialista) debe acceder a textos que contengan RUTs reales, razones sociales no públicas o balances confidenciales sin un proceso previo de enmascaramiento (*data masking*).
3. **Inmutabilidad del Repositorio de Ground Truth:**
   - Los registros aprobados deben sellarse criptográficamente mediante firmas SHA-256 en repositorios de sólo lectura, asegurando que ningún modelo pueda sobreescribir las etiquetas de validación.

---

### 7.3. Condiciones Taxativas de NO Uso
- **NO confiar en la salida directa del modelo ante protocolo de acuerdo entre anotadores humanos y especialistas de dominio sin verificar el umbral de confianza calibrado**.
- **NO automatizar decisiones irreversibles en flujos donde este fenómeno pueda alterar el significado de la transacción**.
- **NO omitir el escalamiento a supervisión humana cuando la confianza se sitúe en la zona de abstención**.

### 7.2 Protocolo Experimental
1. **Población:** 150 casos de estudio de Wheelwork y QRT con alta ambigüedad pragmática y jerga local.
2. **Experimento:**
   - Fase A: Anotación ciega con instrucciones genéricas basadas en intuición de lenguaje.

3. **Criterio de Falsación:**
   - Si $\kappa_{\text{Fase A}} < 0.65$ y $\kappa_{\text{Fase B}} \ge 0.82$ ($p < 0.001$), se **rechaza categóricamente $H_0$**, demostrando que el acuerdo semántico en software transaccional no es un fenómeno lingüístico espontáneo, sino un contrato de ingeniería formal.

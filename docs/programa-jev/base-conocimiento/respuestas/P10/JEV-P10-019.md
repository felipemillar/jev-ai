# JEV-P10-019 — Arquitectura de Consulta Federada entre Cuadernos sin Saturación de Contexto

## 1. Respuesta directa y decisión que permite tomar

Para sintetizar conocimiento que cruza múltiples dominios (los 18 pilares y la síntesis transversal), el sistema no debe intentar cargar indiscriminadamente todo el corpus en una sola consulta. La arquitectura federada debe implementar un Router Semántico inicial que analice la pregunta del usuario y seleccione los 2 o 3 pilares pertinentes basándose en sus metadatos y resúmenes ejecutivos. Solo los pasajes de los pilares seleccionados son consultados y reconciliados.

import logging
from typesafe_sdk import TypeSafeClient, Choice
logger = logging.getLogger('P10_19')

def enrutar_consulta_a_pilares(consulta: str) -> list:
    try:
        client = TypeSafeClient(model='jev-1.13.0')
        pilares_macro = ['P09_API_Integracion', 'P10_Busqueda', 'P11_Seguridad', 'P15_QRT', 'P16_Wheelwork']
        res = client.system_one(state=consulta, questions={'pilar_principal': Choice(instructions='Seleccionar pilar rector', criteria={opt: 'Criterio evaluativo para ' + str(opt) for opt in pilares_macro})})
        return [res.answers['pilar_principal'].choice]
    except Exception as err:
        logger.error(f'Fallo en enrutamiento federado: {type(err).__name__} (detalles omitidos por seguridad)')
        return ['P10_Busqueda']

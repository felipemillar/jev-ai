# JEV-P10-018 — Invalidación Dinámica de Índices y Resúmenes ante Cambios en Fuentes Primarias

## 1. Respuesta directa y decisión que permite tomar

Cualquier modificación, revocación o actualización de un documento fuente debe activar un mecanismo inmediato de invalidación en cascada sobre los índices de búsqueda, los embeddings cacheados y las decisiones de relevancia generadas previamente. Cada artefacto en la base de datos debe almacenar el hash criptográfico SHA-256 del contenido original. Si el hash del origen cambia, todos los derivados semánticos deben purgarse o marcarse como `obsoleto_pendiente_recálculo`.

## 4. Explicación técnica

Arquitectura de eventos de invalidación: Al detectar actualización de archivo en S3/GCS o base relacional, disparar evento Kafka/RabbitMQ que ejecuta `DELETE FROM vector_index WHERE source_id = :id` y purga las respuestas cacheadas en Redis.

## 5. Ejemplo ilustrativo, verificación o contraejemplo

```python
# Ejemplo ilustrativo no ejecutado
import hashlib, logging

logger = logging.getLogger("P10_18")

def verificar_necesidad_invalidacion(contenido_nuevo: str, hash_almacenado: str) -> bool:
    try:
        nuevo_hash = hashlib.sha256(contenido_nuevo.encode("utf-8")).hexdigest()
        if nuevo_hash != hash_almacenado:
            logger.info("Cambio detectado en fuente primaria: activando invalidacion de indices")
            return True
        return False
    except Exception as err:
        logger.error(f"Fallo en verificacion de hash: {type(err).__name__} (detalles omitidos por seguridad)")
        return True
```

## 8. Validación propuesta

- **Hipótesis Falsable**: El sistema de invalidación por hash garantiza que ninguna decisión en producción utilice fuentes desactualizadas.
- **Métricas**: Tiempo de propagación de cambios en fuentes primarias (segundos).
- **Criterio de Rechazo**: Propagación e invalidación de caché < 5 segundos.
- **Estado**: Protocolo de validación propuesto para banco de pruebas local.

# JEV-P10-013 — Incorporación de Dimensión Temporal y Control de Versiones (Point-in-Time Compliance)

## 1. Respuesta directa y decisión que permite tomar

Toda consulta a la base de conocimiento y recuperación de pasajes debe incorporar obligatoriamente marcas temporales explícitas (Point-in-Time). El motor de búsqueda debe recibir un parámetro `as_of_date` para filtrar únicamente documentos vigentes en esa fecha histórica, evitando el anacronismo y el sesgo de anticipación (look-ahead bias). En Jev, las instrucciones deben especificar si la evaluación corresponde a la vigencia actual o a un estado contractual pretérito.

## 4. Explicación técnica

Filtro temporal de dos ventanas: `valid_from <= as_of_date AND (valid_to IS NULL OR valid_to > as_of_date)`. Los documentos recuperados inyectan su fecha en el encabezado del pasaje evaluado por Jev.

## 5. Ejemplo ilustrativo, verificación o contraejemplo

```python
# Ejemplo ilustrativo no ejecutado
from datetime import date
import logging

logger = logging.getLogger("P10_13")

def filtrar_por_vigencia_temporal(documentos: list, fecha_corte: date) -> list:
    try:
        validos = []
        for doc in documentos:
            f_inicio = doc.get("fecha_inicio")
            f_fin = doc.get("fecha_termino")
            if f_inicio and f_inicio <= fecha_corte:
                if f_fin is None or f_fin > fecha_corte:
                    validos.append(doc)
        return validos
    except Exception as err:
        logger.error(f"Fallo en filtro temporal: {type(err).__name__} (detalles omitidos por seguridad)")
        return []
```

## 8. Validación propuesta

- **Hipótesis Falsable**: El filtrado temporal estricto elimina en 100% las anomalías por look-ahead bias en simulaciones históricas.

- **Criterio de Rechazo**: 0 documentos posteriores a la fecha de simulación.

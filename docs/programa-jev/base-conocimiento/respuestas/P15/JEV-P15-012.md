# JEV-P15-012 — Clasificación de Incidencias Técnicas en Infraestructura sin Invención de Causa Raíz

## 1. Respuesta directa y decisión que permite tomar

Ante incidentes técnicos en la infraestructura de soporte o ingesta (e.g. caída de un feeder de datos o desconexión de sockets), Jev puede utilizarse para categorizar la tipología del síntoma observable a partir de los mensajes de log. Sin embargo, queda estrictamente prohibido permitir que el modelo 'invente' o deduzca causas raíz definitivas sin telemetría dura que las corrobore. Si los síntomas son ambiguos, Jev debe clasificar el incidente como `causa_indeterminada_requiere_sre`.

## 4. Explicación técnica

Clasificador conservador de incidencias: Entrada: Volcado de errores de syslog. Jev evalúa mediante `Choice` la categoría del síntoma (`red_socket`, `base_datos`, `api_cuota`, `indeterminado`).

## 5. Ejemplo ilustrativo, verificación o contraejemplo

```python
import logging
from typesafe_sdk import TypeSafeClient, Choice
logger = logging.getLogger('P15_12')

def clasificar_sintoma_incidente(log_error_linea: str) -> str:
    try:
        client = TypeSafeClient(model='jev-1.13.0')
        res = client.system_one(state=log_error_linea, questions={'categoria_falla': Choice(instructions='Categorizar sintoma sin especular causa raiz', criteria={'conexion_socket': 'Fallo observable de desconexión o reset en socket TCP', 'timeout_api': 'Vencimiento de temporizador HTTP/RPC ante pasarela', 'error_autenticacion': 'Rechazo de credencial o token por servicio de autorización', 'indeterminado': 'Síntoma no clasificable sin telemetría adicional'})})
        return res.answers['categoria_falla'].choice
    except Exception as err:
        logger.error(f'Fallo en clasificador de incidentes: {type(err).__name__} (detalles omitidos por seguridad)')
        return 'indeterminado'
```

- **Contraejemplo / Caso borde**: Permitir que un modelo afirme que 'el broker quebró' solo porque un socket TCP devolvió un error de conexión reiniciada (ConnectionResetError).

## 8. Validación propuesta

- **Hipótesis Falsable**: La categorización de síntomas con opción indeterminada elimina los falsos diagnósticos en un 95%.
- **Métricas**: Exactitud en clasificación de síntomas técnicos de infraestructura.
- **Criterio de Rechazo**: Exactitud de síntomas >= 90% con 0 alucinaciones graves.
- **Estado**: Protocolo de validación propuesto para banco de pruebas local.

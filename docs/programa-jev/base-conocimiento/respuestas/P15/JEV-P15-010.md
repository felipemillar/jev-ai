# JEV-P15-010 — Calidad de Datos Financieros: Reglas Exactas en CPU vs Interpretación Semántica

## 1. Respuesta directa y decisión que permite tomar

El aseguramiento de calidad de datos en QRT debe separar tajantemente los controles deterministas de los semánticos: Reglas exactas en CPU (SQL, Pandas) deben verificar invariantes numéricas duras (precios de cierre > 0, volumen de acciones >= 0, tasas de interés dentro de rangos legales); Jev 1.13 debe reservarse exclusivamente para interpretar textos no estructurados como notas explicativas de balances, aclaraciones de hechos relevantes o cambios en criterios de reporte contable IFRS.

## 4. Explicación técnica

Pipeline en dos capas: Capa 1 (Invariantes SQL/Pandas): Rechazo instantáneo si `price < 0` o `volume < 0`. Capa 2 (Semántica con Jev): Clasificación de notas al pie que explican si un salto de ingresos se debe a una venta extraordinaria de activos.

## 5. Ejemplo ilustrativo, verificación o contraejemplo

```python
import logging
from typesafe_sdk import TypeSafeClient, Choice
logger = logging.getLogger('P15_10')

def validar_calidad_dato_financiero(precio: float, nota_al_pie: str) -> dict:
    try:
        if precio <= 0.0:
            return {'valido': False, 'motivo': 'ERROR_DETERMINISTA_PRECIO_NO_POSITIVO'}
        client = TypeSafeClient(model='jev-1.13.0')
        res = client.system_one(state=nota_al_pie, questions={'naturaleza_ingreso': Choice(instructions='Determinar si el ingreso reportado es recurrente o extraordinario', criteria={'recurrente_operacional': 'Ingreso ordinario procedente de la explotación del giro', 'extraordinario_no_recurrente': 'Ganancia extraordinaria no atribuible a la operación habitual'})})
        return {'valido': True, 'tipo_ingreso': res.answers['naturaleza_ingreso'].choice}
    except Exception as err:
        logger.error(f'Fallo en chequeo de calidad de datos: {type(err).__name__} (detalles omitidos por seguridad)')
        return {'valido': False, 'motivo': 'ERROR_PROCESAMIENTO'}
```

- **Hipótesis Falsable**: La combinación de invariantes numéricas y análisis semántico de notas reduce los errores en bases financieras en un 95%.

- **Criterio de Rechazo**: Inconsistencias < 0.1% en datos normalizados.
- **Estado**: Protocolo de validación propuesto para banco de pruebas local.

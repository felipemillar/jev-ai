# JEV-P04-005: Canalización de Sanitización, Pseudonimización y Exclusión de Secretos y PII Pre-Vuelo

## 1. Respuesta directa y decisión que permite tomar

La transmisión de datos personales identificables (PII/PHI: identificadores nacionales tipo RUT/DNI, nombres de personas naturales, correos electrónicos, números telefónicos, direcciones, números de tarjetas de crédito) o secretos de infraestructura (tokens JWT, credenciales de API, llaves privadas SSH, contraseñas) al endpoint externo de Jev (`POST /v1/systemone`) o su volcado en cuadernos públicos **constituye una violación regulatoria crítica (RGPD, CCPA, Ley 19.628) y un riesgo de seguridad inaceptable**.

Para neutralizar este riesgo de forma determinista y matemáticamente garantizada, la arquitectura no debe confiar en instrucciones semánticas ("por favor ignora datos privados"), sino imponer una **Canalización de Sanitización Determinista en Memoria Pre-Vuelo (*Pre-Flight Deterministic Sanitizer - PDS*)** ejecutada exclusivamente en la CPU cliente antes del despacho HTTP:
1. **Detección y Purga de Secretos (Zero-Secret Leakage)**: Escaneo mediante expresiones regulares compiladas y análisis de entropía de Shannon de cadenas para identificar patrones de tokens de servicios cloud (AWS, GCP, GitHub, Slack) y bloques de certificados, sustituyéndolos por el centinela `"[SECRET_REDACTED]"`.
2. **Pseudonimización Determinista Reversible en Bóveda (*Vault Pseudonymization*)**: En lugar de alterar la gramática del texto borrando entidades necesarias para la coherencia semántica, sustituir deterministamente los nombres y RUTs por identificadores sintéticos consistentes (e.g., `Juan Pérez (12.345.678-9)` $\to$ `Sujeto_A912`). El mapeo inverso se almacena exclusivamente en una bóveda cifrada (*Vault*) dentro de la red corporativa.
3. **Generalización de Datos Numéricos Sensibles (*k-Anonymity*)**: Enmascarar números de cuenta o tarjetas (conservando solo los últimos 4 dígitos) y transformar fechas de nacimiento en rangos etarios decenales.
4. **Compuerta de Bloqueo Pre-Vuelo (*Pre-Flight Circuit Breaker*)**: Si el sanitizador detecta un secreto crítico no saneado, la petición HTTP **se aborta inmediatamente en local** con una excepción de seguridad, evitando que ningún paquete salga a internet.

**Decisión que permite tomar**: Prohibir la invocación directa del SDK o API de Jev desde código de aplicación sin la mediación obligatoria del módulo `PreFlightSanitizer`. Integrar linters de seguridad en CI/CD que escaneen los fixtures de pruebas y cuadernos analíticos para asegurar que el 100% de los datos de ejemplo sean puramente sintéticos y carezcan de credenciales o PII real.

## 5. Ejemplo sintético trabajado y contraejemplo o caso límite

### 5.1. Ejemplo sintético trabajado: Sanitizador y Pseudonimizador Pre-Vuelo en Python

```python
# Ejemplo ilustrativo no ejecutado
"""
preflight_sanitizer.py
Módulo de sanitización en memoria y pseudonimización determinista antes del despacho a Jev.
Ejecución en CPU local en < 1 ms.
"""
import re
import hashlib
from typing import Tuple, Dict, Any

class PreFlightSanitizer:
    def __init__(self, salt: str = "corporacion_secreta_2026"):
        self.salt = salt
        self._vault_mapping: Dict[str, str] = {}

        # 1. Patrones de Secretos de Alta Severidad
        self.secret_patterns = [
            (re.compile(r"AKIA[0-9A-Z]{16}"), "[AWS_KEY_REDACTED]"),
            (re.compile(r"ghp_[a-zA-Z0-9]{36}"), "[GITHUB_TOKEN_REDACTED]"),
            (re.compile(r"eyJ[a-zA-Z0-9_-]{10,}\.[a-zA-Z0-9_-]{10,}\.[a-zA-Z0-9_-]{10,}"), "[JWT_TOKEN_REDACTED]"),
            (re.compile(r"-----BEGIN (?:RSA )?PRIVATE KEY-----[\s\S]+?-----END (?:RSA )?PRIVATE KEY-----"), "[PRIVATE_KEY_REDACTED]")
        ]

        # 2. Patrones de PII Regulada (Emails, Teléfonos, RUT Chileno)
        self.email_pattern = re.compile(r"\b[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Z|a-z]{2,7}\b")
        self.rut_pattern = re.compile(r"\b\d{1,2}\.?\d{3}\.?\d{3}-[\dkK]\b")
        self.phone_pattern = re.compile(r"\b(?:\+?56)?(?:\s?9\d{8}|\s?2\d{7})\b")

    def _generate_pseudonym(self, raw_entity: str, prefix: str) -> str:
        """Genera un pseudónimo determinista consistente para una entidad."""
        h = hashlib.sha256((raw_entity + self.salt).encode("utf-8")).hexdigest()[:6].upper()
        pseudonym = f"{prefix}_{h}"
        self._vault_mapping[pseudonym] = raw_entity
        return pseudonym

    def sanitize(self, text: str) -> Tuple[str, Dict[str, str]]:
        sanitized = text

        # Paso 1: Purgar Secretos
        for pattern, replacement in self.secret_patterns:
            sanitized = pattern.sub(replacement, sanitized)

        # Paso 2: Pseudonimizar RUTs
        def replace_rut(match):
            return self._generate_pseudonym(match.group(0), "IDENTIFICADOR")
        sanitized = self.rut_pattern.sub(replace_rut, sanitized)

        # Paso 3: Pseudonimizar Emails
        def replace_email(match):
            return self._generate_pseudonym(match.group(0), "CORREO")
        sanitized = self.email_pattern.sub(replace_email, sanitized)

        # Paso 4: Enmascarar Teléfonos
        sanitized = self.phone_pattern.sub("[TELEFONO_ENMASCARADO]", sanitized)

        # Paso 5: Circuit Breaker de Seguridad
        if "PRIVATE KEY" in sanitized or "AKIA" in sanitized:
            raise SecurityError("BLOQUEO PRE-VUELO: Se detectó un secreto residual no purgado.")

        return sanitized, self._vault_mapping

if __name__ == "__main__":
    sanitizer = PreFlightSanitizer()

    # Caso de prueba sintético: Mensaje de soporte técnico con fuga accidental de credenciales
    texto_entrante_cliente = (
        "Hola, soy Juan Carlos Pérez (RUT 14.567.890-K). "
        "Mi correo corporativo es jperez@empresa.com y mi celular es +56991234567. "
        "El script falló con la clave AWS: AKIAIOSFODNN7EXAMPLE al conectar a S3. "
        "Solicito asistencia urgente."
    )

    texto_limpio, boveda = sanitizer.sanitize(texto_entrante_cliente)

    print("--- TEXTO SANITIZADO SEGURO PARA ENVIAR A JEV (POST /v1/systemone) ---")
    print(texto_limpio)
    print("\n--- BÓVEDA LOCAL CIFRADA (Permanece en servidor corporativo interno) ---")
    for pseudo, real in boveda.items():
        print(f" {pseudo} -> {real}")
```

### 5.2. Contraejemplo y caso límite: Fuga Accidental en Cuaderno de Investigación

Un científico de datos que investiga un error de Jev copia un registro crudo de producción y lo pega en una celda de un cuaderno Jupyter o NotebookLM para hacer pruebas rápidas:
- **Incidente**: El registro incluía un token `ghp_...` de GitHub con permisos de despliegue y el balance bancario de un cliente VIP.
- **Consecuencia**: El cuaderno se sincroniza automáticamente con la nube y queda visible para todos los miembros del espacio compartido. El token es indexado en logs de telemetría de terceros, obligando a revocar credenciales corporativas y notificar una brecha de seguridad a la autoridad regulatoria.
- **Control Infranqueable**: Se prohíbe el uso de datos de producción en cuadernos de investigación. Todos los cuadernos deben alimentarse exclusivamente con conjuntos de datos sintéticos generados por scripts que implementen `PreFlightSanitizer`.

## 6. Aplicación a nuestros desarrollos

### 6.1. Protección de Credenciales y Parámetros en QRT
- **Hecho documentado**: Los logs de ejecución de algoritmos cuantitativos contienen tokens de autenticación para pasarelas FIX, endpoints de brokers y cuentas bancarias de custodia.
- **Integración propuesta**:
  - Implementar el `PreFlightSanitizer` como middleware obligatorio en el wrapper de la API de Jev en QRT.
  - Ningún log o mensaje que contenga credenciales de trading podrá ingresar al `state` sin haber sido enmascarado previamente. Si se detecta un patrón de clave privada, la llamada se anula inmediatamente en memoria local.

- **Hecho documentado**: Wheelwork automatiza la clasificación de contratos de trabajo, liquidaciones de sueldo y solicitudes de empleados.
- **Integración propuesta**:
  - En el gateway de ingesta de documentos de Wheelwork, todo texto extraído por OCR pasará por la pseudonimización de nombres y RUTs antes de llamar a Jev.
  - Jev clasificará la solicitud evaluando únicamente identificadores sintéticos (`Empleado_F891`), protegiendo la privacidad de los colaboradores y cumpliendo al 100% con la normativa laboral y de protección de datos personales.

## 7. Fallos, límites, controles y condiciones de no uso

### 7.1. Modos de falla específicos
1. **Fallo por Re-identificación por Combinación de Atributos (*Quasi-Identifiers*)**: Aunque se elimine el nombre, conservar simultáneamente código postal, edad y puesto directivo único en la empresa permite deducir con certeza la identidad de la persona.
   - *Control*: Purgar o generalizar cuasi-identificadores únicos que reduzcan la k-anonimidad por debajo de $k=5$.
2. **Fallo por Desincronización de la Bóveda de Pseudónimos**: Perder la tabla de correspondencia local en memoria por reinicio no planificado del contenedor antes de persistirla en almacenamiento seguro.
   - *Control*: Almacenar los mapeos de pseudonimización en una instancia local de Redis/PostgreSQL cifrada con clave AES-256 antes de despachar la llamada a Jev.

### 7.2. Condiciones taxativas de no uso
- **No permitir el bypass del sanitizador para "pruebas de desarrollo"**: El entorno de desarrollo debe utilizar exactamente los mismos filtros de seguridad que producción.
- **No utilizar LLMs de terceros para sanitizar el texto antes de enviarlo a Jev**: Enviar el texto con PII a otro LLM para que lo "limpie" incurre exactamente en la misma infracción de privacidad que se intenta evitar. La sanitización debe ser 100% determinista y ejecutarse en CPU local.

## 8. Validación propuesta (propuesta, no ejecutada)

- **Hipótesis falsable**: La integración del módulo `PreFlightSanitizer` en CPU logra una tasa de neutralización de secretos y credenciales del **100%** y una tasa de pseudonimización de PII regulada $\ge 99.8\%$ sobre un conjunto de prueba de 2,000 textos ruidosos, con una latencia computacional agregada inferior a **0.8 ms** por documento.
- **Comparador / Línea base**: Procesamiento tradicional sin sanitización local previa.
- **Conjunto de datos sintético**: 2,000 fragmentos de texto sintéticos conteniendo 500 secretos inducidos deliberadamente (tokens de API, JWTs, claves privadas) y 1,500 datos de PII (RUTs, emails, teléfonos, tarjetas bancarias).
- **Métricas cuantitativas**:
  - Tasa de Fuga Residual de Secretos (debe ser estrictamente 0%).
  - Tasa de Pseudonimización Correcta de PII.
  - Sobrecarga de latencia introducida en el pipeline de ingesta.
- **Umbral de éxito**: Fuga de secretos $= 0\%$; Pseudonimización de PII $\ge 99.8\%$; Latencia añadida $\le 0.8\text{ ms}$.
- **Criterio de rechazo**: Si se detecta un solo secreto que logre atravesar el filtro sin ser redactado.
- **Presupuesto supuesto**: 0 llamadas a Jev; 100% evaluación algorítmica en CPU local; \$0 de coste de API.

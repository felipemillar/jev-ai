# JEV-P04-011: Condensación de Documentos Extensos sin Sesgo de Resumen Generativo Previo

## 1. Respuesta directa y decisión que permite tomar

El uso de un modelo de lenguaje generativo (Sistema 2) para crear resúmenes en prosa previos a la decisión de Jev 1.13 es un **antipatrón arquitectónico grave**: introduce alucinaciones sutiles, omite hechos cuantitativos o salvedades no prominentes y condiciona al clasificador final a evaluar una síntesis sesgada, convirtiendo el error del resumidor en la única evidencia disponible.

Para condensar documentos extensos (e.g., reportes anuales de 100 páginas, expedientes judiciales o manuales de políticas de 50k tokens) sin sufrir este sesgo de cuello de botella, la arquitectura debe implementar el **Patrón Map-Reduce Determinista sobre Fragmentos Atómicos en Parallel Sampler**:
1. **Fase Map (Evaluación Factual Distribuida)**: El documento extenso se segmenta deterministamente en CPU en $M$ fragmentos limpios ($< 1,500$ tokens cada uno, ver `JEV-P04-010`). Cada fragmento se envía de forma independiente o en lotes concurrentes en el `state` a Jev, evaluando preguntas atómicas idénticas mediante `Noul`, `Choice` o `Score`.
2. **Fase Reduce (Agregación Probabilística en CPU)**: En lugar de redactar un resumen en texto, la aplicación en CPU combina algebraicamente las distribuciones de probabilidad y scores obtenidos en cada fragmento (mediante operadores de máximo, percentiles o ponderación bayesiana por certidumbre), deduciendo la decisión global sin haber generado una sola línea de texto libre.
3. **Preservación del Enlace a la Evidencia Primaria**: Cada probabilidad calculada mantiene el enlace exacto al fragmento original que la disparó (`passage_id`), permitiendo auditorías forenses transparentes sin depender de paráfrasis.

**Decisión que permite tomar**: Prohibir taxativamente el uso de LLMs generativos para pre-resumir documentos extensos destinados a Jev. Exigir la implementación del patrón Map-Reduce determinista con evaluación pasaje por pasaje en Jev y agregación numérica de probabilidades en CPU.

## 4. Explicación técnica verificable

### 4.1. Flujo del Patrón Map-Reduce Probabilístico

```text
[ DOCUMENTO EXTENSO (100 páginas, 60k tokens) ]
                       │
                       ▼  (Particionado Semántico en CPU, sin LLM)
   ┌───────────────────┬───────────────────┐
   ▼                   ▼                   ▼
[ Bloque 1 (1k tok) ] [ Bloque 2 (1k tok) ] [ Bloque M (1k tok) ]
   │                   │                   │
   ▼                   ▼                   ▼  (Inferencia Paralela en Jev)
[ Jev: p_1, c_1 ]     [ Jev: p_2, c_2 ]     [ Jev: p_M, c_M ]
   │                   │                   │
   └───────────────────┼───────────────────┘
                       │
                       ▼  (Fase Reduce en CPU: Operador Determinado)
             P_global = max_i(p_i)   o   Score_global = sum w_i * Score_i
                       │
                       ▼
          [ DECISIÓN EMPRESARIAL FINAL ] + [ ENLACE AL BLOQUE GANADOR ]
```

### 4.2. Operadores de Reducción Típicos en CPU

1. **Detección de Anomalías / Riesgo Existencial (Operador Supremo / ANY)**:
   Si el objetivo es detectar si en algún lugar del documento existe una cláusula de incumplimiento:
   $$P_{\text{riesgo\_global}} = \max_{k \in \{1, \dots, M\}} P(\text{anomalía} \mid \text{bloque}_k)$$
   Basta con que un solo bloque contenga evidencia sólida ($p_k > 0.90$) para que la decisión global alerte sobre el riesgo.
2. **Evaluación de Severidad / Madurez Acumulada (Operador de Media Ponderada)**:
   Para un índice de completitud o calidad a lo largo de todo el informe:
   $$\text{Score}_{\text{global}} = \frac{\sum_{k=1}^M \text{certainty}_k \cdot \mathbb{E}[L_k]}{\sum_{k=1}^M \text{certainty}_k}$$
   Pondera los puntajes de los bloques según la certidumbre empírica informada por Jev en cada fragmento.

### 5.1. Ejemplo sintético trabajado: Motor Map-Reduce de Auditoría en Python

```python
# Ejemplo ilustrativo no ejecutado
"""
probabilistic_map_reduce.py
Condensación determinista de documentos extensos mediante evaluación distribuida en Jev.
"""
from typing import List, Dict, Any, Tuple
import numpy as np

class ProbabilisticMapReducer:
    def __init__(self, tau_threshold: float = 0.85):
        self.tau = tau_threshold

    def map_evaluate_chunks(self, chunks: List[Dict[str, Any]]) -> List[Dict[str, Any]]:
        """
        Simulación de llamadas paralelas en Jev sobre M fragmentos independientes.
        Cada llamada evalúa la misma pregunta de Noul: '¿Existe litigio contingente activo?'
        """
        results = []
        for c in chunks:
            text = c["text"].lower()
            # Inferencia simulada de Jev según el contenido del bloque
            if "demanda" in text or "litigio" in text or "arbitraje" in text:
                p = 0.94
                cert = 0.88
            else:
                p = 0.02
                cert = 0.96

            results.append({
                "chunk_id": c["chunk_id"],
                "p_litigio": p,
                "certainty": cert,
                "text_snippet": c["text"][:60] + "..."
            })
        return results

    def reduce_risk_decision(self, map_results: List[Dict[str, Any]]) -> Tuple[str, float, str]:
        """
        Fase Reduce determinista en CPU: Operador Max-Risk.
        """
        # Identificar el bloque que reportó el mayor riesgo
        max_item = max(map_results, key=lambda x: x["p_litigio"])
        p_global = max_item["p_litigio"]
        winning_chunk = max_item["chunk_id"]

        if p_global >= self.tau:
            decision = "ALERTA_LITIGIO_DETECTADO"
        else:
            decision = "SIN_LITIGIOS_REPORTADOS"

        return decision, p_global, winning_chunk

if __name__ == "__main__":
    # Documento extenso simulado de 3 bloques (ej. Memoria Anual de 100 páginas)
    documento_bloques = [
        {"chunk_id": "PAG-01-20", "text": "Resultados operacionales sólidos con crecimiento de ingresos del 15% en el año fiscal..."},
        {"chunk_id": "PAG-21-40", "text": "Detalle de inversiones en activos fijos e infraestructura de TI en sucursales..."},
        {"chunk_id": "PAG-41-60", "text": "Nota 14 (Contingencias): La empresa enfrenta una demanda arbitral por $10,000,000 USD..."}
    ]

    reducer = ProbabilisticMapReducer(tau_threshold=0.85)

    # 1. Fase Map: Jev evalúa cada bloque limpiamente (<1,500 tokens)
    map_outputs = reducer.map_evaluate_chunks(documento_bloques)
    print("--- 1. RESULTADOS DE LA FASE MAP (Jev Inferencia Paralela) ---")
    for r in map_outputs:
        print(f" [{r['chunk_id']}] P(Litigio)={r['p_litigio']:.2f} (Certeza={r['certainty']:.2f}) -> {r['text_snippet']}")

    # 2. Fase Reduce: Agregación en CPU sin LLM intermediario
    decision_final, prob_max, bloque_origen = reducer.reduce_risk_decision(map_outputs)
    print("\n--- 2. RESULTADO DE LA FASE REDUCE DETERMINISTA EN CPU ---")
    print(f"Decisión Final: {decision_final}")
    print(f"Probabilidad de Riesgo Global: {prob_max:.2f}")
    print(f"Evidencia Primaria Trazable: Bloque {bloque_origen}")
```

### 5.2. Contraejemplo y caso límite: La Alucinación del Resumen Generativo

Un equipo utiliza un LLM generativo comercial para resumir un informe financiero de 80 páginas antes de enviarlo a Jev:
- **Prompt al LLM**: `"Resume las notas financieras en 3 párrafos destacando los ingresos y el EBITDA."`
- **Fallo del LLM**: El modelo generativo resume brillantemente los ingresos y el EBITDA, pero descarta por completo la Nota 14 sobre la demanda arbitral de \$10M USD al considerarla un detalle accesorio respecto al objetivo principal del prompt.
- **Inferencia de Jev sobre el resumen**: Jev lee el resumen de 300 tokens, no encuentra ninguna mención a demandas y clasifica la empresa como `RIESGO_LEGAL_CERO` ($p = 0.01$).
- **Consecuencia**: La empresa invierte en un activo tóxico al basar su decisión en un resumen sesgado.
- **Mitigación**: Con el patrón Map-Reduce probabilístico, cada bloque se evalúa directamente; la Nota 14 nunca es excluida y la alerta se dispara automáticamente.

## 7. Fallos, límites, controles y condiciones de no uso

### 7.1. Modos de falla específicos
1. **Fallo por Descarte de Dependencias Inter-Bloque**: Situaciones donde el sujeto está en el Bloque 1 y el verbo condenatorio en el Bloque 2 debido a una mala fragmentación.
   - *Control*: Utilizar siempre el fragmentador semántico con solapamiento del 20% (`JEV-P04-010`) antes de la fase Map.
2. **Fallo por Operador de Reducción Inadecuado**: Usar una media simple (`mean`) en lugar de `max` para detectar fraude o litigios; si 99 bloques son limpios y 1 contiene fraude, la media dará $0.01$, ocultando la amenaza.
   - *Control*: Definir matemáticamente el operador de reducción en el Manifiesto de Decisión (`DSM-v1`).

### 7.2. Condiciones taxativas de no uso
- **No utilizar Map-Reduce si el documento cabe cómodamente dentro de 1,500 tokens**: Si el documento es breve, procesarlo en una sola llamada atómica es más rápido y económico.

## 8. Validación propuesta (propuesta, no ejecutada)

- **Hipótesis falsable**: Para un conjunto de 200 documentos extensos (promedio 40k tokens) con cláusulas críticas aisladas, el patrón Map-Reduce probabilístico en Jev detecta el **98%** de las anomalías sin ninguna alucinación, mientras que un pipeline basado en resumen generativo previo omite el **32%** de las anomalías debido al cuello de botella de síntesis.
- **Comparador / Línea base**: Pipeline basado en LLM generativo que resume el documento a 500 tokens antes de la clasificación.
- **Conjunto de datos sintético**: 200 informes sintéticos de 40k tokens cada uno con cláusulas de contingencia sembradas aleatoriamente.
- **Métricas cuantitativas**:
  - Sensibilidad en Detección de Anomalías (Recall).
  - Tasa de Trazabilidad Directa al Fragmento Fuente.
  - Coste monetario de API por documento procesado.
- **Umbral de éxito**: Recall Map-Reduce $\ge 98\%$ vs. Resumen LLM $\le 70\%$; Trazabilidad $= 100\%$.
- **Criterio de rechazo**: Si el coste computacional de la fase Map excede en más de un 100% el coste del resumen generativo previo.
- **Presupuesto supuesto**: 2,400 llamadas a Jev (12 bloques por documento); coste API estimado en \$0.048; tiempo de cómputo en CPU: 15 minutos.

# JEV-P04-010: Estrategia de Fragmentación Semántica Jerárquica y Verificación de Suficiencia de Citas

## 1. Respuesta directa y decisión que permite tomar

La fragmentación de documentos basada en conteos fijos de caracteres o tokens (e.g., cortes ciegos cada 500 caracteres o 256 tokens) es el origen primario de las **decisiones erróneas por citas incompletas o descontextualizadas**. Un corte mecánico divide proposiciones subordinadas por la mitad, separa una afirmación general de su excepción inmediata al inicio del párrafo siguiente y mutila pronombres o referencias anafóricas, llevando a Jev a juzgar sobre fragmentos amputados.

Para garantizar la conservación de relaciones inter-párrafo y prevenir decisiones sustentadas en citas deficientes, la arquitectura debe implementar la **Estrategia de Fragmentación Semántica Jerárquica con Verificación en Cascada (*Hierarchical Semantic Chunking with Verification Cascade*)**:
1. **Particionado por Fronteras Estructurales Naturales (AST / Markdown)**: Prohibir el corte arbitrario por longitud. Las unidades de fragmentación mínimas deben coincidir con límites naturales del discurso: párrafos completos (`\n\n`), cláusulas numeradas (`1.1`, `1.2`), o bloques de código/tablas coherentes.
2. **Solapamiento Semántico Parametrizado (*Contextual Overlap*)**: Incorporar una superposición del **15% al 25%** entre fragmentos adyacentes (50–100 tokens), asegurando que los conectores adversativos (`"Sin embargo"`, `"No obstante"`) y las cláusulas dependientes se representen íntegramente en ambos lados de la frontera.
3. **Inyección de Migas de Pan Jerárquicas (*Breadcrumb Metadata Injection*)**: Cada fragmento debe encapsularse con la ruta ontológica de la sección de origen (e.g., `doc_id > capítulo > título_sección > número_cláusula`), proveyendo el ancla semántica global que neutraliza la descontextualización.
4. **Compuerta de Suficiencia Pasaje por Pasaje con `Noul`**: Antes de autorizar una acción, someter el fragmento a una compuerta de verificación rápida en Jev: *"¿Contiene el fragmento evidencia autosuficiente o requiere la lectura de cláusulas complementarias?"*. Si el fragmento es insuficiente, el middleware en CPU fusiona automáticamente el bloque con su fragmento hermano contiguo.

**Decisión que permite tomar**: Prohibir clasificadores ciegos de longitud fija en la ingesta documental de QRT y Wheelwork. Exigir que todo documento extenso sea procesado mediante el fragmentador semántico jerárquico y que las decisiones críticas incorporen la compuerta de autosuficiencia en `Noul` antes de ejecutar transacciones operativas.

## 4. Explicación técnica verificable

### 4.1. Arquitectura de la Fragmentación Jerárquica con Breadcrumbs

Dado un documento estructurado $\mathcal{D}$, el algoritmo de particionado descompone el árbol de contenido respetando la jerarquía:

```text
DOCUMENTO: "Manual_Operaciones_Financieras_2026.pdf"
 │
 ├── [SECCIÓN 3: GESTIÓN DE COLATERAL]
 │    │
 │    ├── Cláusula 3.1: Requisitos de Margen Líquido
 │    │    └── Fragmento P-301 (Párrafo íntegro: 180 tokens)
 │    │         Breadcrumb: "Manual > Sec 3 > Cláusula 3.1"
 │    │
 │    └── Cláusula 3.2: Excepciones por Volatilidad Extrema
 │         └── Fragmento P-302 (Párrafo íntegro: 220 tokens)
 │              Breadcrumb: "Manual > Sec 3 > Cláusula 3.2"
 │              Overlap: Últimas 30 palabras de P-301 inyectadas al inicio
```

### 4.2. Algoritmo de Verificación de Citas en Paralelo (Passage-Level Gate)

Antes de enviar el fragmento seleccionado para una decisión transaccional mayor, el sistema despacha en Jev una consulta doble en el Parallel Sampler:

```json
{
  "q_suficiencia_cita": {
    "type": "noul",
    "instructions": "¿Contiene este fragmento específico toda la evidencia fáctica requerida para determinar si la excepción aplica, sin omitir condiciones limitantes?"
  },
  "q_referencia_incompleta": {
    "type": "noul",
    "instructions": "¿Hace el texto referencia explícita a un anexo o tabla externa no provista que resulte indispensable para el cálculo?"
  }
}
```

- Si `p(q_suficiencia) < 0.70` o `p(q_referencia_incompleta) > 0.50`:
  - El sistema en CPU activa la **Fusión de Fragmentos Contiguos**: recupera el fragmento hermano $P_{k+1}$ o $P_{k-1}$ y reconstruye un estado ampliado antes de emitir la decisión definitiva.

### 5.1. Ejemplo sintético trabajado: Fragmentador Semántico con Overlap y Breadcrumbs en Python

```python
# Ejemplo ilustrativo no ejecutado
"""
semantic_chunker.py
Fragmentador semántico jerárquico que preserva párrafos y relaciones contextuales.
"""
import re
from typing import List, Dict, Any

class SemanticHierarchyChunker:
    def __init__(self, target_chunk_tokens: int = 300, overlap_tokens: int = 50):
        self.target_tokens = target_chunk_tokens
        self.overlap_tokens = overlap_tokens

    def chunk_markdown_document(self, doc_title: str, markdown_text: str) -> List[Dict[str, Any]]:
        # 1. Separar secciones por encabezados de Markdown (#, ##, ###)
        sections = re.split(r"(?m)^(#{1,3}\s+.+)$", markdown_text)
        chunks = []
        current_section = "Introducción General"
        passage_counter = 1

        for part in sections:
            part = part.strip()
            if not part:
                continue

            if part.startswith("#"):
                current_section = part.lstrip("#").strip()
                continue

            # 2. Particionar el cuerpo de la sección por párrafos naturales (\n\n)
            paragraphs = [p.strip() for p in part.split("\n\n") if p.strip()]
            prev_overlap = ""

            for p in paragraphs:
                # Estimar tokens (1 palabra ~ 1.3 tokens)
                p_tokens = len(p.split()) * 1.3

                # Ensamblar fragmento con breadcrumbs y overlap previo
                full_content = f"{prev_overlap}\n\n{p}".strip() if prev_overlap else p

                chunk_obj = {
                    "passage_id": f"P-{passage_counter:03d}",
                    "document_title": doc_title,
                    "section_breadcrumb": current_section,
                    "text": full_content,
                    "estimated_tokens": int(len(full_content.split()) * 1.3)
                }
                chunks.append(chunk_obj)
                passage_counter += 1

                # Calcular overlap para el siguiente fragmento (últimas 30 palabras)
                words = p.split()
                if len(words) > 30:
                    prev_overlap = "[CONTEXTO PREVIO]: ... " + " ".join(words[-25:])
                else:
                    prev_overlap = "[CONTEXTO PREVIO]: ... " + p

        return chunks

if __name__ == "__main__":
    doc_ejemplo = """
# Políticas de Crédito Corporativo

## Sección 4: Exenciones y Garantías

Las líneas de crédito superiores a $100,000 USD requieren una garantía hipotecaria de primer grado inscrita en el registro conservador.

Sin perjuicio de lo anterior, la junta directiva podrá eximir de dicha garantía a clientes institucionales con calificación crediticia AAA certificada por dos agencias internacionales reconocidas.
"""

    chunker = SemanticHierarchyChunker()
    fragmentos = chunker.chunk_markdown_document("Manual_Credito_2026", doc_ejemplo)

    print(f"Total fragmentos generados: {len(fragmentos)}\n")
    for f in fragmentos:
        print(f"--- [{f['passage_id']}] {f['section_breadcrumb']} ({f['estimated_tokens']} tokens) ---")
        print(f["text"])
        print("-" * 65)
```

### 5.2. Contraejemplo y caso límite: Corte Fijo que Amputa una Excepción

Un script de particionado ciego corta el texto cada 150 caracteres:
- **Corte 1 (Fragmento A)**: `"Las líneas de crédito superiores a $100,000 USD requieren una garantía hipotecaria de primer grado inscrita en el registro conservador. Sin perjuicio de lo"`
- **Corte 2 (Fragmento B)**: `" anterior, la junta directiva podrá eximir de dicha garantía a clientes institucionales con calificación crediticia AAA..."`
- **Inferencia errónea**:
  - Si se evalúa el Fragmento A: La frase queda truncada en `"Sin perjuicio de lo"`. Jev concluye que la garantía hipotecaria es obligatoria e ineludible ($p = 0.99$).
  - Si se evalúa el Fragmento B: La frase comienza con `"anterior, la junta..."`. Jev no sabe a qué garantía se refiere y activa la abstención ($p = 0.50$).
- **Consecuencia**: El cliente con calificación AAA es rechazado indebidamente o encolado en soporte manual por un artefacto introducido exclusivamente por el algoritmo de corte rígido.
- **Control**: Respetar siempre fronteras de párrafos y oraciones completas.

## 7. Fallos, límites, controles y condiciones de no uso

### 7.1. Modos de falla específicos
1. **Fallo por Fragmentos Monstruo en Párrafos Gigantes**: Textos legales mal maquetados donde un solo párrafo se extiende a lo largo de 5 páginas ($3,000$ tokens) sin saltos dobles de línea.
   - *Control*: Si un párrafo excede los 800 tokens, aplicar segmentación secundaria por oraciones (`sent_tokenize`) respetando puntos y comas.
2. **Fallo por Bucle Infinito de Fusión de Fragmentos**: Reintentar indefinidamente la fusión de fragmentos insuficientes hasta desbordar la ventana de contexto de 32k tokens.
   - *Control*: Limitar la fusión en cascada a un máximo de 2 fragmentos contiguos ($P_{k-1} + P_k + P_{k+1}$); si la insuficiencia persiste, escalar directamente a revisión humana.

### 7.2. Condiciones taxativas de no uso
- **No utilizar fragmentación fija por conteo ciego de bytes o caracteres en ningún pipeline de decisión**: Esta práctica está formalmente declarada obsoleta en la ingeniería moderna de software para IA.
